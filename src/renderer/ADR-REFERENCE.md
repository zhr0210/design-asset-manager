# renderer — Future ADR reference

Moved verbatim from this module's README on 2026-09-07. These are planned
constraints, not claims that functionality exists. Read only the relevant
entry when the task touches its domain; the canonical ADR retains authority.
ADR 0483/0484 supersession applies to affected clauses in these historical copies.
The full future catalog is not a prerequisite for core AI+ development; current
scope is [PRODUCT-FOUNDATION.md](../../docs/product/PRODUCT-FOUNDATION.md).
Do not append a parallel specification here. Return to [module entry](README.md).

- Planned ADR 0455 crash-draft recovery UI should expose its Text records only through ADR 0465's content-free library counts and contextual recovered-field markers after exact-instance activation. It must not auto-navigate, auto-commit, notify with content, expose protected storage details, or treat recovered drafts as current metadata.
- Planned ADR 0456 Undo routing should give an active Text draft priority within ADR 0465's shared typed framework. When no draft owns the shortcut, it exposes the identified newest manual Custom Field commit across types; revision drift or memory-expired steps must show conflicted/unavailable state rather than falling through, and the shared committed stack remains current-library-session-only.
- Planned ADR 0457 Batch Text UI should show All Missing/Same/Mixed plus No Change before offering Set, Clear, Prefix, Suffix or Exact Literal Replacement. It should render the trusted frozen plan's bounded examples and outcome counts, keep exact action/Missing behavior visible, and project persisted per-owner results instead of looping over selected values in the renderer.
- Planned ADR 0458 Batch Text recovery UI should show aggregate committed/remaining state and keep interrupted work Paused until explicit evidence-qualified action. On a device without the initiating journal it may offer Cancel Remaining but must explain why Resume, Undo Completed and Clear Result And End Undo are unavailable; a later new batch is visibly separate. It must not display previous Text outside bounded reviewed detail, invent journal availability, auto-resume, or silently select no-Undo.
- Planned ADR 0459 Text editors and Batch Text parameter inputs should accept only an explicit Unicode plain-text clipboard/drop representation. They preserve received whitespace, line breaks and valid invisible formatting, then show ordinary validation without trimming or stripping. Rich-only, file, image and asset-object transfers are rejected contextually; paths/URLs already present in accepted plain text remain literal and never trigger import, links or relationships.
- Planned ADR 0460 native Text Copy/Cut should require an editor selection and emit only plain Unicode. Cut removes selection only after successful copy and stays draft-local. Copy Full Text must visibly choose the complete Unsaved Draft when present or otherwise the authoritative value, never Compact summary text; Missing is unavailable. Unsafe controls block without mutation, and clipboard-retention disclosure must not imply reliable automatic clearing.
- Planned ADR 0461 Text writing UI should keep spelling/grammar markers advisory, distinguish Checked/Not Checked/Unavailable and default every automatic mutation Off. Device-local opt-in replacements and explicitly applied proposals remain range-bound draft edits with Undo and ordinary validation. Any possibly external action must disclose provider, purpose and selection-versus-complete-draft scope in trusted UI and must never start from typing, focus, provider setup, AI Value Suggestions or extension permission.
- Planned ADR 0462 Number editors should show the active device-local input locale and trusted exact parse preview. Conflicting locale/canonical interpretations must remain visibly blocked with all candidate exact values; invalid grouping, currency, percent, unit, expression and rich/object transfers stay uncommitted rather than being guessed or stripped. Existing values edit from a complete round-trip exact representation, while precision-limited display is marked approximate whenever it differs numerically and provides direct full-exact access.
- Planned ADR 0463 Number display UI should default to Automatic Exact and expose field-level Fixed Decimal Places 0–34, Significant Digits 1–34 and grouping Auto/On/Off. It must render trusted exact-decimal projections, mark only numerically changed rounded values with `≈`, avoid negative-zero display, keep units outside the number, disable grouping for scientific notation and provide direct full-exact access for every approximation.
- Planned ADR 0464 inline Number UI should replace over-64-grapheme or non-fitting requested formatting with a labelled normalized scientific fallback that preserves the existing exact/rounded result and `≈`. Its detail surface separately renders complete requested formatting and authoritative exact value on demand. If even fallback cannot fit, ellipsis requires a visible overflow state, accessible explanation and detail affordance rather than standing alone as numeric content.
- Planned ADR 0465 manual Custom Field UI should project one typed draft model, one contextual Save/Discard/Stay gate and one chronological current-library Undo stack across field types while retaining type-specific validation and gestures. Window blur never commits. Number blank input is an explicit Clear-to-Missing proposal rather than zero; invalid, ambiguous and stale drafts remain blocking and recoverable, with restored Number literals visibly reparsed under current rules.
- Planned ADR 0466 multi-draft gate UI should group affected drafts by owner and show field, type, validity/recovery state and explicit Save/Discard disposition without leaking values to notifications. Save All stays disabled until every draft is current and valid; Fix/Stay focuses the first blocker, and multi/recovered Discard All confirms loss. After trusted execution, resolved/failed/remaining groups remain visible, a partial result keeps navigation blocked, and the renderer must not claim global atomicity or turn the gate into Batch Activity.
- Planned ADR 0467 Undo UI should present a same-owner multi-field save as one compound entry with owner, affected field count/types and group eligibility. Undo/Redo acts on the complete entry or not at all; one drifted field blocks the group, and type-filtered views cannot offer Text-only, Number-only or other partial replay. Cross-owner steps appear in actual commit order, with no entries for discard, failed or unstarted groups.
- Planned ADR 0468 Unavailable Undo Step Review should identify owner, ordinary/compound scope, field count/types and typed blocking reasons, with Keep as default. Read-only eligibility recovery re-enables but never executes Undo. Remove Undo Step requires confirmation and removes only the whole still-unavailable entry and its Redo branch; the next older step is not auto-run. Do not expose skip-once, partial/type removal, bulk/automatic removal or imply that removal changes metadata/history.
- Planned ADR 0469 Advanced Settings should expose Manual Undo Steps 20–1,000 (default 200) and Memory 8–256 MiB (default 64) as synchronized exact integer inputs/sliders, plus current retained count/estimated bytes. Cap reductions review projected whole-step loss; normal eviction reports only aggregate expiry. Oversized Manual Undo Review must appear before writes with owner scope, field count/types, estimate/limit and Increase Limit, Return To Editing or Save Without Manual Undo as applicable. It must not imply split compound evidence, disk spill, post-save warning or guaranteed process-memory reservation.
- Planned ADR 0470 Save Without Manual Undo confirmation should explicitly disclose both the unrecorded prospective save and the aggregate retained manual Undo/Redo count and estimated memory that success will clear. Return/failed commit leaves history untouched; proven success clears it before UI success, leaves no selectable barrier, and refreshes the shortcut/menu state. A cross-owner plan must show each boundary at its frozen owner position and represent later recordable owner steps as a new timeline without suggesting that operation-scoped Undo was cleared.
- Planned ADR 0471 critical-pressure UI must not prompt while fresh trusted Critical memory pressure requires last-resort manual-history reclamation. It should refresh Undo/Redo availability and show one content-free session aggregate with pressure-expired complete-entry count, retained count and estimated bytes; it must not expose values/per-entry detail, send a system notification, claim Unknown pressure is Critical, offer restoration or imply that the configured lower budget is guaranteed.
- Planned ADR 0472 Boolean fields should render explicit localized Not Set/Yes/No choices as an accessible three-choice control or a semantically identical dropdown at constrained widths. A switch, indeterminate checkbox, click-current-to-clear and implicit default are forbidden. Current choice is a no-op; another shows field-scoped Pending until trusted success, without optimistic authority or draft/recovery state. Failure restores the prior authoritative projection and contextual reason, while success refreshes ordinary manual Undo availability.
- Planned ADR 0473 Boolean definition UI should keep Default disabled initially, offer only True or False when enabled and state Future New Owners Only before confirmation. It must not offer Missing as a default, imply existing-value fill or hide Promotion/import precedence. New-owner creation/import review shows Explicit, Imported, Transferred or Definition Default source and refreshes on revision drift; existing-owner initialization routes to a separate previewed batch rather than the schema control.
- Planned ADR 0474 default editors should reuse the exact type editor/validation for Text, Number, Date, DateTime, Boolean, Single Select, Multi Select and URL, while clearly labelling the value Static and Future New Owners Only. They must not offer Missing as a value, dynamic Today/Now/context/path/user/device/random/AI/plugin/formula/reference choices, formatted-number authority or Select labels without stable identities. Every creation/import review shows source and revision; later-ineligible defaults remain visibly non-applicable pending a dedicated repair rule.
- Planned ADR 0475 invalidating schema/option reviews should show the exact affected default and require Replace With Valid Value, Disable Default or Cancel; Select merge may show an explicit stable-identity retarget. Unexpected invalidity renders the definition-level Default Needs Attention state and Suspended default without asset-level badges. Direct creation/import explains Missing; automatic creation remains non-blocking and silent per owner. Repair offers valid replacement/disable, never automatic label matching, and states that previously Missing owners are not backfilled.
- Planned ADR 0476 initialization UI should let users choose current selection, one stable-filter generation or explicit library-wide scope, then configure one or more fields from a current static default snapshot or explicit exact typed value. Review shows owner/field-type eligible Missing, present/Out-of-Constraint excluded, unchanged, invalid and conflict counts plus bounded examples. It must never offer overwrite-present. Progress/pause/cancel/result surfaces use owner groups and truthful partial outcomes; terminal Undo says it clears only still-current successful effects back to Missing and cannot restore drifted groups.
- Planned ADR 0477 recovery UI should identify the exact library and show only bounded aggregate state until trusted inspection establishes complete compatible authority. It must never auto-resume after restart, device change or reconnect. Offer explicit Resume and Cancel Remaining; offer Undo Completed directly only for terminal work, otherwise one Cancel Remaining And Undo Completed consequence that explains remaining owners become terminal before still-current successes clear to Missing. Copied/colliding libraries, restored backups and missing/corrupt/unsupported evidence render blocked or read-only rather than guessed recovery.
- Planned ADR 0478 scope UI should label Current Selection, Stable Filter generation and Library-Wide as current-library scopes and separately count Active Candidates and non-deleted Design Assets. Show selected Candidate History, cleanup, Asset Trash and other-library occurrences as exclusions rather than silently omitting or editing them; offer Restore/Open Library as navigation only, never an implicit plan step. Offline source bytes must not appear as a Custom Field eligibility error. Membership drift before confirmation requires Refresh Preview, while post-confirm lifecycle changes appear as exact-owner conflicts with no replacement-owner action.
- Planned ADR 0479 result UI should label only proven transient, uncommitted terminal owner groups Retry Eligible and allow manual selection from that subset. It must show attempt count up to the existing three-attempt limit, disable duplicate in-flight attempts and merge refreshed outcomes into the same result. Present values, lifecycle/schema drift, ambiguous writes and recovery states show their exact non-retry reason. Do not offer automatic retry or a catch-all Retry All; changed intent routes to Create New Plan rather than editing the frozen assignment.
- Planned ADR 0480 result UI should present forward recovery and Undo as one-way directions, not simultaneous controls. While Retry is active, disable Undo admission until it settles; include retry successes in later Undo counts. Undo confirmation must show the still-current success count and retry-eligible count that will be permanently abandoned. Commit the visible reverse direction only after trusted preflight succeeds; then remove every old Retry action before showing Undo progress. Partial Undo must show unresolved effects without restoring Retry or offering Redo, and assigning again routes to Create New Plan.
- Planned ADR 0481 result UI should show one exact expiry for detail, Retry and Undo, defaulting to 30 days from first terminal reconciliation. Do not reset the displayed deadline after retry, Undo, view, restart, library switch or device change. At expiry show that no new item will start while the current atomic item settles. Clear Result And End Actions requires a terminal idle confirmation showing Retry-Eligible, Undo-eligible, conflict/exclusion counts and current direction; it changes no field. After expiry/clear, render only value-free aggregate Pruned Batch Detail with no executable control.

## Status center, recovery and Text editing

The following additional paragraphs were preserved from the same README.
Status center/notification/recovery semantics belong to ADRs 0400–0403;
Text editing and draft recovery belong to ADRs 0453–0465. These are future
constraints; current route/source inspection does not establish their delivery.

- Planned no-window status UI should use one static monochrome application icon and compact card anchored to the native macOS menu-bar or Windows notification-area item, project only the highest aggregate attention mark with full tooltip/accessibility text, organize export/AI/download-install/preview-index work into independently controlled path-free sections, and follow platform focus, keyboard, contrast and reduced-motion behavior.
- Application Status Center global Quit should use the content-free Safe Stop And Quit confirmation when work is active; after acceptance it should show an aggregate Safely Quitting state for the application-wide 30-second maximum, without Force Quit, Finish Entire Queue, cancellation or private work detail.
- Startup reconciliation should leave the normal application interface and unaffected work available, project unresolved work as aggregate Needs Attention in Application Status Center, and route detail to the existing owning visual recovery surface rather than a whole-application blocking modal.
- Startup recovery should never auto-open or auto-navigate. Main UI and Application Status Center keep an aggregate attention count, affected work carries Recovery Required, and the explicit review workspace groups read-only Evidence-Proven Complete/Safely Paused results separately from Ambiguous items with only their operation-owned safe actions.
- Defer Startup Recovery Review should affect only the current session's expanded presentation; durable attention, affected-work marks and conflict isolation remain, while relevant evidence changes may trigger a silent read-only recheck without reopening UI or sending an OS notification.
- Long-unavailable recovery dependencies should project Waiting For Recovery Evidence, while Storage Management accounts safely calculable journal/receipt/required-staging bytes in a distinct read-only interrupted-operation category rather than cache cleanup.
- Storage Management may expose Release Safely Rebuildable Recovery Staging for a freshly proven eligible item only; its confirmation shows bytes and full-reprocessing impact, while success retains evidence and projects Safely Paused Without Staging.
- Recovery Staging Release Batch should start unselected, support multi-select and Select All Currently Eligible, summarize item/byte/full-reprocessing counts, and project independent per-item validation and commit without batch rollback or remembered cleanup policy.
- In-flight recovery-staging release should expose Cancel Remaining Releases rather than Pause/Resume, stop new dispatch, let the current item settle, retain completed releases, mark untouched selections Cancelled Before Release, and never resume after restart.
- Interrupted multi-member staging removal should reconcile per-member outcomes into Released, Release Failed, or Staging Release Reconciliation Required; the recovery UI shows aggregate member/byte evidence and offers explicit Complete Remaining Release only after fresh proof, never automatic continuation or partial-staging reuse.
- Staging Release Reconciliation View may group, filter and sort multiple items but should expose no selection or batch recovery action; Complete Remaining Release stays separately reviewed per item, while a wholly intact recheck returns only that item to ordinary unselected batch eligibility.
- Complete Remaining Staging Release Review should use one item-scoped confirmation showing remaining count, proven bytes and full-reprocessing consequence, with no typed-name/password challenge; confirm revalidates current evidence and drift refreshes without mutation or reusable consent.
- Successful Complete Remaining Release should use Recovery Staging Release Result Merge to show Released After Reconciliation in the original record, retain interruption history, project Safely Paused Without Staging, add only proven bytes, and resolve item attention without a new record/notification/retry count.
- Failed completion should append a minimal path-free Recovery Staging Completion Attempt to the same item and expose Try Again only after fresh proof plus new confirmation; show manual attempt count without an arbitrary limit, batch retry, automatic retry, or reusable consent.
- Recovery Staging Attempt Compaction should preserve every state-changing attempt and coalesce only consecutive identical no-change failures into count/first/latest time/latest typed reason; resolved 30-day history keeps the interruption, changes and final result without paths, filenames, raw errors or payloads.
- After that history expires, remove its visible timeline, reasons and statistics. ADR 0401 keeps only a non-rendered path-free Recovery Staging Terminal Marker while a live reference or replay-prevention need remains, and deletes it when both end.
- If a live reference finds its terminal marker missing, damaged or contradictory, show Recovery Staging Terminal Evidence Unverifiable only for the item and exact shared conflict scope. Allow read-only reconstruction to repair one uniquely proven terminal marker; otherwise keep recovery attention and expose no release or automatic-cleanup action.
- Reconstruction should present claim-scoped evidence rather than imply a fixed source priority: journals/receipts establish intent and boundaries, matching current-member identity/generation establishes physical state, and task state is only a projection. Timestamp recency cannot resolve a contradiction, and the UI must not offer Mark Successful.
- Offer Retire Unverifiable Recovery only as an explicit user decision when missing evidence is not expected to return. It should claim no success/failure and mutate no files, stop the old attention/isolation, show Recovery Retired — Outcome Unknown, retain a non-rendered anti-replay tombstone, and require complete new preflight for any later same-target write.
- Retire Unverifiable Recovery Review should be item-scoped and two-step with no batch/apply-to-all control: show scope, unavailable evidence, unknown result and irreversible consequences, then require an acknowledgment checkbox plus confirm without typed name/password. Confirm rechecks evidence and routes changed/restored evidence to normal reconciliation without retiring.
- Returned Retired Recovery Evidence Check should run once per returned evidence generation, read-only and without reviving the old operation: silently settle a uniquely proven tombstone, keep still-unknown state silent, or project fresh exact attention/isolation only for a proven current mixed/partial conflict. It must not mutate, auto-open UI or notify the OS.
- Review Returned Recovery Conflict should be read-only and offer only Defer or Create Returned-Evidence Recovery Plan. The plan gets a new operation identity, current evidence/member scope, complete owner-specific preflight and independent review/consent; the old tombstone supplies lineage/anti-replay evidence only, and evidence drift invalidates the draft.
- Returned-evidence plans should offer Safely Release only for a complete current set proven application-owned, unpublished, outside destructive boundaries, no longer outcome-bearing and rebuildable. Otherwise a complete identified app-owned set may be Preserve First copied and verified to a user-selected local folder outside app data while staging remains unchanged; releasing it is a separate confirmation. Ambiguous identity/ownership/publication keeps the view read-only and never touches source or published files.
- After a verified preserve-first copy, Keep Staging may show Preserved — Staging Retained and clear conflict attention/isolation only when staging is app-owned, inert, cannot affect user paths and is no longer outcome evidence. Surface its bytes as Protected Preserved Recovery Staging outside cache/automatic cleanup, with no recurring reminder; later release needs a new plan. Otherwise keep exact attention/isolation.
- Recovery-staging release results should separate Released, Proven Already Absent, Cancelled Before Release, Staging Release Reconciliation Required, Excluded After Evidence Change and Release Failed with Complete/Partial/None Released/Cancelled aggregate, report only proven reclaimed bytes, and offer explicit freshly validated retry for failed items only.
- A user-cancelled release with no Released item should aggregate as Cancelled; with earlier releases it is Partial plus cancelled count. Cancelled items create no result attention/retry/completion notification, retain original recovery attention, and require a new batch for later release.
- Recovery-staging batch results should use 30-day-default lightweight Reviewed Batch Action history; Complete has no activity badge, while explicit acknowledgment or dismissal affects only result history and never the affected work's recovery attention/evidence/isolation. Opening detail alone is not acknowledgment.
- A user-confirmed long-running recovery-staging release may emit one ordinary aggregate background-completion notification only when OS permission and every represented owning-operation preference allow it; automatic/read-only recovery never notifies, and activation opens only the current batch result.
- Planned Text Custom Field editors should honor ADR 0453 portable Compact or Expanded defaults while preserving identical multiline content. Compact must disclose and expand for multiline editing; Expanded may resize vertically within Inspector bounds and should show authoritative grapheme, whitespace and invisible-format evidence without changing field schema.
- Planned Text editing should follow ADR 0454 as an ADR 0465 typed-draft specialization with IME keyboard ownership: defined Save/Enter shortcuts and valid same-Inspector field exit may commit, window blur must not, invalid/stale drafts stay inline, and owner/result/route/library/close transitions use the shared contextual Save/Discard/Stay gate.
- Forget Library Registration should default Batch Text recovery to Keep and show only path-free active/Paused and terminal-Undo counts. It must route non-terminal clearing through explicit Cancel Remaining first. Uninstall Preparation recommends cancelling uninstall to review recovery; explicit proceed warns that Undo is irrecoverable but leaves unfinished operations Paused rather than implying cancellation, while external removal is described as outside the app's interception guarantee.
