# Gallery presentation

Shared Renderer presentation extracted from the latest user-approved Gallery & Glass prototype.
`DESIGN.md` owns the complete visual contract and tokens; mobbin.md is only a redirect.

- `gallery.css` scopes the approved cascade to `.gallery-design`; the prototype and formal host both use it.
- `tokens.css` is generated by `scripts/sync-gallery-tokens.mjs`, checked with `--check`. Included workspaces opt into `html.app-design`; shared semantic roles and accessibility overrides live in the app design scope.
- `work-window-legacy-tokens.css` preserves the excluded Work Window and its dedicated preview roles. Updating included workspace tokens must not silently restyle those consumers.
- `AnchoredGrid` takes ordered identities/render callbacks, preserves columns and shrinks on inspector opening.
- `BottomDock` takes query/tag/format actions, live feedback and mounted retrieval controls. Its collapsed retrieval surface stays mounted to retain example grants and task state. The host supplies the local action inventory; global navigation uses the shared narrow rail and a body-level menu portal. No router, API or fake actions inside BottomDock.
- `WorkReferencePanel` is the shared multi-reference window presentation; native/prototype adapters own dragging, persistence and callbacks.
- `FolderCard` renders supplied covers/colors; it does not decide membership, copy files or persist folders.
- `FocusView`/`FocusCanvas` provide hard cuts, zoom, pan, note tools and filmstrip. NotebookAdapter supplies
  session/load/save state. No localStorage, Main, filesystem or fixture imports in shared presentation.
  Before conflict reconciliation it requires unfinished text, sticky notes and drawing
  to be completed or cancelled. The pending read locks annotation and navigation
  controls; failure releases them with the existing pages intact. Formal persistence
  and conflict-copy checkpointing remain the Notebook Adapter's responsibility.
- `ColorTools` renders color context actions. Formal ratios and availability must come from the host.

Prototype wrappers alone own generated fixtures and prototype storage. Formal `library/canvas` adapters
supply controlled previews, actual capabilities and existing trusted operations. The visual tracer can substitute
synthetic media under its own Vite plugin; production preview guards never accept that substitute.

Verification: `node scripts/check-gallery-parity.mjs` (15 groups at 3 widths), original focus-note interaction
checks, and formal Electron tests are separate evidence. `DAM_GALLERY_REFERENCE` can point to a frozen
pre-change prototype root for an independent baseline. Screenshots and metrics state which baseline was used.
