# Generated-image service acceptance

Formal AI Console -> narrow Main IPC -> acceptance service -> signed one-use permit -> existing
Connection Gateway / Visual Controller -> owned generated temporary Active Library Host.
Plan generation reads public configuration only: no Vault, catalog, probe or network.
The current user library is never supplied to this service. Its controlled generated
96x64 PNG and library are created within one canonical owned temporary root.

Explicit confirmation issues a private HMAC permit binding configuration, credential revision,
model, origin, generated input SHA, action and finite request/token/time/estimated-cost budgets.
Reserve before every invocation: no refunds, replay or implicit renewal. Truncation retry spends
a second request. Acceptance disables OAuth refresh, preventing unbudgeted authentication traffic.
Cost is the user's conservative estimate, not measured usage or a guaranteed billing cap.
Unknown prices (default zero on chargeable connections) reject execution. Only owned synthetic
tests use zero-price fixtures.

Prepare and confirmation are tracked before their first await. Drain suspends admission and
waits preparation, confirmation, controller completion, verification and disposal. Unknown owned
process exit retains resources until release; a bounded drain timeout does not claim storage
closed. Successful evidence is verified after Host reopen and source bytes are unchanged.
Only bounded diagnostic codes are public, never raw errors, credentials, images or private paths.

node scripts/ai-service-acceptance.mjs defaults to PLAN_ONLY and imports no app/credential/model
service. CLI execution refuses to mint approval: use the formal reviewed UI. Tests use owned
loopback services, generated temporary data and synthetic vault protection. They prove fixed
SDK, Main/preload/Renderer and real Host chains. Account, quality, billing, OS Keychain, Windows
and signed installer checks remain NOT_RUN.
