# Capture Intake

Main owns the reviewed **Copy Into Library** path. The production Active Library
Host composes AddAssetsWorkflow, Capture Gateway, SQLite persistence and Sharp
System Preview; the Library UI uses path-free prepare/confirm/inspect commands.
Browser selection is a Host capability, never an arbitrary browser file path.

## Interface and authority

- prepare() selects local files through an injected Adapter and returns a
  read-only Copy Plan. Planning creates no managed files, Candidate or Asset.
- dispatch({ kind: 'confirm-plan', planReceipt }) confirms that exact plan.
- inspect({ batchIdentity }) reads the authoritative batch projection.

Renderer must not allocate identities, write Asset state or copy files. One
inspected and locked Active Library connection owns the destination and SQLite
transaction. Capture Gateway owns request identity, Candidate lifecycle,
required-preview gating, Design Asset identity and Promotion Link. The additive
schema does not infer ownership or backfill existing Assets.

Accepted requests retain per-item envelopes and ordered batch membership.
Replay checks source/locator/method/metadata intent and returns durable state;
it never silently retries or creates new identities. Promotion leaves a
historical Candidate and atomically commits the Asset and Promotion Link.

## Copy, preview and recovery protections

Ordinary PNG/JPEG/WebP selection uses signature routing, attempt-owned staging,
SHA-256 verification, managed-root/symlink containment and atomic no-replace
publication. Required Preview is an independent derivative of the committed
Original, matches source generation/format, and exposes only an opaque reference.
Windows disables Sharp's file-handle cache so owned files can be removed after
processing. Original bytes remain distinct from previews and variants.

The Main-only resumeAccepted option supports held owned-download recovery.
It requires the original admission tuple, resumes incomplete items, verifies
retained staging/Originals and never replaces conflicts. Preview identity reuse
requires matching newly generated bytes. It is not an arbitrary source rescan.

Copy Plan preparation runs at most eight source checks concurrently and retains
selection order and review of every item. Confirmation still checks the reviewed
source evidence. Folder recursion, new formats and producer integration must be
checked against their actual consumers; this module does not grant them support.

## Evidence and verification

Focused workflow/SQLite tests cover zero-write planning, source preservation,
replay, no-replace publication, containment, restart-visible Promotion and
transaction rollback. Use the repository Electron test launcher for SQLite;
do not rebuild shared native dependencies for a shell Node ABI mismatch.

```sh
npm run test-capture-intake-workflow
npm run test-capture-intake-sqlite-persistence
npm run test-windows-library-production
npm run typecheck
```

The Windows production regression uses generated PNG/JPEG/WebP. The F Host
load run imported 9834 filename copies of three approved public contents into
a recoverable 166-record copy, reaching 10000 records. Its dialog test seam is
internal load evidence, not Browser intake acceptance or 10000 quality samples.
