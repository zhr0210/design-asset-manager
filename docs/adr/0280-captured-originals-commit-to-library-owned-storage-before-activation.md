# Captured Originals Commit To Library-Owned Storage Before Activation

Every built-in, browser-extension, Local Capture API, and plugin capture follows Capture Gateway ownership. During Candidate Intake, incomplete bytes may exist only as a Managed Intake Artifact in bounded operational staging. Before Candidate Activation, the gateway must finish integrity and real-format validation, allocate ADR 0285 Original Storage Object Identity plus safe bucket/name with ADR 0289 Validated Storage Extension, and atomically commit the complete Candidate Artifact as ordinary member files in the ADR 0282-bound ADR 0281 user-visible Managed Originals Directory under the active user-selected Library Root. Most artifacts contain one member; ADR 0340 extends this boundary to one atomically complete Compound Original when a capability declares and validates multiple members, and ADR 0341 publishes its complete dedicated directory through one same-volume atomic rename. Application installation, application data, cache, temporary, runtime, model, plugin, and producer storage are never the final home of an activated capture.

Candidate Promotion reassigns Asset File Ownership to the Design Asset without downloading, transcoding, moving, or duplicating the original merely to promote it. A producer never owns the accepted file and plugin uninstall cannot remove it. If the active library is unavailable, read-only, identity-mismatched, unsafe, or lacks Storage Safety Reserve, capture remains intake/recovery work or fails explicitly; it never reports success and silently falls back to application data or an unrelated downloads directory.

Library Start rejects a proposed Library Root nested inside the application installation or its application-managed data, cache, temporary, runtime, model, or plugin roots. Application removal, plugin uninstall, reinstall, settings reset, cache clearing, and ADR 0279 Forget Library Registration never delete Original Asset Storage. Reinstalling the application can rediscover the surviving library only through explicit open/reconnect plus ADR 0276 inspection; it does not scan private storage automatically.

Uninstall independence does not make every candidate immortal. Explicit Candidate Rejection, Candidate Retention Policy and its Recoverable Window, Asset Trash/Permanent Asset Delete, and a separately confirmed future physical library-deletion workflow retain their existing ownership rules. An incomplete Managed Intake Artifact is not a successfully captured image and may disappear with operational staging; its durable Candidate Record reconciles or exposes acquisition failure when the library is opened again rather than activating partial bytes.

Full Library Backup therefore includes every activated Candidate Artifact still owned by a retained candidate as well as Managed Asset originals, including complete Compound Original manifests and members, while excluding incomplete transfer staging. ADR 0281 places those durable ordinary member files in one user-visible Managed Originals Directory for every library type, including In-Place Reference Library, while Library Control Directory remains the hidden authoritative-state and Required Preview boundary.

The current renderer download flow simulates transfer progress and creates path-bearing records without writing original bytes, image normalization uses a separate fixed managed location, and the database remains application-global. The project has no atomic gateway commit into per-library Original Asset Storage or uninstall-independence proof. This ADR records target architecture only and downloads, moves, reads, or deletes no runtime file, user asset, database, cache, plugin data, or model and changes no public IPC, schema, or AI Worker API.
