# Managed Metadata Writeback Requires Recoverable Prior Bytes

Before a material Original Metadata Writeback may replace a Managed Asset's current bytes, the item must establish one **Managed Metadata Writeback Recovery Basis** for the exact current Source Content Generation and complete Original Asset. The basis is either a newly validated **Managed Metadata Writeback Recovery Copy** or an already completed, authenticated and verified Full Library Backup that contains every exact payload and manifest needed for that generation. An in-progress, unverified, incomplete, changed or merely remembered backup is not recovery evidence. Byte-identical writeback needs no recovery basis because it publishes no source change.

A new recovery copy must contain the complete pre-write single-file or Compound Original set, be independently recoverable from the write target, pass identity, byte, format, member-role and manifest validation, and preserve the Storage Safety Reserve before the source-write boundary. If neither a qualifying backup nor enough safe capacity for a complete recovery copy exists, the affected Managed item is blocked before mutation; confirmation, batch membership, retry or storage pressure never silently downgrades it to an unprotected write.

The recovery copy is library-owned recovery material, not a current Original Asset, backup archive, revision timeline, duplicate Design Asset, preview/analysis input or rebuildable cache. Storage Management accounts for it separately, and cache eviction, storage pressure, Library Switch, settings reset, application/plugin maintenance or a later successful writeback cannot automatically clear it. Only a separately reviewed user cleanup may retire its recovery role; ADR 0363 governs the explicit keep, backup-preserve, replace or cancel decision when another writeback would add a recovery point. ADR 0364 separately exports recovery bytes without changing the asset or returns them as a freshly protected new current generation rather than hidden undo.

When a qualifying Full Library Backup supplies the recovery basis, the writeback does not create another local full-file copy merely to duplicate the same proven prior generation. The plan identifies that dependency and revalidates the archive evidence immediately before the source-write boundary. If it becomes unavailable or unprovable before that boundary, the item must create and validate a local recovery copy or return to blocked review. Later loss of the user-controlled archive makes that historical recovery route unavailable but never changes, rolls back or invalidates the successfully written current Original Asset.

Referenced Metadata Writeback does not use this managed recovery basis. It follows the existing trash-before-publication and Rewritten Old Source Recovery Receipt boundaries of ADRs 0319–0321 for user-owned external bytes. ADR 0361 therefore presents and confirms the recovery consequences independently for Managed and Referenced sub-batches even when their outcomes share one activity record.

The current application has no Managed Metadata Writeback Recovery Basis, Managed Metadata Writeback Recovery Copy or backup-backed writeback preflight. This ADR records target architecture only and inspects, reads, validates, stages, copies, restores, moves, rewrites, trashes, clears, deletes or changes no runtime/user file, directory, database, cache, backup or system-trash item and changes no public IPC, database schema or AI Worker API.
