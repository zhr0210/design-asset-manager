# Retired Recovery Uses Anti-Replay Tombstones And Fresh Evidence Plans

Activity history may expire while a live operation reference still needs protection against duplicate or replayed cleanup, and required recovery evidence may sometimes never return. Design Asset Manager therefore separates user-visible history from operational replay protection: ADR 0087 history may expire normally, while this ADR governs lifecycle-bound terminal markers, explicit unknown-outcome retirement and any later returned-evidence recovery. It rejects both permanent user-visible recovery history and the unsafe inference that missing evidence means an operation never ran.

When visible recovery-staging history expires, its timeline, reasons and statistics are deleted. A non-user-facing **Recovery Staging Terminal Marker** may retain only opaque operation/item identity, terminal result class, final evidence generation and proven completion time while a live reference or replay-prevention need remains. It is excluded from search, activity/history UI, export and backup, stores no path, member name or private payload, authorizes no action, and is deleted when every reference is terminal and replay is proven impossible.

A missing, damaged or contradictory marker puts only the affected item and its exact shared staging/publication/recovery boundary into **Recovery Staging Terminal Evidence Unverifiable**. Read-only reconstruction follows **Claim-Scoped Recovery Evidence Authority** rather than a fixed database/log/filesystem priority: journals and receipts prove committed intent and operation boundaries, matching current-member identity and evidence generation prove physical state, and task state is a consistency projection rather than an override. Wall-clock recency has no authority. The marker is repaired only when the required facts yield one contradiction-free terminal outcome; otherwise recovery attention and exact isolation remain, with no release, automatic cleanup or manual Mark Successful action.

If the user no longer expects the missing evidence source to return, **Retire Unverifiable Recovery** is the only way to end active recovery governance. It is never time-triggered, changes no file or staging content, claims neither success nor failure and cannot resume or retry the old operation. **Retire Unverifiable Recovery Review** is item-scoped, has no batch or reusable decision, explains the exact scope, unknown outcome, irreversible end of old recovery and future fresh-preflight requirement, then requires a dedicated acknowledgment checkbox and confirmation rather than a typed name or operating-system password. Confirmation performs one final read-only check; returned evidence or state drift consumes consent and routes to normal reconciliation without retirement.

Successful retirement records **Recovery Retired — Outcome Unknown**, ends the old task's active attention and isolation, and leaves a non-visible **Recovery Anti-Replay Tombstone** while its library or operation identity remains. The tombstone contains only opaque operation/item identity, retired-unknown class, last-known evidence generation and retirement time. It is neither activity history nor recovery authority. Any future write to the same target is a new operation with complete current preflight and conflict review; it cannot reuse the old plan, consent, selection or retry state or treat retirement as proof that the physical action never ran.

When the relevant volume or evidence source later returns, one bounded read-only **Returned Retired Recovery Evidence Check** may run for that evidence generation without reviving or mutating the old operation. One uniquely proven terminal result silently updates the tombstone with the proven class, matching evidence generation and verification time, then follows normal reference/replay pruning without fabricating the original completion time. Still-insufficient evidence leaves the retired-unknown state silent. A proven current mixed or partial publication, removal or recovery conflict creates fresh exact Recovery Required attention and isolation but does not auto-open UI, send a system notification or change files.

**Review Returned Recovery Conflict** is the sole interactive route from that fresh attention. It presents current evidence read-only and offers only Defer or **Create Returned-Evidence Recovery Plan**, never Continue Old Task, Repeat Release or Mark Successful. Defer keeps exact attention and isolation. Plan creation itself mutates nothing: the plan receives a new operation identity, current evidence generation and member scope, repeats complete owning-operation preflight and requires independent review and authorization. The old tombstone remains lineage and anti-replay evidence only. Evidence drift invalidates the draft.

The new plan has no generic force action. **Safely Release Returned Recovery Staging** is available only when current proof covers every remaining member and establishes exclusive application ownership, unpublished state, no replacement or destructive publication boundary, no remaining outcome-evidence need and safe rebuildability; a new item-scoped confirmation removes only that reviewed set. **Preserve Returned Recovery Staging** is available when the complete remaining set and application ownership are known but safe disposal or rebuildability is not: it copies and verifies the complete set at an explicitly selected user-owned local destination outside application data while leaving staging unchanged. ADR 0386 visual destination-conflict rules prevent silent overwrite. Releasing preserved staging is always a later, separately revalidated decision. Ambiguous ownership, membership, completeness or publication boundary leaves the plan read-only, and neither action may overwrite or delete a user source or published output.

After successful preservation, choosing to keep original staging settles as **Preserved — Staging Retained** only when current proof also establishes that the staging is inert, cannot publish or alter user paths and is no longer needed to determine an outcome. Attention and isolation then end, while Storage Management reports safely calculable usage as **Protected Preserved Recovery Staging**. This is neither cache nor Managed Recovery Storage and is excluded from TTL, LRU, storage pressure, generic cleanup, settings reset and maintenance; it produces no recurring reminder or notification. Later release requires another current-evidence plan and confirmation. Outcome-bearing or publication-capable staging remains Recovery Required and isolated even after preservation, and the external user-owned copy remains untouched.

ADR 0402 owns startup reconciliation, and ADR 0403 owns the original recovery-staging release mechanisms. ADR 0392 maps this policy to Asset Export placements. ADR 0088 owns the minimal evidence fields and privacy exclusions. This ADR adds no generic cleanup authority and never broadens an owning operation's safe actions.
