# Local AI Uses One Global Resource Governor

All local automatic analysis, explicit local analysis and ADR 0172 calibration pass through one host-owned Local AI Resource Governor across Tag Suggestions, Embedding, OCR, Short Description and future capabilities, regardless of Python, ONNX, Core ML, llama.cpp or another approved runtime. Individual workers may batch or serialize their own operations, but they cannot independently decide that enough system resources exist. External providers remain outside local model residency while retaining their separate privacy, network and consent gates.

The governor admits at most one Heavy Model Execution at a time by default. A Heavy Model may remain loaded for bounded reuse, but another heavy inference cannot overlap it. Small Model Co-residency is allowed only when exact artifact/runtime evidence and current telemetry show that the combined measured or conservative estimated peak RAM/VRAM plus the platform safety reserve fits, the execution paths are compatible, and no pressure signal is active. Unknown telemetry, missing calibration or incomparable resource evidence falls back to sequential execution rather than assumed capacity. A user concurrency setting cannot override this admission rule.

Work is scheduled by visible priority: an explicit foreground user action precedes interactive preview-supporting work, newly changed asset baseline analysis, existing waiting intents, confirmed historical backfill and opt-in Idle Extended Analysis. Within a priority class, aging prevents starvation. The governor may group a bounded number or bounded duration of jobs for the currently resident model to reduce load thrash, but it must yield to higher-priority work and cannot keep lower-priority batches resident indefinitely. Capability independence from ADR 0168 remains: one waiting or paused capability does not block another safe eligible capability.

Idle Model Residency keeps a verified model loaded only for a bounded, policy-controlled reuse window derived from model class, measured load cost, selected ADR 0171 profile and current headroom. Residency is not a guarantee or a fixed permanent cache. Active jobs and calibration pin their exact model until a safe unit boundary; otherwise least-recently-used unpinned models are released first. A visible **Release Idle Models Now** action bypasses the remaining idle window without cancelling active work. Model unload releases runtime references and reclaimable accelerator caches but does not uninstall artifacts, delete results or evict Model Blob Store content.

Foreground interaction, no-visible-window policy under ADR 0174, operating-system memory pressure, accelerator-memory pressure and ADR 0176 battery/low-power/thermal policy immediately stop admission of affected new background units. At ordinary pressure, an in-flight deterministic Analysis Unit may finish and commit atomically before the governor pauses the intent and releases unpinned models. At critical pressure, the governor may abort the unit through the runtime's bounded cancellation/termination path; incomplete output is discarded, the intent becomes Waiting for System Resources, and retry never treats it as failure or success. The system does not kill an uninterruptible worker blindly, corrupt a model/index, or commit partial embeddings. When pressure clears, ADR 0168 reconciliation resumes eligible work under the same gates.

Platform adapters provide evidence for application foreground demand, memory, accelerator, battery and thermal state. Each signal carries availability and freshness. Unsupported or stale pressure telemetry is Unknown, never fabricated healthy state; the governor uses conservative concurrency and residency when a required signal is unavailable. macOS unified memory is not converted into fictitious dedicated VRAM, and Windows dedicated/shared GPU memory remains separately evidenced. Resource decisions and reasons are path-free and content-free.

The governor continuously compares actual peak and pressure evidence with ADR 0172 calibration and catalog estimates. A transient spike pauses or downsizes future admission without rewriting benchmark evidence. Repeated reproducible breaches mark the current artifact/runtime/recipe execution envelope stale or incompatible for that device and return the capability to a reviewed safer-plan choice; they do not silently select another model. Scheduler state distinguishes Running, Resident Idle, Waiting for Foreground Idle, Waiting for Memory, Waiting for Accelerator Memory, Waiting for Power/Thermal and User Paused. AI Console exposes aggregate state and controls, while Asset Inspector shows the owning capability state without private process or path details.

The current implementation has a Python ModelManager with hard-coded 60–300 second keep-alive values, estimated per-model VRAM weights, local Qwen/light-model eviction, a tag-oriented batch worker, a main-process memory guard and partial CUDA/MPS telemetry. These are useful implementation inputs but do not govern every capability/runtime, prove safe light-model co-residency, consume OS foreground/battery/thermal pressure, enforce one heavy execution globally, provide priority aging or support atomic critical-pressure cancellation. The generic application concurrency setting cannot claim this contract. This ADR records target scheduling semantics without running models, inspecting runtime data or changing public IPC, database or Worker APIs.
