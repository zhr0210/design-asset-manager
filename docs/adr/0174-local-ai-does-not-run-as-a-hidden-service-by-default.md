# Local AI Does Not Run As A Hidden Service By Default

Design Asset Manager does not install or launch a daemon, Windows service, login helper or other hidden persistent AI process by default. Local automatic analysis runs only while the main application process is alive and ADR 0173 admits work. Explicit **Quit Design Asset Manager**, operating-system logout/shutdown and application update restart always stop local analysis and its managed runtimes; no worker continues independently after the host exits.

The default **Continue Analysis After Closing The Window** preference is Off. This preference controls AI work when no application window is visible, independently of platform window conventions. On macOS, closing the last window may retain the normal application process but the governor pauses background analysis by default. On Windows or another platform that normally quits with the last window, default close behavior remains quit. Enabling the preference may keep or hide the application after the last window closes only through an explicit visible application lifecycle policy; it does not install a service or change explicit Quit semantics.

When no main window is visible and continued analysis is enabled, the one shared **Application Status Center** makes the running application discoverable through a persistent macOS menu-bar or Windows notification-area/system-tray item and anchored card. It never creates a separate AI icon. The AI Analysis section exposes aggregate Running/Waiting/Paused counts, current capability and resource-wait reason, **Pause/Resume Automatic Analysis**, and ADR 0173 **Release Idle Models Now**. Global **Open Design Asset Manager** and **Quit** actions belong to the card rather than a subsystem. Export, downloads/installations, preview/indexing and later long-running subsystems contribute independently controlled sections; empty sections collapse, active sections remain visible and Needs Attention sections sort first. No section-wide pause changes another subsystem.

Application Status Center never displays asset names, thumbnails, paths, OCR text, tags, descriptions, model paths or credentials. ADR 0175 aggregate system notifications may report user-initiated long-operation outcomes but do not replace this persistent control surface. If the platform cannot provide a trustworthy visible status/control surface, no-window analysis and any other no-window work requiring it are unavailable rather than hidden.

ADR 0430 contributes an independently controlled Custom Field Migration section with aggregate Running, Queued, Paused, Waiting and Needs Attention counts, the effective performance profile and scoped Pause All Custom Field Migrations/Resume Eligible Migrations controls. These lane controls never resume an individually user-paused task. The section exposes no field name, field value, Candidate or Design Asset identity, conversion mapping or per-item reason, and it never changes another subsystem's profile or pause state.

The native status item uses a static platform-appropriate monochrome/template icon and never continuously spins or pulses. One small state mark projects the highest current application priority in this order: Needs Attention, Paused/Waiting, Running, then Idle. Concurrent subsystem states do not add icons or numeric clutter; exact counts stay inside the card. A localized tooltip and accessible name state the full aggregate status, and any color is supplementary rather than the only distinction.

ADR 0402 governs the one bounded Safe Stop And Quit deadline, exact startup reconciliation isolation, non-modal recovery review and non-cache Startup Recovery Evidence. Closing a window is still not Quit, and this application-lifecycle ADR remains the owner of the visible host/status behavior that makes no-window work discoverable.

ADR 0403 governs evidence-gated release of rebuildable recovery staging, per-item interruption reconciliation, batch cancellation/results, attempt compaction and activity attention. ADR 0401 separately governs lifecycle-bound terminal markers, explicit unknown-outcome retirement and anti-replay evidence after visible recovery activity expires. Neither policy turns recovery staging into cache or grants generic cleanup authority.

System sleep, user-session lock and wake are not Quit. The governor stops new background admission before sleep or when ADR 0176 session/power evidence requires it, releases reclaimable residency when time permits, and re-evaluates all resource and storage evidence after wake before ADR 0168 reconciliation. Sleep does not authorize a service wake-up, a power-save blocker or prevention of system sleep. A user may pause automatic analysis from the tray/menu item without disabling capability preferences or deleting intents.

**Launch At Login** is a separate default-Off permission and operating-system integration. Enabling Continue Analysis After Closing The Window does not enable login launch; enabling login launch does not silently enable no-window analysis, automatic model/runtime installation, library backfill or external AI. Login-launch review states whether the app opens a window or starts with its visible status item, and the user can revoke it from application Settings and normal operating-system controls. Application updates preserve the two choices independently and do not broaden them.

The current main lifecycle already keeps the application alive after the last macOS window, quits after the last Windows/default-platform window, recreates a macOS window on activation, and performs a bounded-style managed runtime shutdown hook before final quit. It has no Application Status Center, no no-window AI admission preference, no independent login-item integration, no shared background lifecycle state, and no proven unit-boundary checkpoint contract across workers. Existing queue polling and platform close policy cannot claim this ADR. This decision records target lifecycle semantics without changing Electron lifecycle code, starting a worker, inspecting task data or adding public IPC.
