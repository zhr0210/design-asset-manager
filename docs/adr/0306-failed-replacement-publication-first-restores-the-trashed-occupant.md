# Failed Replacement Publication First Restores The Trashed Occupant

Before Replace Transfer Destination asks the operating system to trash its current occupant, it durably prepares a **Transfer Destination Replacement Receipt** containing only the exact identity and device/platform evidence needed to verify and restore that item. The receipt is device-local operational recovery authority, not Portable Referenced Source Deletion State, a Referenced Source Trash Receipt, Full Library Backup content, Offline Library Catalog data or permission to enumerate system trash. If the occupant is proven trashed but verified staging publication is not proven committed, the operation enters **Replacement Publication Recovery** while the original referenced source, Design Asset relationship and staging remain unchanged.

Recovery first makes one automatic rollback attempt only when the receipt proves the exact trash item, the intended destination remains safely vacant, and current evidence proves publication did not commit. A successful restore revalidates the occupant at its original path, keeps the verified staging, clears Replacement Publication Recovery and returns to current Referenced Source Transfer Conflict Review. A collision, unavailable or changed trash item, unsupported platform context, failed restore, ambiguous publication boundary or insufficient evidence blocks automatic restoration without selecting another item, overwriting a path, publishing staging, repeating trash, guessing success or retrying in a loop.

Blocked rollback opens **Replacement Recovery Review** with validated previews and current safe evidence for the original source, staging, intended destination and exact receipt-linked occupant where available. It offers: restore that occupant to its original destination when safe; restore it to another explicitly selected safe location while leaving publication uncommitted; or explicitly continue publishing the verified staging after fresh validation, accepting that the occupant remains in operating-system trash. Every action is current-evidence-bound and reports failure without automatic fallback. Closing the page or restarting preserves recovery state and staging; cache cleanup, settings reset, storage pressure and plugin/preview/AI maintenance cannot resolve or delete them. ADR 0307 retains the receipt after a fully successful replacement for displaced-file recovery without representing whole-transfer undo. The current application has no replacement receipt, system-trash restore adapter, staging publisher or recovery surface. This ADR records target architecture only and accesses, restores, publishes, trashes, removes, reads or writes no runtime/user file and changes no public IPC, database schema or AI Worker API.
