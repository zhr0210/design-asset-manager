# Keeping Model Results Resolves Attention But Preserves Provenance

Choosing ADR 0193 **Keep Existing Results** creates an explicit **Model Advisory Acknowledgement** for the reviewed advisory semantics and affected result-generation scope. It resolves the pending-attention presentation in Model Library and removes that advisory from AI Console's unresolved Model Advisory Summary. It does not delete, replace, migrate, suppress, de-rank or reclassify any result; enable a suspended/revoked model; select/download a replacement; grant network access; or change the Has Model Result Advisory filter match.

Result Provenance Advisory remains permanently available beside affected result provenance in Asset Inspector, and Model Library retains a resolved advisory/history view containing the trusted statement identity, reason category, affected model/generation/capability scope, acknowledgement decision/time and current recovery state. “Permanent” means the evidence remains while the owning committed result/provenance exists under ADR 0143; it does not preserve result content after the user explicitly deletes the result or permanently deletes its owning asset.

Acknowledgement matching uses stable trust-root/statement lineage plus a canonical semantic fingerprint of response class/severity, reason category, affected artifact/result-generation/capability scope and any remediation change that introduces a new user decision. A newer signed statement reopens attention only when that semantic scope materially changes: severity/response changes, a new reason applies, affected assets/generations/capabilities expand, or a new required action materially changes the user's choice. The reopened view explains the exact diff and never reverses the prior keep decision by modifying results.

Sequence increments, re-signing/key rotation under an already verified recovery chain, freshness/expiry refresh, mirror/source failover, wording/localization changes, corrected counts within the same declared scope and repeated catalog downloads do not reopen attention. They update trusted provenance/freshness in place. A signed recovery statement that ends the active advisory clears active warning state without erasing its historical provenance marker; it does not claim the committed results were regenerated or newly verified.

The user may inspect resolved advisories and explicitly **Review Again**, which restores the centralized pending-attention presentation without altering result state. Opening a model, AI Console, Asset Inspector, filter or search result is only a read receipt and never acknowledges the advisory. Batch Keep Existing Results requires one homogeneous statement/generation scope preview; a single acknowledgement cannot silently cover unrelated models, reasons or materially different statements.

The acknowledgement record is non-content library state scoped by ADR 0196 Portable Library Lineage Identity and included in ADR 0185 Full Library Backup. Restoring the same library preserves it, while another library never inherits it merely because the same model or statement exists there. Public notifications/logs carry only opaque library/advisory identity and aggregate resolved/reopened status, never asset/result content or private paths.

The current project has no Model Advisory Acknowledgement record, semantic fingerprint/diff, resolved history, attention reopening projector or Review Again action. Existing review/batch acknowledgement patterns are analogous but do not establish model-generation scope. This ADR changes documentation only: it reads/writes no result/library/model/runtime state and changes no public IPC/schema/AI Worker API.
