# Metadata Portability Import Conflicts Are Field And Provenance Aware

Every confirmed mapping in ADR 0376 is compared against the target Design Asset by declared semantic field/result type, scope and provenance before it can be applied. A **Metadata Portability Value Conflict** is never resolved by Last Writer Wins, source export time or a single rule across unrelated classes. A compatible target field with no current value defaults to Import Value; a semantically equivalent current value and provenance/equivalence contract is Already Present and produces no duplicate value or result.

A conflicting scalar field such as title, rating, copyright or another single-valued property defaults to **Keep Current Value**. The user may explicitly choose Use Imported Value for that reviewed field; Keep Both is available only when the domain actually supports distinct scoped or language-specific values and never stores contradictory values in one scalar slot. A current and imported user-authored value conflict therefore remains visible rather than preferring the newer timestamp.

Resolved set-valued metadata such as Tag Concept associations or Collection Membership defaults to **Add Missing Imported Set Values**: preserve every current member, add only absent compatible imported members and remove nothing. Exact stable identities or an ADR 0380 Portability Object Mapping determine membership equality. Display-label equality, normalized spelling, translation, collection-name equality or visual similarity never merges Tag Concepts, Asset Collections or their relationships; unresolved referenced objects stay excluded or pending rather than being silently created. Replacing or removing the current set requires a separate explicit reviewed choice.

User-authored or user-confirmed tags, scoped OCR and descriptions always outrank unconfirmed AI results regardless of which side supplied them. Imported AI evidence cannot overwrite, downgrade, delete or reactivate a suppressed current user value. Compatible AI results from distinct models, model versions, Analysis Recipes, Analysis Units, input views or result generations retain their typed provenance and may coexist; the import review separately identifies which result, if any, would become the active Asset Analysis Projection. Exact result identity, contract and payload-digest equivalence is Already Present, while incompatible embeddings, untyped vectors, unsupported scopes and incomplete provenance are excluded or blocked rather than coerced into the active model space.

Batch conflict choices follow ADR 0100: only a Homogeneous Conflict Set with the same semantic type, scope, provenance relationship, conflict reason and available choices may share one Resolution Preview and decision. Mixed scalar/set values, manual/AI provenance, OCR scopes, Tag Concepts, collection relationships, embedding spaces and result recipes remain separate groups. The review reports imported, already-present, kept-current, additive, conflicting, excluded and unsupported counts without treating an unresolved or omitted value as applied.

These choices modify only library metadata and durable compatible result evidence for the explicitly mapped Design Assets. They never write back to Original Assets or sidecars, change Asset File Ownership, create Tag Concept/collection identity from a display string, run AI analysis, download a model, or make an imported result trusted merely because it was packaged. ADR 0378 commits and can briefly undo these selected effects atomically per mapped asset while allowing batch partial success; pending-mapping persistence and source-package retention remain separate decisions.

The current application has no Metadata Portability Value Conflict classifier, field/provenance-aware portability resolution surface or imported-result equivalence resolver. This ADR records target architecture only and reads or imports no actual package, resolves no runtime conflict, and selects, analyzes, stages, writes, rewrites, converts, moves, deletes or changes no runtime/user file, credential, sidecar, directory, database, cache, backup, metadata value, analysis result or source relationship and changes no public IPC, database schema or AI Worker API.
