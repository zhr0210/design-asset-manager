# Trust Notifications Route By Attention Class And Scope

Clicking an ADR 0199 Trust Attention Summary Notification creates a host-validated **Trust Attention Navigation Intent** containing only opaque notification-transition identity, attention-class flags and optional opaque target library/statement references. The operating-system payload, URL, command line and renderer query never contain model/package names, library names, paths, asset/result identity or vulnerability detail. Electron main process resolves current state before selecting a destination; the renderer never trusts notification-supplied routing directly.

When the current unresolved batch contains only model/runtime execution containment, the intent opens AI Console at the relevant **AI Execution Trust Status** aggregate. That surface shows affected capability/runtime state, last verified trust freshness and safe remediation entry points without opening a model file, starting a repair or revealing private process details. Model Library may remain linked for an affected model, but execution safety remains owned by AI Console.

When the batch contains only Model Result Advisories for exactly one available library, the intent opens that library's Model Library advisory view, scoped by opaque current advisory identities. It does not open an individual asset or automatically enable Has Model Result Advisory filtering. The user sees centralized affected scope/counts and ADR 0193–0195 actions while committed results remain unchanged.

When attention mixes execution containment and result advisories, spans more than one library, or cannot be represented by one safe destination, the intent opens an **AI Trust And Advisory Summary**. The summary groups current unresolved execution state globally and advisory attention by opaque library context, then offers explicit links to AI Console or the appropriate Model Library. It is a current attention router, not a notification center, catalog log, asset list or durable audit trail.

Resolution occurs at click time, not notification creation time. If all attention is already resolved, the app opens the nearest aggregate surface with “No current trust attention” and optional resolved-history entry rather than recreating attention. If a target library is closed, unavailable or no longer registered, the summary reports that opaque target context is unavailable and does not expose/reconstruct its path or auto-open/import it. If only part of a coalesced batch remains, routing uses the remaining current subset.

Navigation activates an existing suitable main window or opens the normal application shell according to window policy; it does not create duplicate library instances, bypass lock/permission checks or replace the user's current library before target validation. Back returns to the prior valid workspace when available. Dismissing/clicking/closing the destination changes no acknowledgement, trust, model/runtime, result, refresh or notification preference state.

The intent is short-lived and replay-safe. Main process binds it to one current accepted attention transition, validates ownership/scope and consumes or safely re-resolves duplicate OS delivery. Durable state stores only opaque transition/emission/navigation resolution and terminal reason, never notification body snapshots or private target data. ADR 0201 class-specific device settings determine which attention classes may be projected into the notification; routing never hides disabled classes from in-app state.

The current project has no Trust Attention Navigation Intent, AI Execution Trust Status projector, Model Library advisory route or AI Trust And Advisory Summary. Existing route/navigation helpers and planned notification intent are implementation inputs only. This ADR changes documentation without sending/clicking a notification, opening the app/library, reading trust/result/private data or changing public IPC/schema/AI Worker APIs.
