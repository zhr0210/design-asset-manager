# Gated Model Access Uses A Dedicated Credential Vault

Model Library prioritizes public ungated Model Artifact Packages for the initial catalog. A gated model may appear only when its source provider, account authorization method, repository/revision scope, license gate and offline-use requirements are explicitly declared. Gated access is a Model Source Account relationship, not a Feature Plugin permission, application account, model capability, or general browser session. Catalog presence never authorizes the application to reuse website cookies, browser credentials or an unrelated provider token.

Authorization and license confirmation use trusted application-owned surfaces. Browser/device authorization is preferred when the provider supports it. If a provider only supports a personal access token, entry uses a dedicated isolated credential surface rather than the primary renderer, plugin UI, logs, command line or ordinary settings form. Renderer, AI Worker, inference runtime, extensions, model packages and other catalogs receive only opaque account identity and path-free states such as connected, expired, scope-insufficient or revoked; they never receive the secret.

Long-lived provider credentials are stored only through a Model Source Credential Vault backed by the operating system's protected credential facility on macOS and Windows. SQLite, JSON settings, Namespaced Extension Storage, model manifests, package directories and logs may store only non-secret provider/account metadata, scope summary, expiry and vault reference. There is no plaintext fallback. When protected storage is unavailable, persistent gated-model access is Unavailable; a separately disclosed memory-only one-session authorization may be used for one explicit download and is erased on cancellation, completion or application exit.

The trusted download broker redeems vault material into a Download Credential Lease scoped to one provider account, repository, immutable revision, exact manifest file set, read-only purpose and bounded lifetime. The lease is delivered only to the trusted transport through a secret-safe channel, never a process argument, inherited/global environment variable, renderer IPC payload, URL, log, progress event or extension handle. Cancellation, logout, credential rotation, scope failure or expiry revokes the lease and clears in-memory copies. Download errors expose structured non-secret reasons without echoing headers, tokens, signed URLs or response bodies that may contain credentials.

Model License Acceptance is separate from source authentication. Before download or ADR 0164 update, trusted UI records publisher/model/checkpoint, immutable revision or declared coverage, license identifier, terms version and digest, acceptance time and any required account identity without storing the terms page's private session. A changed or unrecognized terms version requires individual new confirmation and excludes the candidate from ordinary Update All; prior acceptance is not inferred across publishers, revisions or materially different terms. Acceptance does not grant repository code execution, external inference, telemetry, asset upload, model selection or automatic updates.

Disconnecting a Model Source Account deletes or revokes its vault material, cancels active gated downloads that can no longer authenticate, and prevents new gated downloads. It does not delete already verified model blobs, manifests, derived runtime cache, active assignments, analysis results, embedding indexes or provenance. Installed local inference does not receive the source credential and remains offline-capable unless the catalog declared a Continuous Model Entitlement Requirement before installation.

A model requiring periodic or continuous online entitlement must display the provider, contacted hosts, cadence, data categories, offline grace/failure behavior and license consequence before installation. It cannot silently add phone-home checks, send asset content or convert a local model into external inference. Entitlement transport remains isolated from model inputs and results. If these requirements cannot be enforced or explained, the model is not eligible for one-click official-catalog installation.

Third-party Model Catalog Trust Roots cannot read, request or inherit credentials merely by referencing the same source provider. Credential use remains scoped to the exact user-approved provider/repository/revision purpose, while the catalog receives only verification status. Gated download conformance tests cover vault-unavailable behavior, no-plaintext fallback, renderer/worker/plugin isolation, lease expiry/revocation, log redaction, terms-version changes, logout preservation and offline inference without accessing real user credentials.
