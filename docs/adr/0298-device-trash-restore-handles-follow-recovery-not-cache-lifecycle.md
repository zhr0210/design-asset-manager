# Device Trash Restore Handles Follow Recovery Not Cache Lifecycle

A Device Trash Restore Handle remains device-local recovery authority for as long as its Referenced Asset stays recoverable in Asset Trash or Referenced Compound Source Delete Recovery and the associated operating-system trash item has not been proven unavailable. Successful Restore Referenced Source File, exact-content reconnection, Restore Source to New Location, Use Existing File as Replacement, Permanent Asset Delete, or authoritative evidence that the trash item no longer exists retires the handle. A compound member handle retires only through its group restoration/deletion lifecycle rather than an independent member-level asset action. Retiring or clearing a handle never empties, restores, moves, or permanently deletes the operating-system trash item; Portable Referenced Source Deletion State follows the Design Asset's separate library lifecycle.

Application restart, Library Switch, cache cleaning, storage-pressure eviction, settings reset, Offline Library Catalog cleanup and ordinary package/plugin maintenance never remove Device Trash Restore Handles. Before Forget Library Registration commits for a library with handles, a path-free confirmation reports the affected count and loss of one-click source restoration and requires a choice: **Keep Local Restore Handles** as inactive Dormant Trash Restore Handles, or **Clear Local Restore Handles**. Keeping is the default and recommended choice; clearing always requires an explicit user selection. Retained handles cannot operate while the library is unregistered and reactivate only after ADR 0279 reconnect plus identity inspection proves the same Local Library Instance on the same compatible device/storage context. Clearing removes only local handles; the portable library, Asset Trash records, source files and system trash are untouched.

An app-managed Uninstall Preparation flow applies the same review across registered and dormant handles before local application state is removed. Neither keep nor clear is preselected: preparation cannot proceed until the user explicitly chooses whether to retain supported device-local restoration state for a later reinstall or clear it. It cannot promise a prompt or retention when the user bypasses the application by deleting its bundle, invoking an external uninstaller/cleaner, erasing the device or clearing application data outside product control. Those external actions still never authorize the application to touch operating-system trash. The current project has no Device Trash Restore Handle store, dormant registry, Uninstall Preparation surface, Asset Trash or platform restore adapters. This ADR records target architecture only and reads, clears, restores, deletes, moves, or writes no runtime/user file and changes no public IPC, database schema, or AI Worker API.
