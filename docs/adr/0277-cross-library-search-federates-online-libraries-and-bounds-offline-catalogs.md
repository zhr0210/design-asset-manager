# Cross-Library Search Federates Online Libraries And Bounds Offline Catalogs

Cross-Library Search covers only Registered Libraries and never changes the rule that one Local Library Instance owns normal write access at a time. ADR 0039 exposes it through the shared Search Palette with all Registered Libraries as the visible default Search Scope and current-library search as an immediate alternative. A connected non-active library contributes a stable search snapshot only through an independent read-only connection after ADR 0276 compatibility and identity inspection; search never acquires its Exclusive Library Lock, migrates or repairs it, creates missing state, rebuilds its indexes, or turns a partial library failure into an empty successful result for that library.

Each Registered Library has a bounded device-local **Offline Library Catalog** by default so basic discovery can continue while its removable volume or location is unavailable. The catalog contains the library and Searchable Library Object identities, source/index generation, object type, display label and bounded visibility/status fields; asset and candidate projections may also include title, filename, confirmed basic tag and collection labels, format, type, and relevant dates. It contains no original bytes, private source paths, ADR 0297 Device Trash Restore Handle or platform trash location, complete preview set, OCR text, descriptions, canonical embeddings, ANN index, AI result bodies, Saved Search query plan/criteria, or search-query history. Recently used result thumbnails use a separate TTL/LRU byte budget; the application never prebuilds a full offline thumbnail mirror.

Offline catalog use and storage are visible per library and may be disabled, cleared, or bounded without changing the authoritative library. Catalogs and thumbnails are device-local rebuildable projections excluded from Full Library Backup, library merge, and portable lineage state. Reaching a storage limit degrades declared offline coverage rather than deleting authoritative metadata or pretending that a disconnected library was fully searched.

An **Offline Library Search Result** is explicitly marked as offline/basic-only. It may identify which registered library contains a matching Searchable Library Object, but opening that object's authoritative surface, an original, Original Handoff, full preview, OCR/description search, semantic/AI search, metadata mutation, or editing requires reconnecting and verifying the same Local Library Instance and current generation. A cached result never substitutes its thumbnail or metadata for the authoritative object.

Cross-library inclusion is based on the selected searchable object and its normal visibility policy, not on whether that result is immediately reusable. Offline, read-only, unavailable, stale, or action-restricted objects may remain discoverable with truthful state; those conditions gate later actions rather than silently removing otherwise valid search matches. Existing explicit visibility rules such as ADR 0069 Include Deleted remain authoritative.

Connected libraries evaluate lexical and available semantic lanes within their own ADR 0181 Hybrid Asset Search Plans. Missing offline OCR, descriptions, embeddings, or ANN data removes those lanes only for that library; raw similarity values from different ADR 0144 Embedding Spaces are never compared as one scale. ADR 0404 then applies Cross-Library Rank Fusion to the independent library ranks inside each object-type group, while library filtering or optional library-grouped presentation changes no write ownership. Every federated result is addressed by Portable Library Lineage Identity, Local Library Instance Identity, Searchable Library Object type, that object's own stable identity, and source/index generation. Design Assets retain Design Asset Identity, Asset Candidates retain Candidate Identity, and no collection, tag, source, or Smart Filter is coerced into a globally ambiguous asset row identifier.

ADR 0038 may present connected, currently verified byte-identical occurrences as an Exact-Content Result Cluster, but federation never converts that cluster into shared ownership or a canonical cross-library object. Exact-content evidence is generation-bound and path-free in UI/log projections; similarity, matching names, and every offline occurrence remain separate results until reconnection plus explicit refresh verifies current content. Expanding the cluster restores every compound result identity, and any target-library action still resolves one occurrence through the normal activation boundary.

Read-only search and a cached result thumbnail do not activate another library. When a result action requires the target library, ADR 0278 performs Library Switch: an already quiescent current library uses the immediate path, while active Library-Bound Work reaches its safe pause/commit/rollback boundary before write ownership is released. The Ephemeral Search Session remains available throughout the wait and transition, and the target re-resolves the compound result identity only after ADR 0276 Library Open Inspection succeeds.

ADR 0279 Forget Library Registration removes that library from every new federation and clears its registration-owned Offline Library Catalog and recent-result thumbnails. An already open Ephemeral Search Session may keep only a non-actionable unregistered placeholder needed to preserve its sequence; it cannot query cleared projections, expose their former metadata as current, or activate the occurrence until the user establishes a new verified Library Registration.

The current implementation opens one application-global SQLite connection, routes tag/asset search directly through it, and identifies renderer results with library-ambiguous asset IDs. It has no Registered Library registry, independent read-only library adapter, compound search identity, federated query coordinator, Offline Library Catalog, or per-library offline storage accounting. This ADR records target architecture only and reads or changes no runtime database, user asset, model, cache, public IPC, schema, or AI Worker API.
