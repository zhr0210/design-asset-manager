# Dammeta Is An Open ZIP64 Metadata Package Container

A **DAM Metadata Package** is the physical single-file representation of ADR 0371 Metadata Portability Package and uses the `.dammeta` extension. Its unencrypted form is a standards-compatible ZIP64 container: the extension supplies application/file association only, and a copied file may be renamed to `.zip` and inspected by ordinary archive tools. ZIP64, streaming serialization and bounded-memory validation are required so package size is not constrained by classic ZIP limits or by loading every selected vector, region payload or future optional media object into memory.

Every package contains one UTF-8 strict-JSON **Metadata Package Manifest** at `manifest.json`, versioned record streams under `records/`, optional typed binary **Metadata Package Blobs** under `blobs/`, and a declared checksum inventory. The manifest declares container/schema versions, export identity and creation evidence, ADR 0374 Export-Scoped Asset Reference/matching-evidence mode, ADR 0375 optional Portability Review Thumbnail profile, record/payload classes, counts, byte lengths, media/semantic types, checksum algorithm and every entry required for completeness. Records use documented versioned JSON or JSON Lines schemas rather than private application object dumps; large binary values remain separate blobs referenced by declared content identity rather than base64 embedded in JSON.

Entry names, separators, Unicode normalization, ordering and record serialization are deterministic for the same selected logical snapshot and export options, while export identity and creation evidence remain intentionally distinct per export. Package entries use safe relative names only and never contain an absolute local path, parent traversal, drive/volume identifier, symlink, device, executable entry or undeclared hidden file. Blobs use opaque/content-derived safe names and expose no original filename merely through their archive path. Every record and blob declares its exact byte length and digest so a reader may validate selected entries independently and the complete inventory before accepting a full package.

Compression is declared per entry and may store already compressed or incompressible payloads without waste. The package writer stages and validates the complete central directory, manifest references, counts, lengths and digests before atomic publication to the reviewed destination. A destination occupant is never silently overwritten or renamed. Cancellation or failure removes only proven operation-owned staging; an incomplete container is never reported as a successful portability export.

The format contains no SQLite database, Electron serialization, Python pickle, application cache layout, executable plugin/model content, credential, secret, source absolute path or undocumented binary object. Unknown optional schema classes may be preserved or skipped only according to the package compatibility rules later defined for import; an unknown required class makes the package unsupported rather than partially accepted as complete. Importers must reject duplicate/colliding normalized entry names, traversal, links/devices, undeclared entries where forbidden, length/digest mismatch and archive expansion beyond reviewed safety limits.

This ADR defines the open unencrypted container. ADR 0373 optionally wraps the complete file in a publicly documented age passphrase envelope as `.dammeta.age`; decryption yields the exact open ZIP64 container and never redefines its inner logical schemas or makes unencrypted `.dammeta` depend on proprietary software. Original Asset and preview inclusion remains excluded by default under ADR 0371 and is not authorized merely because ZIP64 can hold large payloads.

The current application has no `.dammeta` writer, manifest/record/blob schemas, checksum inventory or package validator. This ADR records target architecture only and selects, serializes, exports, packages, compresses, encrypts, attaches, imports, stages, writes, rewrites, converts, moves, deletes or changes no runtime/user file, sidecar, directory, database, cache, backup, metadata value, analysis result or source relationship and changes no public IPC, database schema or AI Worker API.
