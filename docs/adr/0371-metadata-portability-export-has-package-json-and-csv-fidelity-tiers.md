# Metadata Portability Export Has Package, JSON And CSV Fidelity Tiers

One **Metadata Portability Export Review** selects the Design Assets, exact library fields, provenance scope and one representation before writing a user-owned destination. The review reports asset/field counts, estimated logical and physical output bytes, every representation gap, omitted value and privacy-sensitive class, and never treats an unsupported value as exported. Export reads a consistent selected library snapshot but does not modify an Original Asset, sidecar, Source Content Generation, Asset File Ownership, Compound Original manifest, source relationship, metadata value or analysis result.

The recommended full-fidelity representation is a versioned **Metadata Portability Package**. It contains a versioned manifest, structured JSON records and only the additional typed binary payloads required for selected vectors, detailed region evidence or other schema-declared non-text data. It may carry selected user-authored values, confirmed tags and labels, corrected OCR, descriptions, ratings, palettes, analysis/provenance evidence, language information, regions, relationships and model/result identities while preserving their types and associations. Original Asset bytes, Required Preview data and evictable preview objects are always excluded. ADR 0375 permits only explicit bounded Portability Review Thumbnails for visual mapping support, without turning this export into Asset Export or Full Library Backup.

**Metadata Portability JSON** is a human-readable, documented structured schema for selected values that can be represented safely in JSON. It supports nested text/number/boolean structures, language and declared provenance but contains no opaque base64 binary cells and makes no full-fidelity promise for large vectors, binary region masks or another package-only payload. Any selected value that cannot be represented under the chosen JSON schema is excluded visibly before confirmation rather than flattened, truncated or serialized through an undocumented private object.

**Metadata Portability CSV** is a documented flat tabular representation with one Design Asset per data row and explicitly declared scalar columns. It is intended for spreadsheet review and interchange of compatible titles, descriptions, ratings, creator/copyright values and other selected flat fields. It does not hide JSON, vectors, region evidence, relationship graphs, provenance objects or multi-language structures inside cells and is never described as round-trip complete. Multi-valued or structured fields are either represented by an explicitly supported lossless flat schema shown in review or excluded with a reason.

All three representations are explicit exports to one reviewed destination and contain only the user-selected field/provenance classes their declared schema supports. Under ADR 0438, a selected Out-of-Constraint Custom Field Value remains exportable rather than being dropped: full-fidelity representations preserve its exact value plus validation status, while a lower-fidelity representation exports every supported scalar value and discloses any status-fidelity gap in review. Under ADR 0442, valid invisible Unicode formatting and retained out-of-constraint Text are preserved through the chosen schema's documented safe escaping/encoding rather than executed, stripped or replaced. They do not embed or attach metadata to originals, generate XMP, create a Compound Original member, relink an exported file, create another Design Asset, change ownership, become a backup, run on metadata save or schedule future exports. Destination collisions require visual review and never silently overwrite or rename existing content. Cancellation before final publication removes only proven operation-owned staging; a completed verified export remains an ordinary user-owned file or package outside library lifecycle.

This ADR defines export fidelity only. ADR 0372 gives Metadata Portability Package an open ZIP64-compatible `.dammeta` physical container with a versioned manifest, documented record streams, typed blobs and checksums. ADR 0373 keeps open representations as the interchange default and optionally encrypts any complete export through a whole-file age passphrase envelope without changing its schema. ADR 0374 always uses random export-scoped references for internal relationships and makes correlation-sensitive stable identity/content evidence default-on for packages but optional in review. ADR 0375 forbids originals and formal preview objects while allowing explicit bounded package-only review thumbnails. ADRs 0376–0381 separately govern inspected, reviewed and atomic import without metadata-only asset creation. ADR 0382 directly recognizes only published native schemas and routes third-party JSON/CSV mapping or plugin adaptation through a host-validated Metadata Import Draft. No representation is accepted as import input merely because the application exported it.

ADR 0393 Compatible Export may embed a deliberately limited set of technical
or explicitly selected descriptive values into a newly generated media file.
That convenient interoperable output is not a substitute for this export's
typed structured evidence, vectors, relationships, provenance or fidelity
claims, and Metadata Portability Export never becomes an automatic companion to
Compatible Export.

ADR 0394 may add an explicitly selected standards-mapped XMP companion to a
Compatible Export media result when the target cannot embed eligible
descriptive fields. That sidecar still excludes vectors, regions, relationships
and private structured provenance and therefore does not replace or duplicate a
Metadata Portability Package automatically.

The current application has no Metadata Portability Export Review, versioned portability package, portability JSON/CSV schema or verified export publisher. This ADR records target architecture only and selects, serializes, exports, packages, encrypts, attaches, imports, stages, writes, rewrites, converts, moves, deletes or changes no runtime/user file, sidecar, directory, database, cache, backup, metadata value, analysis result or source relationship and changes no public IPC, database schema or AI Worker API.
