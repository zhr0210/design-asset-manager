# Copy Into Library Batches Commit And Activate Per Item

After the user explicitly selects Copy Into Library, trusted application UI first presents a read-only **Copy Into Library Plan**. It reports the selected file count and source-byte estimate, estimated managed-storage demand, detected format/capability or readability exclusions, and the exact file/folder scope before one confirmation starts work. Estimates are informative rather than reservations or success guarantees: live source identity, readability, format, path, target-volume and Storage Safety Reserve evidence is validated again for each item. ADR 0336 may include a reviewed one-time folder-to-Collection mapping in this plan, ADR 0338 defines recursive discovery and mandatory Copy Scope Exclusions, and ADR 0339 blocks or pauses admission when the destination cannot preserve its reserve. Planning creates no Candidate Record, managed original, Collection, preview or AI job and never modifies the selected external files.

Confirmation creates one Capture Gateway request identity and Candidate Identity per planned item, then performs progressive item-scoped Candidate Intake. For each item, the gateway reads the unchanged selected source into attempt-owned managed staging, validates and copy-verifies the complete bytes, allocates the ADR 0285 through ADR 0291 managed-original destination, atomically commits the complete single-file artifact or ADR 0340/0341 Compound Original directory under ADR 0280, and only then activates the Candidate. A committed item becomes usable in Capture Inbox immediately while later items continue. Success, exclusion and failure are recorded per item; one failure never rolls back, removes, repeats or hides other committed items, and an explicit retry targets only selected failed items after a fresh preflight rather than replaying the whole batch or reusing unverified staging.

Cancel stops unstarted items and safely aborts only in-progress work that has not crossed its managed-original commit boundary, removing only proven operation-owned incomplete staging. A non-interruptible commit finishes or rolls back before cancellation resolves. Already committed originals and activated Candidates remain ordinary successful results and are never deleted to simulate batch atomicity. Application exit, restart and Library Switch use the Capture Gateway's durable item identities and ADR 0278 safe boundaries to reconcile committed, failed and safely resumable intake without duplicating a source or converting the operation to Reference in Place.

Candidate Activation automatically schedules required preview generation. A Candidate may truthfully show Preview Pending or Preview Generation Failure while the copy batch continues, but Candidate Promotion remains blocked until ADR 0123 System Preview Ready; preview failure stays explicit and retryable rather than being replaced by a placeholder or treated as a successful preview. Optional OCR, description, tagging, embedding and other AI analysis begins only under its normal capability and scheduling rules and never blocks copying, Candidate Activation, later batch items or non-AI use. The current application has no reviewed Copy Into Library Plan or item-committed local-copy batch pipeline. This ADR records target architecture only and selects, reads, copies, stages, imports, previews, analyzes, modifies or deletes no runtime/user file and changes no public IPC, database schema or AI Worker API.
