# Referenced Source Rewrite Recovery Reconciles Before One Safe Rollback

After the ADR 0329 Referenced Source Rewrite Destructive Boundary, entering **Referenced Source Rewrite Publication Recovery** first revalidates the expected old Source Content Generation, exact Rewritten Old Source recovery evidence, verified Referenced Source Rewrite Staging and current source path without issuing a file mutation. If the path already contains the complete expected staging output, recovery finalizes the same Design Asset's new Source Content Generation and retains the old-source receipt under ADR 0319. If the path contains the exact old source, it finalizes an aborted rewrite with the prior generation still current. A different, partial, unsafe or unprovable occupant is never treated as either outcome.

Only when publication is proven absent, the source path remains safely vacant and the receipt proves the exact old source may recovery make one automatic operating-system restore attempt. Success revalidates the old bytes at the original path, keeps the prior Source Content Generation current, marks the rewrite aborted and removes only exact operation-owned staging after that rollback is durably committed. Collision, changed or unavailable trash evidence, unsupported platform context, failed restore, ambiguous publication or insufficient proof blocks automatic rollback without another restore attempt, staging publication, overwrite, generated naming or guessed success.

Blocked rollback opens **Referenced Source Rewrite Recovery Review** with current evidence for the exact old source, staging and source-path occupant. The user may restore the old source to its safely vacant original path and abort the rewrite; restore it to another explicitly selected safe path, revalidate it and relink the same Referenced Asset while retaining the prior generation; or, only while the intended source path is safely vacant and staging remains complete and valid, explicitly continue atomic publication and commit a new generation. An occupied source path is never overwritten: it must be made vacant outside the operation and refreshed, or the old source must use a reviewed alternate path. A changed or unprovable stage cannot be published.

Closing the page, restarting, disconnecting the volume or switching libraries preserves recovery state, exact proven staging and the non-repeatable destructive-call evidence. Reconciliation may observe a completed result but never automatically repeats trash, publication or restoration. Cache cleanup, settings reset, storage pressure and plugin/preview/AI maintenance cannot resolve or delete this state or staging. This active-asset recovery remains library-bound and distinct from registration-independent Local File Recovery; only after successful rewrite does the old-source receipt enter that utility, where ADR 0321 governs external recovery without treating it as rollback. ADR 0347 applies the same evidence-first, no-overwrite principles to the whole compound staging/receipt set but does not run this single-file automatic rollback independently for each member; only its group recovery may finish the complete new group or restore the complete prior group. The current application has no referenced-source rewrite journal, staging publisher, trash restore adapter or recovery review. This ADR records target architecture only and accesses, creates, copies, restores, relinks, moves, rewrites, trashes, removes, deletes, reads or writes no runtime/user file and changes no public IPC, database schema or AI Worker API.
