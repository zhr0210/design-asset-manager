# Analysis Results Follow Asset Lifecycle and Support Manual Control

The current compatible tag, OCR, description, embedding, coverage, failure, and Asset Analysis Projection results remain durable while their Candidate or Design Asset exists. They are analysis records rather than ADR 0168 Analysis Intents or image-input cache and are not removed by pending-intent cancellation/deletion, Analysis Proxy Cache cleanup or ADR 0146's Clean Analysis Cache Now action. A superseded generation retains at most the immediately preceding result generation for 30 days by default, including after an explicit ADR 0145 model migration; after that window, result values and large vectors are removed while bounded non-content provenance may retain model and recipe identifiers, time, coverage, terminal status, and supersession reason. The retention duration may later become an explicit library preference without changing active-result semantics.

Candidate Promotion transfers active and retained analysis through ADR 0142. Asset Trash retains current results so Asset Restore recovers search and analysis context without recomputation. Permanent Asset Delete removes result values, embeddings, projections, suppression records, analysis jobs, and reproducible proxies with the asset. Rejected or expired Candidate analysis follows the Candidate Recoverable Window and is removed on Candidate Hard Delete. No analysis retention rule preserves private result content after its owning artifact is permanently deleted.

User-confirmed or user-authored tags, descriptions, and corrected OCR become User-Authored Analysis Values or ordinary confirmed library metadata rather than AI history. They remain active across model upgrades and are never overwritten, downgraded, or deleted merely because an AI generation is superseded. Each value records user-authored provenance and its asset or Analysis Unit scope without copying an image input. Tag Suggestions remain distinct until accepted under ADR 0016.

ADR 0419 applies the same separation to Custom Field Value Suggestions. An
accepted or edited-and-accepted result becomes a normal user-confirmed Custom
Field Value; unresolved/rejected/deleted suggestions remain analysis evidence
and never overwrite or clear that value.

Users may manually add, edit, or delete tags, OCR text, descriptions, and embedding results. Tag and description values may be entered directly. OCR additions or corrections declare their page, artboard, frame, crop, or asset-level scope and may include bounded spatial evidence when the UI supports it. Embedding addition means an explicit Generate or Attach Embedding action using a declared model space, dimensions, normalization contract, source scope, and recipe; arbitrary untyped numeric vectors are rejected because they cannot participate safely in similarity search. A validated advanced import may be supported only when it supplies the same contract evidence. ADR 0144 keeps additional embeddings in their own model-space namespace until an explicit Active Embedding Space migration succeeds. ADR 0169 capability toggles and valid empty states never overwrite or downgrade these user-authored values.

Manual deletion immediately removes the selected result from active projections and search. After a short-lived undo window, the stored result value or vector is deleted. A content-free Result Suppression marker tied to the prior internal evidence identity prevents projection rebuilds or the same queued generation from immediately restoring that deleted item; it does not retain the deleted text or vector. A later explicit user action may restore the item, remove suppression, or run a new analysis generation. Automatic analysis cannot silently reinterpret deletion as permission to recreate the same suppressed evidence.

Deleting an AI result does not delete the original asset, System Preview, unrelated results, confirmed user metadata, or the model itself. Deleting a User-Authored Analysis Value is an explicit metadata edit and follows the same immediate projection/search update and short undo behavior. Batch deletion is allowed only when result type and scope are clear and the UI shows affected counts; embeddings additionally require search-index reconciliation before the operation reports complete.
