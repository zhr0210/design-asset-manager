# Tag Auto-Confirmation Rules Are Version Bound And Reversible

AI Tag Suggestions remain pending by default. A user may explicitly create a Tag Auto-Confirmation Rule, but the application ships with no active rule and no global “trust all AI tags” switch. A rule confirms only an already materialized ADR 0179 Raw Tag Suggestion and never bypasses suggestion evidence, creates a new concept silently or grants an analysis provider confirmation authority.

Each rule binds the exact Model Artifact/Result Generation, Analysis Recipe and output schema, source capability, vocabulary/catalog version, concept-mapping method and calibration version, calibrated content-confidence threshold, calibrated mapping-confidence threshold, allowed Tag Concept/category scope, coverage requirement and optional collection/scope. Model confidence and concept-mapping confidence remain separate; neither is rewritten to `1.0` on confirmation. Confidence from another model, quantization, recipe or vocabulary is not comparable without explicit calibration evidence.

Only a uniquely resolved existing Tag Concept may pass. Unmapped suggestions, multiple/ambiguous candidates, proposed new concepts, Language Undetermined mappings, incomplete required coverage, invalid output and concept conflicts remain pending for review regardless of numeric confidence. Existing User Tag Concepts may participate only through an explicit rule mapping/allowlist chosen by the user; spelling or machine translation cannot enroll them automatically. Deprecated, redirected or trust-blocked concepts pause the affected rule branch until reviewed.

Rule creation and material edits use an Auto-Confirmation Rule Preview. It shows the bound versions, exact allowed concepts/categories, thresholds and confidence semantics, excluded conditions, scope, and a dry-run count of would-confirm/would-remain-pending/conflict/already-confirmed suggestions when compatible evidence exists. The preview never runs new analysis or backfills the library. Confirmation activates only the displayed rule; expanding concept scope, lowering a threshold, changing mapping method or widening assets requires a new preview and consent.

Artifact, recipe/output schema, vocabulary, mapping, calibration or confidence-semantics change moves the rule to Stale And Paused before new confirmations. A signed vocabulary update that adds display labels without changing concept identity/mapping semantics may remain compatible only when its manifest explicitly proves that narrow compatibility. Reapproval compares old/new bindings and dry-run impact. Disabling or deleting a rule stops future decisions but does not silently remove already confirmed metadata.

Every automatic decision writes a minimal Auto-Confirmation Decision Record containing opaque rule/version, suggestion/evidence identity, concept identity, evaluated confidences, mapping method, decision time and owning operation/run. Confirmation is idempotent and preserves the raw suggestion and original model confidence. It must not overwrite a manual confirmation, manual rejection, user-authored tag, later manual edit or a higher-priority reviewed decision. Extension providers may emit attributed suggestions under ADR 0154 but cannot create/modify rules or mark results confirmed.

**Undo Auto-Confirmed Tags** previews a rule, run, time range or selected-asset scope and separates reversible from excluded outcomes. It reverts only unchanged relationships whose confirmation provenance is solely the targeted automatic decision, normally returning the corresponding suggestion to Pending. It does not remove a concept association that the user later confirmed/edited, that another retained confirmed source independently owns, or that has a conflicting newer decision. Partial undo reports succeeded/excluded/failed counts, preserves unrelated tags and supports the bounded batch undo/activity rules from ADR 0078 through ADR 0088.

Rule evaluation stops safely when evidence is missing rather than treating missing fields as zero or success. Repeated rule exceptions or a calibrated false-positive signal may pause the rule and surface one aggregate attention item, but never auto-adjust thresholds. Rule status and decisions remain path-free and content-minimal; the Raw Tag Suggestion retains its own value under normal result privacy/retention, while the rule record does not duplicate asset content.

The current pipeline normally writes pending suggestions and pending asset-tag relations, but resolves concepts by mutable tag name and may create a name-based tag before user review. Bulk confirmation loops pending relations without rule/dry-run evidence, and confirmation replaces confidence with `1.0` then updates suggestions through asset/name/source matching. There is no version-bound rule, separate mapping confidence, stale/pause lifecycle, decision record, conflict exclusion or provenance-safe batch undo. This ADR records target behavior without changing schemas/APIs, reading the tag database or running AI.
