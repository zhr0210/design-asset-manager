# Referenced Source Path Batches Serialize Active Work Per Physical Volume

Referenced Source Path Batch scheduling uses one exclusive **Referenced Source Volume Lane** per stable physical-volume identity. A same-volume relocation holds that volume's lane while it performs current validation, its atomic filesystem change and immediate outcome reconciliation. A cross-volume transfer acquires both source and destination lanes in a stable deterministic order and holds them through copy, complete verification, publication and old-source cleanup or until it reaches a safe checkpoint or truthful attention state. Therefore at most one active batch path operation involves a given physical volume, while operations whose involved volume sets are disjoint may proceed independently.

An item waiting for user input in conflict review or recovery does not retain a volume lane indefinitely. It keeps its existing Design Asset and physical-path conflict guards, releases the I/O scheduling lanes, and must reacquire every currently involved lane plus freshly revalidate its evidence before continuing. Volume removal, disconnection or cancellation likewise releases a lane only after the item reaches its ADR 0303 or ADR 0316 safe checkpoint; a non-interruptible commit finishes or reconciles before release. Deterministic multi-lane acquisition prevents two opposite-direction transfers from deadlocking each other.

Version one exposes progress and waiting reasons but no ordinary user concurrency setting and does not silently raise per-volume concurrency based on guessed device class. A future increase requires representative local, removable and nonlocal-volume performance and recovery evidence plus an explicit policy revision; it cannot weaken item-scoped operation guards or recovery truthfulness. ADR 0318 automatic and manual retry attempts reacquire the same current volume lanes rather than bypassing this scheduler. ADR 0345 also acquires every source, staging and destination volume involved by one Referenced Compound Source Path Operation in the same deterministic order, so its member steps cannot deadlock or bypass single-file source operations. ADR 0348 removes the superseded cross-format current-source-change participant from this scheduler. The current application has no referenced-source path batch coordinator, stable volume-lane scheduler or these per-volume limits. This ADR records target architecture only and accesses, creates, copies, removes, restores, moves, renames, trashes, deletes, reads or writes no runtime/user file and changes no public IPC, database schema or AI Worker API.

ADR 0390 names the shared underlying scheduler Physical Volume File Lane and
adds Asset Export as another participant. Referenced Source Volume Lane remains
the source-operation view of that same exclusive per-volume boundary; export
cannot create a separate namespace or bypass this ADR's deterministic ordering.
