# Same-Volume Relocation Collisions Use Visual Conflict Review

When Relocate Referenced Source finds its intended same-volume destination occupied, the application opens **Referenced Source Relocation Conflict Review** rather than failing through a generic rename dialog, overwriting, deleting, silently suffixing or switching to cross-volume transfer. The dedicated page compares the current source and destination occupant with validated previews where available, safe filenames and locations, format, size, dimensions or structure, modification evidence and complete-content relationship. There is no Referenced Source Transfer Staging: the current source and Design Asset relationship remain protected while review is unresolved.

For a completely verified byte-identical occupant, **Use Existing Identical Relocation Destination** is recommended but still explicit. The relationship first commits to the verified destination, then the application makes one separately evidenced request to move the prior source to operating-system trash. Proven trash success creates a device-local **Relocated Old Source Recovery Receipt** in Local File Recovery; Recover Relocated Old Source File restores it only as an ordinary untracked external file. Failed or ambiguous cleanup leaves the asset at the verified destination, reports that the old source remains and never rolls back, retries automatically or claims a recovery receipt.

For different or unverified content, **Relocate Source With Unique Name** is recommended and presents a reviewed safe unoccupied name for an atomic same-volume move. The page also offers Choose Another Destination, **Replace Relocation Destination**, and Cancel Relocation. Replacement is never preselected: after separate confirmation and fresh source, destination, occupant, permission and platform-trash validation, it records exact recovery intent, moves the occupant to operating-system trash and only then attempts the atomic source move. It never overwrites, truncates, unlinks or permanently deletes the occupant. Trash failure leaves both files unchanged; ADR 0312 governs a proven trash success followed by failed or ambiguous source movement and retains the receipt after successful replacement. Every choice revalidates current evidence, preserves Design Asset and Source Content Generation for byte-stable movement, and never executes from a remembered or batch default. ADR 0313 offers short undo only after an unoccupied or unique-name move; identical-destination adoption and replacement remain excluded because they have independent displaced-file lifecycles. The current application has no referenced-source relocation, visual relocation-conflict page, relocation receipt store or platform restore adapter. This ADR records target architecture only and inspects, previews, restores, moves, renames, trashes, deletes, reads or writes no runtime/user file and changes no public IPC, database schema or AI Worker API.
