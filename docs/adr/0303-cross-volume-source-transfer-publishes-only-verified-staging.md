# Cross-Volume Source Transfer Publishes Only Verified Staging

Transfer Referenced Source Across Volumes writes first to **Referenced Source Transfer Staging** on the selected destination volume, using an exclusively created application-owned temporary identity that can be atomically published within the chosen destination directory. The intended final path remains absent until the staged bytes completely match the current Source Content Generation, real-format validation passes, and the source, destination volume, directory boundary, permissions and path limits are revalidated. Publication additionally requires either proven final-path vacancy or one current explicit ADR 0304 conflict resolution that safely produces a vacant reviewed path or adopts an identical occupant. Staging is never a Referenced Asset source, Design Asset, user-visible destination, Source Tree item, preview/analysis input, Original Handoff, backup member or cache entry, and old-source trash is never requested before verified final publication.

A durable **Referenced Source Transfer Checkpoint** binds the confirmed operation, expected source generation, destination-volume and staging identities, verified byte progress and commit boundary. Restart or volume reconnection may resume only when current source, staging and checkpoint evidence prove that continuation cannot append to changed bytes or publish another file. Insufficient, changed or ambiguous evidence stops recovery without guessing: the application may restart the copy only after it has safely removed its own proven staging, or preserve the artifact for item-scoped attention when ownership cannot be proven. A complete verified stage may publish after restart only after the final path is freshly proven vacant or a still-current conflict choice is revalidated; a stage already published before interruption is revalidated and reconciled rather than copied again.

Cancellation, terminal copy/validation failure and later reconciliation may remove only the exact staging artifact whose application ownership and operation binding are proven. They never remove the selected source, a committed destination, an occupant at the intended path, an unknown lookalike, a Referenced or Managed Asset original, or any other user file. Ordinary cache cleanup, settings reset, storage-pressure eviction, plugin maintenance and preview/AI cleanup do not govern this staging. ADR 0309 resolves post-publication reversal as a new verified transfer rather than whole-operation undo, ADR 0316 resolves user-visible batch cancellation before publication, ADR 0317 bounds batch transfer I/O through its source and destination volume lanes, and ADR 0318 bounds automatic retry to evidence-stable pre-publication work. The current application has no referenced-source transfer staging/checkpoint pipeline; its existing managed path migration is not this user-file operation. This ADR records target architecture only and accesses, creates, resumes, copies, verifies, publishes, removes or writes no runtime/user file and changes no public IPC, database schema or AI Worker API.
