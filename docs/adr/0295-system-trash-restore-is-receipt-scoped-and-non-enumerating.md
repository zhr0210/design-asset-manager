# System Trash Restore Is Receipt Scoped And Non-Enumerating

Restore Referenced Source File may operate the system trash/recycle bin only for an exact source item that this application previously moved there through Delete Referenced Source File or as one proven member call inside ADR 0346 Delete Referenced Compound Source. A successful member call records a two-part **Referenced Source Trash Receipt**: Portable Referenced Source Deletion State binds the Design Asset, referenced-source relationship and content generation without platform location data, while a Device Trash Restore Handle retains only the local platform evidence needed for later verification. ADR 0346 groups those member receipts into one Referenced Compound Source Trash Receipt Set without replacing their independent identity proof. A receipt is restoration evidence, not a source backup or recovery promise: automatic eligibility still requires the Design Asset to remain recoverable in Asset Trash or Referenced Compound Source Delete Recovery, the original device/platform storage context and local handle to be available, and the trash adapter to prove that the handle still identifies the expected bytes. Filename, deletion time, original path, file size, a missing source, or visual similarity alone never proves a match.

The application does not enumerate, search, index, display, empty, or otherwise manage unrelated system-trash items. When a receipt and current item verify and the original destination is available without collision, Restore Referenced Source File asks the platform adapter to return that exact item, validates the restored source, and only then completes Asset Restore. If the receipt is unavailable, the item was cleared or changed, the platform cannot prove identity, or the destination is unsafe or occupied, automatic restoration stops without selecting another trash item, overwriting a destination, inventing a filename, or claiming recovery. The user may instead handle system trash manually, select/relink a source through the trusted recovery flow, or leave the Design Asset in Asset Trash.

Referenced Source Trash Receipts are retained only as governed restoration state for their deleted Design Assets or an active Referenced Compound Source Delete Recovery; removing either part or permanently deleting the Design Asset never empties system trash or deletes the external item again. ADR 0296 resolves an occupied original destination through exact-content reconnection, alternate placement, or explicit replacement, and ADR 0297 keeps platform handles device-local. The current Electron dependency exposes trash placement but no common restore API, and the project has no macOS/Windows restore adapters, receipt persistence, referenced ownership model, or Asset Trash implementation. This ADR records target architecture only and reads, enumerates, moves, restores, deletes, or writes no runtime/user file and changes no public IPC, database schema, or AI Worker API.
