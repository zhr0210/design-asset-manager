# Portability Packages May Carry Review Thumbnails But Never Originals

A Metadata Portability Package never contains complete Original Asset bytes, Compound Original members, Required Preview data or evictable preview objects. Moving complete source material belongs to ADR 0383 Original Asset Export, while authoritative library recovery belongs to Full Library Backup; including either in `.dammeta` would blur ownership, restoration and interchange boundaries and make an otherwise metadata-focused package unexpectedly large and sensitive.

Metadata Portability Export Review may offer an explicit package-only **Portability Review Thumbnail** option. The user selects whether to include these thumbnails for all eligible selected assets or a reviewed subset; the review reports eligible, included, unavailable and omitted counts plus estimated additional logical and physical bytes before publication. JSON and CSV never carry thumbnails, binary image cells, data URLs or sidecar image directories.

Each included Portability Review Thumbnail is a newly serialized, bounded sRGB raster with manifest-declared media type, pixel dimensions, encoded byte length, digest, generation profile and its Export-Scoped Asset Reference. The versioned package profile enforces declared maximum dimensions, pixels and encoded bytes per thumbnail plus aggregate archive safety limits. It may use already trusted preview evidence or bounded generation available to the export operation, but unavailable/offline Original Assets are not read, reconnected or treated as export failures merely to produce one; every missing thumbnail remains explicit.

A Portability Review Thumbnail is only visual review evidence for a future import/mapping workflow. It is never an Original Asset, ownership handoff, Required Preview restoration source, general Asset Preview cache, AI analysis input, Original Content Match Evidence, exact-match proof or newly imported Design Asset. A package remains structurally complete and its metadata remains importable when thumbnails are disabled, absent, omitted or unreadable; thumbnail digest validation proves only that the declared review image is intact, not that its pixels or source correspond exactly to an Original Asset.

Package readers treat thumbnails as optional non-authoritative typed media entries and apply the same safe-name, declaration, length, digest and expansion-limit validation as every other Metadata Package Blob. A rejected thumbnail may degrade visual review for its referenced record but cannot make otherwise valid metadata unavailable; an undeclared, executable or over-limit entry remains a package-integrity failure under ADR 0372. ADR 0376 permits visual review during a current-library Metadata Import Mapping Plan but forbids thumbnail-based automatic matching or asset creation. ADR 0379 permits thumbnails only in a bounded device-local Metadata Import Review Cache that is never authoritative saved-session or backup content.

The current application has no Portability Review Thumbnail profile, selection review, package writer or package reader. This ADR records target architecture only and reads no unavailable source, generates no thumbnail, and selects, serializes, exports, packages, encrypts, attaches, imports, analyzes, stages, writes, rewrites, converts, moves, deletes or changes no runtime/user file, credential, sidecar, directory, database, cache, backup, metadata value, analysis result or source relationship and changes no public IPC, database schema or AI Worker API.
