# Trust Refresh Notifies Only New Material Attention

Automatic Model/Runtime Catalog Metadata Refresh, ADR 0198 Post-Merge Trust Reconciliation and ordinary trust freshness updates are silent at the operating-system level when they produce no new material attention. Successful refresh, current/stale timestamp change, Trust Not Assessed becoming verified without a problem, semantically identical statement sequence/re-signing/mirror/wording changes, corrected same-scope counts, signed recovery and refresh failure/offline waiting update in-app state only. They do not produce “everything is fine,” “still waiting” or repeated system notifications.

A system notification is eligible only when a verified transition introduces **New Material Trust Attention**: a new Critical Model/Runtime Security Revocation or Analysis Suspension that blocks future execution, or a new/reopened ADR 0193 Model Result Advisory whose ADR 0195 semantic fingerprint materially changed. Existing accepted blocks, already pending unchanged advisories and acknowledged same-semantics advisories do not notify again merely because the catalog refreshed or the application restarted.

One metadata refresh/reconciliation batch emits at most one **Trust Attention Summary Notification**. It coalesces related model/runtime statements and affected libraries/capabilities during a bounded window rather than notifying per model, package, library, asset, result or statement. Content is path-free and result-free: application name, generic attention class, aggregate affected capability/library counts and “Open to review” only. It never includes model/repository names, asset/result counts that reveal library composition, filenames, collections, tags, OCR, descriptions, prompts, paths, URLs, vulnerability details, credentials or source account identity.

Notification deduplication uses accepted trust-statement lineage plus response/semantic fingerprint and target attention transition, not fetch attempt, catalog sequence or notification delivery uncertainty alone. Restart reconciliation persists only opaque emitted/coalesced transition identity and cannot replay a storm. A later materially expanded scope may update/replace the aggregate or emit one new summary; ordinary count reconciliation inside the same semantic scope does not.

Clicking routes through ADR 0200 opaque validated Trust Attention Navigation Intent: execution-only to AI Console, one-library advisory-only to Model Library, and mixed/multi-library attention to AI Trust And Advisory Summary. Dismissing the operating-system notification does not acknowledge Keep Existing Results, clear a revocation/suspension, dismiss Model Library attention, retry refresh, start remediation or alter notification settings. Denied OS permission leaves all in-app state available and is never bypassed.

This is a narrow extension of ADR 0175 beyond user-initiated long-running operations. Ordinary per-asset AI, automatic baseline completion, freshness-only refresh, recovery success, package discovery and non-material reconciliation remain silent. ADR 0201 provides separate device-local AI Execution Security and Model Result Advisory notification switches; disabling delivery never changes in-app/safety state. ADR 0203 keeps every eligible notification ordinary-priority and separates immediate containment from delivery. Operating-system Focus, quiet hours and permission always remain authoritative.

ADR 0205 Prolonged Trust Refresh Notice is also in-app only. Refresh age or repeated transport/verification failure accepts no new signed trust statement, so it is not New Material Trust Attention and never becomes eligible for an operating-system notification merely because seven days or a longer period elapsed.

The current project has no trust-attention notification class, semantic transition dedupe/coalescing, privacy projection or opaque trust navigation. Existing renderer toasts and planned Long-Running AI Operation notifications do not implement it. This ADR records target behavior without refreshing metadata, sending a notification, reading library/result/model/runtime/private data or changing public IPC/schema/AI Worker APIs.
