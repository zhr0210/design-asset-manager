# Referenced Source Path Batches Commit And Recover Per Item

A **Referenced Source Path Batch** is a coordinator, not a filesystem transaction. Each selected single-file Referenced Asset receives its own durable intent and is independently classified and executed as Relocate Referenced Source or Transfer Referenced Source Across Volumes from current physical-volume evidence. Under ADR 0345 one selected Referenced Compound Original instead contributes one Referenced Compound Source Path Operation item: its member actions share one group journal, availability boundary and complete relationship commit and never become independent batch items. Validation, staging where required, commit, source relationship update, old-source cleanup, receipts, restart reconciliation and recovery remain Design-Asset-scoped; one item never borrows another item's proof or causes already committed items to roll back.

An item that reaches destination conflict, attention or recovery leaves that item in its normal visual review while other safe non-conflicting items continue. A failure likewise reports only that item and does not block or cancel the remainder unless a proven shared-path, same-asset or volume-safety dependency makes continued execution unsafe. Operation conflict guards prevent one Referenced Asset or physical source/destination from participating in incompatible concurrent writes. Restart reconciles every started item independently and does not repeat ambiguous or destructive calls.

The resulting **Referenced Source Path Batch Result** groups succeeded, conflict-review, failed, recovery and cancelled items with current reasons and direct entry points to each item's normal conflict or recovery surface. Replace Transfer Destination and Replace Relocation Destination choices are always bound to the one freshly validated item and are never inferred from, remembered from or automatically applied to the rest of the batch. The batch is not reported as wholly failed merely because attention remains, and its result never hides successful file changes behind a single rollback claim. ADR 0315 resolves batch undo, ADR 0316 resolves bounded cancellation, ADR 0317 resolves per-volume concurrency and ADR 0318 resolves bounded retry without weakening these item boundaries. The current application has no referenced-source ownership model, path-batch coordinator, source-path conflict surfaces or platform trash recovery adapters. This ADR records target architecture only and accesses, copies, restores, moves, renames, trashes, deletes, reads or writes no runtime/user file and changes no public IPC, database schema or AI Worker API.
