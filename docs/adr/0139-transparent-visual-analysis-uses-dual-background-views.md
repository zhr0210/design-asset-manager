# Transparent Visual Analysis Uses Dual Background Views

AI analysis never silently discards meaningful alpha. Preview Broker validates whether an Analysis Visual Source is fully opaque, contains non-opaque pixels, is fully transparent, or has malformed or unsupported alpha representation. Alpha Evidence records channel presence, opacity range and coverage, non-transparent bounds, premultiplication interpretation when known, decoder provenance, and validation state without treating transparency as a color profile. Fully opaque sources use one ordinary Analysis Input View and incur no dual-view work.

A source with validated non-opaque alpha produces two related RGB Analysis Input Views: one composited against white and one against a neutral dark background. Exact background values, color-management behavior, alpha interpretation, edge handling, and recipe version belong to a deterministic Alpha Compositing Recipe. The views share one Analysis Unit identity and differ only by declared background variant. Checkerboard backgrounds are prohibited for AI input because they add artificial edges and texture; silently dropping alpha or using an undeclared default background is also prohibited.

Both views are prepared in memory and released after the model job. When repeated work justifies disk reuse, either view may enter the shared Analysis Proxy Cache under ADR 0137, with Alpha Compositing Recipe and background variant included in the content-addressed key; they never become required System Preview media or permanent per-model derivatives. A fully transparent unit produces explicit Empty Transparent Content evidence rather than allowing background-only model output to masquerade as source content.

When Authoritative Color Evidence exists, foreground samples and backgrounds use the declared color-managed sRGB analysis path before deterministic compositing. Unprofiled foreground pixels remain explicitly Unprofiled through both variants; adding a known background must not relabel unknown foreground color as sRGB or remove its reliability warning. Alpha-dependent bounds, OCR crops, tags, captions, embeddings, palettes, and other results retain the source alpha state and Analysis Input View provenance.

Model adapters analyze the two variants as related views and apply the evidence-preserving projection rules in ADR 0140 rather than treating them as unrelated assets or silently choosing whichever output looks preferable. Provider batching may reduce execution overhead, but cannot change view identity or coverage evidence. The aggregation result must remain traceable to both variants and surface disagreement when foreground interpretation materially depends on background.
