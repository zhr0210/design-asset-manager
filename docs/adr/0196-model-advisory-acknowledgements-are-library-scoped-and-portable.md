# Model Advisory Acknowledgements Are Library Scoped And Portable

Each Model Advisory Acknowledgement is owned by exactly one **Portable Library Lineage Identity** plus its ADR 0195 Model Advisory Semantic Fingerprint. Acknowledging Keep Existing Results resolves attention only for affected committed results in that library. Another library using the same model, artifact digest, result generation or signed statement computes its own affected scope and remains unacknowledged until reviewed there. No application-wide preference, Model Library install state or OS account silently propagates the decision.

Portable Library Lineage Identity is generated independently of a physical path, database row number, device, application installation or display name and remains stable through ADR 0185 Full Library Backup and New Library Restore. Restore creates a distinct **Local Library Instance Identity** for that physical restored instance, so two restored instances can coexist without pretending to be one live synchronized database. A raw filesystem copy also copies the old instance value and therefore enters ADR 0279 Library Instance Identity Collision when both independently addressable roots are observed; it is not considered distinct until an explicit verified copy-adoption flow assigns a new instance identity. Distinct instances initially contain the snapshot/copied acknowledgement state; later acknowledgement/reopen/recovery changes remain local to each instance unless a future explicit library synchronization contract is designed.

Full Library Backup includes acknowledgement identity, semantic fingerprint, reviewed affected generation/capability scope, decision/time, resolved/reopened state and non-content statement provenance inside the encrypted/digested authoritative snapshot. It excludes device identity, OS account, current path, raw catalog URL, credentials and result content duplicated solely for acknowledgement. Restoring the backup preserves the pending/resolved presentation exactly as of the snapshot, then reconciles newer signed statements under ADR 0195 material-change rules without changing committed results.

Application-level Runtime/Model Trust State remains global execution safety policy for the installed application. A library acknowledgement cannot enable a revoked/suspended model or runtime, clear a trust statement, suppress a security update, authorize external AI or affect another library's job admission. Conversely, global trust metadata does not convert Keep Existing Results into a cross-library acknowledgement.

ADR 0279 Forget Library Registration does not remove the library's local acknowledgement records. Only a separately confirmed physical library-deletion workflow removes them with ordinary library ownership, while an existing encrypted backup retains its historical snapshot until the user deletes that backup. Renaming or moving a library, changing its storage root, restoring it on another device or opening it from another supported platform does not change lineage identity. Exporting selected assets outside Full Library Backup does not carry acknowledgement as an ambient global decision; result provenance may still identify the advisory-bearing generation.

ADR 0197 Merge Into Current Library imports a source-library acknowledgement only as decision history. It never clears target attention; only an existing exact target acknowledgement covers imported results, otherwise the target library receives one grouped review. Public state exposes opaque lineage/instance/advisory identities and aggregate status only, never private paths, asset/result content or device/account identifiers.

The current project has no Portable Library Lineage/Local Instance identity contract, library-scoped Model Advisory Acknowledgement store, backup/restore serialization or cross-instance reconciliation. This ADR records the target ownership model without opening a runtime database/library, changing a path, creating/restoring a backup or altering public IPC/schema/AI Worker APIs.
