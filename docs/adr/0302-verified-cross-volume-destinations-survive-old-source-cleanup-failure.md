# Verified Cross-Volume Destinations Survive Old-Source Cleanup Failure

When Transfer Referenced Source Across Volumes has committed and completely verified the selected destination but the request to move the old source to operating-system trash reports failure, the application keeps the verified destination, updates the same Referenced Asset and Source Tree relationship to that destination, and records **Transferred With Old Source Remaining**. It does not delete or quarantine the new file, revert to the old relationship, create a second Design Asset, pretend the whole transfer failed, or hide that two physical copies may now exist. The Design Asset, Source Content Generation, authored metadata, derived evidence and referenced ownership remain unchanged.

The attention state offers **Retry Old Source Cleanup** and **Keep Both After Source Transfer**. Retry is always a fresh explicit request: it first proves the old location still contains the exact transfer source content and remains the intended old physical source, then makes one operating-system trash request. Proven absence resolves the residual state without claiming the file entered trash; changed, replaced, ambiguous or unavailable evidence blocks deletion and keeps truthful attention. A reported failure remains retryable by another explicit action, but restart, activation, reconciliation, monitoring, scheduling and storage cleanup never repeat this destructive request automatically.

Keep Both resolves the attention while the Referenced Asset continues to point only to the verified destination. The old copy becomes an ordinary untracked user file rather than a second source relationship, duplicate Design Asset, Managed Asset or library-owned backup. Neither outcome invokes Delete Referenced Source File or moves the active Design Asset into Asset Trash. ADR 0309 provides no whole-transfer undo: a desired return to the prior volume is a new verified transfer, which may use an exact still-present old copy only through the normal current destination-conflict decision. When an initial or later explicit cleanup does successfully trash the old copy, ADR 0310 retains a separate Transferred Old Source Recovery Receipt in Local File Recovery. The current application has no Referenced Asset ownership model, cross-volume transfer journal, residual-source state or old-source cleanup action. This ADR records target architecture only and accesses, verifies, copies, moves, trashes, deletes or writes no runtime/user file and changes no public IPC, database schema or AI Worker API.
