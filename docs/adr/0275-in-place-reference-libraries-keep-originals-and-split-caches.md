# In-Place Reference Libraries Keep Originals And Split Caches

Library Start supports adopting an existing asset directory as an In-Place Reference Library without copying, moving, rewriting, or taking ownership of its existing originals. The Library Root receives one reserved hidden Library Control Directory for its manifest and identities, SQLite/catalog state, user metadata, transaction and lock state, and Required Preview Storage plus one ADR 0281 user-visible Managed Originals Directory for new library-owned Candidate/Managed Asset originals. Both reserved subtrees are excluded from referenced-source discovery, while eligible pre-existing originals elsewhere in the adopted tree remain Referenced Assets. ADR 0292 later reuses the same no-copy ownership boundary through Reference in Place when adding an ordinary source to an already active library, but does not turn that source directory into Library Root. Application removal, plugin uninstall, or ADR 0279 Forget Library Registration deletes neither class; even a separately confirmed physical library deletion never deletes referenced originals.

Portable authoritative state and the small required overview/render-manifest baseline stay in Library Control Directory so moving the complete root preserves a usable library. High-churn reproducible content such as Preview Cache tiles, Analysis Proxy Cache entries, and temporary exports defaults to device-local application cache outside the adopted tree, preventing ordinary cloud-folder synchronization, removable-volume writes, and backup size from growing with every pan, zoom, or analysis run. Explicit cache co-location is allowed only after a storage/write/synchronization review and never changes backup classification or source ownership.

Adoption preflight requires a writable root plus proven regular-file semantics, durable atomic state updates, ADR 0276 Exclusive Library Lock capability, adequate Storage Safety Reserve, no conflicting nested Library Control Directory, an ADR 0282 empty safe Managed Originals Directory binding, and enough ADR 0291 Managed Original Path Headroom for the minimum managed allocation. The binding operation never adopts, scans, overwrites, or renames a non-empty unbound `Originals` or alternate target; the user must select or create another empty directory before confirmation. After another empty binding is selected, any later consideration of the colliding folder as a referenced source follows ADR 0282's separate read-only Reference Adoption Scan Plan and explicit confirmation rather than becoming an automatic import. A read-only, unsupported, placeholder-only, network, or otherwise locking/durability-unproven source is not modified; Library Start instead creates or opens the control-bearing library at a safe location and adds that source as an ordinary reference, still without copying originals. Moving or copying a root does not create live multi-device synchronization, and ADR 0196 lineage/instance identity continues to distinguish physical library instances. Once a Library Control Directory exists, every later open follows ADR 0276 Library Open Inspection rather than repeating adoption or silently recreating state.

Before adoption writes Library Control Directory or indexes an asset, a read-only **Reference Adoption Scan Plan** recursively inventories the selected tree and shows estimated file count, total source bytes, detected format distribution, unreadable or capability-missing items, mandatory exclusions, and user-selected subtree or pattern exclusions. Library Control Directory, the proposed or established Managed Originals Directory Binding, known operating-system metadata, application cache roots, and nested library control boundaries are always excluded. Directory symlinks are not followed outside the selected root, loops and duplicate physical targets are rejected, and application packages or special system-library containers are not recursively entered as ordinary folders. The plan reads only the selected scope and creates no asset record, preview, AI job, source-side sidecar, or hidden cache before the user confirms it once.

Confirmation starts durable **Progressive Reference Indexing** rather than one blocking transaction. Each item independently passes bounded real-format/readability/safety validation, basic metadata extraction, and ADR 0123 System Preview Ready before it appears as a Referenced Asset in normal Asset Grid results; under ADR 0344 an item may be one complete capability-declared member group rather than one physical file. Duplicate evidence remains advisory and does not silently merge or exclude a valid source, while one source's competing standalone/compound roles require explicit Referenced Compound Membership Conflict Review. Corrupt, encrypted, unreadable, unsupported, required-member-missing, membership-conflicted, or missing-capability items become Reference Scan Exceptions with honest reasons and later retry/rescan eligibility instead of successful placeholders. Completed items remain usable while later items continue, and pause, resume, application restart, or an interrupted worker preserves committed item state without rescanning completed content unnecessarily.

During ADR 0278 Library Switch, Progressive Reference Indexing admits no new item, completes or rolls back the current item-atomic unit, persists its cursor and exceptions, releases source/control-directory pins, and resumes only when that same library is active again and its source/generation evidence remains valid.

Initial indexing performs only source identity, required validation, basic metadata, and Required Preview work. AI tags, OCR, descriptions, embeddings, extended analysis, and optional high-detail preview cache never delay reference admission; when enabled they begin only after the Referenced Asset exists under their own resource and capability policies. After the initial baseline completes, reference monitoring applies the same item pipeline to relevant additions and Source Content Generation changes while permanently excluding Library Control Directory and Managed Originals Directory; startup/resume reconciliation remains the bounded backstop rather than repeating the original full adoption transaction.

The current referenced directory hierarchy, excluding Library Control Directory and Managed Originals Directory, is projected as a non-mutating **Source Tree** for provenance and browsing inside ADR 0034's Sources Section. Selecting a root or node applies a visibly labeled Source Scope to Asset Grid. ADR 0344 projects a Referenced Compound Original only at its primary member location while retaining companion relationships as expandable provenance. External source rename, move, addition, and removal update that projection and the referenced-source relationship, but never move library-owned files or silently create, delete, or rearrange Collection Memberships. In-app collection and Source Tree organization changes likewise never write, rename, or move source folders or originals, and there is no two-way folder/Collection synchronization. ADR 0292 nevertheless permits separate explicit Referenced Source Operations to move, rename, or rewrite a user-owned referenced original through the application while preserving its Referenced Asset ownership class; ADR 0344 requires a future explicit group-level operation before any such command can target a compound member.

During adoption, an optional **Folder Collection Mapping** preview lets the user select source subtrees and mapping depth and shows the Collection Groups, Asset Collections, memberships, name collisions, and unmapped item count that one confirmation would create. The resulting organization is a one-time snapshot independent from later Source Tree changes. Newly indexed references without an explicit mapping or later user-authored source-assignment rule enter Unsorted Collection; merely residing in a directory never creates an ongoing hidden rule.

The current application uses one settings-level library path and global managed database/media paths, has no portable Library Control Directory or In-Place Reference Library adoption workflow, and does not yet monitor referenced source trees under this ownership contract. This ADR records target architecture only and changes no runtime library, user asset, database schema, public IPC, or filesystem content.
