# External Managed Original Changes Reconcile Without Silent Lifecycle Actions

The user-visible Managed Originals Directory remains library-owned even though users may browse, open, and copy its ordinary files through Finder or File Explorer. An external filesystem event is evidence that must be reconciled, not a command to delete a Design Asset, change Asset File Ownership, import an unknown file, or mirror physical folders into Collection Memberships. Filesystem notifications are only low-latency hints; bounded startup, resume, library-activation, and watcher-gap reconciliation remains the authoritative backstop.

When stable reads and real-format validation prove that a known managed original's bytes changed in place, ADR 0406 keeps the same Design Asset and creates a new Source Content Generation. A bounded settling interval prevents an external application's temporary, partial, or replace-on-save state from being accepted as current content. Byte-identical metadata changes create no generation. User-authored metadata remains attached, while generation-bound preview and analysis evidence follows its existing stale, supersession, and regeneration policy; an invalid or still-changing observation never replaces the last verified generation.

ADR 0342 specializes this rule for a Compound Original: every affected member and the complete declared relationship revalidate before one group Source Content Generation commits. A missing primary or required member enters Compound Original Recovery, while a missing optional member creates a Degraded Compound Original rather than silently changing the authoritative manifest.

An external rename or move that remains inside the physically resolved Managed Originals Directory updates only the owned file's safe root-relative path when current evidence uniquely proves the same file, the renamed extension remains an ADR 0289-valid alias for its verified format, and no ADR 0288/0291 portable-name/path-budget, case, normalization, link, type, or ownership collision exists. Byte-identical relocation creates no Source Content Generation. The path update is journaled and item-atomic; ambiguous correlations or a misleading extension enter Managed Original Recovery/repair rather than matching by filename, timestamp, proximity, or a single create/delete event. Physical subdirectories remain storage layout only, and files not already present in the authoritative owned-file inventory never become Candidate Artifacts, Managed Assets, Referenced Assets, or Collections merely because they appear inside the directory.

For ADR 0341 storage, a whole Compound Original Directory may relocate inside the binding only when its group identity, every member identity and the complete capability-required layout are uniquely proven. A single member relocation is accepted only when the same full relationship still validates; otherwise ADR 0342's group state applies. Unknown directory entries remain unmanaged evidence and never join the compound by adjacency.

If a known managed original is deleted, moved outside the bound directory, replaced by unsafe or unsupported content, or cannot be uniquely reconciled, only that item enters **Managed Original Recovery**. Its Design Asset identity, Collection Memberships, tags, ratings, user-authored metadata, last verified Source Content Generation, and generation-bound evidence remain recorded with truthful original-availability state. Preview media may help identify the item but cannot substitute for Original Handoff, external editing, export that requires source fidelity, fresh analysis, or any other operation requiring the current original. The application does not silently create a replacement file, download or reacquire content, move the asset to Asset Trash, perform Permanent Asset Delete, convert it to a Referenced Asset, or bind an external path.

Recovery may clear automatically only when the authoritative path and exact prior content are safely restored and revalidated. ADR 0284 makes verified copy-back from explicitly selected input or Full Library Backup the default explicit recovery, keeps external input untouched, and offers Convert to Referenced Asset only as a consequence-disclosed advanced ownership change. ADR 0342 permits exact role-mapped member or complete-set input for a Compound Original but requires full group revalidation before availability changes. A different valid replacement requires an explicit new Source Content Generation decision; the application never guesses that intent. Item-scoped recovery does not block unrelated library work unless reconciliation evidence exposes a directory-binding, inventory, lock, or transaction inconsistency requiring ADR 0276 Library Recovery Mode.

ADR 0278 Library Switch stops new reconciliation commits for the outgoing library, completes or rolls back the current item-atomic update, persists unresolved observations, and revalidates them when that same library becomes active again. The current implementation stores path-bearing asset rows, deletes database records directly, and has no portable Managed Originals Directory inventory, external-change watcher, Source Content Generation persistence, or Managed Original Recovery workflow. This ADR records target architecture only and watches, reads, hashes, moves, restores, or deletes no runtime or user file and changes no public IPC, database schema, or AI Worker API.
