# Extension Permissions Use Tiered Consent and Update Reapproval

Scope: Target architecture, refined by [ADR 0484](0484-extension-contracts-and-deferred-agent-development-access.md)
and the AI+ core boundary in [ADR 0483](0483-ai-plus-core-product-and-extension-boundaries.md).
The full ecosystem below is not a prerequisite for core product work; selected public
capabilities must satisfy their applicable contracts before third-party execution.
No SDK, catalog or sandbox is delivered merely by this decision.

Extension permissions use two consent tiers in the official build. Ordinary Extension Permissions cover bounded commands, declared Extension UI Slots, Namespaced Extension Storage, and access to already-derived preview or metadata projections within the current operation. They are summarized before installation and remain individually inspectable and revocable. Sensitive Extension Permissions cover declared network hosts and purposes, browser page DOM or content scopes, staged original-file access for format workers, ADR 0382 staged user-selected metadata-import source access, and native or external worker execution. Each sensitive permission requires its own explicit, individually disclosed and selectable grant before the dependent contribution can activate; multiple such choices may be confirmed in one trusted application review under ADR 0484, and that grant remains unusable when ADR 0156 confinement evidence is missing or the plugin is quarantined. An extension surface, catalog review, signature, installation, or prior approval of a different permission never implies another grant.

The trusted application shell owns every consent surface. Extension panels and workers may report that a declared permission is unavailable, but cannot render, cover, imitate, auto-accept, or repeatedly trigger the permission dialog. Undeclared permissions cannot be requested dynamically. A declared but ungranted sensitive permission may be enabled later only from Extension Library, plugin settings, or an explicit user action routed through trusted application UI. Developer Mode preserves the same permission checks and labels unsigned packages as untrusted rather than bypassing consent.

Extension Host computes an Effective Permission Set from the installed manifest, publisher and package identity, current user grants, platform capability, contribution context, and current policy or revocation state. It issues only bounded Extension Capability Grants and operation handles derived from that set. Revoking a permission immediately blocks new calls, invalidates related reusable or operation handles, stops or isolates affected in-flight work within a bounded grace period, and removes staged access. Contributions that do not depend on the revoked permission may remain active. Revocation does not silently delete plugin-owned user data, derived analysis results, or prior provenance; those follow their own lifecycle rules.

Before activating an update, the installer compares the normalized old and new permission manifests. Any added permission, broader host/domain match, broader page-content scope, new original-content access, new worker/process authority, or materially expanded contribution surface puts the plugin into Permission Reapproval Required. The updated plugin remains suspended until the user reviews the exact permission diff and approves it. Approval creates grants only for the displayed new effective set; rejection rolls back to a still-compatible verified prior version when available or leaves the plugin disabled. Version changes, renamed permissions, wildcard substitutions, and manifest migration cannot silently inherit broader authority.

Permission reduction may proceed without additional consent but removes the corresponding grants at activation. ADR 0158 Critical Security Revocation or Safety Suspension, publisher trust loss, policy denial, failed ADR 0157 admission evidence, or incompatible capability evidence can override prior user grants and suspend the plugin with a specific reason; ordinary Catalog Delisting does not revoke existing grants by itself. Extension Library shows granted, denied, unavailable, revoked, and reapproval-required states per permission, offers per-plugin revocation and later re-enable controls where trust state permits, and records a content-free local audit trail of consent decisions without asset content, credentials, paths, or plugin payloads.
