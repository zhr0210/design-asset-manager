# Portability Exports Separate Package References From Exact Match Evidence

Every Metadata Portability Export assigns each selected Design Asset a random **Export-Scoped Asset Reference** unique to that export. All records, regions, relationships, provenance links and Metadata Package Blobs inside the same output refer to this value, never to an array position, filename, path or database row. The reference has no meaning outside the export, is not reused across later exports and is always present in `.dammeta`, JSON and CSV so the output remains internally coherent without disclosing a stable library identity.

Metadata Portability Package enables **Exact Asset Matching Evidence** by default because its primary purpose includes reliable future interchange. For each asset it may include one **Portable Asset Identity** formed from the stable Portable Library Lineage Identity plus the stable Design Asset Identity, and **Original Content Match Evidence** for the current verified Original Asset: real format, exact byte length/content digest for a single file or complete member-role, member-length/digest and manifest digest evidence for a Compound Original. These are opaque portable values, not local database primary keys, Local Library Instance Identity, filesystem identifiers, filenames, paths, volume labels, usernames, credentials or source URLs.

The export review explains that stable identity and content digests can correlate the same asset or bytes across separate exports and shows which selected assets have complete, partial or unavailable matching evidence. The user may disable Exact Asset Matching Evidence for the entire export; the output then retains only Export-Scoped Asset References and states that a future import cannot perform stable or content-exact automatic matching. The option never triggers hidden reads or hashing of offline/unavailable Referenced Assets merely to make the evidence complete; it exports only current trusted evidence already available to the reviewed snapshot and exposes gaps.

Metadata Portability JSON and CSV default to Export-Scoped Asset Reference only. Portable Asset Identity and individual content/compound evidence are separately selected documented fields/columns with the same correlation warning; CSV never compresses a compound manifest or multi-member evidence into an opaque cell and excludes it when its flat schema cannot represent it losslessly. Selecting one stable identity field does not silently add paths, source provenance or every matching field.

The `.dammeta` manifest declares whether exact matching is enabled, which evidence classes are present, their schema versions and every per-asset gap. ADR 0376 permits a Metadata Import Mapping Plan to propose a target only from a unique same-lineage identity or unique exact complete content/member match; multiple targets, disagreement and insufficient evidence remain unresolved for review. Filename, former path, display title, timestamp, byte length alone, visual similarity or one compound member can never become an exact automatic match, and exporting evidence itself neither imports metadata nor merges, creates, relinks or changes an asset.

The current application has no Export-Scoped Asset Reference, Portable Asset Identity export, matching-evidence review or content/compound match schema. This ADR records target architecture only and generates no runtime identity, hashes no user source, selects, serializes, exports, packages, encrypts, attaches, imports, matches, stages, writes, rewrites, converts, moves, deletes or changes no runtime/user file, credential, sidecar, directory, database, cache, backup, metadata value, analysis result or source relationship and changes no public IPC, database schema or AI Worker API.
