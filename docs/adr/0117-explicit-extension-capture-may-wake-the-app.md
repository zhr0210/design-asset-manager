# Explicit Extension Capture May Wake The App

When a paired browser extension cannot reach a running Local Capture API, only an explicit user-triggered capture may issue a Capture Wake Request through a registered application protocol. The wake payload carries only a one-time Capture Wake Nonce, Producer Identity, and Capture Request Identity; it must not carry an artifact, source URL, Scoped Capture Token, Capture Envelope metadata, or other private content. The extension keeps Pending Extension Capture payload only in volatile memory until the authenticated loopback service is ready, then submits it normally. Failed startup or connection remains visibly pending or failed and requires retry rather than reporting success. Background pages cannot silently wake the app, while a user-initiated batch may reuse one wake handshake for its batch requests.
