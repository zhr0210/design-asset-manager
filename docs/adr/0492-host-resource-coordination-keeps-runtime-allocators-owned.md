# Host Resource Coordination Keeps Runtime Allocators Owned

Status: Proposed, revised design awaiting overall confirmation (2026-10-06). The user has agreed to balanced resource reuse, automatic same-model placement before new units, unchanged input/output requirements, bounded audited local OOM recovery and compatible permissively licensed adoption. After requesting revision at Q13, the user added retrieval design (Q15), offline use of verified installed models (Q16), and Chinese lexical/combined, semantic-text and image-example retrieval (Q17). These are recorded in the revised foundation design; the overall understanding has not been confirmed and product implementation has not begun.

One Host-owned Local AI Resource Governor plans and admits DAM's local work across Torch, ONNX and native GGUF, including declared retrieval-model, query and index-maintenance consumers, while Runtime Adapters own their actual allocators, model handles and supported reclaim operations. Execution plans freeze model, quantization, recipe and semantic limits; idle residency may be reclaimed only with fresh owner-scoped Runtime Reclaim Evidence, retaining active protection and unconfirmed occupation. This extends ADR 0173 and 0491 without granting authority over external processes or combining incompatible allocator caches into a fictitious shared tensor pool. Retrieval continues the model-space and rebuildable-index semantics in ADR 0181–0184; adding those consumers does not turn the Governor into the owner of library results or indexes.

Embedding a framework-specific memory manager as the cross-runtime authority would make native and ONNX ownership, cancellation and failure depend on mechanisms they cannot necessarily perform. The Host/Adapter split preserves verified existing paths while allowing real offload, warm reuse or cold release where each runtime supports them. It trades a universal per-layer offload promise for explicit capability and release evidence; physical headroom, estimated reservations and allocator caches remain separate.

Model selection and runtime resource preferences are distinct. Same-model verified placement can adapt before a unit, but a resource optimization cannot silently change checkpoint, weight quantization, input coverage, output standards or external destination. Overall acceptance and the licensed source/adoption choices are tracked in [the resource design](../product/LOCAL-AI-RESOURCE-COORDINATION.md); this record is not implementation evidence or release approval.
