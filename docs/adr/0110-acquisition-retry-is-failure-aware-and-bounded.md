# Acquisition Retry Is Failure-Aware And Bounded

Candidate Artifact acquisition retry must be classified by failure type and bounded. Retryable Acquisition Failure such as transient network interruption, timeout, or temporary service failure may receive at most two Automatic Acquisition Retry attempts with increasing backoff and any authoritative server retry delay respected. Authentication or permission failure, missing source content, unsupported format, and artifact validation failure are Acquisition Manual Recovery Required and must not retry automatically. Exhausting the Automatic Retry Budget turns the intake into an Unresolved Acquisition Failure with an explicit manual recovery action. Every retry reuses the original Capture Request Identity and Candidate Identity, updates the same Candidate Record and failure trace, and must not create a duplicate Asset Candidate.
