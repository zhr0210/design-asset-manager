# Transfer Destination Replacement Trashes Before Publishing

**Replace Transfer Destination** never overwrites, truncates, unlinks or permanently deletes the occupying file. Its separate confirmation identifies the exact current occupant, explains that the occupant will move to operating-system trash, and revalidates the expected source generation, completely verified staging, destination volume and directory, occupant identity/type, permissions and platform trash capability immediately before execution. A directory, link, special file, protected boundary or unprovable occupant is not replaceable through this action; the conflict page retains non-destructive unique-name, another-location and cancel choices.

After durably recording the exact replacement intent, the application asks the operating system to trash the occupant first. Only a reported and reconciled success makes the path eligible for atomic publication of the already verified Referenced Source Transfer Staging. A reported failure, unchanged occupant or inability to prove the trash outcome leaves the occupant and staging unmodified, returns current evidence to Referenced Source Transfer Conflict Review, and never falls back to direct overwrite, permanent deletion, generated naming, another destination or repeating the destructive call automatically. The old referenced source remains untouched until destination publication and relationship commit later succeed.

If the occupant is proven trashed but staging publication does not commit, the application must preserve truthful durable intermediate evidence rather than claim replacement or retry destructive work. ADR 0306 uses exact device-local replacement evidence to attempt one safe rollback restoration and otherwise opens visual recovery; post-success receipt retention for broader undo remains a child decision. Successful publication still requires post-commit destination validation before the same Design Asset relationship moves to it and the ordinary ADR 0301 old-source cleanup phase begins. The current application has no referenced-source transfer staging, conflict review, replacement journal or platform restore support. This ADR records target architecture only and trashes, overwrites, publishes, restores, removes, reads or writes no runtime/user file and changes no public IPC, database schema or AI Worker API.
