# OCR Source Language Is Separate From Metadata Language

OCR Source Text and generated Metadata Language are separate contracts. OCR recognizes and preserves the visible source-language text and writing system without automatic translation, while ADR 0169 Short Description targets one user-selected Metadata Language. The initial Metadata Language defaults to the current application display language at first setup, then becomes an explicit independent preference; later UI-language changes do not silently rewrite it, regenerate stored results or relabel prior evidence.

OCR evidence preserves the recognized Unicode text, region/Analysis Unit and reading-order evidence, exact OCR artifact/runtime/recipe, configured recognition languages, and per-span Script/Language Detection Evidence when the provider can establish it. Script and language are distinct: detecting Han, Latin, Arabic or another script does not by itself prove a specific language. A span or unit may be Known, Mixed or Language Undetermined with confidence/method provenance. Application locale, filename, source site, collection, prior tags and user identity are never used to fabricate the source language.

Recognition output is not translated or overwritten. Search may use a separately versioned reversible normalization projection for case, compatibility forms or whitespace, but the raw recognized text remains available with provenance. Optional OCR translation is a later explicit derived action with source/target language, translator/model and scope evidence; it never replaces source OCR. User correction follows ADR 0143 manual-result rules and remains distinguishable from model evidence.

OCR Language Coverage is an explicit local capability setting. Starter Setup recommends the application language plus English only as a reviewable coverage choice, not as a claim about any asset, and the user may add, remove or defer languages. A multilingual model may satisfy several declared languages only when its manifest and benchmark evidence say so. Provider-specific language packs/models are fully expanded as ADR 0160/0170 dependencies with exact language/script coverage, license, trust, platform/runtime, download, deduplicated/additional storage, memory and ADR 0177 network-cost evidence.

When visible text uses an unsupported or undetermined language/script, the result records Partial OCR Coverage or Waiting for OCR Language Capability as appropriate. It cannot be converted to ADR 0169 No Text Detected. Independent recognized spans remain valid, but omitted/unsupported scope stays visible in Analysis Coverage Evidence. Installing another language pack reconciles compatible waiting/new work under ADR 0168; it does not silently OCR the historical library without an explicit Backfill Plan.

Short Description is generated directly in the selected Metadata Language only when the exact model/recipe declares that output capability. Otherwise the reviewed capability chain may include a verified local translation model with separate provenance and resource/dependency cost. Translation failure, wrong-language output or undetermined output language is not silently accepted as the target language and cannot be replaced by a generic fabricated caption. The original model output may remain scoped evidence with its detected/declared language, while the target-language Short Description stays failed, waiting or absent honestly.

Changing Metadata Language applies to future or materially changed description intents. Existing model-generated and user-authored descriptions keep their language/provenance. The application offers a separate selected/collection/library Analysis Backfill Plan to create target-language alternatives; it does not overwrite manual descriptions, delete earlier languages or mix translations into one unlabeled field. Each description value therefore carries a BCP 47-style language tag or Language Undetermined plus source type and model/translation provenance.

Tag localization follows ADR 0179 stable concept and language-aware label rules and cannot define OCR or description language implicitly. Embeddings retain their exact model-space semantics; a multilingual embedding may index OCR/descriptions only according to its declared recipe and does not turn a translation into source text. Settings, Model Library, Starter Setup and Asset Inspector present these language boundaries consistently.

The current implementation hard-codes EasyOCR to simplified-Chinese plus English in one path, PaddleOCR to Chinese in another, uses fixed Chinese/English prompt fields and has English-to-Chinese tag/caption translation behavior. Shared settings and stored projections do not provide one explicit Metadata Language, declared OCR Language Coverage, per-span script/language evidence, unsupported-language coverage or multilingual description alternatives. Some defensive prompt fallbacks also produce generic Chinese text rather than an honest missing/invalid result. This ADR records the target semantics without changing schemas/APIs, loading language packs, running OCR/translation or reading assets/runtime data.
