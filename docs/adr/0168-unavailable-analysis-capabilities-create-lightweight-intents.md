# Unavailable Analysis Capabilities Create Lightweight Intents

When automatic local analysis is enabled, each eligible Candidate or Design Asset may receive a durable lightweight Analysis Intent per ADR 0169 enabled capability, Source Content Generation, recipe generation and requested coverage class. The default baseline capabilities are Tag Suggestions, semantic Embedding, bounded OCR and one Short Description; capability toggles prevent new intents independently. The intent records opaque owning identity, trigger, capability, priority, automatic/manual origin, coverage goal, generations, timestamps and lifecycle state; it contains no original path, image bytes, Analysis Input View, proxy filename, tensor, model credential or preselected mutable model path. Intent creation represents desired future work, not model execution or a claim that analysis succeeded.

Analysis Intent is distinct from Analysis Execution Job. The intent remains model-agnostic for ordinary automatic analysis until admission time. Only after Preview/format capability, Active Capability Model, runtime/capability binding, Model Storage Root, trust state, local policy and ADR 0173 global resource admission are all eligible does the scheduler create a generation-keyed execution job with exact artifact/runtime/recipe provenance. One normalized key deduplicates repeated automatic triggers; a changed source, recipe or coverage request supersedes stale unstarted intent/work instead of multiplying the queue.

Non-eligible intents expose a typed Analysis Waiting Reason: Waiting for Preview Capability, Waiting for Model, Waiting for Runtime, Waiting for Model Storage, Waiting for Trust or Compatibility, Waiting for System Resources, Waiting for Library Activation, or User Paused. Waiting is not failure, completion or promotion blocking. It never downloads a model, installs a runtime/capability pack, selects a model, reconnects a disk, weakens trust, starts an external service or requests upload consent. Independent capabilities may execute while another capability waits.

Pending Intent Reconciliation runs after application restart, ADR 0174 wake/visible-lifecycle recovery and relevant verified state changes such as model installation and explicit selection, ADR 0170 Starter Setup completion or repair, runtime/capability repair, storage-root reconnection, trust recovery, source-preview readiness or resource availability. If the specific ADR 0169 capability and master automatic analysis remain enabled, eligible automatic intents resume through the normal resource-aware scheduler without another per-item confirmation because they implement the existing local-analysis preference. External providers never resume automatically, and a model install/update/switch, Starter Setup or newly enabled capability does not create intents for already completed historical assets or the rest of the library; library backfill requires its own visible plan and confirmation.

Users can pause, resume, cancel or delete single, selected-batch, capability-level or all pending intents. Pause retains future eligibility; cancel records a terminal user decision that can be explicitly retried; delete removes only the intent and its unstarted job state, never the asset, preview, completed results or model. Disabling automatic analysis pauses existing automatic intents by default and prevents new ones rather than silently deleting intent history. Foreground explicit analysis can create a higher-priority intent without duplicating the same normalized generation/coverage work.

ADR 0278 Library Switch stops new execution admission for the outgoing library. An unstarted intent enters Waiting for Library Activation; admitted work reaches its declared Analysis Unit/evidence-commit boundary, commits or rolls back that unit, releases library/proxy pins, and preserves the remaining intent as switch-paused work. Reactivating the same library reconciles generations, capability preferences and committed evidence before eligible switch-paused automatic work resumes. A prior User Paused, cancelled, deleted, failed or superseded decision is never converted into automatic resume merely because the library reopened.

Intents follow owner lifecycle. Candidate Promotion preserves and relinks compatible pending intent to the resulting Design Asset. Candidate Hard Delete and Permanent Asset Delete remove their intents and unstarted jobs. Asset Trash pauses automatic intent execution while retaining state for Asset Restore. A Source Content Generation change supersedes stale intents/jobs; removal of an installed model, trust suspension or storage disconnect returns unstarted/eligible automatic work to the appropriate waiting reason rather than downloading a replacement. Model update or active-model switch affects only pending/future admitted work unless the user separately confirms ADR 0145 migration.

Preview Broker creates or validates Analysis Visual Source and model-specific Analysis Input Views only when an execution job reaches admission. Common bitmap in-memory decode, structured overview/tile rendering, transparency views and provider preprocessing still follow ADR 0137 through ADR 0140. One-use inputs are released after use; shared Analysis Proxy Cache entries are created only when repeated admitted work justifies them and are pinned only for active jobs. If capability disappears after input preparation, the job releases its pins/intermediates and the surviving intent returns to a waiting state; the system does not retain a disk proxy merely because work is waiting.

Retryable execution failures receive bounded job retries; capability/storage/resource loss returns the intent to a typed waiting state; malformed source, invalid output or a non-retryable model failure becomes a structured failed intent/job outcome requiring explicit retry or repair. Application restart reconciles intent, job, proxy pins and committed View-Level Analysis Evidence without converting uncertain work into success. An unresolved in-flight job places only work sharing its exact governed model runtime behind ADR 0402 Startup Reconciliation Isolation; jobs using other reconciled runtimes and non-conflicting application work remain eligible. Reconciliation may recognize completely committed evidence or return safely incomplete work to Paused/Waiting, but it never automatically repeats inference or commits partial output. Deferring review preserves that runtime-scoped isolation; a verified runtime restoration may trigger only a read-only evidence recheck, not inference. Completed evidence remains governed by ADR 0143 and is not deleted with a pending-intent action.

Asset Inspector shows per-capability state, while AI Console shows aggregate waiting reasons, running work and controls; Model Library may show how many intents await a model or unavailable storage without exposing asset content. Queue summaries are counts and capability/reason metadata only. The implementation must replace legacy concrete path/model task restoration with opaque intents and brokered admission before claiming compliance; this ADR does not authorize an immediate database schema or Worker API change.
