# Cross-Format Source Change Adopts The Export Before Old-Source Cleanup

Status: Superseded by ADR 0348.

**Use Exported File as Current Source** treats the one explicitly selected complete Compatible Export file at its existing user-owned location as the proposed new Referenced Asset source; it does not copy, move, rename, rewrite or hide that file. Before commit, Change Referenced Source Format freshly validates the current Design Asset and Source Content Generation, exact current source, export identity and availability, real format and matching extension, path safety, permissions, professional-unit consequences and source-relationship conflicts under ADR 0324. It durably records intent and prepares exact old-source restore evidence before any destructive call.

After validation, the application atomically commits the same Design Asset's relationship to the export file and its new Source Content Generation while preserving referenced ownership and user-authored values. ADR 0325 defines this as the Source Format Change Commit Boundary and governs cancellation on either side. The application then revalidates that the committed new source remains complete and available before making one request to move the exact prior source to operating-system trash. The new relationship therefore exists before cleanup, and disappearance, mutation or ambiguity of the export after commit blocks old-source trash rather than sacrificing the last proven source. The export remains where the user placed it and is not duplicated as hidden staging or library-owned content.

Proven old-source trash success retains a device-local **Format-Change Old Source Recovery Receipt** in Local File Recovery. **Recover Format-Change Old Source File** restores only that exact prior source to a selected safe empty location as an ordinary untracked file and never changes the active export relationship, Source Content Generation or Design Asset. Reported cleanup failure, blocked safety revalidation or ambiguous trash evidence keeps the new source current and records **Format Changed With Old Source Remaining** rather than rolling back, deleting the export or pretending the format change failed. **Retry Format-Change Old Source Cleanup** is always a freshly validated explicit trash request; **Keep Both After Source Format Change** resolves attention and releases the old file as untracked user content. No restart, monitoring, scheduling or cleanup process repeats the destructive call automatically.

Restart reconciliation never infers authority from intent alone. If the new relationship and generation are not proven committed, it does not trash the old source. If they are proven committed, it revalidates the export and reconciles only existing old-source cleanup evidence; proven ambiguity remains attention without another trash call. Restoring the old source as an external file is not format-change undo, and making it current again requires another explicit current-source change. The current application has no cross-format source-change relationship commit, old-source cleanup state or recovery receipt. This ADR records target architecture only and exports, accesses, creates, copies, relinks, moves, rewrites, restores, trashes, deletes, reads or writes no runtime/user file and changes no public IPC, database schema or AI Worker API.
