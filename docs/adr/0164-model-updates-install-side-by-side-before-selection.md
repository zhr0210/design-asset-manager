# Model Updates Install Side By Side Before Selection

Model Library may run a bounded Model Catalog Metadata Refresh under ADR 0204: automatic refresh is stale-driven, limited to one eligible attempt per trust root/channel per rolling 24 hours while the application is active, and always has a manual action. Refresh retrieves and verifies only signed path-free catalog/manifests, ADR 0165 Model Trust Statements and ADR 0172 Catalog Benchmark Evidence; it does not download model blobs or benchmark datasets, accept a license, authorize a source account, install a runtime, load a model, select an artifact, start analysis or read user assets. Offline or failed refresh retains the last verified catalog and trust state with visible freshness rather than treating unverified metadata as current or clearing a prior revocation.

A newer immutable Model Artifact Manifest creates a Model Update Candidate, not an in-place replacement. Update remains user-triggered. Before download, a Model Update Plan shows source and target family/checkpoint/variant, publisher and trust source, exact revision, change notes, total and per-artifact download, shared/already-present bytes, additional physical disk, ADR 0167 root availability/identity, old-artifact rollback retention, license/terms changes, gated-account need, runtime/capability dependencies, platform compatibility, expected derived-cache work, active assignments and result/index implications. New terms, new source identity, unproven compatibility or changed runtime dependency receives separate confirmation rather than being hidden inside Update All. ADR 0166 Unverified Local Models do not receive update candidates by resemblance; only a later exact signed manifest match may propose user-reviewed reclassification and update lineage.

ADR 0206 Fresh Trust Install Admission applies before an online Model Update Plan transfers payload and again before promotion if the trust state became stale during a long transfer. A stale or Trust Not Assessed state waits for a successful signed metadata refresh; cached update discovery cannot authorize installation. Exactly verified official offline model packages may instead use their signed Dated Offline Trust Evidence while visibly retaining its issue date and never rolling back newer local trust state.

Batch update is one explicit user action over the fully expanded plan. Each artifact remains its own transactional unit so one failure does not roll back already verified independent updates or damage existing installations. The installer stages exact ADR 0161 files, verifies manifest/signature/digests/formats/license/runtime compatibility, atomically adds ADR 0162 blob references, and runs a bounded local readiness probe without user assets or source-network access. Failure removes only unreferenced partial/staged data and failed derived outputs; the previously installed and active artifact, assignments, results, indexes and shared blobs remain unchanged.

Successful installation produces Installed Update Available. It does not change Active Capability Model, Active Embedding Space, fallback order, automatic-analysis recipe, Model Source Account, external-upload authority or existing-library analysis. Model Activation Preview shows the exact source and target result generations, Cross-Variant Equivalence Evidence or its absence, future-analysis behavior, retained prior results, runtime/backend change, resource difference, and whether explicit Analysis Result Migration or Embedding Space Migration would be required. Selection is a separate trusted user action even when the update is recommended. ADR 0170 is a narrow first-configuration exception that combines only the explicitly displayed new installs and Starter Capability Assignments in one reviewed consent; it grants no authority for later updates or migration.

When selected, the new artifact applies only to future or explicitly migrated work under ADR 0144 and ADR 0145. The immediately previous active artifact and required shared blobs remain pinned for a bounded visible Model Rollback Window after selection. Rollback restores the prior future-analysis assignment and compatible runtime binding; it does not erase results produced by either generation, merge embedding spaces, or reverse an already completed result/index migration. Storage Management reports rollback-pinned bytes and the release date. If disk admission cannot hold both verified versions, update blocks or asks for an explicit reduced-recovery choice after the new artifact verifies; it never silently deletes the active model to make space.

An update may be selected without reanalysis only in the limited sense that existing results retain their original valid provenance. Treating old and new artifacts as one result generation requires ADR 0162 Cross-Variant Equivalence Evidence for the capability/runtime matrix. Embedding updates without strict vector/ranking equivalence always create a separate target space and show rebuild coverage, compute, additional storage, pause/cancel behavior and atomic cutover before migration consent.

Update All includes only candidates whose complete manifests and plan are known. It may group ordinary unchanged-license compatible artifacts, but excludes candidates needing new license acceptance, gated authorization, new capability-pack installation, incompatible platform/runtime changes, unresolved or adverse ADR 0165 trust state, insufficient storage, active-job conflict or individual migration choice until those items are reviewed. A critical revocation can block an artifact immediately but cannot auto-download its replacement. No setting enables automatic model blob download, install, activation, migration or old-artifact deletion.

Model update status and progress are expressed through opaque manifest/artifact identities and path-free errors. Public IPC and renderer state never return model directories, blob locations, credentials, raw source URLs, subprocess output or private verification details. Catalog freshness, update discovery, download/install, readiness, selection, rollback retention, migration and uninstall remain distinct states rather than one downloaded boolean.
