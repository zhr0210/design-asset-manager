# Capability Declared Companions Form One Compound Original

Copy Into Library supports a **Compound Original** when a Capture Format Capability explicitly declares one primary visual member plus exact companion-member roles, discovery constraints, required/optional status, validation and preview/analysis consequences. Examples may include a RAW primary with a declared XMP companion, but matching basename, extension, adjacency, folder convention, metadata resemblance or plugin suggestion never establishes membership by itself. One stable Compound Original Identity groups the members while every ordinary member keeps its own Original Storage Object Identity and verified bytes.

The Copy Into Library Plan presents one proposed asset row with expandable primary and companion members, each member's role, required/optional state, individual and total bytes, validation/capability state and any missing-member consequence. All discovered declared companions are selected by default. A required member cannot be deselected, and its absence or invalidity excludes that proposed asset from admission. An optional member may be explicitly deselected before confirmation; a missing optional member permits admission only with a visible incomplete-companion warning. Once the plan is confirmed, every selected optional member is part of the authorized artifact and must stage and validate successfully or the group remains uncommitted until a refreshed plan explicitly removes it.

One Copy Into Library item, Capture Request Identity, Candidate Identity and Candidate Record owns the complete member set. Candidate Activation occurs only after every included member is independently copied and byte-verified, the declared relationship is revalidated, and the Compound Original identity/member manifest plus all included ordinary files commit atomically as one Candidate Artifact. Cancellation, retry, storage pause and restart reconciliation operate at that group boundary; they may remove only uncommitted attempt-owned member staging and never leave a partially activated group. Every selected external primary and companion remains unchanged.

Candidate Promotion transfers the same Compound Original to one Design Asset without duplicating or separating members. Candidate retention/rejection, Asset Trash, Permanent Asset Delete, Full Library Backup/restore, managed-original recovery and Asset File Ownership address the group as one lifecycle unit even when recovery diagnoses one missing member. A member never becomes an independent Asset Candidate or Design Asset merely because it has its own stored file and identity. Any material byte/member-manifest change creates a new Source Content Generation for the same Design Asset rather than a second asset.

System Preview and analysis use the primary visual member plus only those companion effects that the declared capability can safely validate and reproduce. Nonvisual XMP or similar members may contribute declared metadata/color/edit evidence but never receive their own grid card, thumbnail, OCR, description, tags, embedding or AI completion state. A capability-declared additional visual member participates only through the Compound Original's explicit Analysis Coverage Plan rather than silently expanding into another asset.

This decision extends ADRs 0280, 0281 and 0285 beyond the previous single-ordinary-file assumption while retaining ordinary member files, one ownership boundary and one Candidate/Design Asset identity. ADR 0341 resolves physical storage as one atomically published Compound Original Directory and makes complete-set Original Handoff the default while keeping external open primary-oriented. ADR 0342 resolves member-level external-change diagnosis through tiered availability and group-validated recovery rather than filename proximity or independent-member lifecycle. ADR 0344 extends the same capability-declared grouping to Reference in Place through user-owned member relationships without managed copying or source-side files. ADR 0349 permits a separately validated and explicitly confirmed post-admission companion attachment without turning later filename discovery into membership. The current application has no Compound Original identity, member manifest or group-atomic intake. This ADR records target architecture only and discovers, groups, selects, stages, copies, validates, previews, analyzes, backs up, restores, modifies or deletes no runtime/user file and changes no public IPC, database schema or AI Worker API.

ADR 0385 preserves every current member name and authoritative relative path in
Original Asset Export. It may normalize only the containing export asset
directory; it blocks an unrepresentable complete member layout rather than
independently renaming companions and breaking this declared relationship.

ADR 0394's Compatible Export XMP Companion is a newly generated user-owned
output member only. It never becomes a Companion Original Member, changes this
manifest or creates a Source Content Generation merely because its name is
associated with an exported media file.
