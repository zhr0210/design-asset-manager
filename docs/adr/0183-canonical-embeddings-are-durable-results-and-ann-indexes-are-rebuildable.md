# Canonical Embeddings Are Durable Results And ANN Indexes Are Rebuildable

A Canonical Embedding Result is durable ADR 0143 analysis evidence, not image/proxy cache. It stores the finite model output needed to reconstruct search without rerunning inference, bound to opaque owner and Query Visual Scope/Analysis Unit, Source Content Generation, exact Model Family/Checkpoint/Artifact Variant and runtime-equivalence evidence, Analysis Recipe, vector dimensions, canonical numeric encoding, normalization contract, distance metric, created time and result lifecycle. A vector missing any required contract, containing non-finite values or using the wrong dimension is failed evidence rather than a usable embedding.

The ADR 0169 baseline creates at most one Search Baseline Embedding per eligible Source Content Generation: the Primary Asset Overview scope. For a transparent or other multi-view recipe, the declared deterministic view/aggregation procedure may produce that one canonical asset vector, with its coverage recorded; it does not create unlabeled extra baseline vectors. PSD/PSB/layered TIFF, multi-page PDF/TIFF, AI artboards, animation/video frames and other structured assets do not receive every layer/page/artboard/frame/crop vector automatically. Additional Unit Embeddings require ADR 0182 explicit query/generate action, selected-scope analysis, confirmed Backfill scope or opt-in Idle Extended Analysis.

The canonical numeric representation preserves the exact declared model output and normalization needed by the model space. Lossy quantization, dimensionality reduction or product quantization cannot replace it unless named Cross-Variant/Encoding Equivalence Evidence proves the capability and tolerance and the manifest declares that representation canonical. Storage optimizations normally belong to the derived index. This prevents a smaller search structure from becoming the only copy of an irreproducibly altered result.

An ANN Search Index is rebuildable derived search data. It references canonical embeddings from exactly one ADR 0144 Active Embedding Space and may use HNSW, IVF, product quantization or another declared index schema/encoding only with versioned build parameters and validation. Deleting or corrupting an ANN index does not delete vectors or require model inference: the app temporarily reports semantic lane unavailable/rebuilding, continues ADR 0181 lexical search, and reconstructs the index from canonical results under resource/storage admission before atomic activation.

Canonical vectors and ANN indexes are accounted separately. Storage Management reports active and retained vector-result bytes by embedding space, derived index bytes, coverage, rebuild estimate and reclaimable superseded data. “Clean Analysis Cache” touches neither. ADR 0185 backup includes canonical vectors and their exact space contracts while excluding rebuildable ANN indexes. A separate **Rebuild/Clear Derived Search Index** action may remove an inactive/corrupt index or intentionally make semantic search unavailable until rebuild; it never removes canonical vectors. Deleting canonical embeddings is an explicit result/batch lifecycle action with affected semantic-search coverage and index reconciliation, not automatic TTL/LRU cleanup.

ADR 0144 Embedding Space Migration writes target canonical vectors and builds a separately namespaced target ANN index while the prior complete space remains active. New and changed assets follow the declared dual-write/migration policy without inserting incompatible vectors together. Atomic cutover requires target coverage and validation; after cutover, prior canonical vectors/index follow ADR 0143 retained-generation/rollback policy and explicit reclaim reporting. Identical dimensions never imply compatibility.

Index generation is transactional and deterministic over a declared canonical-vector snapshot. Inserts/deletes use generation-aware staging so search never observes vector metadata from one generation with an index node from another. Startup reconciliation can repair staged/index references without opening original assets. If canonical vector validation fails during rebuild, that item is excluded with a typed coverage reason rather than padded, truncated or silently normalized differently.

Expected raw vector storage is shown as evidence-based estimates: for example, float32 uses four bytes per dimension before metadata, while another declared lossless encoding uses its actual size. ANN overhead varies by algorithm and is never presented as equal to raw vector bytes by assumption. Storage estimates include per-unit growth for optional structured-asset coverage so users can preview Backfill or Idle Extended choices.

ADR 0182 Transient Query Embeddings are explicitly excluded: they remain session-only and never enter canonical result storage or the ANN candidate index. Search queries use the same exact model-space contract but are released when the search session ends.

The current repository exposes embedding capability/readiness and a generated-fixture ONNX forward probe but has no embedding result table, canonical vector codec, Active Embedding Space index, ANN implementation, coverage/rebuild state, vector/index storage accounting or migration executor. Embeddings remain disabled in current settings. This ADR records target storage semantics without changing the schema/API, creating vectors/indexes, running models or reading library/runtime data.
