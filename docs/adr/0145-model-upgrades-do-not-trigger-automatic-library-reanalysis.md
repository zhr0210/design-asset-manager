# Model Upgrades Do Not Trigger Automatic Library Reanalysis

Installing, registering, updating, or selecting a newer verified Model Artifact Manifest or another ADR 0162 quantization/backend variant does not automatically reanalyze the existing library. ADR 0164 installs updates side by side, keeps installation separate from selection, and retains the immediately previous active artifact through a visible rollback window. A model update or unproven variant switch is a new immutable artifact/result-generation identity rather than an in-place rewrite or an equivalence assumption. After an Active Capability Model version changes, new or explicitly changed assets use the new version while existing compatible View-Level Analysis Evidence and Asset Analysis Projections remain usable with their original model and recipe provenance. A library may therefore temporarily contain results from multiple model generations without pretending that their confidence values or embeddings are interchangeable.

Reanalysis of existing assets is an explicit Analysis Result Migration. Before start, the UI identifies capability, source and target model/recipe generations, selected assets, collection or whole-library scope, Analysis Coverage mode, eligible and excluded counts, estimated Analysis Unit count, approximate compute/time and additional storage when estimable, local execution backend, and whether an embedding index migration is required. The user confirms the visible scope; selection of a new default model, application update, or model artifact discovery is not migration consent.

Migration uses durable, resource-aware, generation-keyed jobs under ADR 0141. It may be paused, resumed, or cancelled for unstarted units and must reconcile after restart. Tag, OCR, and caption migration activates a validated target generation per asset atomically while retaining the prior active generation for assets whose target work fails. User-authored tags, corrected OCR, descriptions, suppression choices, and manually attached results remain unchanged and are never reclassified as model output. External execution, if explicitly chosen, still requires the scoped grant from ADR 0141.

Embedding model changes always use the separately namespaced Embedding Space Migration in ADR 0144. The prior complete search index remains active until target coverage and validation pass; raw similarity scores never cross spaces. The migration preview distinguishes new vector/result storage from ephemeral Analysis Proxy Cache, and low disk, power, memory, thermal, or foreground pressure pauses work without deleting the usable old index.

ADR 0165 separates model execution revocation/suspension from committed result ownership. Scoped signed or locally verified evidence of a serious correctness, integrity, privacy or security defect may attach an ADR 0193 Model Result Advisory to the exact artifact/runtime/recipe/capability/result scope, but it does not remove, hide or de-rank committed AI results in active projections or semantic search. Existing values retain provenance and ordinary ADR 0143 controls; the user explicitly chooses keep, delete or a previewed Analysis Result Migration. No statement automatically calls a replacement model, overwrites User-Authored Analysis Values, confirms new tags, deletes results, rebuilds embeddings or authorizes network transmission. When no safe model exists, new analysis may remain unavailable while existing results and non-AI functionality remain available.

Removing a model artifact does not by itself delete still-valid stored results. Successful migration supersedes prior generations under ADR 0143 retention, allowing the immediately previous generation to remain for the default 30-day window and support bounded rollback or comparison. Migration history retains only non-content scope, generation, status, and timing after result values expire.
