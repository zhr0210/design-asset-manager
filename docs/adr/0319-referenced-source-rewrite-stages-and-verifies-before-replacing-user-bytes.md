# Referenced Source Rewrite Stages And Verifies Before Replacing User Bytes

**Rewrite Referenced Source** is a separately invoked Referenced Source Operation; editing application-owned titles, confirmed tags, ratings, Collections, OCR, descriptions, vectors or other metadata never implies source-byte mutation. ADR 0322 limits it to the same physical path, verified real format and valid extension. It is available only when a trusted installed capability can encode that format and preserve every source structure the operation promises to retain. If PSD/TIFF layers, pages, RAW sensor data, AI/PSB structure, color evidence or another material unit cannot be preserved reliably, the application blocks source rewrite and offers Compatible Export as a separate file without relinking, replacing or changing ownership of the original. ADR 0348 rejects the previously proposed cross-format current-source replacement flow.

Before confirmation, **Referenced Source Rewrite Review** compares current and proposed format, dimensions, color space/profile, bit depth, quality/compression and applicable layers, pages, artboards, frames or other structure, with every known loss or unsupported property visible. After fresh source-generation, permission, path, space and capability validation, the operation writes complete **Referenced Source Rewrite Staging** on the source volume, validates its real format and requested properties, and compares it with the exact expected source before any destructive call. Staging is not the source, preview input, analysis input, Original Handoff, backup member or cache. Byte-identical output is resolved without replacing the source or creating another Source Content Generation.

For materially changed verified output, durable intent and exact device-local restore evidence precede a request to move the current source to operating-system trash. Only proven trash success allows atomic publication at the freshly validated source path, and a new occupant is never overwritten. Trash failure leaves the source authoritative and does not publish staging. Proven old-source trash without proven publication enters **Referenced Source Rewrite Publication Recovery** and never claims success or automatically repeats trash or publication; ADR 0320 reconciles the real path outcome before one safe rollback attempt or visual recovery. Successful publication and post-commit validation retain a **Rewritten Old Source Recovery Receipt** in Local File Recovery, excluded from portable library state and backup, rather than creating automatic full-file revision history.

A successful material rewrite keeps the same Design Asset, Referenced Asset ownership, Collection Memberships, confirmed tags, ratings and other user-authored values while committing a new Source Content Generation. Prior-generation preview, color, generated OCR/description/tag suggestions, embeddings and other derived evidence becomes stale under its existing supersession and regeneration rules without deleting or overwriting user-authored analysis values. ADR 0329 permits cancellation through verified staging but not after the old-source trash request begins. ADR 0330 completes batch semantics through one explicit Source Rewrite Plan, per-item encoder eligibility and item-committed mixed results without silent export or format-change fallback. ADR 0320 resolves failed-publication recovery, ADR 0321 separates post-success external-file recovery from a newly reviewed same-format current-source replacement and rejects one-click rewrite undo, and ADR 0348 keeps every cross-format output source-separated. Rewrite Referenced Source remains a single-file contract and cannot target a Referenced Compound Member Relationship. ADR 0347 provides the separate whole-group plan, staging set, coordinated publication recovery and generation commit required to rewrite a Referenced Compound Original without invalidating companions. The current application has no referenced-source rewrite review, encoder contract, staging publisher, recovery receipt or Source Content Generation commit. This ADR records target architecture only and encodes, accesses, creates, copies, restores, moves, rewrites, trashes, deletes, reads or writes no runtime/user file and changes no public IPC, database schema or AI Worker API.
