# Capture Artifact Transfer Has Two Paths

Capture Envelope must declare one Artifact Transfer Mode. Stable public HTTPS originals use Gateway Artifact Fetch, letting Capture Gateway acquire the resource without browser session material. Content that depends on browser login state, a blob URL, an expiring signed URL, or page execution uses Producer Artifact Upload: the paired extension reads the original bytes within the browser context and streams binary or multipart data to Local Capture API. Browser cookies, authentication headers, and site credentials remain inside the browser and are never forwarded. Base64 artifact payloads in JSON are prohibited. Both paths stream incomplete bytes into managed intake staging and remain subject to gateway size, file-signature, MIME, integrity, and safety validation; ADR 0280 then atomically commits the complete Candidate Artifact into the active Library Root before Candidate Activation. Failure to obtain or durably commit the original is explicit; Screenshot Capture is a separate Capture Method and must not silently replace original-quality capture.
