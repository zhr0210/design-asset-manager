# Successful Replacement Retains Device-Local Displaced-File Recovery

After Replace Transfer Destination, destination publication and relationship commit succeed, the application retains the **Transfer Destination Replacement Receipt** as device-local recovery authority for the exact displaced occupant instead of discarding it with operation staging. **Recover Replaced Destination File** verifies the receipt-linked system-trash item and restores it to one explicitly selected safe empty location. Because the original destination normally contains the newly published Referenced Asset source, alternate-location recovery is the default; the action never overwrites, renames, moves or deletes that active source, reverses the cross-volume transfer, changes its Design Asset or Source Content Generation, creates another Design Asset, or treats the recovered external file as a library backup.

Recovery to the former destination is available only if that path later becomes safely vacant and the user explicitly selects it. Any occupied, unsafe or unprovable destination returns to a visual choice without automatic suffix, overwrite or fallback. Successful platform restore is followed by complete identity/format validation; failure, cleared/changed trash content, unsupported context or ambiguous evidence preserves truthful recovery state and offers another safe destination or manual system-trash handling without enumerating unrelated trash items.

The receipt retires after successful recovery, **Clear Replacement Recovery**, or authoritative proof that the exact trash item no longer exists. Clearing removes only this application's device-local restore evidence and warns that one-click recovery will be lost; it never restores, moves, empties or deletes operating-system trash. Restart, cache cleanup, storage pressure, settings reset and ordinary plugin/preview/AI maintenance do not retire it. The receipt is excluded from portable library state, Full Library Backup, merge, Offline Library Catalog, Cross-Library Search and exports. ADR 0308 exposes it through registration-independent Local File Recovery, retains it by default after Forget Library Registration and includes it in the explicit Uninstall Preparation decision. ADR 0309 keeps this displaced-file recovery independent when moving the Referenced Asset again and never consumes it as part of whole-transfer undo. ADR 0312 gives a successful same-volume replacement's Relocation Destination Replacement Receipt the same Recover Replaced Destination File and retention boundaries; ADR 0356 applies them to a Conversion Destination Replacement Receipt without making recovery ownership-conversion undo. The current application has no replacement receipt store, recovery surface or platform trash restore adapter. This ADR records target architecture only and accesses, restores, clears, moves, deletes, reads or writes no runtime/user file and changes no public IPC, database schema or AI Worker API.

ADR 0392 gives a successful Asset Export replacement an Asset Export
Destination Replacement Receipt with these same recovery and retirement
boundaries. Its export activity history may expire independently and never
clears that receipt or changes the new exported output.
