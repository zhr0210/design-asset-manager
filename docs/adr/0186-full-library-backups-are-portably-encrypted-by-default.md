# Full Library Backups Are Portably Encrypted By Default

ADR 0185 Full Library Backup defaults to Portable Passphrase Encryption because the archive contains original assets, OCR, descriptions, metadata, canonical embeddings and library structure. The user enters and confirms a backup passphrase in a trusted application-owned surface before writing. The passphrase and derived key are never written to the archive, SQLite, settings, renderer state, logs, telemetry, crash reports, subprocess arguments or environment variables, and are retained in memory only for the bounded backup/restore operation.

The initial versioned Backup Encryption Suite uses Argon2id password-based key derivation and chunked XChaCha20-Poly1305 authenticated streaming encryption through a vetted maintained cryptographic implementation. Every backup receives fresh cryptographic random salt and stream header/nonce material. The clear header contains only format magic/version, encryption-suite identifier, bounded KDF parameters, salt and non-secret compatibility framing required to derive/decrypt; the Backup Manifest, logical entry names, counts, content hashes, dependency inventory and all payload bytes are encrypted and authenticated. File size and existence remain unavoidable external metadata and are not claimed hidden.

KDF memory/time/parallelism parameters are versioned, stored in the header and selected from a platform-tested policy that balances password-guessing resistance with cross-device restore feasibility. Restore rejects parameters outside supported safety bounds before allocating memory, preventing a malicious header from requesting unbounded resources. Stronger future suites or parameters create a new envelope version; existing backups remain readable through an explicit compatibility implementation rather than silently reinterpreting parameters.

Streaming encryption authenticates ordered chunks and an explicit final record so modification, insertion, deletion, reordering or truncation fails closed. Backup writes to a managed incomplete destination and reports Complete only after finalization plus a bounded reopen/authentication/manifest verification pass. Restore authenticates/decrypts only into isolated staging, validates the complete encrypted stream and ADR 0185 archive/manifest/digest rules before any library commit, and removes staged plaintext on wrong passphrase, corruption, cancellation or failure. It never exposes partially verified assets or results.

Wrong passphrase and damaged/tampered archive may share a non-revealing “Cannot authenticate backup” failure with safe local troubleshooting detail; neither condition triggers fallback parsing. There is no plaintext downgrade, recovery backdoor, vendor escrow, reset link or derivation from the user's OS login. If the passphrase is lost and no local convenience copy exists, the backup cannot be restored. The creation UI states this before confirmation and encourages the user to store the passphrase in their chosen password manager.

Saving a backup passphrase or derived wrapping key in the operating-system credential facility is an explicit per-backup or user preference for local convenience only. It stores an opaque backup identity reference and secret in the OS vault, never inside the archive. A portable restore on another machine always accepts the user passphrase and never requires the original keychain, account or device. If secure storage is unavailable, encrypted backup still works with a memory-only passphrase while “Remember on this device” is unavailable; there is no plaintext secret fallback.

The user may explicitly choose **Create Unencrypted Backup** after a separate warning listing originals and private result classes that will be readable to anyone with the file. Unencrypted mode remains digested and archive-validated but makes no confidentiality claim, is visibly labelled in the filename/status and is never chosen merely because encryption/keychain setup fails. Changing an existing backup passphrase creates and verifies a new encrypted archive transaction; it does not modify the only backup in place.

Public progress and ADR 0175 notifications expose only opaque operation identity, encrypted/unencrypted mode, aggregate bytes and terminal status. They never expose the passphrase, KDF output, salt/header bytes, archive entry names, source/destination paths, asset names or authentication error internals. Clipboard use for passphrase entry is not retained or monitored by the application.

ADR 0373 later makes age encryption optional and open output the default for field-selected Metadata Portability Export; that explicit interchange policy does not weaken this ADR's encrypted-by-default Full Library Backup or reuse either format's passphrase/envelope as the other. The current project has no portable backup crypto envelope or vetted Argon2id/XChaCha20-Poly1305 dependency. Electron `safeStorage` is used in a separate browser-auth-state path and includes legacy plaintext fallback behavior; it is device-bound and must not be reused as the backup encryption format or downgrade policy. This ADR records the target contract without reading credentials, creating/encrypting an archive, changing that legacy service or altering public APIs.
