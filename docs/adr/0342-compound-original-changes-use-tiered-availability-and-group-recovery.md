# Compound Original Changes Use Tiered Availability And Group Recovery

External filesystem observations for a Compound Original are reconciled against its authoritative Compound Original Identity and member manifest after the same bounded settling and stable-read rules as ADR 0283. A notification, filename, adjacency, timestamp or directory appearance is only evidence. The application revalidates every affected member's identity, bytes, role, real format and capability-declared relationship before changing current state, and an unknown file inside the Compound Original Directory never joins the group or becomes an asset automatically. ADR 0349 may surface it only as a non-authoritative Companion Attachment Candidate until explicit validation and confirmation.

When one or more known members change but the complete included set and declared relationship validate, the application keeps the same Design Asset and Compound Original identities and creates one new Source Content Generation for the group. Byte-identical filesystem metadata change creates no generation. User-authored organization and metadata remain attached, while prior-generation System Preview, color, OCR, description, embedding and other derived evidence becomes stale under its existing policy. No member receives an independent content generation or Design Asset.

A uniquely proven byte-identical move or rename of the whole Compound Original Directory inside the bound Managed Originals Directory updates only its safe root-relative group path. A single member move or rename is accepted as path-only only when the same member identity, role and complete capability-required relative layout still validate under ADRs 0288 through 0291; otherwise the group enters the applicable degraded or recovery state. No rename or move is correlated from basename, proximity or one create/delete pair, and movement outside the managed boundary is never silently converted to referenced ownership.

If the primary or any required companion is missing, unreadable, unsafe, invalid, newly unsupported or no longer satisfies the declared relationship, the whole group enters **Compound Original Recovery**. The Design Asset, member manifest, last verified Source Content Generation, user-authored metadata and last valid preview evidence remain recorded, but that preview is identification-only rather than a current original substitute. Default External Open, complete Original Handoff, source-fidelity export, fresh source-dependent preview/analysis and source rewrite remain unavailable until recovery succeeds; surviving members never become independent assets or an implicit primary-only original.

If only an included optional companion is unavailable or invalid while the primary, all required members and their relationship remain proven, the asset becomes a **Degraded Compound Original**. The UI identifies the affected role and consequence. Only operations the active capability explicitly proves independent of that member may continue with a visible degraded warning; complete Original Handoff remains blocked because the current authoritative member set is incomplete. The application never silently removes the member from the manifest. ADR 0350 permits an explicit **Remove Optional Companion** only after the capability validates the remaining set and resolves referenced versus managed former-member disposition; success commits one material member-manifest change and one new Source Content Generation without modifying any retained member.

Recover as Managed Original may accept one or more explicitly selected files mapped to affected member roles, an explicitly selected complete member set, or an authenticated Full Library Backup. It never scans unselected siblings, adopts a containing directory, follows links, guesses roles from filenames or uses preview media as source bytes. Every selected external file remains untouched. Recovery stages and verifies the supplied bytes, freshly revalidates all retained and supplied members plus their complete relationship, and commits availability only through one group-scoped recoverable journal boundary. Exact prior member bytes restore the last verified generation; any different but valid member set is presented as Use as Replacement and requires separate confirmation to create a new Source Content Generation. An occupied or ambiguous member destination is never overwritten or auto-renamed.

Full Library Backup records Compound Original Recovery or degraded state, the authoritative manifest and every currently available owned member without claiming a missing group is complete. A prior authenticated backup can recover only member payloads whose identities and digests it proves. Keeping either attention state is non-destructive and does not block unrelated assets; Delete Design Asset remains separate and group-scoped. ADR 0351 Convert to Referenced Asset cannot flatten the group or select only one surviving member and is unavailable unless a separately valid complete referenced relationship can be proven.

ADR 0343 resolves physical publication through vacant-path Compound Member Repair or a complete new-directory rebuild with an explicit authority switch and non-destructive old-directory cleanup review. ADR 0349 reuses those publication shapes for an explicitly attached new companion but never treats discovery itself as a member-manifest change. The current application has no Compound Original reconciliation, degraded state, group recovery or role-aware repair input. This ADR records target architecture only and watches, reads, hashes, stages, opens, copies, renames, moves, restores, rewrites or deletes no runtime/user file or backup and changes no public IPC, database schema or AI Worker API.
