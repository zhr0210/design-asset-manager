# Metadata Writeback Is Limited To User-Confirmed Interoperable Fields

**Original Metadata Writeback** accepts only explicitly selected **Writeback-Eligible Metadata Values**. The initial interoperable field classes are title, description, rating, keyword/tag labels, creator and copyright when the current Design Asset contains the value and an active trusted format capability declares an exact safe target mapping. No field is admitted merely because it is visible in Asset Inspector, editable in the library, supported by another format, present in a preset or previously written elsewhere. The user invokes writeback separately from editing metadata and receives one **Original Metadata Writeback Review** bound to the exact current Original Asset and Source Content Generation.

The review shows each library field and provenance, exact embedded namespace/property or existing declared companion target, serialized value and language, current target value, supported limits, truncation or lossy consequence and whether the source bytes or Compound Original manifest will change. A generated suggestion or result is ineligible until the user explicitly confirms it for writeback or edits it into a user value; model completion, confidence, popularity or prior acceptance on another asset never supplies approval. For a Tag Concept, the user sees and selects the exact language-tagged label that will become an ordinary keyword; the write never serializes the opaque concept ID, aliases, hierarchy, mapping confidence or whichever label the current UI happened to display.

OCR text, embeddings/vectors, model/recipe provenance, analysis coverage, confidence and raw suggestions, Collection or Collection Group membership, Smart Filters, Source Tree relationships, internal Design Asset/Candidate/Compound/member identities, storage paths, recovery state and application history are **Library-Only Metadata Fields**. They are not embedded into originals, forced into comments/keywords, hidden in a private XMP namespace or flattened into another standard field even when user-authored or manually corrected. Unsupported or ambiguous mappings remain excluded with an explanation; the application never silently drops, truncates, translates, merges or substitutes them to make a writeback appear successful.

Users who need those values outside the library use a separate **Metadata Portability Export**. ADR 0371 gives it three declared fidelity tiers: a recommended versioned package with structured records and typed binary payloads for selected vectors/region evidence, human-readable JSON for safely representable structures, and flat one-row-per-asset CSV that cannot claim round-trip completeness. Review selects assets, fields and provenance, exposes representation gaps, and writes one user-owned export without changing an original, Source Content Generation, Asset File Ownership, member manifest or source relationship. Export does not attach its result as XMP, create a Compound Original member, infer associations by filename, import into another library or become Full Library Backup.

After the user confirms a conflict-free writeback review, actual source mutation still follows ADR 0357's ownership-appropriate protected rewrite, complete-group and companion boundaries. ADR 0359 resolves existing target values through field-aware review without Last Writer Wins, and ADR 0360 coordinates explicitly requested batches without changing field eligibility. A byte or authoritative manifest change creates one new Source Content Generation and stales generation-bound generated evidence without deleting user-authored library values; byte-identical serialization is a no-op. Writeback never runs on metadata save, batch edit, import, conversion, analysis completion, application exit, synchronization, scheduled work or external-open. Metadata Portability Export import remains a separate decision rather than a hidden default in this field-scope rule.

ADR 0393 separately permits explicit Compatible Export metadata only in a new
generated output. Its ability to place selected corrected OCR or an explicitly
chosen AI-derived description into a compatible copy does not make either value
eligible for Original Metadata Writeback and does not weaken this source-file
allowlist.

The current application has no interoperable writeback field registry, Original Metadata Writeback Review or Metadata Portability Export. This ADR records target architecture only and selects, serializes, exports, embeds, attaches, stages, writes, rewrites, converts, imports, moves, deletes or changes no runtime/user file, sidecar, directory, database, cache, backup, metadata value, analysis result or source relationship and changes no public IPC, database schema or AI Worker API.
