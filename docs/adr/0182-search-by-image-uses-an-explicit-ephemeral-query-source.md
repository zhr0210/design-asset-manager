# Search By Image Uses An Explicit Ephemeral Query Source

ADR 0181 Hybrid Asset Search supports Search By Image from either one existing library asset/unit or one explicitly selected external visual file. The query is a foreground user action and never imports the external file, creates a Candidate, watches its folder, uploads content or grants future filesystem access. Clipboard contents, recent files and directory scanning are not implicit query sources; they require a separate future explicit interaction design.

For a library asset, Query Visual Scope is the explicitly selected page, artboard, frame, declared view or other stable Analysis Unit. An explicitly chosen current viewport/crop may be supported only when the UI labels that narrower scope and records its deterministic geometry. Without a selection, the query uses the Primary Asset Overview rather than guessing a semantically important unit or searching every page/layer. The search header and every result explanation identify the scope used.

If that exact owner/source/recipe generation already has a compatible vector in the Active Embedding Space, search reuses it. Otherwise the explicit action may create a transient foreground query embedding through ordinary ADR 0173 admission. That transient vector does not become a durable asset analysis result or trigger other capabilities/backfill; storing an asset embedding remains the normal automatic or explicit Generate Embedding action. Search waits honestly when no compatible local model/runtime/index exists and never downloads a model or calls an external provider as fallback.

An external query begins with a Trusted Query File Grant from the operating-system file picker or an explicit drag/drop onto the Search By Image target. The grant covers exactly one regular file for one search session and bounded read/format validation. It does not persist the path, enumerate siblings, follow arbitrary links outside the grant or expand to a directory. The Preview Broker detects the real format and produces an Ephemeral Query Visual Source using the same composition, orientation, alpha, color and structured-format fidelity rules as asset analysis. Filename, containing path, source-site metadata and unrelated EXIF are not semantic query inputs.

The external original remains in place and is never copied into the library. Ordinary inputs and the query vector remain memory-resident when safe. Large/structured decoding may use managed one-session temporary render/proxy files only when required by the Preview Broker; they are path-private, pinned only for active search, removed on completion/cancel, and reconciled after crashes/restart. They never enter the persistent System Preview Store, Analysis Proxy Cache, model cache or ADR 0184 Saved Search/history. No query image, vector, thumbnail or content-bearing explanation survives the search session unless the user separately imports the file.

Query embedding and candidate vectors must share the exact model-space identity, dimensions, normalization, distance metric and input recipe/equivalence evidence. The system never projects, pads or compares incompatible vectors merely to return results. Search results default to excluding the owning library asset itself; the user may choose Include Query Asset when useful. Other pages/views from the same structured asset are excluded with the owner by default unless the query explicitly targets unit-level results and offers that separate scope.

Results show Search By Image, Query Visual Scope, embedding family/checkpoint/artifact/recipe generation and visual-similarity contribution. Similarity is presented as rank/relative evidence or calibrated range, not a universal semantic-match percentage. Exact/perceptual duplicate detection, if available, remains a separate evidence lane and is not relabelled as embedding similarity. Candidate index coverage and missing-vector state remain visible so sparse indexing is not mistaken for exhaustive dissimilarity.

Cancel releases query jobs, visual-source/proxy pins and vector memory without deleting indexed asset vectors. A source file changed during the session invalidates the query generation and requires re-read through the existing grant or a new selection. Public IPC/UI state carries opaque query/session/scope identities and aggregate status only; logs and errors never expose the external path, original bytes, thumbnail, vector or model path.

The current project exposes embedding runtime/readiness routes and a generated-fixture ONNX embedding probe, but settings mark embeddings unavailable and there is no active asset vector index, image-query session, trusted query-file picker/drop grant, query-scope model, ephemeral Preview Broker path, transient query vector or self-exclusion/result explanation. Existing settings/runtime-package file pickers are unrelated and cannot be reused as proof. This ADR records target behavior without opening files, changing public contracts, building an index or running a model.
