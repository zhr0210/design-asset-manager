# Copy Into Library Shortfall Blocks Or Pauses Without Cleanup

Before Copy Into Library confirmation, the plan assesses the destination volume against the complete selected scope and its dynamic Storage Safety Reserve. It separately shows exact enumerated source bytes, conservative estimated peak operation staging, estimated Required Preview baseline and other declared authoritative overhead, current available space, protected reserve, projected remaining space and any **Copy Into Library Storage Shortfall**. Estimated components are labeled rather than presented as reservations or exact final usage. If current evidence proves the complete scope cannot preserve the reserve, or capacity cannot be assessed reliably, confirmation remains disabled and no Candidate Record, staging file or storage claim is created.

The blocked plan offers only explicit routes: reduce or exclude selected items and recalculate; open Storage Management for independently authorized actions; checkpoint the plan while a separately reviewed ADR 0276 Material Library Migration governed by ADR 0003 changes the library storage boundary; or return to Add Assets and deliberately create a new Reference in Place plan. It never deletes Preview Cache, Analysis Proxy Cache, Required Preview Storage, Candidate/Managed originals, models, runtimes or another class automatically. It also never silently changes Asset File Ownership, writes outside the active library, lowers the reserve, assumes free space on another volume or treats a large supported original as invalid merely because this destination is currently too small.

Every item admission repeats live destination and reserve checks. If external disk use, capacity drift, staging growth or newly known required overhead makes safe continuation impossible after work begins, the gateway reaches the next safe item boundary, removes only proven incomplete attempt-owned staging and enters durable **Copy Intake Storage Pause**. If an item is in a bounded non-interruptible commit, that item first commits or rolls back and is reconciled truthfully. Already committed Candidate Artifacts and activated Candidates remain valid; no successful item is rolled back, rejected, deleted or moved, and no unstarted item is reported as an acquisition failure.

The paused surface shows committed, pending and stopped item counts plus a fresh remaining-scope shortfall. The user may free space and explicitly Recheck And Resume, initiate a separate compatible Material Library Migration, reduce/cancel remaining items, or leave the batch paused across restart and Library Switch under ADR 0278. Resume requires a fresh complete remaining-scope projection and per-item validation; it never relies on the earlier estimate or captures newly appeared source siblings. Selecting Reference in Place after partial success requires explicitly cancelling the remaining Copy Into Library items and creating a separate Add Assets plan; committed Managed Candidates keep their ownership and are not converted.

Copy Intake Storage Pause has no authority to start cleanup, migration, source deletion, cache eviction, ownership conversion or background retry. Storage becoming assessable or sufficient may update the explanation, but copying resumes only after the user's explicit action. The current application has no complete-scope copy admission projection or durable storage-pause state. This ADR records target architecture only and assesses no real volume, opens no Storage Management action, creates no Candidate, and reads, writes, migrates, converts, deletes or cleans no runtime/user file, library, cache, model or database; it changes no public IPC, database schema or AI Worker API.
