# Local AI Starter Setup Has Three Preference Profiles

ADR 0170 Local AI Starter Setup exposes three recommendation intents: Resource Saver, Balanced and Quality First. Balanced is the first-use default. A profile is a planner preference, not a fixed model bundle, hardware tier, quality guarantee or permanent execution mode. It influences only a newly generated or explicitly recomputed draft plan; selecting a profile never downloads, installs, activates, replaces, removes or migrates a model and never changes an already Active Capability Model.

All profiles first apply the same hard admission gates: current platform and architecture, verified artifact and runtime compatibility, trust and license state, available Model Storage Root, safe RAM/VRAM headroom, dependency closure and the four enabled ADR 0169 baseline capabilities. A preference cannot override an incompatibility, use an unverified artifact, weaken the resource safety reserve or silently omit a requested capability. When no safe compatible assignment exists, that capability remains visibly unavailable or Not Assessed instead of receiving a guessed or unsafe recommendation.

Resource Saver minimizes additional physical storage, download bytes, peak working memory, runtime/dependency duplication and expected foreground latency or energy when comparable evidence exists. It favors verified quantized variants, already-present shared blobs and one artifact serving multiple declared capabilities, but it may not claim equivalent quality without ADR 0162 Cross-Variant Equivalence Evidence. Balanced seeks the smallest stable coherent set that clears declared baseline quality and responsiveness thresholds, retaining resource headroom for the desktop application. Quality First prioritizes capability-specific evaluated output quality and may recommend separate specialist models or larger variants, but remains inside the same safe hardware, storage, trust and foreground-resource gates; it never means largest model at any cost.

Plan comparison shows per profile and per capability: exact assignments, reused versus specialist artifacts, total and additional download, shared/already-present and additional physical storage, expected derived-cache storage, peak working RAM and VRAM under the ADR 0173 declared sequential/co-residency policy, and speed/throughput, quality and energy evidence when available. Every value follows ADR 0172 Catalog Benchmark, Local Calibration and derived evidence rules and is labelled Local Measured, Catalog Estimate, Derived Estimate or Not Assessed with its evidence version and applicable platform/runtime. Ranges replace false precision. Total model sizes are not added and presented as peak memory, and current free memory is not treated as guaranteed capacity. Quality comparisons require capability- and recipe-relevant evaluation evidence; parameter count, quantization label, marketing text and a flat `quality` string are insufficient by themselves.

The planner orders eligible plans deterministically. Trust, compatibility, resource safety and requested capability coverage are gates rather than weighted tradeoffs. Within the remaining set, profile objectives rank candidates; stable verified evidence, fewer new dependencies, already installed compatible artifacts and deduplicated bytes are tie-breakers. The review explains the decisive tradeoffs, for example lower peak memory at reduced evaluated OCR accuracy or higher caption quality with another runtime. If evidence cannot distinguish candidates, the plan says so instead of inventing a winner.

Changing profile or hardware/storage evidence recomputes only an unconfirmed draft. A user-replaced assignment marks that capability Custom and remains pinned while other assignments recompute unless the user explicitly resets it to profile recommendation. Before **Install And Enable This Setup**, the plan runs admission again and reports any drift in catalog, license, storage, hardware or dependency evidence. After confirmation, ADR 0170 transactional and Partial Local AI Setup rules apply. Later switching profile creates a comparison draft against current assignments and requires a new explicit activation decision; it is not an automatic optimization service.

The current implementation's static model `quality`, size and VRAM guidance can be catalog inputs only. Its route-specific Llama selector ranks Qwen GGUF candidates from total VRAM thresholds and does not provide four-capability quality evidence, safe headroom, comparable latency/throughput, aggregate peak-resource modelling, profile objectives or custom-assignment pinning. This ADR records the target planner semantics without authorizing runtime probing, benchmark execution, public contract changes or model downloads.
