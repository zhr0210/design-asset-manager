# Managed Originals Use A User Visible Library Directory

Every Library Root contains two reserved ownership boundaries. The hidden **Library Control Directory** holds the portable manifest and identities, authoritative database and metadata, transactions, lock state, and Required Preview Storage. The user-visible **Managed Originals Directory** holds activated Candidate Artifacts and Managed Asset originals as ordinary member files, including members of ADR 0340 Compound Originals. Original Asset Storage is never embedded only in the database, concealed inside application data, or mixed with caches, runtimes, models, plugin storage, and temporary acquisition chunks.

The visible directory exists so a user can locate and inspect library-owned original members through Finder or File Explorer even when the application is not installed. Visibility does not transfer ownership away from the library: candidate rejection/retention, Asset Trash, Permanent Asset Delete, backup pinning, and storage-reserve rules retain their explicit lifecycle authority. Candidate Promotion changes Asset File Ownership and records without moving, renaming, transcoding, redownloading, or duplicating a single original or Compound Original member merely because its domain identity changed. Complete external handoff of a Compound Original remains group-aware rather than assuming that copying one visible member is complete.

An In-Place Reference Library keeps every pre-existing source original in place and user-owned. It creates the same visible Managed Originals Directory for new captures, ADR 0292 Copy Into Library results, and other library-owned originals, and permanently excludes that reserved subtree from Reference Adoption Scan, Progressive Reference Indexing, reference monitoring, Source Tree, and Folder Collection Mapping. It therefore never re-admits one managed original as a Referenced Asset or treats the dedicated directory as part of the adopted source hierarchy.

Managed Originals Directory is a storage boundary, not a Collection, Collection Group, Smart Filter, or source folder. An Original Asset remains one single physical file or one Compound Original member group even when its Design Asset belongs to multiple Collections, and changing Collection Membership, tags, capture batch, source context, or workspace organization never rearranges the filesystem. ADR 0282 gives the directory a stable manifest binding and default `Originals` name. ADR 0283 treats external edits as Source Content Generation changes, identity-safe internal relocation as a path update, and external deletion, boundary escape, or ambiguity as item-scoped recovery without silent lifecycle actions. ADRs 0285 through 0291 resolve shallow application-managed storage buckets, stable readable names, format-derived extensions, and path budgets for scale without turning physical layout into user organization; ADR 0341 stores each Compound Original in one dedicated atomically published directory and makes complete-set handoff the default.

Existing libraries whose managed originals are stored inside an older hidden control layout do not move them silently on open. A transition to this visible boundary changes authoritative paths and therefore requires an ADR 0276 Material Library Migration governed by ADR 0003, with a dry run, affected-file/byte inventory, space and collision checks, backup/rollback evidence, explicit confirmation, atomic item progress, and post-migration validation.

The current application uses one settings-level library path, application-global database/media locations, a separate fixed normalization directory, and simulated download completion rather than a portable control/originals split. This ADR records target architecture only and creates, reveals, scans, migrates, moves, reads, or deletes no runtime directory, user asset, database, cache, model, or plugin data and changes no public IPC, schema, or AI Worker API.
