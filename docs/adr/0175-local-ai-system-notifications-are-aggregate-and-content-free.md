# Local AI System Notifications Are Aggregate And Content Free

ADR 0400 supplies the shared background-only notification boundary for user-
initiated long-running application operations. This ADR further narrows which
AI operations qualify and preserves the separately governed material trust-
attention exception.

Ordinary automatic per-asset analysis is silent at the operating-system level. Creating, waiting, starting, retrying or completing an individual Tag Suggestions, Embedding, OCR or Short Description intent does not create a system notification. In-app Asset Inspector, AI Console, ADR 0174 no-window status and lightweight activity state remain the source of truth; renderer synchronization events and transient toasts are not notification requests.

System notifications are reserved for a user-initiated Long-Running AI Operation whose result is useful after the user leaves the relevant surface: ADR 0170 Starter Setup, model/runtime installation or calibration, an explicitly confirmed Analysis Backfill Plan, explicit selected/batch analysis, and a later comparable foreground operation. Eligible terminal events are Completed, Partial/Failed with attention required, or Blocked awaiting a durable user decision. ADR 0199 adds one narrow non-operation class for newly verified material model/runtime trust attention; freshness/no-change/recovery refresh remains silent. Transient resource pressure, ordinary Waiting states, bounded retries, model residency changes and automatic baseline progress remain silent.

ADR 0223 Pending Package Decision Warning is explicitly in-app only even though it precedes cleanup of app-owned verified bytes. Its countdown, app restart and expiry do not qualify as a long-running-operation terminal notification or create a new system-notification class.

Notifications aggregate by opaque operation identity and terminal transition. One operation produces at most one terminal notification, with closely related completions coalesced during a bounded window rather than one notification per capability, model, asset or retry. A later material attention state may replace or update the aggregate when the operating system supports it. Restart reconciliation deduplicates already emitted terminal transitions and never replays a notification storm.

Notification content is path-free and content-free. It may show the application name, operation kind, aggregate completed/failed/waiting counts and a generic next action, such as “Backfill partially completed — open to review 3 items.” It never shows asset names, filenames, collection names, thumbnails, source sites, paths, OCR text, tags, descriptions, embeddings, prompts, model paths, credentials, private error text or user-authored content. Lock-screen-visible text uses the same minimal projection; ADR 0203 requires ordinary priority, no forced/custom sound and no emergency/time-sensitive/Focus bypass.

Clicking a notification activates or opens Design Asset Manager and routes through a validated opaque Navigation Intent to the operation's current in-app result/attention surface. ADR 0200 specializes trust-attention routing by execution/advisory class and library scope. No intent encodes private values in a URL, command line, notification identifier or renderer query string. If the operation or detail was pruned, the app opens the nearest aggregate activity surface with an honest unavailable-detail state. Dismissing a notification does not cancel work, resolve attention, delete activity evidence or change automatic-analysis preferences.

**Long-Running AI Operation Notifications** is an independent user setting. It defaults On only for the bounded user-initiated operation classes above, remains subordinate to operating-system notification permission and can be disabled without affecting in-app status or ADR 0174 tray/menu-bar controls. ADR 0202 requests OS permission only after a contextual explicit user action and never repeatedly prompts after Not Now/denial. Automatic per-asset notifications have no enable-everything shortcut in the default product; any future fine-grained notification class requires its own visible privacy review.

System notifications are projections, not a new durable audit log. The operation retains only the minimal path-free counts, state, timestamps, reason category and opaque navigation identity needed by its existing activity/result lifecycle. Notification delivery state may record pending/emitted/dismissed-or-unknown semantics without storing body snapshots or private OS payloads. Batch Activity privacy principles from ADR 0086 through ADR 0090 apply, while their retention periods are not automatically imposed on every AI operation.

The current renderer has local transient toast state and receives per-asset AI completion synchronization events. There is no Electron system-notification service, notification permission/status model, aggregate Long-Running AI Operation identity, terminal deduplication/coalescing, content-free projection, opaque notification navigation or independent preference. Existing per-asset events must not be promoted directly. This ADR records the target feedback contract without sending a notification, changing public IPC/database contracts, reading task data or launching the application.
