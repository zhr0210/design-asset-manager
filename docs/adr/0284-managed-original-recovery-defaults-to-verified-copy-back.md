# Managed Original Recovery Defaults To Verified Copy Back

Managed Original Recovery defaults to **Recover as Managed Original**, preserving the ownership, backup, and deletion guarantees the user originally accepted for a Managed Asset. For a single-file original, the user selects either one external file through a bounded trusted picker or one Full Library Backup. ADR 0342 permits one or more explicitly role-mapped member files, a complete explicitly selected member set or one Full Library Backup for a Compound Original. Recovery never scans unselected siblings, adopts a containing directory, follows links, infers a match from a filename, or treats a preview as original content. Keeping the item in Managed Original Recovery remains a valid non-destructive choice, while Delete Design Asset is a separate explicit ADR 0067 action that enters Asset Trash.

For external input, a read-only preflight validates every exact selected regular file, resolved boundary and type, real format, stable byte identity, role/current Source Content Generation relationship, destination collision, required storage and Storage Safety Reserve. Confirmation copies into transaction staging under the ADR 0282-bound Managed Originals Directory and verifies the completed copy. A single-file original then atomically commits its owned path, inventory and availability state; an ADR 0342 Compound Original additionally revalidates every retained and supplied member plus the complete declared relationship before a group-scoped journal may commit availability. Recovery never moves, renames, truncates, or deletes an external input and does not retain authority over that location after success. Failure or cancellation removes only transaction-created staging that is still proven to belong to the attempt and leaves the Design Asset in recovery or degraded state.

ADR 0343 permits an efficient Compound Member Repair only for one missing member whose exact declared path is proven vacant; it publishes that staged member without allocating or rewriting the complete directory. Occupied/ambiguous destinations, multiple-member repair, layout change or missing/unsafe directories use a complete new-directory allocation and authority switch. An existing valid occupant may be accepted without a file write only through exact-prior reconciliation or explicit Use as Replacement. Neither path overwrites or silently renames an occupant, and a superseded old directory remains separately reviewable rather than becoming automatic cleanup.

If all selected bytes exactly match their last verified member evidence, successful copy-back restores availability without creating another generation. Different but valid bytes or a deliberately changed optional-member manifest are shown as **Use as Replacement**, never as an exact recovery; only separate explicit confirmation may commit them as one new Source Content Generation under ADR 0406/0342. Unsafe, unstable, unreadable, format-invalid, role-ambiguous, identity-ambiguous, relationship-invalid or destination-colliding input remains blocked without overwriting an existing path. ADR 0285 allocates safe managed storage for a new destination, but its collision plan cannot turn another file into implicit replacement.

Backup recovery first authenticates and validates the Full Library Backup under ADRs 0185 and 0186, then resolves the same Portable Library Lineage Identity, Portable Object or Compound Original Identity, every selected member identity, and verified original digest before extracting only those payloads into the same copy-back staging path. It does not perform New Library Restore, Merge Into Current Library, or Replace Current Library and does not import the backup's older metadata, Collections, tags, results, Trash state, or library settings. An exact last-generation payload or complete member set restores availability; an older or otherwise different valid payload requires the same Use as Replacement decision and becomes a new current generation rather than resurrecting an old generation identity.

**Convert to Referenced Asset** is an advanced alternative when the user intentionally wants the selected source to remain outside Original Asset Storage. Before confirmation, the action explains that the library will no longer own or include those source bytes in future Full Library Backups, future availability and Original Handoff depend on that external relationship, and external deletion remains outside Asset Trash. Exact selected regular-file input must pass source access, stable-identity, format, path-safety, and current-generation validation. A Compound Original cannot flatten into one surviving member or independent references; conversion is unavailable unless a separate complete capability-valid referenced relationship can be proven. Commit atomically changes only this Design Asset's ownership and source relationship; it does not copy, move, rename, or delete any file, scan or adopt the containing folder, create Collection Memberships, or modify sibling assets. A different valid source still requires Use as Replacement and a new Source Content Generation.

Immediately before either commit, recovery rechecks library lock, item state, destination/source identity, generation, and collisions. If the prior managed original reappears, another recovery succeeds, or evidence changes, the attempt stops for a fresh plan rather than creating dual ownership or overwriting current state. ADR 0351 now governs normal healthy conversion in both ownership directions and extends the same one-asset, exact-generation and complete-compound-set invariants to this recovery specialization. Batch conversion, external-source folder registration, and post-conversion source relink policy remain outside this recovery decision.

The current project has no Managed Original Recovery UI, trusted role-mapped recovery picker, object-level backup extraction, portable ownership state, Source Content Generation persistence, Compound Original recovery/rebuild or transactional managed-to-referenced conversion. This ADR records target architecture only and reads, copies, restores, moves, or deletes no runtime/user file or backup and changes no public IPC, database schema, or AI Worker API.
