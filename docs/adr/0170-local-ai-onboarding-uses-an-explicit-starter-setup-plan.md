# Local AI Onboarding Uses An Explicit Starter Setup Plan

The four assignments below bound automatic model setup, not the entire product.
ADR 0483 includes core palette/proportion and prompt-reconstruction workflows;
ADR 0484 defers external development access. Setup consent may be grouped, but
capability readiness and future asset-analysis scope remain separately evidenced.

First use of local AI offers a reviewable Local AI Starter Setup Plan instead of requiring the user to understand every model, artifact variant, runtime and capability pack. ADR 0188 post-library Bootstrap, after explicit setup consent under ADR 0483, may already have installed the model-free Baseline AI Runtime; this plan assigns an exact verified local model artifact and any remaining runtime chain for each ADR 0169 baseline capability: Tag Suggestions, semantic Embedding, bounded OCR and one Short Description. One model artifact may satisfy multiple assignments when its manifest, runtime and readiness evidence declare those capabilities. The planner applies ADR 0171 Resource Saver, Balanced or Quality First preferences to eligible coherent sets and deduplicates shared model blobs, runtimes and capability packs; it does not install every plausible model.

The plan is generated only from current verified platform, operating-system, architecture, accelerator, RAM/VRAM, available runtime/capability and ADR 0167 storage-root evidence. Missing evidence is shown as Not Assessed and produces conservative compatible choices or no recommendation rather than guessed hardware facts. Hardware probing does not read user assets, model weights, caches or runtime databases. Reopening the plan after hardware, storage or runtime changes recomputes recommendations without changing an existing Active Capability Model.

Before any model or remaining dependency download, the review shows the selected ADR 0171 preference, ADR 0178 Metadata Language/OCR Language Coverage and each exact Model Family, Checkpoint and Artifact Variant, quantization/backend, assigned capabilities, publisher/source/trust state, immutable revision, license or gated-account requirement, required Model Runtime Capability Packs and Managed Shared Runtimes, total/already-present/shared/download/additional physical storage, expected derived-cache storage, available RAM/VRAM guidance and ADR 0177 Network Cost Evidence. Baseline packages from ADR 0188 appear as Already Installed rather than being downloaded again. The user may expand the complete dependency closure, replace any recommendation with another compatible variant, change/defer language coverage, leave an individual capability unavailable, or skip setup entirely. Every replacement reruns compatibility, dependency, storage, license and network admission and becomes a pinned Custom assignment until explicitly reset. Skipping leaves the rest of the application usable and does not create recurring modal pressure; Model Library and AI Console provide a resumable entry point and honest per-capability waiting state.

The primary action is explicitly labelled **Install And Enable This Setup**. Confirmation authorizes only the fully displayed artifact/runtime/capability-pack installs and, after verification, the displayed Starter Capability Assignments. Combining those two reviewed phases is not silent model selection: every future Active Capability Model assignment is part of the consented plan. Consent does not authorize later model updates, external providers, asset upload, additional permissions, existing-library reanalysis, embedding-space migration or old-artifact deletion.

The trusted host expands ADR 0160 capability dependencies before consent. Each artifact or package remains its own transactional install unit, and activation begins only after its complete dependency chain passes identity, digest, format, runtime compatibility and bounded readiness verification plus any required ADR 0172 local resource gate. Successfully verified independent packages may remain installed when another unit fails. Only capabilities with a complete verified chain receive their planned active assignment; an existing valid assignment remains unchanged for a failed replacement. Assignment failure rolls back that capability's activation without removing unrelated successful installs. The overall outcome is Partial Local AI Setup, not success, and reports installed, enabled, waiting, failed and retryable items separately.

Completing or repairing the setup triggers ADR 0168 Pending Intent Reconciliation only for existing compatible waiting intents and for future or materially changed assets while the relevant automatic-analysis controls remain enabled. It does not enumerate the completed historical library. Historical work requires a separate ADR 0169 Analysis Backfill Plan, and embedding migration remains separately previewed and confirmed. The setup never downloads or activates an external AI provider as fallback.

Model Library owns creation, review, install activity, partial outcome and later resumption of this plan; AI Console presents runtime health and capability readiness. Public state uses opaque identities and path-free aggregate evidence. The current route-specific Llama/GGUF recommendation and static selected-model defaults are implementation inputs at most: they are not a four-capability coherent plan, complete consent surface, verified activation transaction or per-capability partial result. This ADR records the target contract without authorizing an IPC, database schema or AI Worker API change.
