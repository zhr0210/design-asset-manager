# Model Trust Revocation Separates Execution And Result Safety

Model trust changes use three distinct responses. Critical Model Security Revocation covers supply-chain compromise, malicious or substituted tensors/data, parser or loader exploitation, credential/data exfiltration, or another artifact/runtime interaction requiring immediate containment. Model Analysis Suspension covers credible privacy, severe correctness, calibration, bias, compatibility or output-integrity evidence that makes new results unsafe while the artifact itself need not be treated as executable malware. Model Catalog Delisting covers maintenance end, publisher withdrawal, catalog policy or listing-license changes without evidence that the already verified local artifact is dangerous. Execution safety and historical result safety are evaluated separately.

A Model Catalog Trust Root publishes a signed monotonic Model Trust Statement scoped to catalog/publisher/source identity, repository and immutable revision, Model Artifact Manifest, file digest, Model Runtime Capability Pack where relevant, platform/runtime, capability, recipe/result generation, and response class. Statements include sequence, reason code, issue time, freshness metadata, affected scope, remediation identity and whether an ADR 0193 Model Result Advisory applies. The application persists Last Verified Model Trust State per trust root, rejects older rollback statements, and requires a newer signed recovery statement to clear or narrow a critical revocation, suspension or advisory. A second catalog, cached older metadata, clock change, reinstall, offline mode or ADR 0166 local acquisition cannot override a known critical artifact/digest statement in the official build. An unknown local digest receives no positive trust inference merely because no statement matches it.

Critical Model Security Revocation blocks new download promotion, installation, readiness probing, loading, activation and analysis for the affected scope. It cancels affected jobs, terminates or restarts the containing worker boundary as needed to remove the model from memory, invalidates active assignments and derived-cache execution, and prevents continue-anyway in Developer Mode. A previously configured, installed, compatible and non-revoked local Capability Fallback Chain may serve future work with recorded fallback reason; no replacement is downloaded, selected or migrated automatically. Verified blobs and derived files remain non-executable and user-removable rather than being silently deleted.

Model Analysis Suspension prevents new work and withholds affected in-flight uncommitted outputs from active result projections. The UI identifies capability, exact artifact/result generation, reason category, affected scope and replacement availability. Every previously committed result remains visible and searchable under ADR 0193 with a non-blocking advisory when scoped evidence applies; suspension does not rewrite or delete historical tags, OCR, descriptions, vectors or user-authored values. A more severe privacy issue may require immediate worker termination using the critical containment path even when the artifact is not classified as malicious.

Model Result Advisory is applied only when signed or locally verified evidence identifies the affected artifact/runtime/recipe/capability/time or result scope. It preserves affected AI results in active Asset Analysis Projections and semantic search without de-ranking, while exposing provenance and explicit keep/delete/reanalysis choices under ADRs 0143, 0145 and 0193. User-Authored Analysis Values and confirmed user metadata remain unchanged. Affected embedding indexes stay active in their original space unless the user explicitly migrates or deletes them; the application does not mix in another model or rebuild automatically.

Model Catalog Delisting stops new official installs and updates and marks the entry Unsupported or Delisted. An installed verified artifact may continue loading and local offline analysis under its already accepted license unless a separate security/suspension statement or disclosed Continuous Model Entitlement Requirement says otherwise. Delisting does not revoke Model Source Account credentials, erase license acceptance, change Active Capability Model or manufacture a security warning. Later verified evidence may escalate the state.

Offline operation uses Last Verified Model Trust State with visible freshness. Network loss does not make a safe model revoked, clear an accepted revocation/suspension/advisory, or permit a stale catalog to downgrade trust state. Stale trust metadata may block new installs, updates or signed recovery, while an already active non-revoked model may continue. Model Catalog Metadata Refresh verifies trust statements without loading models or reading user assets; ADR 0205 prolonged-failure presentation remains passive and does not itself change execution trust.

No trust response automatically deletes Model Blob Store files, Model Derived Runtime Cache, manifests, results, indexes, user metadata or assets. Remediation installs a new side-by-side artifact through ADR 0164, selection remains explicit, and result or embedding migration remains separately previewed and confirmed under ADR 0144 and ADR 0145. Uninstall, cache cleanup, index deletion and result deletion keep their own scopes. Public status and diagnostics expose opaque identities, reason codes and safe summaries without model paths, user content, confidential vulnerability details or credentials.

ADR 0216 also denies deletion authority over a matching pre-acquired external model package. Foreground inspection blocks import/installation by exact trust identity while leaving the user-owned source untouched; only app-owned ephemeral verification state may be cleaned.
