# Optional Capabilities Use An In-App Extension Library

Scope: Target architecture, refined by [ADR 0484](0484-extension-contracts-and-deferred-agent-development-access.md)
and the AI+ core boundary in [ADR 0483](0483-ai-plus-core-product-and-extension-boundaries.md).
The full ecosystem below is not a prerequisite for core product work; selected public
capabilities must satisfy their applicable contracts before third-party execution.
No SDK, catalog or sandbox is delivered merely by this decision.

The target application provides a dedicated Extension Library page for optional Format Capability Packs and Feature Plugins. Permissively licensed core preview workers for common bitmap, SVG, TIFF, PSD/PSB, common RAW, PDF and PDF-compatible AI paths remain bundled under ADR 0136. Core AI+ color/proportion, tag, description and prompt workflows remain built into the product even when their providers are replaceable. Advanced matting and editable-layer tools are optional. Large, rare, license-constrained, hardware-specific, or independently evolving capabilities may appear in Extension Library for user-initiated in-app download and installation rather than inflating or legally coupling the base package.

Format Capability Pack and Feature Plugin are distinct package kinds. A capability pack supplies declared isolated worker capabilities and ADR 0160 capability/runtime requirements; it cannot silently gain renderer, library, network, or arbitrary process access. A feature plugin declares its UI, commands, data scopes, network access, worker execution, other permissions, and public capability requirements before installation and runs under the narrowest available sandbox. Neither kind may name another plugin as a direct code dependency or invoke undeclared shell scripts, delegates, paths, network hosts, or child processes. Ghostscript and similarly constrained components remain absent unless a separately approved license/compliance package and product decision exist.

Extension Library initially consumes an official curated catalog whose ADR 0157 admission classes distinguish First-Party, Open-Source Community, and Verified Proprietary Extensions, while ADR 0153 defines public SDK/protocol tooling, Developer Mode, open contribution, and explicitly trusted third-party catalog sources. Each entry exposes publisher, package kind, version, release notes, license, source availability, cost/entitlement label and required acknowledgement, supported formats or features, Declared Extension API Range, worker protocol/native targets, platform/architecture, installed and download size, dependencies, permissions, privacy/data-handling disclosures, review evidence, restart requirement, capability/fidelity evidence, and compatibility status. Catalog metadata is signed and versioned; the package manifest pins artifact digest and size. Successful catalog display or paid status alone never establishes format support or executable trust, and official-build trust policy does not restrict source forks from modifying their own distribution.

Install is one user-initiated application action. ADR 0160 expands and displays the complete bounded Dependency Install Plan before download; no plugin or hidden transitive package starts installation itself. Ordinary Extension Permissions are summarized before installation, while each Sensitive Extension Permission, license acknowledgement, restart, or material storage impact receives an individually disclosed grant in trusted-app review under ADR 0155; these choices may share one review surface and do not require repetitive modal dialogs for an unchanged accepted plan. The remote adapter downloads to managed quarantine with resume and cancellation, verifies catalog signature, manifest schema, target platform/architecture, size and digest, then hands verified local artifacts to a transactional installer. Extraction limits, path and symlink defenses, staging, atomic activation, registry commit, capability health probe, rollback, and path-free progress reuse or parallel the existing Runtime Package Executor guarantees without weakening its current local/bundled-only policy or exposing its internal package-id graph as the public dependency ABI.

Installed does not mean Active until post-install verification, required consent, and ADR 0156 Platform Confinement Evidence succeed. Capability activation records package and worker version, Effective Permission Set, confinement/platform evidence, and supported format matrix. Failed verification rolls back or leaves a repairable inactive package without advertising the capability. Updates use the same staged transaction and never install automatically; a broadened permission manifest suspends the updated plugin in Permission Reapproval Required until the exact diff is approved under ADR 0155. Uninstall checks active jobs and dependents, removes only application-managed package files, and cannot delete originals, previews, model artifacts, analysis results, or user-authored plugin data without a separate scoped lifecycle decision.

Extension Library is a separate application route rather than another dense section inside AI Console. It shows installed, available, updating, incompatible-api/protocol/native-target, restart-required, permission-reapproval-required, quarantined, probationary, security-revoked, safety-suspended, unsupported/delisted, developer-loaded, untrusted-source, failed, and repair states plus bounded Download and Install Activity. It exposes application-upgrade Extension Compatibility Preflight, each plugin's negotiated or missing contract evidence, granted/denied/unavailable/revoked permissions, confinement compatibility, Last Verified Extension Trust State, and safe failure or recovery controls through trusted application UI. Renderer and public responses use opaque package identities and path-free status; package archives, native paths, verification internals, confidential review material, and credentials remain main-process owned.
