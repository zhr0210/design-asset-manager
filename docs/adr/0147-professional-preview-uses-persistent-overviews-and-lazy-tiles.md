# Professional Preview Uses Persistent Overviews and Lazy Tiles

Embedding an open-source decoder or renderer does not make professional originals directly displayable by Electron. PSD, PSB, layered TIFF, RAW, AI, PDF-compatible artwork, and similar sources still require isolated decode, composition, color transformation, and raster output. The backend therefore distinguishes rendered pixels from persistent full-size image files: it may produce pixels in a bounded working buffer or tile without storing a complete JPEG or PNG derivative.

Common bitmap formats may use the original directly for ordinary display only when signature, decode, orientation, alpha, color, resource, and renderer-safety checks authorize that path. They still receive a persistent Grid Thumbnail for dense library rendering. Professional formats persist a faithful approximately 512-pixel overview; structured assets use the single Primary Asset Overview and lazy unit-thumbnail rules in ADR 0150. ADR 0149 permits an evictable approximately 2048-pixel Quick Preview only when validated embedded data or an already-required bounded operation makes it available without a separate render. They do not produce permanent full-source-dimension sRGB and P3 JPEG or PNG files by default.

Full-detail preview uses an On-Demand Render Manifest created by Preview Broker after the selected format worker validates source dimensions, composition access, tile/region behavior, color evidence, alpha, and decoder capability for that artifact. Asset Preview requests only the visible region, zoom level, page, artboard, or frame. The worker renders a color-managed sRGB or eligible P3 tile according to Display Gamut Selection, then streams the validated result to the renderer. The original remains read-only and complex parsers remain outside the renderer process.

Rendered tiles enter a bounded Preview Tile Cache keyed by original content, format capability and decoder version, composition and color generation, rendering policy, destination gamut, visual unit, region, and scale. It uses active-view pinning, byte budget, TTL, LRU and regeneration-cost eviction, low-disk response, and orphan reconciliation. Only requested regions and gamuts are cached; a complete Tiled Preview Pyramid is not precomputed or retained by default. Preview Tile Cache is separate from Analysis Proxy Cache even when AI requests the same broker render contract.

System Preview Ready requires a validated persistent overview plus an On-Demand Render Manifest for formats that cannot safely display the original. A validated embedded composite may provide the immediate overview, but RAW or professional-format readiness still requires the full-detail worker path to pass its artifact-specific preflight. Opportunistic Quick Preview, P3 tiles, and previously viewed detail tiles may be absent or evicted without invalidating the sRGB overview and render capability. Failure to produce the overview or establish the declared render path remains Preview Generation Failure under ADR 0123.

AI analysis consumes ephemeral overview, crop, or tile pixels from the same broker boundary under ADR 0137 and does not require a permanent full-size preview. The first uncached high-detail view may therefore incur decode latency; subsequent views can reuse bounded tiles. ADR 0148 keeps the persistent overview visible, prioritizes the current viewport, and rejects stale tile results during that latency. Inspector and Storage Management distinguish original-direct display, persistent overview, Opportunistic Quick Preview, cached detail tiles, and current gamut so users can understand both quality and storage cost.
