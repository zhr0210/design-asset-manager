# Referenced Source Deletion Commits Per Item After OS Trash

Delete Referenced Source File is a single-file item-committed operation, not one cross-filesystem/database transaction or a batch-wide all-or-nothing promise. Before mutating a source, the application durably records the user's exact operation intent and validates that the selected Design Asset still resolves to the expected user-owned referenced original and that the operating system can attempt a trash/recycle-bin move. It invokes that operating-system operation first and moves the Design Asset into Asset Trash only after source deletion reports success. If source validation or the operating-system operation fails, the Design Asset remains active, the item reports a retryable or terminal reason, and the application never falls back to Remove Referenced Asset from Library or permanent deletion.

An interruption leaves a durable pending item rather than guessing from one missing path. On restart, library activation, or worker recovery, reconciliation uses the operation intent, current source evidence, and any durable platform outcome evidence: proven successful source disposition completes the Asset Trash transition; proven failure or an unchanged expected source keeps the Design Asset active and reports failure; ambiguous absence, replacement, or identity evidence creates item-scoped attention without repeating the destructive operating-system call, relinking another file, hard-deleting the record, or claiming success. Library Switch admits no new source-deletion item while the outgoing library quiesces and lets only the current non-interruptible operating-system call finish or enter this reconciliation state.

Batch Delete Referenced Source File applies the same sequence independently to each selected item. Successful items enter Asset Trash, failed or ambiguous items retain truthful per-item state, already successful operating-system moves are not rolled back to make the batch look atomic, and the result reports succeeded, failed, and needs-attention counts. ADR 0346 treats one Referenced Compound Original as one batch item whose member trash calls share a group intent: it succeeds only after the complete member set reaches Asset Trash, while a partial member outcome remains one group recovery item rather than successful or failed member items. ADR 0295 allows a later explicit Restore Referenced Source File only through an exact app-created Referenced Source Trash Receipt and its collision policy; this delete transaction does not claim that every successful move is still recoverable. ADR 0300 may immediately request that same restoration for successful items, but failed or ambiguous delete items never participate because they have no successful source deletion to undo. The current project has no ownership-aware source-operation journal, operating-system trash adapter, Asset Trash persistence, or reconciliation path; its existing `assets:delete` command directly deletes rows. This ADR records target architecture only and reads, moves, deletes, restores, or writes no runtime/user file and changes no public IPC, database schema, or AI Worker API.
