# Relocation Replacement Recovers Trashed Occupants Before Retry

Before Replace Relocation Destination asks the operating system to trash its exact current occupant, the application durably prepares a **Relocation Destination Replacement Receipt**. If trash succeeds but the atomic same-volume source move is not proven committed, the operation enters **Relocation Replacement Recovery** with the original Design Asset relationship unchanged until current filesystem evidence resolves whether the move occurred. A destination containing the complete expected source with the prior source absent finalizes the relocation and retains the receipt; it is never overwritten by rollback.

Recovery makes one automatic rollback attempt only when the receipt proves the exact trash item, the intended destination is safely vacant, the complete expected source remains at its original location, and no move commit occurred. A successful restore revalidates the occupant at its path and returns to Referenced Source Relocation Conflict Review. Any collision, source/destination drift, unsupported platform context, failed restore, ambiguous move boundary or insufficient evidence blocks automatic rollback without repeating trash, moving the source, guessing success or retrying in a loop.

Blocked rollback opens **Relocation Replacement Recovery Review** with current evidence for the source, destination and exact receipt-linked occupant. It may restore the occupant to its original path when safe, restore it to another explicitly selected safe location while leaving the source unmoved, or continue the source move only after fresh validation and explicit confirmation. Restart and closing the page preserve recovery state. If the replacement ultimately succeeds, the receipt remains in Local File Recovery and Recover Replaced Destination File defaults to an alternate safe empty location because the original path now contains the active source. Recovery or clearing never changes that Referenced Asset, represents relocation undo or enumerates unrelated system trash; ADR 0308 retention, Forget Library Registration, Uninstall Preparation and portability exclusions apply. The current application has no referenced-source relocation, replacement receipt store, recovery review or platform trash restore adapter. This ADR records target architecture only and accesses, restores, clears, moves, renames, trashes, deletes, reads or writes no runtime/user file and changes no public IPC, database schema or AI Worker API.
