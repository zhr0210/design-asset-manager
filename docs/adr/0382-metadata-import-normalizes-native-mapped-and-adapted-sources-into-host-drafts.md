# Metadata Import Normalizes Native, Mapped And Adapted Sources Into Host Drafts

Metadata Portability Import directly recognizes only the project's published versioned `.dammeta`, Metadata Portability JSON and Metadata Portability CSV schemas. A current compatible schema normalizes through the trusted host; an older supported schema migrates only into an isolated **Metadata Import Draft** with every conversion, default, omission and fidelity change shown before mapping. A safely inspectable newer schema reports its identity, declared classes and unsupported version but cannot be guessed, partially written or treated as current. Source files are never rewritten during normalization.

Arbitrary third-party JSON or CSV enters a separate **Field Mapping Import**, never the native-schema path. Its trusted review lets the user map documented columns or JSON paths to supported scalar and explicitly supported set-valued fields, define type/language/null conversions, inspect representative values and see truncation, ambiguity, invalid rows and unsupported content before producing a draft. Under ADR 0436, DateTime mapping preserves whether the source supplied an explicit offset/IANA zone or only local components; a missing zone remains Unzoned unless the reviewed mapping declares a zone-assignment rule, including any daylight-saving overlap choice. ADR 0437 also preserves zero-to-nine declared fractional digits; minute-only values require a visible append-seconds rule, while greater precision remains a conflict until an explicit rounding/truncation rule is selected. Under ADR 0440, mapped Text is NFC-canonical while otherwise preserving case, whitespace and line breaks; an over-limit value remains a visible conflict and is never silently shortened. ADR 0441 requires the draft and review to distinguish source null/missing, zero-length Text and non-empty whitespace-only Text: the first two produce no current value after confirmed mapping, while the last remains exact, present and visibly warned. ADR 0442 makes ill-formed Unicode or an unsafe control a position/code-point-specific conflict requiring explicit correction, while preserving valid invisible formatting with a revealable warning. ADR 0443 also validates every present mapped value against the target's grapheme minimum and exact portable pattern version/match mode, never an adapter's or operating system's regex semantics. ADR 0444 further freezes the target definition's case, multiline, dot-all and Unicode-property options into that validation. A user-named **Import Mapping Preset** may retain only mapping/conversion rules, ADR 0421 stable Custom Field Dependency References and a non-content source-shape signature; it stores no imported values, credentials, source path or source file. An archived or missing definition leaves the affected mapping visibly non-executable until explicitly repaired and never falls back to its field name. Preset personal/library scope and sharing remain separate decisions.

CSV mapping cannot hide JSON, base64, vectors, masks, region evidence, relationship graphs, multilingual objects or binary payloads inside cells. JSON mapping accepts only host-declared typed shapes and bounded structures; an arbitrary object is not preserved as a private blob. Missing exact asset/shared-object identity evidence remains missing, so field mapping does not upgrade filenames, paths, labels or third-party IDs into ADR 0376/0380 automatic matches. Unsupported or unselected source fields stay visible with row/value counts and reasons rather than disappearing silently.

The public Extension API adds a scoped **Metadata Import Adapter** contribution for formats such as another asset manager's export, XMP-oriented interchange or a documented vendor schema. For one explicit operation, Extension Host gives the selected adapter a read-only bounded staged source handle after compatibility, permission and isolation checks; the adapter receives no original path, library/database access or reusable file grant and writes only a bounded structured draft candidate to host-owned output staging. The handle and staging expire at operation end under ADRs 0155 and 0156.

Every adapter candidate must validate against the public versioned Metadata Import Draft schema. The draft is data-only and may contain typed asset records, declared source object definitions/relationships, ADR 0418 Custom Field Definition Proposals, provenance, stable/exact evidence classes when genuinely supplied, field-level warnings and unsupported-field inventory; it contains no executable content, SQL, private IPC, host database keys, filesystem paths, permission claims or direct write instructions. Adapter identity/version and transformation provenance remain attached to every proposed record, while a malformed, oversized, timed-out or unsafe response fails/quarantines only that contribution under the normal Extension Failure Budget.

Neither a plugin nor a mapping preset can create Design Assets or Custom Field Definitions, confirm matches, merge Tag Concepts/collections, resolve value conflicts, choose an active AI projection, write library state or invoke Original Metadata Writeback. Under ADR 0438, a preset affected by a restrictive target validation change remains visible but cannot execute until reviewed against the current rule, and imported values must satisfy that rule rather than recreating retained Out-of-Constraint values as new assignments. After host validation, every draft—native, user-mapped or adapter-produced—enters the same ADR 0376–0381 inspection, asset/shared-object mapping, conflict, item-atomic commit, result and undo pipeline. The host remains the sole write authority, and no imported data package executes code merely because an adapter recognizes it.

ADR 0474 requires a new-owner import plan to disclose every applicable typed
static default and bind it to the exact definition revision. An explicit mapped
typed value or Missing intent wins; omission may use the reviewed default,
while definition drift invalidates the plan rather than changing the result.
ADR 0473 supplies Boolean's exact specialization.

The current application has no native Metadata Portability Import parser, Metadata Import Draft, Field Mapping Import, Import Mapping Preset or Metadata Import Adapter surface. This ADR records target architecture only and reads or adapts no actual user file, loads or grants no plugin, and selects, imports, analyzes, stages, writes, rewrites, converts, moves, deletes or changes no runtime/user file, credential, sidecar, directory, database, cache, backup, metadata value, analysis result, source relationship, public IPC, database schema or AI Worker API.
