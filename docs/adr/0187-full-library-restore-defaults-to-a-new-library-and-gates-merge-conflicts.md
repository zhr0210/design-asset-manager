# Full Library Restore Defaults To A New Library And Gates Merge Conflicts

A Full Library Backup restores to a newly created empty library by default. Restore authenticates and validates the complete archive under ADRs 0185 and 0186, performs schema migration in isolated staging, and runs ADR 0276 Library Open Inspection against the staged result before atomically exposing it as a usable library. It does not mutate the currently open library, inherit its storage identities or silently redirect imported memberships. The user chooses a managed destination with preflighted space and compatibility; cancellation or failure removes only the incomplete new library.

**Merge Into Current Library** is a separate advanced action, never the default continuation of Restore. Before any write it produces a side-effect-free Merge Dry Run that reports new, identical, storage-deduplicated and conflicting assets; metadata/result conflicts by class; collection/Tag Concept/Saved Search conflicts; required bytes; lifecycle effects; and blocking compatibility or integrity issues. The user can leave without mutation. A confirmed merge uses a journaled transaction, bounded checkpoints and rollback under ADR 0003 rather than applying records while the plan is still being calculated.

Portable identity resolution uses the backup's stable library namespace plus stable object identity and verified content digests, never filename, display title, collection name or former physical path. The same portable object identity with the same digest is Already Present and is not duplicated. Identical content bytes belonging to different logical asset identities reuse one verified content blob when the storage model safely permits it, but their Design Asset records, collection memberships, lifecycle state, provenance and user metadata remain distinct. Similarity signals and matching filenames are advisory only and never trigger automatic deduplication or merge.

New non-conflicting objects and fields may be imported as planned. When the same portable identity has divergent content, lifecycle state, metadata or durable analysis evidence, merge does not use last-writer-wins or silently prefer a newer timestamp. It creates an Import Conflict grouped by field/result class. The available explicit choices are **Keep Current**, **Use Imported**, or **Keep Both** when the domain can represent coexistence without inventing meaning. “Keep Both” creates a distinct logical identity or retains provenance-separated result generations as appropriate; it never stores two contradictory values in a single-value field.

Conflict handling reuses the field-aware principles of ADR 0097 and permits a batch choice only for an ADR 0100 Homogeneous Conflict Set with a Resolution Preview. User-authored/manual values and suppressions are never automatically displaced by model output. Tags, collection memberships and other set-valued fields are shown as current/imported differences; any union is an explicit reviewed choice rather than an assumed safe merge. OCR, descriptions, palettes, embeddings and other results deduplicate only when identity, payload digest and provenance/equivalence contract match; otherwise compatible generations may coexist, or the user selects which is active without deleting the other merely to complete restore. ADR 0197 imports source Model Advisory Acknowledgements as history only; only an exact target-library acknowledgement can cover imported advisory attention.

Unresolved conflicts may be deferred only when the resulting library remains internally valid. They stay visible through a persistent Import Conflict state and do not block access to unaffected assets. Integrity, ownership, required-preview, schema or single-owner content conflicts that cannot safely coexist are Blocking Issues and must be resolved before the affected object is committed. Resolution results are summarized without private content in the operation record and support a short-lived transactional undo where technically safe.

**Replace Current Library** is not a merge option. It is a separate destructive workflow that first validates the source archive, creates and verifies a recoverable backup of the current library, closes active writes, presents exact aggregate replacement scope, and requires explicit confirmation. Replacement writes a new staged library and swaps it atomically; failure rolls back to the verified prior library. The application never deletes the only current library merely to make destination space and never treats a failed backup as permission to continue.

This full-backup restore policy is separate from restoring one Asset Trash record. ADR 0071 continues to default an individual Asset Restore conflict to Restore as Copy and forbids silent deletion or merge of its Trash record. Both policies share the invariant that content resemblance does not erase logical history without an explicit user decision.

It is also separate from ADR 0284 object-level Managed Original Recovery. Extracting one identity- and digest-verified original payload for managed copy-back neither creates a new library nor merges backup metadata into the current library; a different or older payload requires an explicit Use as Replacement decision instead of bypassing this ADR's merge-conflict rules.

The current project has no Full Library Restore, Merge Dry Run, portable object namespace resolver, import-conflict persistence, content-blob deduplication transaction or atomic library replacement workflow. This ADR records the target behavior without reading or modifying a runtime library/database/assets, creating a backup, changing schema/public contracts or implementing replacement.
