# System Trash Restore Handles Stay Device Local

A Referenced Source Trash Receipt is deliberately split because library history is portable but operating-system trash authority is not. **Portable Referenced Source Deletion State** remains authoritative library data: it records that Delete Referenced Source File succeeded, the owning Design Asset and Asset Trash lifecycle, the prior referenced-source relationship and the last verified Source Content Generation without containing a platform trash path, opaque restore handle or promise of automatic recovery. It travels with the portable library and ADR 0185 Full Library Backup so another device can explain the state and offer manual source restoration or trusted relink truthfully.

The corresponding **Device Trash Restore Handle** remains only in device-local restoration state bound to the relevant Local Library Instance, operating-system adapter and storage context. It contains the minimum platform evidence needed to verify one exact app-trashed item, is excluded from Library Root portable state, Full Library Backup, library merge, Offline Library Catalog, Cross-Library Search projection and portable exports, and is never reconstructed from filename/path/time/size guesses. ADR 0346 keeps one independently verified handle per successfully trashed compound member rather than inventing a portable or synthetic whole-folder handle. ADR 0353 applies the same portability boundary to each Managed Residue Trash Restore Handle while keeping its separate Managed Conversion Residue Cleanup State in the library. Opening or restoring the library on another device cannot import, synthesize or remotely exercise the original device's system-trash capability; even on the original device, one-click Restore Referenced Source File or Recover Cleaned Managed Conversion Residue requires the matching local handle and currently accessible storage context.

The user-visible Asset Trash entry reports automatic source restore as available only when the active device proves that local capability. Otherwise it preserves the portable deletion state and offers manual system-trash recovery, Restore Source to New Location through a trusted picker, Use Existing File as Replacement where applicable, or relink, without treating local-handle absence as corruption or permanent source loss. ADR 0298 governs local-handle retention, dormant preservation and explicit clearing. The current project has no portable library/Asset Trash state, Device Trash Restore Handle store, platform restore adapters or ownership-aware restore availability projection. This ADR records target architecture only and reads, exports, backs up, enumerates, moves, restores, or deletes no runtime/user file and changes no public IPC, database schema, or AI Worker API.
