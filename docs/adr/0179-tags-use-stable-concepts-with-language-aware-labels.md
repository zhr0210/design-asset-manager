# Tags Use Stable Concepts With Language-Aware Labels

Asset membership binds to a stable opaque Tag Concept identity, not to a mutable display string. A Tag Concept represents one intended semantic meaning and owns language-aware labels, aliases, hierarchy/relations, provenance and lifecycle. Switching application or Metadata Language selects another display label through a declared fallback chain but does not change the concept ID, asset association, confirmation status, usage count or AI evidence. “red” and “红色” therefore resolve to one concept only when trusted vocabulary evidence establishes that meaning, not merely because a translator produced both strings.

Built-In Tag Concepts use immutable catalog identities and signed versioned vocabulary definitions. Each Tag Label or Alias records its BCP 47-style language or Language Undetermined, normalized search form, source/provenance and whether it is an official preferred label, official alias, user-authored label or unconfirmed generated proposal. Locale/script-aware normalization supports search but never replaces the preserved label. Homographs, polysemy and cross-language collisions may belong to different concepts; lowercase equality, slug equality or machine translation alone cannot merge them.

AI produces a Raw Tag Suggestion with exact source term, declared/detected language when evidenced, model/recipe, source/view scope and confidence. Mapping to an existing concept is allowed when the model emits a versioned trusted vocabulary ID or when an exact preferred-label/alias rule resolves uniquely in the declared vocabulary version. Fuzzy, translated or embedding-assisted mapping must expose candidate concepts, method and calibrated mapping confidence and may auto-map only under a separately reviewed high-trust rule. ADR 0180 separately governs whether a uniquely mapped suggestion may become confirmed. Ambiguous or insufficient evidence remains an Unmapped Tag Suggestion; it is not silently converted into a new concept or attached to the closest spelling.

ADR 0016 confirmation lets the user accept a mapped concept, choose another candidate, create a new User Tag Concept from the raw suggestion, add a manual alias to an existing concept, or reject it. Batch acceptance requires homogeneous mapping evidence and excludes ambiguous items for review. The raw model term and mapping provenance remain evidence after acceptance without becoming a second confirmed tag. Rejection/suppression applies to the exact suggestion/evidence identity and does not globally ban the same word in another language or meaning.

User Tag Concepts are owned by the user. The application may show advisory possible duplicates across labels/aliases but never automatically translates, merges, renames, converts to a Built-In Concept or reassigns their assets. The user may add language-tagged labels and aliases manually. An explicit Merge Tag Concepts preview shows source/target meaning, affected assets, labels/aliases, hierarchy/relations, suggestions and conflicts; confirmation moves references transactionally and leaves an opaque Concept Redirect/tombstone so stored references and imports do not silently break. Undo follows the bounded metadata-action policy while available.

Display label selection prefers the user's explicit label preference for that concept, then the current UI language's official/user label, compatible language fallback, the concept's declared canonical label, and finally an honest unlabeled/opaque state. It never invokes translation synchronously while rendering. ADR 0181 search matches all allowed localized labels and aliases but results deduplicate by concept ID; pending suggestions require an explicit include option. User-authored capitalization, script and spelling are preserved even when normalized search keys coincide. ADR 0358 writes a Tag Concept to an interoperable keyword field only through an explicit exact label-and-language choice; it never serializes opaque concept identities, aliases, hierarchy or the current UI label by accident.

Changing UI language only changes presentation. Changing Metadata Language may influence future AI suggestion vocabulary or label preference but neither operation relabels stored user concepts, remaps suggestions, rewrites tag history or triggers library analysis. Vocabulary catalog updates may add labels/aliases or deprecate a concept, but semantic merges/splits require an explicit reviewed migration with affected counts; a catalog publisher cannot silently redirect user-defined concepts.

The current schema has tag IDs, one mutable primary `name`, lowercase `normalized_name`, an untyped alias table/JSON snapshot and name-based uniqueness within tag type. AI suggestions store `tag_name` rather than a concept or mapping candidates; localization commonly replaces English with a Chinese display string; current merge moves asset links/aliases and deletes the source without a durable concept redirect. These are migration inputs, not compliance with stable multilingual concepts. This ADR records target domain semantics without authorizing a schema/API change, migrating tags, reading the runtime database or running localization/models.
