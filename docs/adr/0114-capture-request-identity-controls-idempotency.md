# Capture Request Identity Controls Idempotency

Capture Gateway must use Capture Request Identity, not URL, title, or filename, as the idempotency boundary. Repeating the same identity with an equivalent Canonical Capture Envelope is Idempotent Capture Replay and returns the existing Candidate Identity and current lifecycle state without creating another Candidate Record. Reusing the same identity with materially different source, artifact locator, capture method, or metadata intent is Capture Identity Conflict and must be rejected without overwriting the accepted request. Different Capture Request Identities may intentionally capture the same URL or content as separate candidates; after Candidate Activation, Duplicate Signal performs advisory content duplicate evaluation under the existing no-auto-merge policy.
