# Referenced Asset Removal Separates Library And Source Deletion

A Referenced Asset exposes two unambiguous deletion actions because removing an app-owned Design Asset and deleting its user-owned original are different authorities. **Remove Referenced Asset from Library** is the default: it invokes Delete Design Asset, moves the Design Asset into Asset Trash, and leaves the external source file untouched. **Delete Referenced Source File** is a separately labeled destructive Referenced Source Operation that requires explicit confirmation, requests that the operating system move the source to its trash or recycle bin rather than permanently unlinking it, and also moves the Design Asset into Asset Trash after source deletion succeeds. A generic Delete command cannot silently choose between them, remember the destructive choice, or turn one action into the other after failure.

Permanent Asset Delete after Remove Referenced Asset from Library removes only the library's record and governed derivatives; it never reaches back to delete the referenced source. Operating-system trash remains distinct from Asset Trash, and library cleanup, retention, application removal, plugin removal, and Forget Library Registration never invoke Delete Referenced Source File. An explicit Restore Referenced Source File action is nevertheless allowed to operate the platform trash/recycle-bin capability rather than being limited to metadata restoration. ADR 0294 resolves source-delete item commit, failure, interruption, and batch behavior; ADR 0295 limits source restoration to exact app-created receipts without global trash enumeration; ADR 0296 resolves occupied-destination behavior without overwrite or automatic rename; ADR 0300 makes short-lived undo a normal receipt-scoped restore request rather than a filesystem rollback.

For an ADR 0344 Referenced Compound Original, Remove Referenced Asset from Library still leaves every member untouched. Delete Referenced Source File remains unavailable because its single-file contract cannot silently mean primary-only or whole-group deletion. ADR 0346 instead provides separately confirmed Delete Referenced Compound Source, which reaches Asset Trash only after every current member has a proven operating-system trash outcome and retains partial results in group recovery.

The current renderer labels one command `移出素材库`, while its shared `assets:delete` path directly deletes asset and tag rows and has neither Asset Trash nor Asset File Ownership-aware source operations. This ADR records target architecture only and deletes, moves, reads, or writes no runtime/user file and changes no public IPC, database schema, or AI Worker API.
