# Automatic Analysis Is Local Progressive and Resource Aware

Product clarification: ADR 0483 makes AI+ a built-in core experience. Local-first
execution and missing-model resilience remain; cloud inference is distinct from
the deferred development connector in ADR 0484.

Automatic analysis for a newly activated visual Candidate begins as lightweight capability-level Analysis Intents under ADR 0168. ADR 0169 defines the default enabled local Baseline Automatic Analysis Profile as Tag Suggestions, semantic Embedding, bounded OCR and one Short Description, each independently controllable. Eligible deterministic work may begin immediately, while Preview Broker produces or validates Analysis Visual Source only when a concrete local job reaches admission. Deterministic metadata/palette and duplicate signaling may supplement the baseline with distinct provenance. It uses the overview and coverage rules from ADR 0137 through ADR 0140 and does not delay Candidate visibility, mutate the original, claim unavailable model output, retain waiting image proxies, or require every detailed Analysis Unit to finish.

Expensive work enters Deferred Detail Analysis instead of the immediate path. Exhaustive page or artboard coverage, large-canvas tiles, extended OCR, detailed captioning, additional model ensembles, per-frame and layer work run only under a separately enabled ADR 0169 Idle Extended Analysis policy or after an explicit user request. A foreground user-requested analysis receives priority over automatic detail work without interrupting a unit that is already committing evidence. All queues remain bounded and generation-aware so changed sources or recipes supersede stale queued work rather than producing active outdated results.

ADR 0173's global Local AI Resource Governor implements Analysis Admission across capabilities and runtimes. It evaluates available memory, derived-media disk budget, low-disk pressure, battery and power state when available, thermal or accelerator pressure when available, foreground interaction load, Preview/model/runtime/storage/trust availability, and safe execution-class concurrency before creating or starting each execution job/unit. Unsafe or inconvenient conditions keep the durable Analysis Intent in its typed waiting state; they do not create unnecessary input proxies, delete completed View-Level Analysis Evidence, or erase the remaining Analysis Coverage Plan. Restart reconciliation resumes eligible work, while the UI distinguishes waiting reason, queued, running, paused, completed, partial, cancelled and failed states.

Automatic analysis may use only in-process algorithms and local runtimes or models that are already available under explicit runtime governance. Under ADR 0144 it selects one active model per capability at job admission and may use only a declared ordered local fallback, rather than running every installed model. It must not download or install models, start an unapproved external service, or return simulated success to satisfy the baseline. ADR 0152 lets the user explicitly install a missing model from Model Library, but the intent/job cannot click or infer that consent. Missing local capabilities leave their named Analysis Intent waiting while independent baseline work continues; verified repair may reconcile it automatically only while the user's local automatic-analysis preference remains enabled.

External HTTP or hosted AI is never selected by the automatic queue and no Analysis Input View is uploaded merely because a provider, endpoint, or credential is configured. External analysis requires an explicit External Analysis Grant for the visible action or batch. Before execution, the UI identifies provider, purpose, asset count, Analysis Unit and Input View scope, coverage mode, and whether derived RGB views rather than originals will be sent. Enabling a provider or saving credentials is not upload consent. A grant does not silently extend to future assets, broader units, exhaustive coverage, or another provider.

Local and external results use the same evidence and projection contracts, but retain execution-location and provider provenance. Cancelling external execution stops unstarted requests and records terminal state for requests already sent; it cannot promise remote deletion. Resource pauses, application restarts, and cache eviction do not convert queued work into success or erase what remains to be analyzed.
