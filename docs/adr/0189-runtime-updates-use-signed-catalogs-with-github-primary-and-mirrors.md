# Runtime Updates Use Signed Catalogs With GitHub Primary And Mirrors

Official Baseline AI Runtime and managed dependency discovery uses an application-owned **Signed Runtime Channel Index**, not a mutable repository branch, filename convention or unauthenticated `latest` response. The small index has a channel identity, monotonic sequence, issue/freshness metadata, minimum compatible application/catalog schema, revocation state and the exact identity plus digest of each signed immutable Runtime Package Manifest. It is verified against an official trust root embedded in the signed application; an older sequence, unknown key, invalid signature, incompatible schema or digest mismatch fails closed while the currently installed verified runtime remains usable.

Signed Runtime Channel Index and Runtime Trust Statement refresh follows ADR 0204's shared Trust Catalog Refresh Policy: it is eligible only when never verified or older than 24 hours, runs at most once per rolling 24 hours per trust root/channel while the application is active, and remains manually refreshable. The application does not leave a background polling service after Quit, and catalog refresh never grants permission to download or install runtime packages.

GitHub Releases is the initial official primary transport. Production runtime packages and manifests are attached only to published release identities, with GitHub Immutable Releases enabled where supported so the tag and assets cannot be rewritten after publication. Clients resolve exact release/asset identities from the verified manifest and never infer package trust from repository ownership, HTTPS success, a release title, tag ordering or `latest`. GitHub Actions workflow artifacts are build inputs/evidence only and are not a production client download source. GitHub artifact attestations may be retained as additional release provenance, but do not replace the application-owned manifest signature, file digest, platform signing evidence or readiness verification.

Official object storage or CDN endpoints may be listed as ordered **Runtime Download Mirrors** for availability, regional performance and scale. Every mirror serves byte-identical content for the same immutable package digest and declared size. Mirror selection or failover changes transport evidence only; it cannot change package identity, dependency closure, publisher, license, permissions, platform/architecture eligibility or trust decision. A mirror returning different, truncated, decompression-variant or unexpectedly executable content fails verification and is quarantined for that transaction rather than becoming a new package.

The remote adapter supports bounded HTTPS redirects required by approved release/object storage, resumable range requests where the origin proves immutable identity, ETag/conditional catalog refresh, retry backoff and ADR 0177 network-cost transitions. Redirect targets must remain inside the source adapter's declared host policy; credentials and authorization headers are never forwarded to an unrelated host. Official public runtime packages require no user GitHub credential. GitHub API limits or source outages produce a typed waiting state and may trigger an approved mirror, cached signed metadata or manual offline package selection; they never disable verification, create retry storms or erase a working installed runtime.

ADR 0209 does not treat GitHub release/API fields, HTTP headers, TLS times, ETags or mirror clocks as trusted current time. Only a catalog-bound, official time-only signed freshness envelope may contribute network time evidence; transport success and repository ownership cannot create it.

The ADR 0188 Offline Full Installer and separately imported official offline Runtime Packages are network-independent transports for the same manifests and bytes. They pass the same signature, digest, archive, platform, staging, atomic promotion and Runtime Registry checks. A package already present by content digest is reused rather than downloaded again. An offline bundle does not become a permanent update channel, and later remote discovery does not replace a healthy runtime merely because its transport source differs.

ADR 0221 may resolve an Official Package Reacquisition Plan after selected external bytes fail their signed digest. It uses only the exact candidate and approved transport sources from this signed channel/mirror policy, never a URL or actual digest supplied by the mismatching file. Reacquired bytes enter new governed staging and pass full verification; the external file is neither repaired nor treated as a partial mirror.

ADR 0206 separates install admission by transport without weakening identity. Online runtime installation/update requires fresh signed trust state before payload transfer/promotion. An official offline package carries signed Dated Offline Trust Evidence, displays its issue date, and can install without network only after exact verification and comparison against newer persisted trust statements; it cannot clear a known revocation or make an arbitrary local/GitHub artifact official.

ADR 0207 keeps official offline evidence usable without a generic age cutoff. Only exact signed validity bounds, signature/trust/compatibility failure or known root/package/runtime revocation blocks new installation; release age, key rotation, mirror timestamp or availability of a newer package does not manufacture revocation.

ADR 0212 requires stable official offline runtime packages to omit current-time install boundaries. A permitted exceptional test/preview, legal/license or incident-transition package carries its signed reason/window/recovery disclosure through every mirror and cannot be relabeled as Stable Offline.

Explicit third-party Runtime Catalogs may be supported later through user-added catalog trust roots, visibly separated from the Official Runtime Catalog. An arbitrary GitHub repository, Release URL, CDN URL, local mirror or successful health probe is not a trusted catalog. Third-party sources cannot weaken archive safety, platform confinement, Managed Path, no-system-modification, network admission, rollback or critical official digest blocking. Forks may ship their own trust roots and source policy without inheriting official publisher claims.

Application update artifacts may reuse the underlying resilient HTTPS/mirror transport, but application release signing/notarization, update metadata and activation remain owned by Release Flow rather than Runtime Registry. Runtime packages likewise cannot replace Electron/application code. Separate trust domains prevent a compromised runtime catalog key from publishing an application update or a normal application-update feed from silently selecting a model/runtime package.

The current Runtime Package Source contract represents remote access as reserved and disabled; the downloader and executor reject every remote source. `package.json` also has no publish provider. There is no signed channel index, production remote catalog adapter, GitHub Release resolver, redirect host policy, range/ETag implementation, mirror health/failover, offline official importer or client attestation verification. This ADR records the target source architecture without enabling a URL, querying GitHub, downloading packages, changing GitHub settings, reading credentials/private storage or altering public IPC/schema/AI Worker APIs.
