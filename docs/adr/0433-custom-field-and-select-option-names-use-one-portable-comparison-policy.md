# Custom Field And Select Option Names Use One Portable Comparison Policy

Custom Field names and Select-option labels must produce the same uniqueness result on every supported device without erasing the spelling a designer chose. The library therefore uses one versioned **Custom Field Name Comparison Policy** for both: remove leading and trailing Unicode White_Space characters, reject a result that is empty, store the display text in Unicode NFC, and derive its collision key by applying locale-independent Unicode full case folding followed by NFC. Display keeps the user's casing, accents and internal whitespace; comparison does not remove accents or collapse internal whitespace. Consequently `Red` conflicts with `red`, canonically equivalent composed and decomposed text conflicts, and `A B` remains distinct from `A  B`.

Active Custom Field Display Names are unique across the library. Active Select-option labels are unique only among options of the same Custom Field Definition. Creation, rename, plugin/import Definition Proposal review and restore all use the same host-owned comparison policy; no operating-system locale, language, filesystem behavior or plugin comparison may override it. Archived fields and options do not reserve labels, so a later restore that collides is blocked: a field requires renaming the archived or active field, while an option allows renaming either option or explicitly merging the archived option identity into the active same-field target under ADR 0432. The application never resolves a collision by automatic suffixing, identity reassignment or name-based merge.

The comparison-policy version and Unicode data version are part of portable library schema interpretation rather than ambient operating-system behavior. Derived collision keys are rebuildable. Adopting a newer comparison version requires reviewed library-schema migration with a collision-impact preview; it never silently renames, merges, activates or deletes definitions or options.

ADR 0440 reuses this pinned, versioned Unicode-data boundary when counting extended grapheme clusters in Text values, but not this name-collision transformation. Authoritative Text content is NFC-canonical and otherwise preserves case, whitespace and line breaks; it is never trimmed or case-folded merely because names are.

ADR 0444 likewise pins Unicode data for portable pattern matching, but its optional case-insensitive mode uses Unicode simple case folding rather than this ADR's full case folding. Pattern acceptance and name collision are distinct questions and must not share derived keys or silently substitute one algorithm for the other.

ADR 0446 Case-Insensitive Duplicate Text Comparison does reuse full case folding plus NFC, but does not reuse this name policy's edge trimming or collision authority. Its Normalized mode uses a separate `NFKC_Casefold` and whitespace transform. Both produce advisory rebuildable grouping keys only.
