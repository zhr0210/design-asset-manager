# Ownership Conversion Never Writes Library Metadata Into Originals

Single-item and batch Convert to Referenced Asset follow **Conversion Metadata Separation**: the published or explicitly adopted external Original Asset is byte/member/manifest-equivalent to the current managed Original Asset, while titles, notes, Collection Memberships, confirmed tags, ratings, manual OCR and descriptions, user-authored analysis values, AI results, embeddings, cover choices, color sidecar assignments and other application-owned metadata remain attached to the same Design Asset in portable library state. Conversion is not a metadata export, does not make external files self-describing, and creates no embedded write, XMP sidecar, application manifest, hidden control file, tag folder or analysis payload at the destination. Full Library Backup continues to preserve authoritative library metadata and referenced relationships without adding the referenced source bytes.

Embedded EXIF, IPTC, XMP, ICC and other metadata already present inside an Original Asset member remain untouched because their bytes are copied exactly. An XMP or other sidecar is copied only when it is already an included capability-declared member of the current Compound Original; its existing role, name, relative layout and bytes remain unchanged. Conversion never scans siblings, attaches an undeclared sidecar, synthesizes a companion from application metadata or writes into an existing member. A Sidecar Profile Assignment and similarly named library sidecar state remain library metadata and are not confused with a physical companion file.

ADR 0356 Use Existing Identical Conversion Destination remains eligible only when the complete destination already matches the unmodified current Original Asset. A destination that differs because it contains exported or rewritten metadata is not identical and cannot be silently adopted, overwritten or treated as the same Source Content Generation. The destination plan discloses that application-only metadata remains in the library, but it never adds a preselected option to write that metadata into files or permits a batch preset, plugin, prior choice or file-format convention to do so.

If the user later wants selected library values serialized into source files, **Original Metadata Writeback** is a separate explicit format-capability-controlled source operation, not a continuation or option of ownership conversion. ADR 0358 limits it to user-selected interoperable values and keeps OCR, embeddings, model provenance, library relationships and internal identities outside original-file writeback. An embedded byte change follows the ownership-appropriate protected source-rewrite workflow, and changing an existing Compound Original member follows ADR 0347 complete-group rewrite. Creating a new physical sidecar requires a separately designed capability-controlled generation flow whose verified output then enters ADR 0349 as an explicitly reviewed Companion Attachment Candidate; ADR 0349 alone never generates it. A byte or authoritative member-manifest change creates one new Source Content Generation and stales generation-bound generated evidence; a fully byte-identical result is a no-op. No application edit, AI completion, background analysis, ownership conversion or metadata-language change invokes writeback automatically.

ADR 0393 Compatible Export metadata is also outside ownership conversion and
writeback. It may serialize explicitly selected values only into a newly
generated source-separated compatible output. That permission never authorizes
an original/member mutation, sidecar attachment or ownership transition.

The current application has no ownership-conversion metadata-separation projection or Original Metadata Writeback workflow. This ADR records target architecture only and embeds, extracts, exports, creates, attaches, stages, copies, writes, rewrites, converts, moves, deletes or changes no runtime/user file, sidecar, directory, database, cache, backup or analysis result and changes no public IPC, database schema or AI Worker API.
