# Local Model Import Is Explicit Verified And Managed

Model Library supports local model import only through an explicit user-created Local Model Import Request from a trusted native file or directory picker. The request grants read-only inspection of exactly the selected scope for that import operation; the application does not crawl Downloads, home directories, external volumes, existing framework caches, configurable model roots or the wider filesystem to discover models. Directory inventory is bounded by file count, bytes, depth and time, does not follow symlinks or parent traversal, and reports unsupported, duplicate, case-colliding, hidden executable or archive content before any managed write.

Inspection runs in an isolated resource-limited validator and never imports or executes Python, JavaScript, WebAssembly, shell, dynamic libraries, binaries, install hooks, pickle/object checkpoints or repository code. It accepts only ADR 0161 Declarative Model Formats and exact supporting roles, computes file sizes and cryptographic digests, validates structure, and builds a path-free Model Import Preview. A folder containing required custom code is not partially treated as a complete model; the preview explains that code must be separately packaged, reviewed, permissioned and confined as a Model Runtime Capability Pack.

Identification is evidence-based. An exact match of every required file role, size and digest to a current signed catalog manifest becomes Catalog-Matched Local Artifact after current Model Trust Statement and license checks. A manifest from an explicitly trusted Model Catalog Trust Root may identify the same way. Otherwise the import is Unverified Local Model: family, checkpoint, capability, publisher, license, quantization, equivalence and model-space identity remain Unknown unless authoritative declarative evidence establishes each field. Filename, folder name, repository-like layout, nearby README or model-size guess cannot fill missing identity.

ADR 0206 Official Offline Model Package is a separate signed-package lane with complete manifest-bound bytes and Dated Offline Trust Evidence. An ordinary Local Model Import Request, detached checksum, unknown signature, repository export or copied framework cache cannot claim that lane. When online catalog trust metadata is stale, resemblance to cached official metadata never promotes a local import to current catalog-matched trust; unmatched content retains Unverified Local Model handling.

Model Import Preview shows identified or unknown fields, selected artifact roles, unsupported files, logical bytes, already-present Model Blob Store bytes, additional physical disk, required runtime/capability binding, hardware compatibility evidence, trust state, license/terms status and whether a safe readiness probe is possible. Unknown license requires the user to acknowledge that the application cannot establish usage rights; this is not a license grant or Official Catalog Review. The user can cancel without changing managed model state.

Confirmed import copies or clone-copies verified bytes into managed partial storage, re-verifies them, and atomically adds content-addressed Model Blob Store and manifest references. It never executes directly from, hard-links to, moves, rewrites, watches or deletes the selected source. A source mutation or removal after import cannot alter the installed artifact. Import provenance retains import time, opaque request/source kind, digests, validator version and identification result without retaining or exposing the full source path in renderer state, logs or analysis provenance.

A catalog-matched artifact follows the same license, trust, compatibility, update, activation and rollback rules as a downloaded artifact, while recording local import as its acquisition method. An Unverified Local Model remains Imported Inactive until an approved built-in runtime schema or separately verified capability binding can interpret its exact declarative metadata and a bounded local readiness probe passes using synthetic input, no user assets, no network and no repository code. If identity or a safe loader cannot be established, the import may remain stored for inspection/export/uninstall but cannot be selected for analysis. Passing a probe proves bounded load compatibility, not publisher identity, license, model quality, Official Catalog Review or cross-variant equivalence.

Unverified local artifacts do not receive automatic catalog updates or Model Trust clearance by resemblance. A later signed catalog manifest that exactly matches their blobs may propose reclassification, current license acceptance and trust review without copying bytes again; the user confirms the identity transition. Critical digest statements under ADR 0165 still block a locally imported matching blob, while an unknown artifact is never assumed safe merely because no catalog statement exists.

The configurable ADR 0167 Model Storage Root is a destination and accounting boundary, not an import/watch folder. Import requires an available verified root identity and accounts for target reserve and deduplicated bytes before copy. Legacy direct model paths and directory-based downloaded checks must migrate through a separate compatibility plan; new Model Library contracts use opaque artifact identities and managed handles rather than renderer-supplied filesystem paths. Import failure removes only its unreferenced staging and leaves the selected source, existing models, active assignments, results, indexes, caches and user assets untouched.
