# Invalid Color Profiles Require Bounded Validation And Review

Invalid Color Profile is split by the boundary of the failed evidence. A Recoverable Invalid Color Profile means bounded ICC validation rejected the embedded or declared profile, but independent validation still confirms that the original file structure, pixel payload, composition decode, and Candidate Artifact are safe and intact. The backend ignores the invalid profile for color transforms, preserves it only inside the unchanged original, and automatically generates a validated Unmanaged Structural Preview with color accuracy marked unknown. The candidate is excluded from Quick Promote and default Batch Promotion, but Promotion Sheet may explicitly ignore the invalid profile and retain the warning through reviewed Candidate Promotion, or accept a separately validated Source Color Profile and regenerate color-managed derivatives.

A Color Evidence Safety Failure means isolated, resource-limited inspection cannot safely complete because of malformed structure, truncation, parser boundary violation, excessive resource behavior, or another integrity condition that reaches beyond ordinary invalid color metadata. It blocks Candidate Activation or Candidate Promotion according to the stage where it is detected and cannot be overridden by ignoring the ICC profile. Parser crashes or deterministic failures on otherwise valid supported-format fixtures are backend defects, not reasons to silently downgrade evidence.

Color profile extraction, validation, and transformation run outside the renderer under explicit byte, memory, time, dimension, and recursion limits. Neither path deletes, repairs, strips, replaces, or rewrites profile bytes in the original. Reviewed promotion of a Recoverable Invalid Color Profile carries its Invalid Color Profile status, Color Accuracy Warning, and validation provenance into the Design Asset until explicit user assignment or newly discovered Authoritative Color Evidence produces and validates replacement derived previews.
