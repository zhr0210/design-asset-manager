# Offline Library Merge Uses Last Verified Trust And Reconciles Later

ADR 0187 Merge Into Current Library is a local data operation and does not require current network access. When offline, it uses the target application's persisted **Last Verified Model/Runtime Trust State** and the backup's verified result/advisory provenance to classify imported advisory history and target attention. The Merge Dry Run displays trust freshness as current, stale or Not Assessed and reports that signed reconciliation remains pending; lack of network is not an Import Conflict or Blocking Issue by itself.

An already accepted critical revocation or suspension remains enforced offline and cannot be cleared by source backup state, imported acknowledgements, older signed statements, clock change or absence of a newer response. It may block future model/runtime execution under ADRs 0165/0192, but does not block importing committed results or alter their visibility, ranking, search participation or provenance. Source-library trust/acknowledgement history is explanatory and never overrides the target's last verified global execution state.

If the target has Last Verified Trust State, merge uses its exact signed semantic fingerprints and freshness without claiming they are current. If no verified state exists for an imported identity, the state is **Trust Not Assessed**: the application neither invents positive trust nor labels committed results unsafe. It may preserve cryptographically verifiable source statement provenance as Imported Advisory Decision History, but it does not promote that library record into application-global trust authority.

After connectivity returns, ADR 0204 debounces and coalesces one eligible bounded signed catalog metadata refresh per trust root/channel to perform **Post-Merge Trust Reconciliation**. Multiple imported libraries do not create one request per library, asset or result. It retrieves no package/model payload, reads no result content and starts no analysis. Monotonic signature/sequence rules reject rollback. Semantically unchanged freshness, re-signing, mirror or wording updates adjust provenance silently; a materially new statement creates/reopens target-library attention under ADR 0195 while preserving every committed result and may produce one ADR 0199 content-free aggregate notification. A signed recovery may clear active warning/execution suspension according to its trust domain without erasing history and does not produce a success notification.

Reconciliation never downloads/selects a model, installs a runtime/dependency, calls an external provider, changes result ranking or launches whole-library reanalysis. Package remediation remains separately governed by ADRs 0177, 0190 and explicit model rules. Offline state uses bounded retry/backoff and does not poll aggressively; returning online does not grant permission for payload transfer.

Merge transaction success is not coupled to later reconciliation success. A refresh failure leaves the merge committed with visible freshness/pending state and the prior Last Verified Trust State intact. Merge rollback removes only reconciliation work/history created for the rolled-back import and never rolls back a newer global trust statement accepted independently. Full Library Backup records the library's advisory/provenance/reconciliation state but does not replace application-global Last Verified Trust State on another device.

The current project has no merge executor, target trust-freshness projection, Trust Not Assessed import state, Post-Merge Trust Reconciliation queue or monotonic mapping from global statements to library advisories. This ADR changes documentation only: it performs no network/catalog/package/model action, reads/merges no runtime library/results/private data and changes no public IPC/schema/AI Worker API.
