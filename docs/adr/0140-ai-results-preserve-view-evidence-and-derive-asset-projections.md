# AI Results Preserve View Evidence and Derive Asset Projections

AI+ result scope under ADR 0483: computed palette/proportion evidence and generated
prompt reconstructions need attributed storage, correction, search and reuse paths.
Measured values, model observations, creative prompts and user-confirmed values
remain distinct. The two-layer evidence/projection design below remains applicable;
it does not make a generated prompt a recovered original or a color ratio an LLM fact.

AI analysis persists two distinct result layers. View-Level Analysis Evidence records the normalized result produced for one model, model version, Analysis Recipe, Analysis Unit, and Analysis Input View together with source and preview/color generation, coverage state, confidence semantics, and failure evidence. Asset Analysis Projection is a separately versioned, reproducible aggregation used by ordinary search, tags, inspector summaries, and asset-level similarity. Deleting ephemeral model inputs or Analysis Proxy Cache entries never deletes compatible result evidence.

View-Level Analysis Evidence retains only the bounded result needed for product behavior and provenance. It does not retain source-image binaries, base64 request payloads, private paths, authentication material, or unbounded provider transport responses. Tags keep their label, normalized identity, provider confidence when meaningful, unit and view provenance; captions and OCR retain their exact unit/view scope; embeddings retain model, dimensions, normalization contract, and unit/view identity. ADR 0169 Valid Empty Analysis Result retains its capability-specific threshold/abstention and coverage evidence. A structured model failure, missing output or incomplete execution is not replaced by an empty successful result.

Asset Analysis Projection never overwrites or mutates its supporting view evidence. Tag projection merges equivalent normalized labels through an explicit versioned confidence-calibration and aggregation recipe, retaining contributing units and views. A tag found only on one transparent-background view is marked Background-Sensitive rather than silently promoted as consensus or discarded. Material contradictions become Aggregation Disagreement with the disagreeing evidence retained. Provider confidence values from different models are not directly compared unless a declared calibration exists.

Captions and OCR remain unit-scoped. Different pages, artboards, frames, tiles, or alpha-background views are not concatenated into fabricated prose. An optional asset summary may reference or summarize unit results under its own recipe, but the original scoped text remains available and coverage state stays visible. Duplicate OCR observations may be reconciled only through a declared spatial/text matching rule that preserves source units and bounding evidence.

Search embeddings retain view- or unit-level vectors for the Analysis Coverage Plan that produced them and may additionally create one versioned Pooled Asset Embedding for ordinary asset search. Pooling records its input vector identities, coverage, normalization, weighting, and recipe version; Partial Analysis Coverage cannot be presented as a complete representation. Detailed search may return the matching page, artboard, frame, crop, or background view while ordinary search returns the parent asset through the pooled projection.

Changing only an aggregation, calibration, summarization, or pooling recipe rebuilds Asset Analysis Projection from compatible View-Level Analysis Evidence without reopening the original or recalling the model. A source, Analysis Visual Source, color generation, alpha recipe, model, model version, unit coverage, or model-input recipe change creates new or invalidated view evidence as appropriate. Previous projections follow the lifecycle, retention, manual-control, and suppression rules in ADR 0143, while active results always identify their supporting evidence and recipe generation.
