# Reference In Place Groups Declared Companions Without Copying

Reference in Place and In-Place Reference Library adoption support a **Referenced Compound Original** rather than indexing every RAW/sidecar or other capability-declared member as an independent Referenced Asset. The read-only Reference Adoption Scan Plan and ordinary Add Assets reference plan may propose one group only when an active verified format capability declares the primary, exact companion roles, discovery constraints, required/optional state, validation and preview/analysis consequences. Basename, extension, adjacency, directory convention, metadata resemblance, plugin suggestion or a prior grouping never proves membership by itself.

The plan presents one proposed asset with expandable member rows, roles, current locations, required/optional state, individual/total source bytes, capability status and missing-member consequences. Discovered declared companions default included; required members cannot be deselected and their absence/invalidity blocks that proposed asset as a Reference Scan Exception. Optional members may be explicitly excluded before confirmation, while an absent optional member permits admission only with a visible incomplete-companion warning. Every included member and the complete relationship must remain stable and valid through item admission; ADR 0349 governs any later companion as a new explicit attachment decision.

One physical source may have only one admitted role in the current library and one confirmed plan generation. If it would be both a standalone item and a compound member, serve multiple member roles, or join multiple proposed Compound Originals, **Referenced Compound Membership Conflict Review** blocks all affected proposals. The user may assign the source to exactly one shown role/group, keep it standalone and re-evaluate affected groups, or exclude affected proposals; any group losing a required member remains unadmitted. No first-match, filename priority, duplicate suppression or batch default resolves the conflict. Known relationships in other available Registered Libraries are disclosed without becoming a global source lock or granting authority over those libraries; unavailable libraries remain explicitly unchecked.

Admission creates one Design Asset, one Referenced Asset, one Compound Original Identity and one authoritative member-role manifest. Each included member receives a **Referenced Compound Member Relationship** with stable source evidence and current path, but no Original Storage Object Identity or library-owned physical name. The application copies, moves, renames, rewrites or deletes no source member, creates no Compound Original Directory, and writes no control, cache, manifest, metadata or sidecar file beside the user-owned sources. Library Control Directory stores only relationships, identities, metadata and required derived state; Full Library Backup stores those relationships and manifest without the source bytes.

Progressive Reference Indexing commits the complete proposed group as one item only after every included relationship, real format, capability rule and required System Preview validates. The group creates one Asset Grid/search result and one preview/analysis lifecycle. Source Tree and Folder Collection Mapping place it once at the primary member's current location; companion paths remain expandable in Asset Inspector and provenance but never create duplicate cards, Source Scope occurrences, Collection Memberships, AI jobs or independent search results. Moving a companion in external tools may change its displayed relationship but never relocates the card away from the primary source location.

External Open targets the declared primary and complete Original Handoff exposes every included source member with its capability-declared relationship, without copying them into managed storage or substituting previews. System Preview and analysis use the same ADR 0340 coverage rules. A valid material change to any member creates one Source Content Generation after the complete current referenced group revalidates; user-authored organization/metadata remains and prior-generation derived evidence becomes stale. No member receives an independent generation or asset lifecycle.

If the primary or a required member/relationship becomes missing, unsafe, invalid or unsupported, the item enters **Referenced Compound Original Recovery** and retains only identification preview under ADR 0342's group-availability boundary. If only an included optional member becomes unavailable, it becomes a Degraded Compound Original and only capability-proven independent operations continue with warning; complete Original Handoff remains blocked. Recovery explicitly relinks one or more roles or a complete selected member set, revalidates the entire relationship and leaves every selected external file in place. Exact prior sources restore the current generation; different valid sources require Use as Replacement and one new group generation. Managed copy-back, Full Library Backup payload extraction, sibling scanning and primary-only relink are never used for a referenced group.

Remove Referenced Asset from Library may still move only the Design Asset to Asset Trash while leaving every member source untouched. ADR 0345 permits relocation/transfer only through one complete Referenced Compound Source Path Plan and group relationship commit; ADR 0346 permits source deletion only through one complete group delete intent and member receipt set; ADR 0347 permits same-format rewrite only through complete candidate-group validation and one group generation commit; ADR 0349 permits companion attachment only through complete proposed-group validation; ADR 0351 permits ownership conversion only for the complete byte-verified group. Existing single-file Delete Referenced Source File and Rewrite Referenced Source remain ineligible for a member, while ADR 0348 keeps every cross-format output source-separated. No command may silently target only the primary, infer companion actions, flatten the group, split members into assets or treat navigation/Collection gestures as filesystem authority.

The current application has no Referenced Compound Original identity, member relationships, exclusive-membership conflict review, group admission, Source Tree primary projection or group relink. This ADR records target architecture only and selects, scans, groups, reads, previews, analyzes, references, copies, moves, renames, rewrites or deletes no runtime/user file, directory, database, cache or backup and changes no public IPC, database schema or AI Worker API.
