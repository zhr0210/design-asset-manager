# Model Result Advisories Are Centralized And Inspector Contextual

Model Library is the primary management surface for ADR 0193 Model Result Advisories. The affected Model Family/Checkpoint/Artifact Variant shows one generation-level advisory state with source trust root, reason category, affected capabilities/generations, trust freshness, aggregate affected asset/result counts, replacement availability and the explicit Keep Existing Results, Delete Results or Reanalysis Plan entry points. It does not repeat the warning once per model file, dependency or asset.

AI Console shows one aggregate **Model Advisory Summary** alongside capability/runtime readiness: affected model generations and capabilities, whether new execution is suspended, safe remediation readiness and an entry point back to Model Library. It does not become the owner of result deletion/migration or expose result content. Runtime security containment remains distinct from model quality advice even when both appear in the same console.

For an individual selected asset, Asset Inspector shows a lightweight **Result Provenance Advisory** only beside the affected tag/OCR/description/palette/embedding result source or generation details. It explains that the committed result remains active/searchable and links to the model-level advisory. It is not promoted to the asset's primary card state, does not replace content preview or ordinary metadata, and does not imply the asset itself is corrupt.

Asset Grid, collection/candidate cards, ordinary search-result rows and workspace navigation do not display per-item advisory badges or default advisory counts. Default search retrieval, ranking, grouping and result presentation remain unchanged. This preserves image-first scanning under ADR 0022 and prevents one model-generation notice from turning a large library into repeated warning chrome. Accessibility does not rely on color alone wherever an advisory is intentionally shown.

Users may explicitly enable a **Has Model Result Advisory** condition from Advanced Filter/search filters. The condition is off by default, filters by stable affected generation/advisory identity without mutating or de-ranking results and may be explicitly saved under ADR 0184 Saved Search rules. It is not a default System Smart Filter, unresolved Review Signal, navigation badge or mandatory queue. Leaving the filtered view restores ordinary result presentation; filtering is not acknowledgement, deletion or migration consent.

Aggregate counts distinguish affected assets, result values and embedding generations/index coverage without exposing names or content in notifications, logs or public status. Counts may be pending/reconciling and become final only after persistence, following existing confirmed-count principles. Batch actions open a scope preview and reuse ADR 0143/0145 controls; a card, filter or console summary never executes a destructive action directly.

Advisory UI state follows stable model/result-generation identity rather than filenames, display labels or mutable catalog ordering. ADR 0195 Keep Existing Results resolves centralized attention while retaining permanent result-provenance evidence, and reopens attention only for a material signed semantic change. A later signed recovery statement clears active warning state without rewriting committed results or erasing history.

The current renderer has Asset Inspector, filter/Smart Filter, Model Library and AI Console surfaces, but no model-advisory generation state, aggregate summary, provenance marker, advanced-filter condition or affected-count/action bridge. This ADR records target information architecture without reading result/library/model/runtime data, rendering private content, changing search ranking or modifying public IPC/schema/AI Worker APIs.
