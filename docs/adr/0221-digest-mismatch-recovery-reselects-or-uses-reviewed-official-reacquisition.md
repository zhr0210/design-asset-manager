# Digest Mismatch Recovery Reselects Or Uses Reviewed Official Reacquisition

An ADR 0220 Digest Mismatch surface offers only two recovery entries: **Choose Another File** and **Review Official Reacquisition**. Neither is a Continue Anyway action. The first starts another explicit local selection; the second opens an **Official Package Reacquisition Plan** and transfers no payload until the user reviews and confirms it.

Choose Another File invokes the native picker without scanning nearby folders, guessing another filename, reusing operating-system recents as application history or modifying the current file. Cancelling the picker returns to the existing blocked session. Successfully selecting a different item atomically releases the old picker grant/comparison state and creates a new ADR 0217 External Package Inspection Session that repeats every signature, digest, trust, compatibility, time, license and admission check. The mismatching External User-Owned Package is never overwritten, renamed, patched, moved, quarantined or deleted.

Review Official Reacquisition is available only when the verified signed manifest identifies an exact Official Catalog candidate and current signed catalog/trust evidence provides an allowed immutable source for that same publisher, package/version, target, size and complete digest. An arbitrary URL in the selected file, adjacent README, unsigned release page, search result, copied GitHub URL or merely similar catalog entry cannot become a recovery source. Stale/Trust Not Assessed state must satisfy ADR 0206 Fresh Trust Install Admission before payload transfer; a known revocation/suspension, Install Window Ended state, unsupported target or missing exact source disables reacquisition of that candidate and shows only its signed stable-replacement/recovery route when one exists.

The plan shows the exact signed package/publisher/target identity, trust freshness and lifecycle state; official source class and mirror policy; total exact payload bytes, already managed/deduplicated bytes and remaining transfer; temporary staging, final managed and rollback-retention storage impact; current Unmetered/Metered/Roaming/Offline/Unknown Network Cost Evidence; resume/restart limitations; license/account requirements; and the fact that the mismatching external file remains untouched and contributes no managed/deduplicated/reclaimed bytes. Raw source URLs, credentials and external paths stay host-owned.

Opening the plan or refreshing its signed metadata does not authorize package bytes. The explicit **Download And Verify Official Copy** action is bound to the reviewed exact candidate and current source/network/storage consequences. Metered, Roaming and Unknown follow ADR 0177's transaction-scoped exceptions; Offline waits without retry storms. Approved GitHub Release/object-storage mirrors may fail over only under ADR 0189's byte-identical digest/size and host-policy rules. No transfer begins from page open, mismatch detection, network return, window opening, app restart or a timer.

An eligible confirmed transfer writes to a new application-owned governed staging transaction, never to the external source location. It does not repair ranges inside the mismatching file, apply a delta against it, replace its manifest/digest, treat its bytes as resumable progress or delete it after success. Downloaded bytes are completely reverified against the signed manifest before they can become installable. Transfer failure/cancellation cleans or retains only application-owned staged state under existing download policy and leaves the user's file untouched.

Official reacquisition does not reuse the blocked selection's Install intent as authority. After the new bytes verify, ADR 0222 closes the mismatch recovery transaction, commits an immutable Verified Managed Package Copy and opens a new decision review for Install Now, Keep For Later or Delete Managed Download Copy; no model/runtime activates merely because download verification succeeded. Any intervening trust, time, compatibility, license, network or storage change is reassessed. Closing the recovery review before confirmation starts nothing; after explicit transfer confirmation, managed progress may continue through the existing activity controls without retaining the external filename/path.

Before a time-bounded package's `notBefore`, ADR 0215 still forbids managed download/staging/installation. Review Official Reacquisition may show the signed external-acquisition source and an explicit host-validated **Open Official Source** action, but the application does not download bytes or remember the destination; the user acquires them externally and reselects them later. After `validUntil`, or when the exact candidate is revoked, the action cannot reacquire it for installation and may route only to a separately signed stable replacement/recovery candidate.

Reacquisition requests never upload the selected basename/path, Selected File Actual Digest, digest pair, directory/media identity, library/assets/results, clipboard content or diagnostics. The remote source necessarily observes the requested official artifact and ordinary connection metadata; product privacy text does not claim otherwise. No mismatch or reacquisition event becomes telemetry, publisher feedback, an OS notification or a durable external-file history.

The current Runtime Package Source contract reserves remote access as disabled, and the downloader/executor deliberately reject every remote source. The current mismatch flow returns only `CHECKSUM_MISMATCH`; its panel can select another local manifest but has no signed-source resolution, Official Package Reacquisition Plan, Network Cost Evidence, storage review or governed remote transfer. This ADR changes documentation only: it opens no picker/source, refreshes no metadata, downloads/stages/installs/modifies/deletes no package, reads no private state and changes no public IPC/schema/AI Worker API.
