# Library Backup Preserves Authoritative Data And Declares Rebuildable Dependencies

A Full Library Backup is a versioned portable snapshot of authoritative user/library state, not a byte-for-byte copy of every managed root or adopted source tree. It includes the ADR 0196 Portable Library Lineage Identity, active/recoverable Candidate Records with every activated Candidate Artifact still owned by them, Managed Asset originals including every ADR 0340 Compound Original identity/member manifest and owned member payload, their lifecycle/collection/source-profile state, Referenced Asset relationships and provenance without the user-owned source bytes, including ADR 0344 Referenced Compound Original manifests and member relationships, current Trash and recoverable records still owned by the library, user metadata including ADR 0415 Custom Field Definitions and Values—including ADR 0420 archived definitions, retained values and unresolved suggestions that still exist at the snapshot boundary—ADR 0179 Tag Concepts/labels/aliases/relations and confirmation evidence, OCR Source Text and corrections, descriptions, palettes and other durable analysis results, ADR 0183 Canonical Embedding Results, Saved Searches/Smart Filters, suppression/manual-edit provenance, ADR 0195 library-scoped Model Advisory Acknowledgements, ADR 0380 library-owned Portability Object Mappings, ADR 0379 explicitly saved Metadata Import Sessions with only their normalized unresolved records/typed payloads and path-free source identity evidence, and the minimum schema/migration metadata needed to interpret them.

For a Referenced Asset whose source was explicitly moved to operating-system trash, ADR 0297 includes Portable Referenced Source Deletion State so the restored library truthfully preserves the deletion reason, prior relationship, content identity and Asset Trash lifecycle. ADR 0346 likewise includes every portable member state and group recovery/commit relationship in a Referenced Compound Source Trash Receipt Set, whether the group is partially deleted or already in Asset Trash. It excludes every Device Trash Restore Handle, platform trash location and any claim that a backup restored on this or another device can operate the original system trash. Manual source restoration or trusted relink remains available when a local handle is absent.

The default backup also includes persistent Required Preview data that is part of the current availability contract: Primary Asset Overviews, cover/Analysis Unit identity and On-Demand Render Manifests. It excludes evictable Preview Cache content such as opportunistic quick previews and high-detail tiles. This distinction preserves immediate understandable restore state for structured/proprietary sources without backing up every reproducible viewport tile.

The backup excludes ANN Search Indexes, Analysis Proxy Cache, Model Derived Runtime Cache, evictable Preview Cache, ADR 0277 Offline Library Catalogs and their recent-result thumbnails, ADR 0379 Metadata Import Review Cache, ADR 0297 Device Trash Restore Handles and platform trash locations, ADR 0347 Compound Rewritten Old Source Recovery Receipt Sets, incomplete Managed Intake Artifacts and temporary/staged downloads, calibration temporary inputs, logs, crash data and other reproducible derivatives whether they are device-local or explicitly co-located inside Library Control Directory. It also excludes Model Blob Store weights, Runtime/Capability Pack payloads, installed Feature Plugin executables, package-manager staging and ADR 0222 Verified Managed Package Copy payloads/decision state by default. These payload/cache exclusions are listed with estimated omitted/rebuildable bytes before backup rather than hidden behind “cache.” ADR 0363 may explicitly add selected Managed Metadata Writeback Recovery Copies as exact named recovery generations; the archive must account for their bytes and prove every selected payload/member digest, and a backup containing only the current Original Asset may not claim that a different prior recovery point is covered. ADR 0369 may later rediscover those exact preserved generations from the authenticated manifest without modifying the archive or treating its bytes as local recovery storage. ADR 0217 External Package Inspection Sessions, External Package Diagnostic Summary counters and device-local trust-ledger state are operational installation state rather than library content; they are never added to the archive/dependency inventory or presented as omitted library content.

ADR 0458 also excludes active Batch Text Edit Operation Records, member/item
detail, device-local Batch Text Undo Journals and Batch Text Terminal Markers.
A snapshot taken during or after Batch Text execution includes only the
authoritative Custom Field Values committed at its logical boundary plus any
value-free terminal aggregate eligible under ordinary Batch Result History;
restore never resumes, undoes or reconstructs the excluded operation.

A path-free Backup Dependency Inventory records exact model artifact manifests and Active Capability/Embedding Space assignments, runtime/capability/extension package identities and versions, vocabulary/recipe/index schema requirements, trust/catalog sources and whether each dependency is required for viewing, new analysis, query encoding or optional fidelity. It contains no raw download URL, local path, credential, token, gated-source account secret, license acceptance proof transferable to another user/device, extension permission grant or private subprocess detail.

Restoring the inventory does not install or activate software. Model Library and Extension Library resolve current compatible trusted catalog offers, display missing/changed/revoked/unavailable dependencies, license/account/network/storage/permission consequences and require the existing explicit install/enable flows. Exact verified artifacts may be reinstalled when still available; otherwise results retain historical provenance and the UI reports which future operations are unavailable. Credentials, license acknowledgement and extension permissions are re-entered or reapproved according to their own policies.

An ADR 0214 Install Window Ended dependency remains historical inventory rather than a current reinstall offer. Restore shows its exact identity, ended state and stable replacement/recovery route when known, but cannot use backup provenance, cached metadata or an offline package copy to reopen its signed installation window. Committed results retain the original package provenance regardless of replacement availability.

Canonical embeddings remain portable result evidence because their exact model-space contract is included. ADR 0183 rebuilds ANN indexes from them without rerunning asset inference. Semantic text/image query encoding still requires a compatible local model/runtime; until then lexical search remains available and semantic capability reports waiting. No restore process projects vectors into another model space or discards them merely because weights are absent.

Snapshot creation obtains one consistent logical generation. The database uses a supported online snapshot/backup boundary; content files and persistent overviews are enumerated by opaque identity and digest, pinned against mutation/deletion while copied, and verified before the archive is committed. Changes after the boundary belong to the next backup. Cancellation/failure removes only the incomplete destination transaction and releases pins, never mutates the live library. A completed Backup Manifest records format/schema version, app compatibility, created time, object classes/counts, logical/physical bytes, cryptographic digests, dependency inventory and declared exclusions without private source paths.

ADR 0281 Managed Originals Directory is the ordinary-member-file source for library-owned Candidate Artifacts and Managed Asset originals during that enumeration, and ADR 0282 preserves its logical role and safe root-relative binding in the manifest. ADR 0285 keeps its user-visible physical names and storage buckets outside portable object identity; ADR 0341 places a Compound Original's members together but keeps the authoritative manifest in library state. Completeness is proven from the group identity, declared member-role manifest, every included member identity and digest rather than directory adjacency. Under ADR 0342, a snapshot of a recovering or degraded Compound Original records that truthful state and every currently available owned member without claiming the absent payload makes a complete current group. ADR 0343 Superseded Compound Directory Residue is non-authoritative physical cleanup residue rather than a current original or retained version: backup declares its unresolved presence/exclusion but does not copy its bytes or unknown entries. Full Library Backup remains a logical verified snapshot rather than assuming that copying the directory alone also captured the database, grouping metadata, lifecycle state, or Required Preview Storage.

ADR 0284 may use an authenticated Full Library Backup as a source for recovering one missing managed original, and ADR 0342 may resolve one or more exact Compound Original member payloads. Recovery resolves the exact library lineage, portable object/group and member identities and original digests and extracts only the selected payloads through managed copy-back validation. This object-level recovery does not merge or restore the archive's metadata and does not change this ADR's complete archive validation, encryption, identity, or integrity requirements.

ADR 0276 Pre-Migration Recovery Snapshot is a narrower verified local rollback
artifact for a compatible metadata-only schema upgrade, not a substitute for
Full Library Backup or permission to alter originals, ownership, source
relationships, or control-directory layout. Its retention and cleanup stay
owned by the completed/rolled-back migration lifecycle and never enter generic
cache eviction while rollback is still possible.

Portable archive entries use logical relative names and validated regular-file types. Restore preflight rejects path traversal, absolute paths, links/devices, duplicate identities, digest mismatch, unsupported schema or unexplained executable content. It previews required destination space, included/excluded classes, unavailable dependencies and compatibility migration before writes. ADR 0003 dry-run, backup, journal, rollback and explicit confirmation principles apply; ADR 0186 owns portable encryption, and ADR 0187 owns new-library restore, merge conflicts and destructive replacement.

Permanent Asset Delete performed before the snapshot boundary excludes that asset and private results. ADR 0420 Permanent Delete Custom Field performed before the boundary likewise excludes the deleted definition, its values and suggestions. Trash/recoverable state included in backup retains its lifecycle semantics rather than silently becoming active. Backup does not extend expired retention or preserve content already scheduled/committed for hard deletion. A restored archive never phones home or refreshes catalogs until the user/app's normal network policy permits it.

The current project can create settings-migration JSON backups and an SQLite backup before path migration, with journals/rollback for that migration. It has no complete library snapshot manifest, content pin/digest enumeration, authoritative/derived class selection, dependency inventory, portable archive validator or restore preflight. This ADR records target backup contents without creating an archive, reading the runtime database/assets/models/caches or changing public contracts.
