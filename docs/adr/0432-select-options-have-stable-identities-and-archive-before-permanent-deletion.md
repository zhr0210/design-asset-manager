# Select Options Have Stable Identities And Archive Before Permanent Deletion

Single Select and Multi Select values, filters and mappings must survive label cleanup without being reinterpreted as different metadata. Every declared **Custom Field Select Option** is therefore a library-owned child of exactly one Select Custom Field Definition with its own stable identity, display label, presentation order and active/archive lifecycle. Rename and reorder change only presentation; existing Candidate/Design Asset values, AI suggestions and dependency references keep the same option identity.

**Archive Custom Field Select Option** is the ordinary removal action for a used option. The archived option remains portable, backed up and visibly marked inactive on existing values, unresolved suggestions and structured query results. Existing filter criteria continue to match its retained values, but the option cannot be selected for a new manual value, accepted from an AI suggestion, proposed as a new AI value, or used as an executable import-assignment target. Restoring the same option identity re-enables those actions without rewriting retained values or dependencies.

Saved Search, User Smart Filter and Import Mapping Preset criteria/mappings store a **Custom Field Option Dependency Reference** to the exact field and option identities rather than the option label. An archived query reference remains executable against retained values with an inactive marker; an archived assignment reference remains visible but blocked because it would create a new archived value. After permanent deletion, the dependent object keeps a Missing Custom Field Option Reference and cannot execute the affected criterion or mapping until the user removes it or explicitly remaps it to an active compatible option.

**Permanent Delete Custom Field Select Option** is a separate high-risk action whose impact review reports affected Asset Candidate, Design Asset, current-value, unresolved AI-suggestion and dependent-object counts. Confirmation removes the option from current values: a matching Single Select becomes empty, while Multi Select removes only that option and preserves its other members. The same removal applies to unresolved suggestions, deleting a suggestion only when no proposed member remains. It also removes the option definition and search projection, but never deletes the owning field, owner object, unrelated option, analysis provenance or source file.

**Custom Field Option Merge** is the only built-in identity-consolidation action. A reviewed source-to-active-target plan may select two distinct options in the same definition, shows all affected values, suggestions and dependencies, and replaces the source identity per Candidate or Design Asset rather than matching labels. Multi Select deduplicates when the target is already present; unresolved suggestions retain their provenance; compatible option dependencies retarget only because the user confirmed this exact merge. Concurrently changed or invalid items are excluded into visible conflict/failure results. An active source archives only after a terminal result and separate confirmation; an already archived source remains archived, including when merge is chosen to resolve an ADR 0433 restore-label conflict. The application never auto-merges same-label options, uses rename as merge, or silently deletes an unresolved source reference.

ADR 0433 owns active-label uniqueness and restore collisions. ADR 0434 owns large-set option-delete/merge scheduling, partial execution, result retention and risk-specific Undo.

ADR 0475 also includes every Static Custom Field Default referencing an
affected option in archive/delete/merge preflight. Archive or delete requires a
valid replacement, Disable Default or cancellation before writes; only an
explicit reviewed merge may retarget the default to the active target identity.
