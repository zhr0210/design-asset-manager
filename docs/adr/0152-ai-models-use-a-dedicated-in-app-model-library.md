# AI Models Use A Dedicated In-App Model Library

Scope: Target architecture, refined by [ADR 0484](0484-extension-contracts-and-deferred-agent-development-access.md)
and the AI+ core boundary in [ADR 0483](0483-ai-plus-core-product-and-extension-boundaries.md).
The full ecosystem below is not a prerequisite for core product work; selected public
capabilities must satisfy their applicable contracts before third-party execution.
No SDK, catalog or sandbox is delivered merely by this decision.

AI model discovery, catalog/trust metadata refresh, download, ADR 0166 explicit local import, installation, verification, selection, ADR 0170 Local AI Starter Setup Plan, side-by-side update, rollback retention, ADR 0165 trust response and removal use a dedicated Model Library page rather than remaining embedded in the already dense AI Console. AI Console remains the runtime, provider, health, evidence and execution cockpit; Model Library owns model artifact lifecycle. Model weights are not Feature Plugins or Runtime Packages and retain separate storage, acquisition, license, compatibility, activation, trust, update and deletion semantics.

Model Library groups entries by ADR 0162 Model Family, Model Checkpoint and expandable Model Artifact Variants instead of flattening every quantization/backend file. Each checkpoint/variant exposes provider/source, publisher or repository, immutable revision and Model Artifact Manifest identity under ADR 0161, exact artifact class, capabilities, architecture, quantization and runtime target, logical/shared/additional/reclaimable size, license and required acknowledgement, supported platforms/backends/accelerators, required Model Runtime Capability Pack, evidence-based hardware recommendation, RAM/VRAM and disk guidance, model-space identity for embeddings, installed verification state, active capability assignment, and whether a newer artifact exists. External HTTP models remain provider configuration rather than downloadable local entries.

Install is a user-initiated one-click action, with informed confirmation when license, storage, ADR 0177 network cost or ADR 0163 gated access requires it. Model License Acceptance is versioned separately from Model Source Account authorization; public responses expose only opaque account and acceptance state. The Model Artifact Installer downloads only the exact files from a catalog-declared immutable revision and signed manifest into managed partial storage, supports progress, pause/resume where the source permits, cancellation and restart reconciliation, and verifies expected roles, formats, file set, sizes, pinned digests, target runtime compatibility, and model identity before atomic promotion. It rejects unexpected executable files, untrusted pickle/object serialization, mutable snapshots, repository code and `trust_remote_code`. It never prints or returns private model paths, credentials, authorization headers, raw download URLs or path-bearing subprocess commands to renderer logs or public responses.

A model becomes Installed only after artifact verification and a bounded local readiness/compatibility probe that neither reads user assets nor contacts the source repository. The promoted package is immutable; runtime-derived conversions and repaired/optimized configuration use a separately keyed cache. ADR 0164 installs updates side by side and requires a separate Model Activation Preview and user selection. Installation does not automatically select the model, start inference, reanalyze assets, change Active Embedding Space, or authorize external upload. After explicit selection, ADR 0168 may reconcile only existing unfinished intents and future/newly changed assets while automatic local analysis remains enabled; it does not enqueue the completed library. Active Capability Model selection follows ADR 0144; model upgrades and library migration follow ADR 0145. Missing or custom runtime code routes to a declared Extension Capability Requirement and separately consented capability pack under ADR 0160 rather than silently installing repository software.

Uninstall is explicit, reports active capability assignments, dependent migrations/jobs, shared references, derived-cache impact and actually reclaimable bytes, and requires replacement selection or an intentional capability-unavailable state when the artifact variant is active. It removes one manifest/import reference plus only unreferenced/unpinned content-addressed blobs and compatible temporary downloads, while leaving stored results under ADR 0143 until their normal lifecycle ends. It never deletes ADR 0166's original user-selected import source. ADR 0167 model-root offline or disconnect state is not uninstall. Disconnecting a source account is a separate ADR 0163 credential action and does not uninstall verified local artifacts. Removing an embedding variant cannot corrupt or merge vector spaces; its index becomes unavailable or is removed through a separate confirmed index-storage action.

Model Library and Extension Library may share a bounded Download and Install Activity vocabulary, network/power/disk admission, retry, checksum, staging and transaction rollback infrastructure, but not package schemas, catalog trust roots or permission boundaries. ADR 0185 Backup Dependency Inventory may list exact missing model/extension/runtime identities for restore, but inventory resolution never installs or restores credentials/permissions automatically. Model transaction rollback is distinct from ADR 0164's user-facing prior-model assignment window. Official and explicitly trusted third-party model catalogs remain distinct from Extension Catalogs; metadata may refresh automatically, but neither page enables automatic model/extension payload download or update. Core automatic analysis still uses only already-installed verified local models under ADR 0141.
