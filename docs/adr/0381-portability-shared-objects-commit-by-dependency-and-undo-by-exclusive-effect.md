# Portability Shared Objects Commit By Dependency And Undo By Exclusive Effect

After ADR 0380 review, every reusable existing object or explicitly created user object becomes one **Portability Shared Object Commit Unit**. The unit revalidates the exact source identity, target choice, target type/lifecycle and relevant parent/name constraints immediately before one atomic transaction. Creating a new target object and its Portability Object Mapping succeeds together or rolls back together; mapping an existing object writes only the mapping/provenance and never edits that object's labels, names, hierarchy, relations or lifecycle.

Units execute in dependency-safe order without one unbounded global transaction. Required parent Collection Groups and endpoint Tag Concepts/collection objects settle before hierarchy or semantic-relation edges, and dependent asset relationships remain ineligible until every referenced target identity is committed. A failed/stale unit blocks only its dependent objects/relationships. The user may refresh or change its mapping, or explicitly exclude the object and dependent relationships so unrelated scalar metadata and resolved relationships may continue; failure never silently removes a selected relationship from an asset item.

Cancellation stops unstarted shared-object units. A started atomic unit finishes or rolls back before cancellation or ADR 0278 Library Switch reaches its checkpoint. Committed units remain truthful partial success and are not rolled back merely because a later unit or asset item fails. The result separates reused, newly created, mapped, relationship-committed, conflict/stale, failed, excluded and cancelled shared-object outcomes and identifies the dependent asset relationships still awaiting review.

A target-visible naming collision never proves identity or triggers automatic merge, suffixing, renaming or reparenting. When target rules disallow the reviewed name/scope, **Portability Shared Object Naming Conflict** offers Map To Existing Object, Create With User-Confirmed New Name, or Exclude Object And Dependent Relationships, consistent with ADR 0337. The application may suggest an available name but cannot select it automatically. Where the domain permits equal display labels for distinct semantics, separate identities remain separate and the review exposes type, source and hierarchy context rather than manufacturing a name difference.

Undo Metadata Portability Import first reverses eligible asset relationships/effects under ADR 0378, then evaluates shared-object effects in reverse dependency order. A mapping to a pre-existing object may be removed only when it was created by this import and no later saved session, import or committed relationship uses it; the target object itself is never changed or deleted. An import-created object and its mapping may be removed atomically only when every import-created dependent relation is gone, the object remains semantically unchanged, and it has no non-import membership, child/parent relation, alias/edit, other source mapping or other user/library use.

If the user edits or reuses an import-created object, or another operation adopts its mapping, undo preserves the object and mapping and reports an Import Undo Conflict rather than stripping shared organization from newer work. Safe cleanup of another independent created object may still succeed because shared-object undo is unit-scoped rather than all-or-nothing across the import. After the short undo window, object removal or mapping changes use their ordinary explicit tag/collection lifecycle and cannot masquerade as old import undo.

No shared-object unit creates or modifies an Original Asset, Design Asset, Source Tree/folder, System Collection, Built-In Tag catalog definition, Collection Board layout or AI result. The current application has no Portability Shared Object Commit Unit, dependency executor, Naming Conflict review or exclusive-effect undo. This ADR records target architecture only and reads or imports no actual package, maps or creates no runtime tag/collection, and selects, analyzes, stages, writes, rewrites, converts, moves, deletes or changes no runtime/user file, credential, sidecar, directory, database, cache, backup, metadata value, analysis result or source relationship and changes no public IPC, database schema or AI Worker API.
