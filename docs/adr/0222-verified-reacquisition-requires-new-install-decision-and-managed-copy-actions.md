# Verified Reacquisition Requires New Install Decision And Managed Copy Actions

After ADR 0221 Official Package Reacquisition downloads complete bytes and fully verifies their signed manifest, digest and archive boundary, the host commits them as an immutable **Verified Managed Package Copy** in application-owned package storage. This state is **Awaiting Install Decision**: it is neither installed, active, executable, selected for a capability nor permission to continue the blocked external transaction. The prior Digest Mismatch/External Package Inspection Session closes without retaining its basename, path, actual digest or picker grant.

A **Verified Package Decision Review** shows the exact package/publisher/target identity, verified digest and trust freshness, current lifecycle/compatibility, logical and physical storage, deduplicated/shared bytes and currently reclaimable bytes. It offers three explicit actions with no preselected/default action: **Install Now**, **Keep Verified Copy For Later**, and **Delete Managed Download Copy**. Download completion, page opening/closing, application restart, network return, time-window transition or a timer invokes none of them automatically.

Install Now creates a new confirmation bound to this exact managed copy and current plan. Before extraction/promotion, the host rechecks complete-byte integrity, accepted trust/revocation state, current time/window, platform/architecture, dependencies/conflicts, license/account, storage and other admission rules. Exact valid managed bytes avoid redownload, but an old digest check or the earlier mismatch install intent is not reused as current authority. Waiting, newly blocked or changed evidence returns the copy to a typed non-executable review state; it never causes silent fallback, model/runtime selection, activation, migration or reanalysis.

Keep Verified Copy For Later changes the decision state to **Kept Verified Package Copy** only after ADR 0226 Keep Pin Admission succeeds. The app-owned immutable bytes remain non-executable and visibly available for a future install review without promising that the package will remain eligible. The copy is listed in the relevant Model Library, Extension Library or AI Runtime package/storage surface with its actual storage ownership, trust/window/compatibility state and delete action. No raw managed path, former external filename/location or source credential enters public state.

Later install from a kept copy repeats the same current gates. A newer revocation, suspension, Install Window Ended state, incompatible application/platform, changed license or missing dependency disables Install without deleting the bytes or converting them into a working package. A newer signed recovery/replacement may be offered separately but cannot rewrite, activate or silently replace the kept copy. ADR 0223 makes explicit Keep a user-controlled pin outside the seven-day pending-decision expiry and generic automatic package-cache cleanup; storage pressure remains visible but cannot silently release it.

ADR 0225 defines Stop Keeping For Later as an explicit Unpin Kept Package Copy action. It atomically replaces the Keep pin with a new Awaiting Install Decision owner and full seven-day retention episode; it never implies immediate deletion. A user who wants to reclaim the app-owned copy immediately uses Delete Managed Download Copy instead.

Delete Managed Download Copy first shows the copy's logical bytes, shared/deduplicated ownership and currently reclaimable physical bytes. Confirmation removes only this app-owned decision/reference and deletes underlying immutable package bytes only when no installed package, rollback set, active transfer/install, other kept copy or declared owner still references them. It never deletes installed/extracted runtime/model/plugin content, rollback evidence, trust statements, results, user assets or an External User-Owned Package. Shared/pinned bytes report zero or partial reclaimed storage honestly rather than claiming the logical package size.

Delete is an application package-storage operation, not Asset Trash or external-file deletion. It has no filesystem reveal/delete authority outside managed roots and no recoverable library-trash record; reacquisition remains a new reviewed network/offline action if the bytes are later needed. An active transaction must first reach a safe cancel/terminal boundary before its pin can be released. Failure to remove an app-owned byte reports the remaining managed state and never broadens cleanup scope.

ADR 0256 eventually prunes minimal terminal deletion evidence after physical/shared completion, result closure and a later clean startup check. A future acquisition of identical package content still receives a new managed-copy identity and full decision review; safe deduplication against currently owned verified bytes may reduce storage but never restores the deleted identity or consent.

ADR 0241 defines a narrower advanced delete for an ADR 0240 recovery-protected copy whose owner outcome cannot be repaired. It may reuse this managed-byte boundary only after an independent complete owner scan proves no installed, rollback, transaction or other declared owner remains, exact package-name confirmation succeeds and final generation revalidation passes. It never converts ambiguous bytes into a valid Keep/Install source.

ADR 0245 gives a timely host-accepted recovery delete one maximum-five-second transaction to durably remove only that ambiguous managed reference and safety gate. The scan deadline no longer controls the accepted request; physical byte deletion is a separate owner-safe continuation that may complete later or enter Physical Reclaim Pending.

ADR 0242 keeps that action disabled when this or another declared package owner is present. The recovery surface may route to the owner's ordinary Install/Uninstall, rollback, activity or managed-copy review, but it neither invokes an action nor transfers its destructive confirmation; every owner lifecycle retains this ADR's current revalidation and safe-boundary rules.

ADR 0230 may apply this same delete boundary to a user-selected batch of eligible managed-copy references. It never changes per-copy authority: each row is freshly revalidated and item-atomic, shared physical bytes are reclaimed only after the last owner is gone, mixed failures do not expand scope and the irreversible batch has no Trash or Undo.

Closing Verified Package Decision Review without choosing does not infer Keep, Delete or Install. The copy remains **Awaiting Install Decision** and appears in managed download/package activity with its storage use and available actions. ADR 0223 gives that unchosen copy a seven-day Pending Package Decision Retention window and final-day in-app warning while excluding an explicit Kept copy from the same cleanup.

Verified Managed Package Copies and their device-local decision state are operational package-manager data, not library content. They are excluded from Full Library Backup, library export/merge/sync and asset storage counts. Backup Dependency Inventory may still name a required package identity without embedding this payload or Keep decision. Copy identity/state and actions remain path-free and user-content-free in renderer/status surfaces; no payload, former external-file evidence or decision is uploaded as telemetry or publisher feedback.

The current Runtime Package executor has one confirmed flow from validating through checksum verification, extraction, promotion and Runtime Registry commit, then cleans staging. Its shared stages/public preview have no verified-only, Awaiting Install Decision, Kept or managed-copy deletion state, content-addressed package-copy owner accounting or separate post-download install confirmation. This ADR changes documentation only: it downloads/verifies/keeps/deletes/installs nothing, reads no package/private/runtime/model/asset/result state and changes no public IPC/schema/AI Worker API.
