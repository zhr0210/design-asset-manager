# Application Notifications Use Normal OS Priority

ADR 0199 Trust Attention Summary Notifications, ADR 0175 Long-Running AI Operation notifications and ADR 0400 Long-Running Application Operation notifications use ordinary operating-system notification priority. Design Asset Manager does not request or declare emergency, critical-alert, alarm, time-sensitive, priority-bypass or equivalent entitlements/channels for trust, advisory, export, download/installation or analysis outcomes. It never attempts to override Focus, Do Not Disturb, quiet hours, notification summary, lock-screen redaction or platform delivery scheduling.

The application specifies no custom/forced alert sound, vibration pattern, repeated alarm, full-screen interruption, topmost window or attention-stealing bounce for these classes. The operating system and user's per-app settings may apply their normal sound/banner/badge behavior; the app does not claim silence if the OS/user configured sound, and it does not increase urgency based on task type, failure, model, asset count, byte count or vulnerability language. All lock-screen-visible text remains the ADR 0175/0400 minimal content-free projection.

Security enforcement is independent from notification urgency/delivery. Once a verified ADR 0165/0192 critical statement is accepted, the host immediately blocks new affected execution and performs bounded containment even if notification permission is Not Requested/Unavailable, the class switch is Off, the device is in Focus mode, delivery is delayed or no main window is visible. A notification is an informational navigation projection after state persistence, never the trigger, acknowledgement or deadline for containment.

Model Result Advisory notifications likewise use normal priority and never interruptively demand Keep/Delete/Reanalysis. Existing committed results remain active under ADR 0193. Long-running operation completion/partial/failure notifications also remain ordinary; a user-requested operation does not acquire higher OS interruption authority because it is expensive or lengthy.

App Settings does not expose a fake “critical priority,” forced-sound or bypass-DND switch. Users manage sound, banners, badges, lock-screen and priority through supported OS controls reached only by ADR 0202 user-triggered settings navigation. Platform adapters report capability honestly and map all app-created notifications to ordinary channels/categories; unsupported priority metadata is omitted rather than simulated.

The current project has no system notification service/channel/category implementation, so it also has no critical entitlement or custom-sound path. This ADR records the target restriction without requesting entitlements/permission, sending a notification, changing OS settings, reading device/private state or modifying public IPC/schema/AI Worker APIs.
