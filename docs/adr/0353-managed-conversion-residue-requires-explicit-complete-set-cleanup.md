# Managed Conversion Residue Requires Explicit Complete-Set Cleanup

After Convert to Referenced Asset commits, its Managed Ownership Conversion Residue remains library-owned recovery material without a timer or automatic expiry. It is not a current source, backup generation, duplicate Design Asset or rebuildable cache, appears only in the owning asset's provenance/recovery detail and separately accounted Storage Management storage, and is never consumed by preview, analysis, search, Original Handoff or Source Tree. Cache pressure, storage shortfall, retention, scheduling, Library Switch, settings reset, application/plugin removal, ordinary library maintenance and later referenced-source failure never delete it or silently promote it to current managed ownership.

**Clean Up Managed Ownership Conversion Residue** is available only as a separately confirmed Storage Management action after fresh inspection proves that the current Referenced Asset has a complete, healthy and accessible current Original Asset. The action also proves every single-file or Compound Original residue member against its conversion-time identity, bytes, real format, declared role and complete-set manifest. A changed, missing, ambiguous, shared, inaccessible or incompletely attributable current or residue member blocks destructive confirmation for the whole set; remembered path, filename, size, adjacency, visual similarity or digest alone never authorizes cleanup.

Confirmation reports the exact residue set and accounted bytes, journals one intent and requests operating-system trash separately for each proven residue member without deleting a parent directory, permanently unlinking, choosing only the primary or applying an automatic unique name. Every result is recorded immediately. A failed, interrupted or ambiguous member call never retries automatically or counts as absence; partial outcome enters **Managed Conversion Residue Cleanup Recovery**, preserves the current Referenced Asset unchanged and offers only freshly revalidated continue-cleanup or receipt-scoped restoration of the affected complete set.

Successful cleanup removes the exact residue from library-owned residue inventory and creates one **Managed Conversion Residue Cleanup Receipt Set**, but movement into operating-system trash is never reported as physical disk reclamation without separate filesystem evidence. Its portable **Managed Conversion Residue Cleanup State** records the owning Design Asset, conversion generation and proven member outcomes without source bytes, host paths or platform authority and follows normal library state and Full Library Backup. Each successfully trashed member has a separate device-local **Managed Residue Trash Restore Handle** under ADR 0297 rather than a synthetic folder handle. Handles survive restart, cache cleaning, storage pressure, settings reset and ordinary package/plugin maintenance; they retire only after successful complete-set restoration, explicit warning-backed clearing or authoritative proof that the exact trash item is unavailable, and retirement never empties or changes operating-system trash. Forget Library Registration and Uninstall Preparation follow ADR 0299. **Recover Cleaned Managed Conversion Residue** requires the same library plus every currently provable member handle, restores and revalidates the complete set into safe vacant library-managed residue storage, and commits only the non-authoritative residue inventory. It never changes referenced relationships, Asset File Ownership, Source Content Generation, preview/analysis evidence or the current Original Asset; ADR 0354 governs the separate explicit decision to make a restored residue current.

ADR 0366 later applies the same no-permanent-delete and complete-set system-trash principles to Managed Metadata Writeback Recovery Points, but keeps their inventories, cleanup authority, receipts and restore consequences separate from ownership-conversion residue. ADR 0368 may originate an Ownership Conversion Residue Cleanup Sub-Batch from one mixed recovery-storage selection; every residue set still validates, commits, recovers and restores independently under this ADR and borrows no writeback-recovery authority. The current application has no managed conversion residue accounting, complete-set cleanup, portable cleanup state, residue restore handle or residue recovery workflow. This ADR records target architecture only and inspects, reads, validates, restores, moves, trashes, deletes or changes no runtime/user file, directory, database, cache, backup or system-trash item and changes no public IPC, database schema or AI Worker API.
