# Retained Conversion Sources Default To Keep With Explicit Release Or Cleanup

After Convert to Managed Asset, each former referenced member defaults to **Keep And Exclude** as one Retained Ownership Conversion Source. The exact retained bytes remain user-owned, provenance-visible and excluded from automatic same-library readmission, but are not current sources, backup payloads or library-cleanable storage. Application removal, settings reset, cache pressure, storage shortfall, retention, scheduled work, Library Switch, plugin removal and ordinary Storage Management never delete them or release their exclusion.

Exclusion applies only while current evidence still proves the exact retained source identity and bytes. A changed, replaced, unreadable, missing or ambiguous file is never silently treated as the original duplicate and is never eligible for cleanup from remembered evidence; the application surfaces the changed status and permits no destructive action until truth is re-established. Newly changed content may re-enter normal discovery after its own validation rather than being hidden indefinitely by a former-path rule.

**Release Retained Source Exclusion** leaves every file untouched, retires the application's cleanup authority for that retained set and allows later ordinary discovery. Rediscovery creates no automatic asset, merge or relationship: normal admission and Duplicate Signals still apply. Release changes no Design Asset, Asset File Ownership, Source Content Generation, managed bytes, preview or analysis and is not conversion undo.

**Clean Up Retained Conversion Sources** is a separately confirmed complete-set operation. It first revalidates the current Managed Asset and exact current Source Content Generation, then proves every retained single-file or Compound Original member still matches the conversion evidence. Any changed, missing, ambiguous, shared or inaccessible member blocks destructive confirmation for the complete set and offers only Keep And Exclude, Release Retained Source Exclusion or an explicit re-selection that must prove the same exact member; filename, original path, adjacency and digest alone never authorize deletion.

Confirmation journals one cleanup intent and requests operating-system trash separately for every exact retained member without deleting a parent directory, permanently unlinking, selecting only the primary or applying automatic unique naming. Every result is recorded immediately. A failed, interrupted or ambiguous call never retries automatically or counts as absence; partial outcome enters **Retained Conversion Source Cleanup Recovery** with freshly validated continue-cleanup or receipt-scoped restore choices and never changes the current Managed Asset. Complete proven success retires the exclusion and records one device-local **Retained Conversion Source Cleanup Receipt Set** in Local File Recovery. Restoring those former sources returns ordinary user-owned files to safe selected locations without reattaching them or undoing conversion.

The current application has no retained-source exclusion, release action, complete-set cleanup, cleanup recovery or receipt set. This ADR records target architecture only and discovers, reads, validates, restores, moves, trashes, deletes or changes no runtime/user file, directory, database, cache, backup or system-trash item and changes no public IPC, database schema or AI Worker API.
