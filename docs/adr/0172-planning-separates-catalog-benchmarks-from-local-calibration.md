# Planning Separates Catalog Benchmarks From Local Calibration

ADR 0171 profile comparison uses two distinct evidence classes. Catalog Benchmark Evidence supplies reproducible capability-quality and cross-device performance results before installation. Local Calibration Evidence measures the exact installed artifact/runtime on the current machine after verification. Neither is inferred from parameter count, marketing copy, a runtime health check, model-load success or one ordinary inference latency. Existing fixed-tensor Runtime Probes, Model Artifact Readiness probes and real-model path probes retain their narrower meanings and cannot be relabelled as benchmark evidence.

Catalog Benchmark Evidence is signed path-free model-catalog metadata under ADR 0164. Each record binds an immutable artifact manifest, capability, Analysis Recipe and output schema, runtime/backend and version, platform/accelerator class, benchmark suite and version, dataset identity/license/split, evaluation code version, sample count, metric definitions, repetitions/statistics, resource measurement method, publication time and declared limitations. Quality ranking requires representative capability-specific ground truth and reports relevant accuracy, retrieval, OCR or description metrics rather than one universal score. Results from incomparable recipes, datasets, model spaces, runtime matrices or metrics remain separate. Missing, stale or unverifiable records are Not Assessed, not zero and not a hidden penalty.

After an artifact and its dependencies pass verification, ADR 0170 **Install And Enable This Setup** may run a disclosed bounded Local Calibration before planned activation. Calibration uses only a versioned, digest-verified, redistributable Calibration Fixture Pack shipped with or verified by the application. It neither discovers nor reads user assets, Candidate/Design Asset records, downloads, clipboard content, runtime databases or prior analysis inputs, and it performs no network request or upload. The pack contains only the minimum deterministic non-user inputs needed to exercise the declared baseline recipes; its manifest records origin, license, expected dimensions/content class and fixture version.

Local Calibration measures operational behavior: cold and warm startup where applicable, bounded per-unit latency/throughput, peak process and accelerator working memory, fallback/backend used, completed units and measurement variance under the declared ADR 0173 residency and co-residency policy. It does not claim broad model quality from the small fixture pack. Capability quality continues to come from reproducible Catalog Benchmark Evidence. Calibration values are labelled Local Measured, bound to the exact artifact digest, recipe, runtime/backend, relevant driver/OS, accelerator and hardware class, fixture version and execution policy, and shown as ranges with sample count rather than false precision.

Calibration runs at low priority with declared warm-up, repetition, time, memory and temperature/power bounds. It pauses or skips when foreground pressure, low battery, thermal pressure or insufficient headroom makes measurement unsafe or misleading, and the user may skip or cancel it without uninstalling the verified artifact. An ordinary timeout, unavailable telemetry or high variance leaves the affected estimate Not Assessed and does not by itself turn readiness failure into success or failure. Actual out-of-memory, process crash, wrong backend, invalid output or a measured breach of a hard resource gate blocks that planned capability assignment and produces ADR 0170 Partial Local AI Setup; the planner offers a safer variant/profile instead of weakening the gate.

Only exact artifacts selected by the current plan are calibrated; the application does not benchmark every installed or catalog variant. A valid result may be reused locally until an evidence key changes. Artifact digest, recipe/output schema, runtime/backend, relevant driver/OS or accelerator, hardware topology, fixture or measurement protocol changes invalidate it. Ordinary application restart does not. Recalibration after an invalidating change is visible and bounded, and users may manually rerun it. Stored and public summaries contain opaque identities and aggregate numbers only, never model paths, fixture bytes, device serials, private hardware identifiers or user content.

Pre-install planning therefore begins with Catalog Estimate or Derived Estimate evidence. After calibration, the confirmed plan and Model Library can replace comparable operational fields with Local Measured values while preserving the catalog quality record and both provenance chains. Local results stay on-device by default and are never contributed to a shared benchmark service without a separate future opt-in design and consent.

The current code has runtime execution, real model-load/inference and OCR evidence probes plus offline evaluation utilities. Those probes prove readiness rather than statistically comparable performance, while the evaluation dataset builder may download public datasets or use manual local directories and correctly excludes synthetic smoke fixtures from accuracy metrics. There is no signed catalog benchmark schema, redistributable calibration fixture manifest, bounded local calibration protocol, evidence invalidation key or profile-planner integration. This ADR records the target evidence contract without running a probe, reading local evaluation data, downloading a dataset/model or changing public APIs.
