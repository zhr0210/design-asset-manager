# Compound Originals Use One Atomic Managed Directory

Each library-owned Compound Original occupies one dedicated **Compound Original Directory** beneath the current Managed Originals Storage Bucket. The directory is one permanent ADR 0286 bucket allocation position, while an ordinary single-file Original Asset remains one flat file and one position. Its cross-platform-safe name uses the primary member's readable stem plus an identity-derived disambiguator from the Compound Original Identity under the ADR 0287 collision-growth rules; the directory name, physical path and proximity never replace the authoritative group identity or member manifest.

Inside that directory, members retain the exact capability-declared relative names and layout needed to preserve their relationship, such as a RAW primary and XMP companion sharing one basename. Every member keeps its own Original Storage Object Identity and validated bytes, but it does not receive an independent physical suffix, truncation or relocation that would break the declared relationship. The capability must reject absolute paths, traversal, links/devices, duplicate or case/Unicode-equivalent relative paths, unsafe hidden/control names and unbounded nesting. If the declared layout cannot be represented safely and portably, the complete item is blocked before Candidate Activation rather than flattened, archived, renamed independently or admitted without a companion.

The authoritative Compound Original identity, member roles, required/optional state, identities, digests and relative paths remain in Library Control Directory state and Full Library Backup. No application-specific manifest is written beside the user-visible member files, so the directory remains understandable and copyable through Finder/File Explorer after application removal without pretending that filesystem adjacency alone can reconstruct authoritative membership.

Candidate Intake builds the complete directory in attempt-owned staging on the same destination volume, validates every member and relationship, then publishes the directory with one atomic rename only after its final path is freshly proven vacant and safe. A journal coordinates directory publication, bucket allocation, owned-member inventory, group manifest and Candidate Activation as one recoverable item boundary: reconciliation either proves the complete published group or keeps it unactivated/recovering, never advertises a partial directory as a Candidate Artifact. Candidate Promotion changes ownership records without moving or renaming the directory or any member.

ADR 0343 reuses complete-directory staging and atomic publication when recovery must rebuild the group, but permits one vacant-path Compound Member Repair without duplicating a large unchanged directory. A rebuild switches the same Compound Original Identity to its new directory only after complete validation; any former directory remains non-authoritative residue until explicit safe cleanup.

External Open opens the declared primary member in place so a compatible application can discover companions through their preserved relative layout. Show in Finder or Explorer remains separate and selects that primary inside the Compound Original Directory. Ordinary drag and Copy File perform complete Original Handoff by default: every included member is exposed together with its declared names and relative layout. If a destination cannot accept a grouped or multi-file handoff, the application stops and offers an explicit complete-set export route rather than silently sending only the primary. **Primary Member Only** is a separate explicit action that warns which companions are omitted and never changes the stored Compound Original.

Every final member path, the Compound Original Directory component and all required staging, rollback and publication paths obey ADRs 0288 through 0291. Path-overflow handling may shorten only the outer directory's readable primary stem while preserving its complete disambiguator and every capability-required internal name/relationship. If even the minimum safe outer directory plus required member layout cannot fit the portable, Windows or live-volume budgets, only that item is blocked with Managed Original Path Headroom guidance; the application never shortens one companion independently, writes outside the active library or substitutes a preview/export.

The whole directory remains ordinary user-visible library-owned storage after application or plugin removal, but its members retain one group lifecycle under ADR 0340 rather than becoming independently managed assets. ADR 0342 classifies external member changes as a complete new group generation, Degraded Compound Original or Compound Original Recovery and requires full relationship validation before recovery clears. The current application has no Compound Original directory allocator, manifest, group-atomic publication or complete-set handoff. This ADR records target architecture only and creates, stages, reads, opens, copies, renames, moves or deletes no runtime/user file and changes no public IPC, database schema or AI Worker API.
