# Metadata Portability Import Commits And Undo Are Asset-Atomic

After ADRs 0376 and 0377 produce a fully reviewed executable plan, each mapped Design Asset becomes one **Metadata Portability Import Item** containing all selected resolved fields, relationships and compatible durable results for that target. Immediately before commit, the item revalidates target identity, lifecycle/availability, relevant content/result generation and every compared field/relationship version against its plan. Any relevant drift makes the complete item stale and returns it to mapping or value-conflict review; the executor never applies a formerly approved choice to changed evidence or silently drops only the changed field.

One item commits through one atomic library transaction: every selected scalar change, additive relationship, imported durable result, provenance link and resulting active projection/count update either persists together or rolls back together. The import batch is not one global transaction. A committed or Already Present item remains terminal when another item is stale, conflicting, unsupported or failed, so large imports can make bounded progress without leaving any individual asset half-imported or rolling back unrelated success.

Cancellation prevents every not-yet-started item from beginning and marks it Cancelled. An item whose commit has started must reach a durable committed or rolled-back terminal state; it is never interrupted between metadata, relationship, evidence and projection writes. Library Switch checkpoints only at item boundaries under ADR 0278 after the current bounded transaction settles. A fresh retry replans only eligible failed/stale items against current evidence and never repeats successful effects or inherits an obsolete conflict choice.

The **Metadata Portability Import Result** reports persisted Imported, Already Present, Kept Current, Additive, Stale/Conflict, Failed, Excluded and Cancelled item/value counts plus direct actions for review or retry. Global navigation, Smart Filter, search and analysis counts become confirmed only from persisted state under ADR 0104; optimistic progress cannot hide a failed or rolled-back item.

Each materially committed item creates a minimal short-lived **Metadata Import Effect Snapshot** containing only the exact pre-import values/active references and identities of relationships/results created or replaced by that item. It contains no Original Asset bytes, preview images, complete source package, private paths or unrelated metadata. **Undo Metadata Portability Import** applies independently and atomically per successful item, removing only still-import-owned additions and restoring only fields/projections that still equal the exact imported effect. It never restores a whole stale asset snapshot.

If a field was edited, a relationship was removed/re-added or gained another owning reason, an imported result was modified/suppressed, or an active projection changed after import, undo leaves that current state untouched and reports an **Import Undo Conflict** for the affected item. Other unchanged effects on that same item are not partially reversed: the item remains unchanged until the user resolves/retries a fresh complete undo plan. Successful undo of one item does not roll back another item's import. ADR 0381 then evaluates import-created shared objects/mappings in reverse dependency order and preserves anything later edited or reused. After the short undo window or explicit finalization, later changes use ordinary metadata/result editing rather than indefinite import history.

The asset-item operation never writes Original Assets or sidecars, changes Asset File Ownership, creates a missing Design Asset/shared object, runs analysis or uses an imported thumbnail as rollback data. ADR 0379 separately persists unresolved normalized content only after Save Pending Metadata Import, without retaining the source package, path, passphrase or authoritative review media. ADR 0380 may explicitly resolve or create reviewed Tag Concepts/collections in a preceding shared-object phase; the item consumes only those committed target identities.

The current application has no Metadata Portability Import Item executor, Import Result, Import Effect Snapshot or Import Undo Conflict workflow. This ADR records target architecture only and reads or imports no actual package, commits or undoes no runtime item, and selects, analyzes, stages, writes, rewrites, converts, moves, deletes or changes no runtime/user file, credential, sidecar, directory, database, cache, backup, metadata value, analysis result or source relationship and changes no public IPC, database schema or AI Worker API.
