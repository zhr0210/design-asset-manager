# 真实应用与用户路径验收

本流程服务 [AGENTS](../../AGENTS.md) 的完成标准。用户已把必要真实验证纳入实施，
不是先交模拟结果再申请真实测试。纯文档或不涉及运行行为的任务只做相应验证，不调用无关付费服务。

## 1. 验收对象

开始先写一个用户结果：普通启动入口 → 可见操作 → 期望内容/效果 → 适用的保存与重开 → 失败/取消保护。
注明需要验证的客户端、平台、数据与服务；内部分票不能缩小父级用户目标。
入口必须属于实际要交付的构建，不能测试一个演示页面、隐藏route或另一套数据库后宣布产品可用。

## 2. 真实范围与隐私

复用已经明确指定的非隐私真实资料、实际库/副本、现有账号/模型、目标服务和费用范围，不逐次询问。
真实验收允许现有真实AI Worker与适用外部推理，只使用现有模型，不下载、补齐或更新模型权重。普通CI禁用真实Worker/外部推理是该CI的隔离方式，不是正式真实验收的替代；缺模型只阻塞依赖它的项目，不能自动下载或改换模型求通过。
范围确实不明时只确认该事实，不扫描用户硬盘；Agent看到的截图/OCR/内容也是披露。
使用真实库副本做迁移、崩溃、删除与故障实验，先核对备份可读与恢复；不损坏唯一副本。
原库非破坏性验证与副本结果分别标注，不能互相代替。实际数据规模、格式和模型条件如实记录。
账号由用户在正规界面输入；应用内部使用凭据。Agent不提取Cookie/token、完整认证地址或保险库内容。
不得让秘密、保密素材、客户身份、私有路径进入共享截图、报告和Git；使用非敏感别名与局部证据。

## 3. 绑定真实版本，不用测试入口替代实现

核对当前源码、候选、实际启动路径/构建ID、平台依赖、应用profile和所选库。
设置、凭据、App数据库、缓存和草稿确实属于同一目标；特殊测试注入不证明普通profile已经正确。
构建需要的Worker/本地import/原生库必须存在于受测产物，而不只存在于开发目录。
测试期间冻结候选，其他会话只能读或另用副本；变化后重测受影响部分，不借用旧PASS。

## 4. 各层证据有什么用

| 证据 | 能证明 | 不能代替 |
| --- | --- | --- |
| 类型/编译/静态检查 | 指定源码与配置的结构性检查 | 页面可达、部署资源、真实推理和数据保存 |
| 单元/模拟/故障注入 | 边界、错误、取消、并发和恢复分支 | 普通产品里的真实数据/服务成功 |
| 真SDK+受控网络、真实数据库集成 | 协议与事务接线、幂等、内容保护 | 实际厂商许可/服务、正常启动、UI可发现性 |
| Browser Computer Use | 该浏览器界面与它连接的正式Host实际操作 | Windows/macOS原生效果或另一构建 |
| Desktop/原生验证 | 当前OS窗口、文件交接、系统选择/凭据/安装等实际结果 | 所有设备、平台、格式和模型质量 |
| 真实模型/服务 | 指定输入、模型、版本、参数的真实行为与质量观察 | 全模型/全库准确率、未测成本上限和所有资源配置 |

内部测试不禁止；它们用于尽早发现错误。用户功能最终还要通过其需要的真实层级。

## 5. Computer Use 怎么执行

日常共享界面默认先用 Codex 内置浏览器；不可用或不能完成相应路径时记录原因后转实际浏览器/桌面；原生专项直接使用对应桌面。
转端不能清除原端的产品失败或必需覆盖缺口。视觉验收依据[DESIGN](../../DESIGN.md)及其最新批准原型，正式接线复用共享展示组件，视觉与数据链路分别验收。入口从正常启动/菜单进入，以可见控件点击、键入、选择。
每次添加、删除、替换或调整前端组件，及改变UI/UX的样式、布局、状态或后端等待/错误/恢复反馈，都对受影响范围执行视觉与交互检查；实施中可反复预览，最后须对实际交付候选从正式入口复验，不沿用旧截图。删除还要核对剩余布局、焦点去向、导航及替代入口。共享影响按开发规范扩大，不要求每次全应用重复验收。视觉规则来自DESIGN，用户行为来自统一交互正文，具体方法见[分别验收](#视觉与交互分别验收)，范围与结论保存在本任务报告。
可使用实际工具对可见控件的定位与可访问名称；不能靠隐形testId、改route/hash、注入Store/DOM、直接IPC/API或写库跳过用户步骤。
测试准备、运行后的只读数据库核对可以是工程步骤，但必须分列，不算用户操作。
需要通过界面发现的目标，不由内部函数直接打开后再宣布“已找到”。

正常路径之外，按风险覆盖：空/加载/失败、快速重复、旧响应、失效review、未保存离开、取消返回、相关尺寸/主题/焦点。
成功保存要关闭/重开并从界面找回；真实AI检查结果内容而不只看JSON合法；工作集移除后检查原素材仍在。
浏览器可以发起原生动作，但“请求成功”不能证明置顶、拖出、跨屏、接收应用或系统凭据真实有效。
UI当前问题不能靠永久禁用按钮关闭任务；临时止血可以交付，但父级功能继续未完成。
缺陷修复须复现原报告场景，并结合实际运行/源码证据核对根因，再从相同适用入口证明修复效果及相关保护。无法复现、换环境后未出现、只有静态截图或通过隐藏入口绕过失败，都不能标记该问题PASS；明确记录待复现/未执行/工具阻塞，保留原失败。新功能按已确认预期检查，不虚构不存在的旧缺陷。

## 6. 真实AI与异步任务

实际服务、模型、参数、输入范围和账号类型明确；已授权测试连续执行，不静默fallback到另一服务或收费方式。
成功至少经过正式预处理、请求、验证、Host保存和回读；研究用loader、wrapper或临时脚本分别登记，不当普通产品入口。
同时检查用户编辑、确认标签和非目标资产未被覆盖；重跑失败留旧有效结果；未知提交不盲目再发。
资源等待/模型未就绪/失败与有效空结果不同；取消要观察占用何时真正释放，不能用Promise结束替代进程结束。
记录可观测的用量与实际限制。拿不到wire请求数、费用或输出硬cap时说明未知，不填猜测。

## 7. 证据与报告

只留足以核对结论的操作记录、关键截图/连续帧、日志和持久结果；不因拍了很多截图就算验证完成。
精确隐私内容留在允许的本地应用内，共享报告用脱敏状态和范围；不能为了证明测试而泄露秘密。
拖拽、动画、闪烁和时序问题用连续截图或录屏逐帧检查，以时间点/帧号关联；采样不足保留未验证。
UI修复后的证据绑定新候选，旧失败保留，不回写成通过。审查者先按用户任务尝试，再读实现者总结。
问题状态写回[本地开发问题](DEVELOPMENT-PROBLEMS.md)，可复用检查写回[LESSONS](../../LESSONS.md)，详细证据仍留对应报告，不重复建立前后端失败台账。
同会话自审可用但标自审；需要独立复核的高风险内容使用只读新上下文，不能冒称已由另一工程师验证。

最小记录（复用当前任务/交接目录，不额外建平台）：

| 字段 | 内容 |
| --- | --- |
| 用户结果 | 从哪里进入、做完后能得到什么 |
| 版本与范围 | 真实构建/客户端/OS；资料和服务别名；原库或副本 |
| 实际步骤 | 操作 → 预期 → 实际结果 → 证据入口 |
| 保护检查 | 相关取消/失败/重开/用户内容与原件保全 |
| 结论 | 本次真正可用的范围、未完成原因、第一步恢复动作 |

## 8. 完成与停止

结果使用 `PASS / FAIL / NOT_RUN / BLOCKED_UX_ACCEPTANCE` 并写具体范围。
内部模块完成不等于用户功能完成；缺真实账号、工具或目标数据只阻塞其依赖范围，其他实现继续。
必需用户路径失败或未测，父级目标保持未完成；不能用其它测试通过覆盖，也不把结果变成用户自行验收责任。
目标已完成就停止，不自动运行历史队列；真实测试长期许可仍按原数据/服务范围持续，不等于新功能自动启动。

## 设计基准与视觉对照

视觉规则只由[DESIGN](../../DESIGN.md)维护，用户行为按[统一交互正文的场景索引](../design/INTERACTIONS.md#按场景定位)确认。批准的设计目标、源码状态和受测产物分别记录，不把设计文件的更新视为界面已更新。

视觉与正式数据是两条分别成立的证据：同窗口、同合成素材、同主题对照导航、卡片、材质、侧栏、专注、笔记、菜单、明暗与缩窄状态；正式执行另验入库、检索、编辑、错误恢复、保存与重开。合成适配器不证明Host接线，数据成功也不证明原生材质或动画。

原DESIGN的≤1 CSS px目标属于批准原型布局对照，来源见[迁移前原文](../history/design-system-restructure-20261013/DESIGN.before.md)。设计发生变化后建立新候选基准，不以旧零像素对照阻止已批准的Apple强调色或原生布局变化，也不将旧截图转记给新产物。1024/1440网页宽度、原生平台与适用设备分别报告；缺连续帧或真实设备覆盖时明确未验。

## 视觉与交互分别验收

视觉、交互、适用的失败恢复各自成立，再判断本次UI/UX完成。功能可用不证明风格一致，截图好看不证明行为正确，静态扫描/token同步只能补充实际观察。AI不得只凭“整体不错”、图片数量或自评分放行；逐项留下基准、观察、差异及证据。具体设计/动作预期归DESIGN/INTERACTIONS，本节只规定怎样验证，不重复定义第二套颜色、布局或状态机。

### 1. 先固定范围和比对基准

在本任务报告写明新增/删减/调整组件及直接消费者，包含改变的反馈与相邻布局/焦点/导航；列需要的表面、平台、状态与输入方式。以当前有效DESIGN条款、统一交互的具体场景、已批准原型/参考为预期，记录版本/章节及适用范围。组件删除后的布局与路径同样有预期，不能只证明旧DOM消失。

比较时保持可比的窗口/内容尺寸、缩放、主题、内容样本及必要平台设置；CSS px与原生pt分开。前后截图用于识别变化，旧实现不是自动正确基准。设计确有变更先标明新批准范围，再建立新候选基准；禁止把当前实现导出的截图或为通过测试更新的baseline自封为批准设计。不使用一刀切像素容差，也不将素材图片、字体渲染或原生材质的合理差异机械当失败。

缺批准截图仍可按DESIGN明确条款/已有行为核对有依据的范围；缺失或冲突影响结论时列具体待定项，不能凭个人偏好创设风格、时长或性能阈值。已确认条款自主执行，不把日常验收转交用户；真正未决定的设计取舍才需收敛。无法比较的必要项保持未验/阻塞。

### 2. 视觉验证

从实际应用普通入口逐个到达受影响状态，查看真实渲染，再按基准检查下列适用项；记录截图和关键可测差异。截图差分、尺寸/样式读取可辅助定位，但不能替代看图，也不能用修改DOM模拟合格结果。

| 比对方面 | 实际检查 | 不足以放行的证据 |
| --- | --- | --- |
| 颜色、材质、层次 | 主题/强调与中性色、对比、透明度/遮挡、系统材质与网页效果的适用范围 | 仅token文件值正确、Browser截图推定原生Liquid Glass |
| 排版、几何与内容 | 字体/字重/字号、间距/对齐/尺寸、长文换行/省略、真实素材等比与元数据未知态；删除后无空壳或断裂布局 | 仅同一短文案/空白页面，或裁图隐藏溢出 |
| 控件与状态 | 默认/hover/pressed/focus/disabled，以及空/加载/无匹配/失败/恢复；菜单不裁切，焦点可见 | 只检查初始成功页、截图中看不到真正操作位置 |
| 适配与相邻区域 | 适用宽度/主题、共享消费者、页面导航和浮层避让；必要减少透明度/对比/动态效果 | 本页通过代表全部页面，固定宽度替代断点两侧 |

### 3. 交互效果比对

以INTERACTIONS具体场景写“前置状态→可见操作/输入→过程与反馈→结果/焦点→保存或恢复”的预期，逐步实际操作并比对。鼠标/键盘及原生拖放等按影响选择；点击入口不能用隐藏route、IPC、Store或写库替代。

| 场景 | 比对过程和终态 | 必要证据 |
| --- | --- | --- |
| 导航、菜单、选择与编辑 | 触发是否可发现；作用对象/范围、焦点、Esc/取消、重复动作、输入法与文本快捷键；移除控件后可继续任务 | 操作记录与实际状态；适用键盘/焦点证据 |
| 动画、拖动、停靠与重排 | 起点/过程中/终点、曲线/时间的既有要求、覆盖层/抓手交接、输入中断、旧完成回调、减少动态效果；不得只验终点 | 足够连续的录屏/帧及时间点；帧率/采样不足不能声称精确时序/流畅性；原生移动/多屏须实际平台 |
| 保存、等待、失败与恢复 | 反馈符合真实执行；草稿/基准/冲突、未知提交、取消与再操作、关闭重开；删除入口不隐去仍在运行的任务 | 实际失败/取消/恢复及适用保存回读；无重放和用户内容保护 |
| 系统/跨应用动作 | 窗口、文件选择、拖出接收、系统权限与安装按实际客户端验证 | 本机/接收应用实际结果；请求成功或拖动结束不等于系统动作/接收完成 |

### 4. 记录差异、修复与放行

本任务报告为每个受影响场景分别填写视觉、交互及适用失败恢复结果；不把PASS数平均为总通过。观察到违反有效要求记FAIL；未执行记NOT_RUN；必要基准/工具/平台或身份不足记BLOCKED_UX_ACCEPTANCE并说明具体缺口；不适用项写理由，不能借“不适用”隐藏必要覆盖。

| 场景/组件与客户端 | 基准条款/版本 | 视觉比对与证据 | 交互步骤/过程与证据 | 失败恢复/保存 | 差异、状态与下一动作 |
| --- | --- | --- | --- | --- | --- |
| 本批实际范围 | DESIGN/INTERACTIONS/已批准参考的适用条款 | 预期→观察→差异；截图/尺寸等 | 前置→输入→过程→终态/焦点；时间点/帧 | 适用检查及结果 | PASS/FAIL/NOT_RUN/BLOCKED_UX_ACCEPTANCE |

发现缺陷先保留原失败，核对根因与影响，在新候选从同一适用入口复验该问题和相关保护/相邻状态；无法复现场景或证明根因/修复效果，不能关闭原问题。候选变化后重验受影响证据，不能改写旧截图/报告为新版本通过。

受影响的必需视觉、交互和失败恢复均实际执行且符合预期，才宣布本范围UI/UX完成。缺动态证据、原生设备、有效基准或真实执行时，只交付有依据的已验范围并保留缺口，不冻结无关工作。纯文档迁移只验结构/保全/实际消费，不因本节新增而运行无关应用或模型。
