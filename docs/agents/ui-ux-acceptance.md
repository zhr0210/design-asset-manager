# 真实应用与用户路径验收

本流程服务 [AGENTS](../../AGENTS.md) 的完成标准。用户已把必要真实验证纳入实施，
不是先交模拟结果再申请真实测试。纯文档或不涉及运行行为的任务只做相应验证，不调用无关付费服务。

## 1. 验收对象

开始先写一个用户结果：普通启动入口 → 可见操作 → 期望内容/效果 → 适用的保存与重开 → 失败/取消保护。
注明需要验证的客户端、平台、数据与服务；内部分票不能缩小父级用户目标。
入口必须属于实际要交付的构建，不能测试一个演示页面、隐藏route或另一套数据库后宣布产品可用。

## 2. 真实范围与隐私

复用已经明确指定的非隐私真实资料、实际库/副本、现有账号/模型、目标服务和费用范围，不逐次询问。
范围确实不明时只确认该事实，不扫描用户硬盘；Agent看到的截图/OCR/内容也是披露。
使用真实库副本做迁移、崩溃、删除与故障实验，先核对备份可读与恢复；不损坏唯一副本。
原库非破坏性验证与副本结果分别标注，不能互相代替。实际数据规模、格式和模型条件如实记录。
账号由用户在正规界面输入；应用内部使用凭据。Agent不提取Cookie/token、完整认证地址或保险库内容。
不得让秘密、保密素材、客户身份、私有路径进入共享截图、报告和Git；使用非敏感别名与局部证据。

## 3. 绑定真实版本，不用测试入口替代实现

核对当前源码、候选、实际启动路径/构建ID、平台依赖、应用profile和所选库。
设置、凭据、App数据库、缓存和草稿确实属于同一目标；特殊测试注入不证明普通profile已经正确。
构建需要的Worker/本地import/原生库必须存在于受测产物，而不只存在于开发目录。
测试期间冻结候选，其他会话只能读或另用副本；变化后重测受影响部分，不借用旧PASS。

## 4. 各层证据有什么用

| 证据 | 能证明 | 不能代替 |
| --- | --- | --- |
| 类型/编译/静态检查 | 指定源码与配置的结构性检查 | 页面可达、部署资源、真实推理和数据保存 |
| 单元/模拟/故障注入 | 边界、错误、取消、并发和恢复分支 | 普通产品里的真实数据/服务成功 |
| 真SDK+受控网络、真实数据库集成 | 协议与事务接线、幂等、内容保护 | 实际厂商许可/服务、正常启动、UI可发现性 |
| Browser Computer Use | 该浏览器界面与它连接的正式Host实际操作 | Windows/macOS原生效果或另一构建 |
| Desktop/原生验证 | 当前OS窗口、文件交接、系统选择/凭据/安装等实际结果 | 所有设备、平台、格式和模型质量 |
| 真实模型/服务 | 指定输入、模型、版本、参数的真实行为与质量观察 | 全模型/全库准确率、未测成本上限和所有资源配置 |

内部测试不禁止；它们用于尽早发现错误。用户功能最终还要通过其需要的真实层级。

## 5. Computer Use 怎么执行

日常共享界面默认先用 Codex 内置浏览器；不可用或不能完成相应路径时记录原因后转实际浏览器/桌面；原生专项直接使用对应桌面。
转端不能清除原端的产品失败或必需覆盖缺口。视觉验收依据[DESIGN](../../DESIGN.md)及其最新批准原型，正式接线复用共享展示组件，视觉与数据链路分别验收。入口从正常启动/菜单进入，以可见控件点击、键入、选择。
可使用实际工具对可见控件的定位与可访问名称；不能靠隐形testId、改route/hash、注入Store/DOM、直接IPC/API或写库跳过用户步骤。
测试准备、运行后的只读数据库核对可以是工程步骤，但必须分列，不算用户操作。
需要通过界面发现的目标，不由内部函数直接打开后再宣布“已找到”。

正常路径之外，按风险覆盖：空/加载/失败、快速重复、旧响应、失效review、未保存离开、取消返回、相关尺寸/主题/焦点。
成功保存要关闭/重开并从界面找回；真实AI检查结果内容而不只看JSON合法；工作集移除后检查原素材仍在。
浏览器可以发起原生动作，但“请求成功”不能证明置顶、拖出、跨屏、接收应用或系统凭据真实有效。
UI当前问题不能靠永久禁用按钮关闭任务；临时止血可以交付，但父级功能继续未完成。

## 6. 真实AI与异步任务

实际服务、模型、参数、输入范围和账号类型明确；已授权测试连续执行，不静默fallback到另一服务或收费方式。
成功至少经过正式预处理、请求、验证、Host保存和回读；研究用loader、wrapper或临时脚本分别登记，不当普通产品入口。
同时检查用户编辑、确认标签和非目标资产未被覆盖；重跑失败留旧有效结果；未知提交不盲目再发。
资源等待/模型未就绪/失败与有效空结果不同；取消要观察占用何时真正释放，不能用Promise结束替代进程结束。
记录可观测的用量与实际限制。拿不到wire请求数、费用或输出硬cap时说明未知，不填猜测。

## 7. 证据与报告

只留足以核对结论的操作记录、关键截图/连续帧、日志和持久结果；不因拍了很多截图就算验证完成。
精确隐私内容留在允许的本地应用内，共享报告用脱敏状态和范围；不能为了证明测试而泄露秘密。
拖拽、动画、闪烁和时序问题用连续截图或录屏逐帧检查，以时间点/帧号关联；采样不足保留未验证。
UI修复后的证据绑定新候选，旧失败保留，不回写成通过。审查者先按用户任务尝试，再读实现者总结。
同会话自审可用但标自审；需要独立复核的高风险内容使用只读新上下文，不能冒称已由另一工程师验证。

最小记录（复用当前任务/交接目录，不额外建平台）：

| 字段 | 内容 |
| --- | --- |
| 用户结果 | 从哪里进入、做完后能得到什么 |
| 版本与范围 | 真实构建/客户端/OS；资料和服务别名；原库或副本 |
| 实际步骤 | 操作 → 预期 → 实际结果 → 证据入口 |
| 保护检查 | 相关取消/失败/重开/用户内容与原件保全 |
| 结论 | 本次真正可用的范围、未完成原因、第一步恢复动作 |

## 8. 完成与停止

结果使用 `PASS / FAIL / NOT_RUN / BLOCKED_UX_ACCEPTANCE` 并写具体范围。
内部模块完成不等于用户功能完成；缺真实账号、工具或目标数据只阻塞其依赖范围，其他实现继续。
必需用户路径失败或未测，父级目标保持未完成；不能用其它测试通过覆盖，也不把结果变成用户自行验收责任。
目标已完成就停止，不自动运行历史队列；真实测试长期许可仍按原数据/服务范围持续，不等于新功能自动启动。
