## 删除、调整与保留的规则

| 原规则或冲突 | 本轮处理 | 理由与保留边界 |
| --- | --- | --- |
| README及插件讨论稿把AI写成可选增强 | 改为内置AI+核心；缺模型时基础管理可用 | 差异化在理解、检索和复用；不把第三方插件安装作为基础分析前置 |
| 核心分析与四项自动分析混为一谈 | ADR 0141/0169/0170澄清；颜色比例、标签、描述、提示词反推是核心，自动模型队列仍有边界 | 核心可用不等于入库即全量运行；提示词通常按需/已配置批次，高阶分层不进入默认队列 |
| 颜色数值、模型观察、反推提示词缺少统一语义 | ADR 0140/0181和词汇表补测量、生成、用户确认与持久检索边界 | 颜色占比要有计算口径；反推不能宣称恢复原作者提示词；临时草稿不静默入索引 |
| ADR 0009/0010/0106仍要求保留内置浏览器 | 0009/0106更新；0010标记由0483替代并保留原文 | 不恢复已移除的网页模块；本地导入、搜索、独立下载、统一入库保持 |
| ADR 0151–0160把完整插件生态写成首版清单 | 明确目标状态；用少量实用插件验证所需契约 | 完整市场、贡献面、语言和平台矩阵不阻塞核心；实际第三方执行仍要满足隔离与权限 |
| ADR 0154把七个贡献面及全面禁止导出固化为v1 | 七项改为候选参考，允许后续评审宿主控制的派生/导出提案接口 | 没有新增可调用导出能力；不能直接写库、访问任意路径、替换原件或调用私有IPC |
| ADR 0155及0151容易被解读为每项权限重复弹窗 | 单项权利仍分别披露、可选、可撤销，可在一次可信审阅中确认 | 同一批准范围不反复询问；权限扩大仍需新批准 |
| ADR 0153/0159在尚无稳定SDK时承诺固定跨主版本/12个月支持 | 改为首个稳定SDK发布前确认的候选政策 | 独立版本、兼容协商、迁移说明保留；实际已对外作出的承诺不能借此缩短 |
| ADR 0002/0188的首次环境自动安装例外与明确同意冲突 | 统一为一次明确审阅的安装计划 | 无计费网络或展示设置页不构成安装许可；同一计划内已披露依赖不逐步重复确认 |
| ADR 0190/0192可能把安全补丁视作自动下载许可 | 仅在明确接受且仍有效的维护政策内自动更新，否则审阅后执行 | 初始安装不自动启用未来更新；并行版本、验签、安全撤销和回退规则保留 |
| 云端推理、AI开发、插件发布容易共享过宽权限 | 0484与词汇表分为独立能力和授权范围 | AGENTS.md是指导，MCP是候选适配协议；权限由宿主校验，开发不默认授予真实库、安装或发布权限 |
| 云端API/MCP/社区远景可能变为当前必做项 | 预留领域边界、上下文包与适配契约；具体服务暂缓 | 不新增占位端点、公开端口或虚假MCP服务；已有显式确认的外部推理不移除 |
| ADR路由仍把已删除网页服务写成当前、把已接线Capture/Trash写成未接线 | 修正领域摘要，删去重复的陈旧完整快照，转向实施状态与调用方 | 决策状态和交付证据分开，不把合成验证提升为真实用户库或模型质量证据 |
| 文档退休流程强制Git检查点与分批提交 | 可恢复源码快照和差异也可作为恢复点 | 保留替代映射和历史；不为了文档清理提交无关工作 |
| 先全面精修UI或先冻结完整接口 | DESIGN改为核心任务/状态→低保真UX与小接口→实际闭环→细化UI | 现有视觉规范继续适用；设计稿不证明功能已交付 |
