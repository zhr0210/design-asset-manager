## 三、目标框架及必须保留的边界

```text
用户动作 / 未来明确启用的后台策略
  → Main准备范围、服务与输入审阅
  → 持久Job、请求代次与执行认领
  → 资源准入 / 已验证Runtime / 受控输入
  → Provider单次推理与有界重试
  → 完整响应校验、各能力独立判定
  → Host事务：Evidence + 当前选择 + Job结果 + Outbox
  → Inspector、搜索、AI文件夹重新读取

用户覆盖层独立：人工描述 / 确认与拒绝标签 / OCR修订
```

上述是目标流程，现行视觉代码仍以综合结果为主。实施过程中必须保持：

- Managed Library由有效Host连接与独占lease掌握写入权；Eagle和Legacy不能混用该权限。
- Copy不等于Move，Original、Preview、Variant身份和所有权分开。
- AI建议可检索，但不是用户确认事实；反推是创作推演，不是原始prompt。
- 用户修改优先；失败、取消、模型更换不能清空已有有效结果或人工状态。
- 配置服务/保存密钥不等于授权上传；持久任务不延续旧会话权限。
- 沿用批准的共享展示组件，视觉交互与正式数据链分别验收。

## 六、第一轮实施任务安排

目标：用户手动选择素材后，独立标签能够完成推理、持久保存、检索分类、确认拒绝、取消与安全恢复。

| 编号 | 任务交付 | 阻塞依赖 |
| --- | --- | --- |
| 01 | 保持现有综合分析兼容，抽取可替换推理入口 | 无 |
| 02 | 确认后保存独立标签任务，重开可查看 | 01 |
| 03 | 单素材标签推理成功后保存并显示建议 | 02 |
| 04 | 标签建议用于检索/分类，并支持确认与拒绝 | 03 |
| 05 | 有界批次、强制重跑与乱序结果保护 | 03 |
| 06 | 重启后只恢复未完成任务，不重跑已成功项 | 05 |
| 07 | 完成正式链路和获准真实模型验收 | 04、06 |

建议按01→02→03→04→05→06→07处理。04与05同依赖03，顺序处理是执行偏好，不是人为新增阻塞关系。

测试以现有控制器/Host产品操作为主要入口，注入合成Provider/时钟，使用真实临时库验事务，再用正式Electron验Preload/权限/UI。每张任务完成实现、相关回归与审查后推进；真实模型验收另记录目标、输入授权、版本、命令、退出码和质量限制。

第一轮暂不包含自动后台分析、全平台Runtime安装、云自动fallback、FTS/向量引擎、设计助手、旧代码清理或真实用户库迁移。相关目标保留在架构包中。
