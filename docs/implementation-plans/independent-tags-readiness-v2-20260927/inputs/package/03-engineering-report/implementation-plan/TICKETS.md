# 任务拆分草案

7张任务；依赖正确但顺序未签收，不是已发布ready-for-agent队列。

| 编号 | 任务 | 阻塞依赖 | 可独立验收的交付 |
| --- | --- | --- | --- |
| 01 | [保持现有综合分析行为，抽取可替换推理入口](draft-tickets/01-preserve-combined-provider.md) | 无 | 用户继续执行综合分析和反推，结果/错误/重试表现保持兼容；内部形成可注入单次Provider的测试边界。 |
| 02 | [确认后保存独立标签任务，并在重开后查看](draft-tickets/02-persist-reviewed-tag-intent.md) | 01 | 用户可审阅单素材标签操作、明确存储升级后保存任务；暂未具备执行条件时如实等待，关闭重开仍可查看。 |
| 03 | [单素材标签分析成功后形成可读取的持久建议](draft-tickets/03-single-tag-result.md) | 02 | 用户运行单素材标签任务，完整有效结果经Host提交后在原Inspector显示；失败、取消和通知丢失不清空旧结果。 |
| 04 | [标签建议可检索、分类、确认与拒绝](draft-tickets/04-find-review-tag-suggestions.md) | 03 | 新建议立即用于现有搜索与AI文件夹；用户确认/拒绝后所有正式表面一致更新，旧综合证据继续可读。 |
| 05 | [有界批次、强制重跑及乱序结果保护](draft-tickets/05-bounded-batch-and-rerun.md) | 03 | 用户手动选择1–8素材批量标签分析，独立显示成功/失败/等待；重跑新意图不会被旧任务迟到覆盖。 |
| 06 | [重启后只恢复未完成标签任务](draft-tickets/06-resume-unfinished-safely.md) | 05 | 关闭或进程中断后，用户在重新审阅范围与服务条件后继续未完成标签；成功项不重复推理，未知远端状态明确待核对。 |
| 07 | [完成正式链路与获准真实模型验收](draft-tickets/07-accept-independent-tags.md) | 04, 06 | 获得可复核的独立标签功能交付报告，覆盖正式界面、持久数据、恢复和限定真实模型；不足之处准确保留。 |

建议顺序01→02→03→04→05→06→07；04与05没有必要的先后阻塞，按用户要求顺序处理即可，不伪造依赖。07是整轮验收关口，覆盖前面各纵向行为而非再造一层架构。

01是使现有行为保持绿色的内部预重构；02–06均交付可从用户入口观察的完整行为，含必要数据/契约/展示/测试，不按数据库、API、UI水平切票。

待确认：测试边界是否以控制器/Host产品意图为主；粒度是否合适；04/05的独立依赖是否保留，哪些票需要合并/拆分。确认后才可按约定标ready或发布，父规格不自动关闭。
