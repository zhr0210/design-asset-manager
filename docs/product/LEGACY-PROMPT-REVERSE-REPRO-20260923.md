# 旧提示词反推 provider 的隔离复现

2026-09-23。根据用户指出旧反推功能可用的经验，复现仓库保留的
`LlamaOpenAIProvider.runPromptReverse` → `OpenAICompatibleProvider.runPromptReverse`调用路径。
这不是当前正式`visual-ai:*`入口，也不是用户提到的原Ollama/llama 8B模型测试。
当前活动库明确拒绝旧`ai-worker:run-prompt-reverse` IPC，而旧IPC还会写全局数据库；
因此只调用旧provider，不启动旧IPC、不写任何素材库。

本次仍使用用户已授权的1份PSD合成预览与7张图片，模型为此前校验的
Qwen3-VL **2B Q4_K_M＋F16视觉投影**，通过隔离的llama.cpp b11057
本机回环服务推理。原文件只读，测试前后8份SHA-256一致；没有上传图片或保留原图、
OCR原文、模型原文到项目。结束后自行启动的服务已停止。

## 旧默认设置的结果

调用旧中文设计提示，使用最长边1024像素PNG、温度0.6、top-p 0.9，
初次输出上限1536 token，检测到未闭合的JSON时提高到3072 token重试。
为了允许重试完整生成，本次隔离服务设置8192上下文；这不是对旧用户配置的推断。

8/8份返回完整、可独立解析的JSON；均含中文描述、独立的英文提示词和中文标签。
其中P和R4首次达到1536 token，上调上限后得到完整结果。
调用耗时中位数约14.9秒，包含这两次重试。标签数从5到89，中位数64.5；
**接口可用不等于标签质量合格**，大量标签不适合作为默认自动分类直接确认。

这证明即使仍使用当前手边的2B权重，旧反推请求与解析路径也能在本轮8份设计稿上
产出完整结构。因此先前2B新入口频繁失败不能解释成“Qwen模型本身一直不可用”。

## 同尺寸与上下文的边界对照

为减少预览尺寸和上下文差异，只对R1、R4另做一次**非旧默认配置**对照：
旧provider改用1280像素PNG、温度0.2、4096上下文；新入口此前使用1280像素JPEG、
温度0.2、4096上下文。两者仍非完全同图编码、同提示或同一随机样本。

这两份旧provider调用都先达到1536 token，再次调用到4096总token上下文边界；
两次最终输出仍不是完整JSON，也没有标签。旧provider仍返回`success: true`，
因为它能从截断文本提取部分描述与提示词。当前`visual-ai:*`会拒绝截断或不合约结果。
所以旧界面“显示有结果”与新界面“拒绝保存残缺分析”在相同受限运行条件下可以同时发生。

## 结论与限制

- 已复现旧**provider**的真实本地推理和两种结果语义；没有恢复旧IPC或全局数据库写入。
- 旧默认设置在8份授权样本上结构完整，说明新旧接口的任务提示、预览尺寸、输出预算、
  重试和解析策略必须分开比较。现有对照不能把差异归因于模型参数量或推理服务单一因素。
- 旧路径对截断文本也可能报告成功；产品接线时仍需坚持完整性校验和用户修订优先，
  不能把旧成功语义原样迁回活动库。
- 用户原来的8B模型具体tag、量化等级及运行服务尚未核实；本轮没有测试或下载8B。
