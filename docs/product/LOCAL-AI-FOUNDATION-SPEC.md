## Problem Statement

DAM 面向视觉创作者，需要把素材收录、理解、找回并解释、检查修正和安全复用接成稳定的本地用户流程。用户不应为了使用基础 AI 能力理解模型分片、运行包、显存分配器或搜索索引。

当前正式应用已有 Qwen3-VL 2B/4B CPU、OCR、独立标签/描述、一键基础分析、模型下载恢复、持久后台派发、事务与中断核对。需要保留这些可用实现。主要缺口是：GGUF 仍只有目录；每 GPU 可用显存没有正式接线；加载预算主要按整进程 CPU 固定估计；来源检查超过 24 小时会阻止已安装模型使用；共享界面的文字搜索读取全库再匹配排序，另一 Host 搜索字段语义更窄；没有正式的语义文字与以图找路径、canonical vectors、可恢复索引代际和检索分页。

用户希望按设备实际余量选到合适模型，可靠安装并真正分析素材，同时尽量减少内存/显存与重复加载成本；离线也能使用已验证模型；库变大后仍能通过中文文字、画面含义或例图找到素材并理解命中依据。升级、资源不足、取消、崩溃和索引损坏不能伤害原件、人工编辑或已保存结果。

## Solution

从普通 Browser 或 Desktop 入口进入同一明确 profile 与唯一可信 Host。用户在“AI 与模型 → 本地模型与 OCR”看到设备余量、模型组合、来源和真实支持状态，完成推荐、选择、下载安装、验证并使用。Hugging Face 目录覆盖相关 Qwen3-VL 生成模型与量化版本，官方优先、可信且许可明确的社区补充；首轮正式运行 2B/4B/8B Instruct GGUF。其它规模、Thinking、FP8 显示链接及实际支持范围。

一个 Host Resource Governor 协调分析、OCR、检索模型、查询和索引维护。各 Runtime Adapter 兑现实际加载、回收和释放能力。默认平衡，可切换最省资源与响应优先；在同模型、同权重量化的已验证加载方式中，于新工作单元前自动选择 GPU、混合或 CPU 方案，保留执行中的计划与输入/输出标准。

标签、描述与 OCR 可独立执行，一键基础分析组合这三项。复用兼容的准备材料、驻留和缓存，受约束生成后继续严格校验并通过现有 Host 事务保存。已安装且验证有效、未漂移/撤信任的组合继续离线可用，在线来源新鲜度单独显示。

素材工作区提供文字与组合条件、中英文自然语言语义找图和以图找相似素材。语义检索支持中文、英文和中英混合查询，以及查询语言与素材描述/标签语言不同的跨语言找回。Host 以有效元数据/分析证据建立增量、可重建的检索投影，返回稳定分页和命中解释；语义路径使用独立且经过启用与双语验证的本地模型空间。旧搜索在新模型/索引准备期间保持可用；无向量或语义暂不可用时，文字搜索与素材管理继续可用。

交付必须证明普通可见入口、正式执行、正确结果、适用的保存重开以及失败/取消保护，并给出准确启动方式、实际版本、真实资源/延迟/质量证据和剩余限制。

## User Stories

1. 作为视觉创作者，我希望通过普通 Browser 或 Desktop 启动 DAM，以便直接使用正式产品。
2. 作为双客户端用户，我希望同一 profile 的配置、模型、任务和资料库状态一致，以便切换客户端后继续工作。
3. 作为素材管理用户，我希望没有模型时仍能收录、浏览和查找已有资料，以便 AI 配置不阻塞基础工作。
4. 作为模型选择用户，我希望查看相关 Qwen3-VL 规模、Instruct/Thinking 与量化版本的完整目录，以便了解可选范围。
5. 作为模型选择用户，我希望清楚区分官方与社区来源、固定版本和许可，以便作出知情选择。
6. 作为模型选择用户，我希望下载组合包含全部语言分片与匹配视觉投影，以便避免缺配套模型。
7. 作为模型选择用户，我希望看到实际选择组合的下载量，以便规划磁盘和网络成本。
8. 作为设备用户，我希望看到 RAM 和各 GPU 可用资源、来源及采样时间，以便理解当前设备余量。
9. 作为设备用户，我希望未知或过期测量被明确标示，以便不把总显存或旧数据当作可用预算。

## Implementation Decisions

1. 保留唯一可信 Host 和共享 WorkspaceClient；Browser、Desktop 与原生窄窗口的会话、角色、成员、素材输入和本机传输校验继续有效。客户端只提交命名业务动作与不透明授权身份。
2. 在现有 Seams 收敛模型与运行包管理、Host 分析执行、Host Resource Governor、Host 检索四个深 Module。它们通过小而明确的 Interface 对真实消费者提供行为，不建设无消费者通用平台或第二份领域权威。
3. 模型管理复用现有库存、传输与来源信任，扩展 Hugging Face Model Bundle：固定 repository/revision、全语言分片、匹配 mmproj、精度、许可、长度和摘要。辅助校准文件不成为运行权重，组合容量只合计已选择文件。
4. 模型组合身份贯穿库存、资格、计划、尝试与结果，包含 runtime 构建、权重/投影、tokenizer/template/processor、平台/设备布局和语义配置。目录能力、预算适合、健康检查和真实任务资格分别表达。
5. 保留受管 staging、发布意图、完整核验与事务恢复。下载支持精确范围恢复；部分字节不授权执行。新版本与旧版本并存到新版本验证完成，失败不替换旧可用配置。
6. 首轮运行固定受测的 Windows x64 原生 GGUF 组合，支持实际合格的 GPU、混合和 CPU 路径。保留现有 Torch CPU/OCR 消费者。旧禁用入口不整套启用，研究脚本和测试启动方式不成为产品 Runtime。
7. 已安装组合的执行资格与在线来源新鲜度分离。纯检查年龄不撤销本地资格；完整字节/依赖/运行包漂移和已知撤信任仍阻止执行。新安装/更新继续遵守来源、许可、完整性及兼容核对；HF 不冒充 DAM 发布者签名。
8. 设备采样提供 RAM、逐 GPU 的物理总量/空闲量、独立/共享拓扑、来源与时间，未知保持未知。UMA 只记一份物理池，多卡显存不简单相加，不宣称 OS 硬预留。
9. 资源账本区分权重/视觉投影、KV/计算工作区、CPU镜像/映射、页锁定/传输、allocator缓存、准备材料、未分配承诺和未确认释放。估计标来源，与实际观测分开，避免重复计算物理空闲与许可。
10. Torch、ONNX/OCR、原生 GGUF 及检索组合的 Runtime Adapters 拥有实际句柄、allocator 和回收能力。GPU迁移、保温、部分卸载、冷释放按真实支持声明，不能跨进程合并缓存或假设所有后端都支持同一粒度。
11. 执行计划冻结模型、量化、配方、语义限制和工作单元。新单元前可选择同模型/精度的已验证加载方式；活跃及首次执行前取得的驻留受保护。未确认释放继续占账，后端异常/超时不假归零。
12. 前台优先，后台有 aging、有界批次和安全边界让出；普通压力回收闲置并停止相应新准入，关键压力通过有界取消收敛。驻留策略根据资源与重载成本调整，用户能主动释放空闲内容。
13. 明确本地 OOM 且确认未保存结果时，清理该执行实例、重新采样，以同模型/量化的已验证低占用计划最多重试一次；计入原总时限与调用上限，保留原失败。未知提交或云服务不走此自动恢复。
14. Analysis Recipe 绑定输入视图/修订、模型/runtime/template/processor、输出schema与时限/调用上限。支持的 Adapter 使用schema/grammar约束；不支持时沿用已验证普通生成与严格后验校验，不静默放宽schema。
15. 标签、描述、OCR继续有独立逻辑尝试、验证和效果事务。一键基础分析只组合三项，不默认生成反推。物理准备或推理共享必须证实语义兼容，部分有效输出不能冒充整个能力成功。
16. 准备材料、运行时视觉/KV缓存和持久分析结果分层；缓存键绑定内容/视图修订、模型/配方与库权限。缓存有界并参与预算；用户明确重跑保持新尝试。持久结果和canonical vectors不受资源LRU删除。
17. 复用现有claim、sent、效果、current、通知outbox与核对语义。效果与回执同事务；通知重放不重推理；撤权/修订/关库使迟到结果不能成为current。人工描述、OCR修订和标签决策优先。
18. 统一共享UI与Host实际检索字段。保留已有建议范围和来源标识、别名、多词跨字段、描述/OCR、反推的创作推演身份；不将历史无效结果或所有旧AI行直接索引。
19. Hybrid Asset Search Plan结合硬条件、Lexical Retrieval Lane和适用Semantic Retrieval Lane。精确命中保持一等证据；排名用版本化融合，不能把不同量纲分数直接相加。Search Match Explanation有界并保留来源。
20. Host检索返回有界ID/修订、排名、解释、代次与不透明cursor，再按需读取展示。库/会话权限、query/index generation、排序和素材有效性绑定；取消/换库撤销查询，分页不会因后台更新跳项或重复。
21. 词法索引为可重建投影。优先评估现有SQLite内的增量/全文方案，需要时采用嵌入式搜索依赖；中文规范化、分词与排名以真实查询验证，具体引擎不改变检索合同或资料库权威。
22. 索引维护使用独立dirty记录/消费水位和幂等增量批次。现有通知outbox的单一delivered状态不被多个消费者抢用。业务保存、索引提交、读快照可见分开，保证编辑后可查并在返回前排除删除、修订或撤权的旧命中。
23. Canonical Embedding Result是持久证据，ANN Search Index是单空间的可重建加速结构。Active Embedding Space绑定模型/制品、文本与图像输入配方、维度、编码、归一化和距离；同维数不能推定兼容。
24. 检索模型作为独立实际消费者，具有中英文及图文/以图检索资格和清晰许可，经明确启用后准备。模型空间明确语言能力证据，中文、英文、混合查询与跨语言找回分别验证；原查询保留，不以默认LLM翻译冒充双语能力。具体组合依据平台、资源和指定查询质量比较；生成模型描述、目录多语言声明或forward probe不授权正式检索。
25. 查询图与Transient Query Embedding会话内临时使用；外部查询由Trusted Query File Grant取得一文件一会话范围，不收录、不上传、不扫描相邻路径、不持久普通历史。缺兼容语义lane显示Lexical Only或明确partial状态。
26. Embedding Space Migration建立独立目标向量与索引，通过覆盖和检索验证后原子切换，期间保留适用旧空间。清理/重建派生索引不重新推理；重新生成向量属于明确范围的分析/迁移。
27. 必要schema与持久文件变更通过现有Host维护、备份、事务、恢复和版本兼容流程接线；索引是派生状态，原件、人工内容与分析证据仍有明确权威。
28. 分析、检索模型、前台语义查询、后台向量生成和索引合并使用同一资源计划/许可。文字查询不等待模型；前台查询不能驱逐受保护活跃任务，后台向量/索引批次有界可恢复。
29. 高级诊断提供实际执行/组合/阶段的有界测量与错误码；不记录账号秘密、完整环境、原始私人素材或普通查询内容，不增加任意文件/SQL/终端入口。
30. 采用兼容MIT/BSD/Apache等代码/依赖并保留许可归属；固定llama.cpp受测构建是直接候选，Ollama/vLLM/Tantivy的机制按收益采用。ComfyUI/AIMDO/Immich等GPL/AGPL实现按已确认路线独立学习，不复制其受约束源码。promptfoo为可选开发工具，远程judge或embedding不默认启用。
31. 实施在同一目标内连续推进：统一资源与保留路径、HF/GGUF及离线、必要分析优化、增量词法查询、独立语义/以图找，最后完成完整真实验收。内部接口/schema/依赖由工程判断处理，不逐切片等待继续。

## Testing Decisions

1. 优先使用最高的现有产品Seam：正式WorkspaceClient与唯一Host命名业务入口。模块测试从该Interface验证公开状态、实际结果、持久化和失败语义；避免复制内部算法、检查私有Map或为每个内部函数造测试Seam。
2. Browser与Desktop的真实用户验收高于协议集成测试：从可发现入口点击/键入完成普通启动、配置、安装/验证、分析、检索、取消、恢复和重开。直接路由、IPC调用、Store注入或写库只作内部测试。
3. 复用已有模型管理、受管视觉负面测试、基础分析Host/SQLite集成、后台执行、OCR生命周期、共享资源策略及检索工作流测试的行为模式。必要新Adapter合同检查只补公开Interface无法覆盖的真实平台/释放行为。
4. 模型制品测试覆盖完整组合、错误/缺投影、分片或摘要不符、暂停/范围恢复、发布与DB提交中断、用户引用/受管复制归属、更新失败保留旧版和已知撤信任。安装完成、健康与真实资格分别断言。
5. 离线测试在正式应用断网下完成已验证模型加载和真实素材分析，并回读保存结果；在线来源超过24h单独不阻使用。另验证损坏/环境变化/撤信任仍拒绝，显示最后检查及远程新状态未知。
6. 资源测试以新鲜RAM/每GPU观测、加载/推理/迁移/释放阶段和实际实例绑定。覆盖GPU/混合/CPU、保温/冷释放、前后台公平、未知/过期计量、活跃保护、停止未退出和跨框架互相占用；预测不能代替真实释放。
7. OOM、取消、断连和进程异常可在可恢复公开内容副本上注入。断言一次本地恢复的前提、次数、总时限/调用上限与审计；未知结果不自动重发，迟到结果不覆盖人工/current或假释放许可。
8. 真实分析使用已指定非隐私素材、资料库、模型/服务和预算；覆盖标签、描述、OCR有字/无字及一键部分失败。schema结构、内容准确性和产品链路分别证明；完整JSON不替代事实质量，合成响应不替代真实推理。
9. 文字检索测试覆盖名称/文件名、标签与别名、已选建议范围、人工/AI描述、OCR修订、反推来源、中文短词与多词跨字段、硬条件、命中解释及稳定分页。保存新文字后可查；删除/修订/拒绝/撤权后旧投影不能错误返回。
10. 语义和以图找用固定公开查询与可核对相关素材验证中英文能力、相似命中、解释、覆盖、过滤和实际模型空间。语义样本含同概念的中英查询对、中英混合查询，以及查询语言与素材描述/标签不同的跨语言目标；按语言分别核对质量与延迟，不要求两种语言的排名或分数逐项相同。外部查询验证一文件授权、会话撤销、无隐式收录/外发/历史、查询取消及真实资源释放。
11. 索引测试覆盖增量提交/重放水位、读快照可见、损坏/缺失/重建、分页期间更新、新模型空间准备与切换、同维数不同空间拒绝。canonical vectors保留，派生索引恢复无需推理；初次向量生成与重建索引操作可区分。
12. 缓存验证覆盖相同输入的适用复用、内容/视图/模型/配方/权限变化失效、明确重跑、大小限制与压力回收；不会把缓存命中算作新的物理模型执行或把半份结果当成功。
13. 质量/性能对照固定素材、输入视图、模型组合、量化、runtime和配方版本，记录格式失败/重试、无据推测、OCR空文本、检索命中及解释，测排队/准备/冷热加载/推理/提交/索引/查询/取消阶段以及实际RAM/VRAM。
14. Chrome中用户指定的“前端审美网站”标签组作为其它应用压力，保留原页；只取允许的资源计量。规模复制/生成夹具明确标为规模基准，不能当真实大库质量证据，也不承诺尚未实测的改善百分比。
15. 正常退出并重开同一候选、profile与公开库，核对模型/资源策略、人工字段、文件哈希、已保存分析、canonical vectors、索引覆盖/查询和任务审计；重开/通知恢复不增加物理推理、尝试或重复效果。
16. 先跑最小相关行为检查，再按资源、schema/ABI、原生和共享客户端风险扩大；修改的测试执行，必要构建完成。源码/依赖/资源变化使受影响证据失效，旧CPU或其它候选证据不能转记。
17. 首轮真实交付平台为当前Windows x64。浏览器共享UI不替代原生文件交接、窗口/退出、安装和凭据行为；工具或平台未验收项保持未验收。父级完成需准确入口、当前候选及完整用户路径证据，局部模块/构建不能关闭父级。

## Out of Scope

- 重做基础文件、重新设计整个产品、建立第二Host/第二资料库权威或开放任意Browser文件/SQL/终端接口。
- 扩散图像生成、通用执行Agent、默认常驻外部daemon、Docker/Redis/多租户推理或完整插件市场。
- 首轮将32B、MoE、Thinking、FP8等目录候选全部接为正式运行；真实支持状态与链接仍需展示。
- 由资源策略自动换检查点/权重量化、降低输入/输出要求、转云、启用LLM查询翻译或远程评测judge。
- 未声明范围的旧库全量回填、跨库/跨站搜索、所有页/图层/帧的自动向量化或隐藏持久搜索历史。
- 把Hugging Face来源冒充DAM官方签名目录，自动推送/发布软件或开展其它未明确增加的C–F任务。
- 读取/导出Cookie、密码、令牌、私钥、完整秘密配置、进程环境/内存转储，或处理未指定私人资料。
- 擅自终止用户自启动的共享服务、关闭Chrome原页，或在唯一重要原件/库上做破坏性实验。
- 本规格发布直接宣称macOS/Linux、软件签名安装发行、真实大库或新GPU/检索能力已验收。
