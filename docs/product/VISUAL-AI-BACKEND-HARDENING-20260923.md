# 新视觉 AI 后端吸收旧接口经验

2026-09-23。用户要求继续完善新后端，吸收旧接口对比测试中有效的实现。
范围是正式 `visual-ai:*` 控制器与 OpenAI-compatible transport 的内部修复。
未恢复旧 Worker IPC、全局数据库写入，也未改变公共 IPC、输出字段或数据库 schema。

## 根据什么修改

[旧provider复现](LEGACY-PROMPT-REVERSE-REPRO-20260923.md)显示：中文设计提示、
1024预览、1536→3072 token重试配合8192上下文，在当时8份授权样本上得到完整JSON。
旧provider在4096上下文的定向对照中又将截断结果报告为成功，不能复制这一语义。
[新入口参数复测](LOCAL-AI-REAL-DESIGN-RETEST-20260923.md)显示：原提示同时要求OCR、
描述、反推及大量标签，发生输出预算耗尽；分离OCR、缩短输出有改善迹象。
这些实验的模型、提示、上下文等因素并未全部受控，不能将成败归因于单个参数。

## 已接入的代码变化

| 环节 | 现在的行为 |
| --- | --- |
| 预览 | 最长边1024，仍为白底JPEG85，不改变原件。确认页同步显示实际输入范围。 |
| 请求 | 中文设计提示要求中文描述与最多8个简短标签，英文提示词；不再要求视觉模型逐字OCR，`ocrText`要求为空。 |
| 输出预算 | 首次1536 token；只有截断或未闭合JSON时，最多一次3072 token重试，并要求更短输出。 |
| 授权与时限 | 确认页披露自动重试；重复使用同一已确认图片、服务、模型与取消信号。两次请求共享控制器最多120秒时限。 |
| 格式兼容 | 可解析完整JSON、代码块、带说明文字的单对象、文本content数组及choice.text。保留字段、类型与长度校验。 |
| 失败行为 | 截断重试仍失败则不保存；格式错误、HTTP拒绝、限流、重定向不自动重试，不回退至旧服务。 |
| 反馈 | 区分长度、格式、超时、权限、地址/模型、请求容量及限流问题；服务原文不进入界面错误信息。 |
| 存储 | 继续通过持有库租约的现有正式保存链路，保留版本/预览复核、用户描述和专用OCR修订保护；标签仍是建议。 |

没有照搬旧PNG编码、温度0.6、十余个输出字段或残缺字段提取成功逻辑。
不自动提高本地服务上下文，也不调整用户模型配置。更高输出上限不能突破服务实际上下文容量；
仍受容量限制时明确失败。中文及标签数量是请求要求，未增加语言检测门槛；解析器保持现有
最多30标签契约，不能据此声称输出必然遵循中文/8标签或画面事实准确。

现有证据仍使用 `visual-ai-v1` 字段契约；本轮未新增执行策略版本字段，不能仅凭该值区分新旧提示。
历史视觉OCR证据保留；新的视觉请求不负责产出OCR，专用OCR结果及人工修订继续独立优先展示和搜索。

## 验证与限制

- `node scripts/run-ts-test.mjs scripts/visual-ai-transport.test.ts`：7组通过，含完整格式兼容、残缺/多对象拒绝、一次重试、相同图片/模型、HTTP失败不重试、响应大小限制、重试读取取消与已取消请求零发送。
- `npm run test-visual-ai-download-integration`：通过。生成1800×1200图经正式预览路径缩至1024内；首次截断、重试成功只存一份证据。持续截断、无效结构、401/400、重试取消和重试超时均不覆盖已有结果；手工描述、标签确认、库重开和既有下载集成检查通过。
- `node scripts/run-electron-node-test.mjs scripts/asset-ocr-storage.test.ts`：通过。新增视觉空OCR结果后，专用OCR人工修订与手工描述仍保留，修订文字可搜索；原有版本/会话/回收站边界检查通过。
- `npm run typecheck`：通过。

所有本轮执行使用临时合成素材、临时SQLite和本机合成HTTP服务。
没有读取真实素材库、模型缓存或用户原图，没有启动推理服务、下载模型或向外部发送素材。
**真实8份设计稿尚未用本轮实现复测，原Ollama 8B也未实测。**
因此本轮结论是正式代码及隔离故障恢复验证通过，不能宣称真实推理成功率或质量已达标。
