# B工作窗：聚焦轮廓、展开锚点与交互动效修正

## Problem Statement

用户从工作模式打开悬浮工作窗后，点击紧凑窗或展开窗取得焦点，会看到玻璃圆角之外的直角黑框及底部方形轮廓。展开目前固定旧窗口左上角，再夹入屏内：位于屏幕中间时向右下扩大，靠右时主要向左下扩大；收起可能偏离原紧凑位置。内容和按钮立即切换，选择背景立即变色，缺少已确认的原生动效体验。

这些问题使工作窗在桌面参考使用中显得突兀，也削弱了位置稳定性。用户希望保留原生Liquid Glass、正常阴影、固定展开尺寸、现有素材信息结构及Host保存保护，同时修正窗口轮廓、展开方向、前景过渡和选择反馈。

## Solution

统一原生窗口系统外轮廓与玻璃圆角，在取得或失去焦点时均不露出额外直角框。以工作窗展开锚点关联紧凑和展开位置：中间固定中心，中心展开会越过左右可用边界时固定对应紧凑边缘与垂直中心；顶部/底部只做必要屏内调整。未主动移动时收起回原位，主动移动展开窗后收起跟随新位置。

保持紧凑220×240pt和默认展开640×520pt，不随素材数量扩大窗口。采用已批准的分段展开与收起交叉淡化；素材选择仅让中性灰背景以160ms渐显/渐隐，业务选择立即生效。已经可见的内容立即可操作，新输入可以中断旧过渡，输入和草稿不因视觉生命周期丢失。

## User Stories

1. As a 使用工作模式的设计师, I want 从正式工作集入口打开原生Work Window, so that 我能在桌面其他应用旁使用参考素材。
2. As a 使用工作模式的设计师, I want 再次打开同一Work Set时聚焦现有窗口, so that 我不会得到重复窗口或重复内容身份。
3. As a 使用紧凑工作窗的设计师, I want 点击窗口后没有额外直角黑框, so that 聚焦状态不会破坏玻璃外观。
4. As a 使用展开工作窗的设计师, I want 展开状态获得焦点时同样没有直角黑框, so that 两种呈现拥有一致轮廓。
5. As a 使用工作窗的设计师, I want 圆角外的底部方形残留消失, so that 窗口边界与玻璃形状一致。
6. As a 使用工作窗的设计师, I want 切换其他应用并重新点击工作窗时轮廓保持正确, so that 焦点切换不会重新引入异常边缘。
7. As a 使用工作窗的设计师, I want 保留明显的原生Liquid Glass与正常阴影, so that 修复仍符合已批准的系统视觉语言。
8. As a 使用紧凑工作窗的设计师, I want 保持220×240pt的紧凑尺寸, so that 参考窗不会占用过多桌面空间。
9. As a 使用展开工作窗的设计师, I want 保持默认640×520pt并滚动查看更多内容, so that 素材数量不会使窗口无限扩大。
10. As a 在屏幕中间使用工作窗的设计师, I want 展开时固定中心向四周扩展, so that 窗口位置关系自然且稳定。
11. As a 在屏幕右侧使用工作窗的设计师, I want 中心展开会越界时固定紧凑右边缘与垂直中心向内展开, so that 内容向左及上下出现。
12. As a 在屏幕左侧使用工作窗的设计师, I want 对称使用左边缘锚点, so that 左侧窗口也能自然向屏内展开。
13. As a 使用工作窗的设计师, I want 靠边规则根据实际可用空间判断, so that 不需要理解额外的固定距离触发区。
14. As a 在屏幕顶部或底部使用工作窗的设计师, I want 只做必要的屏内调整, so that 内容可达而不会发生多余移动。
15. As a 使用工作窗的设计师, I want 未主动移动时展开再收起回到原紧凑位置, so that 呈现切换本身不造成漂移。
16. As a 使用工作窗的设计师, I want 主动移动展开窗后收起跟随新位置, so that 我的拖动不会被撤销。
17. As a 使用工作窗的设计师, I want 程序为避免越界做的夹取不被当作主动拖动, so that 临时边界修正不会永久改变原位置关系。
18. As a 使用工作窗的设计师, I want 窗口框在展开时平滑改变尺寸, so that 展开过程具有原生响应感。
19. As a 使用工作窗的设计师, I want 顶部按钮和主体按已确认时序分段淡入, so that 前景不会突然整块替换。
20. As a 使用工作窗的设计师, I want 收起时展开前景与紧凑前景交叉淡化, so that 收起过程协调清晰。
21. As a 查看图片和文字的设计师, I want 前景在过渡中不拉伸或动态模糊, so that 内容保持易辨认。
22. As a 使用色板和备注的设计师, I want 它们随展开主体协调出现, so that 窗口呈现形成完整一致的状态。
23. As a 使用工作窗的设计师, I want 已经可见的按钮立即可点击, so that 无需等待约480ms的完整淡入结束。
24. As a 使用工作窗的设计师, I want 已经可见的素材立即可选择和拖动, so that 视觉动画不会阻塞工作。
25. As a 使用工作窗的设计师, I want 尚未显现或仅作退出画面的控件不接收误点, so that 透明内容不会触发意外操作。
26. As a 使用工作窗的设计师, I want 再次收起或拖窗时立即接管旧动画, so that 快速输入不会排队等待。
27. As a 使用工作窗的设计师, I want 中断从当前显示位置和透明度接续, so that 窗口不会跳回旧起点或旧目标。
28. As a 使用工作窗的设计师, I want 旧延后任务及完成回调不能恢复旧呈现, so that 新操作始终拥有最终状态。
29. As a 选择参考素材的设计师, I want 选中背景以160ms渐显, so that 选择反馈轻快而不生硬。
30. As a 选择参考素材的设计师, I want 取消背景以160ms渐隐, so that 退出选择也有一致反馈。
31. As a 查看参考素材的设计师, I want 只有中性灰背景过渡而图片和文字保持清晰, so that 选择不影响素材判断。
32. As a 快速选择素材的设计师, I want 选择状态立即生效且反选从当前视觉状态接续, so that 拖出、菜单范围与显示不会等待或落后。
33. As a 多选素材的设计师, I want 旧选择动画不能复活已取消的选择, so that 多选拖出和交付范围保持正确。
34. As a 编辑备注的设计师, I want 展开、收起和动画中断保留输入与草稿, so that 视觉切换不会丢失工作内容。
35. As a 使用输入法的设计师, I want 未结束的组合输入仍遵循既有保护, so that 呈现切换不绕过输入法和保存语义。
36. As a 添加颜色的设计师, I want 颜色浮层确认与取消仍按既有草稿规则执行, so that 视觉调整不造成未确认颜色提交。
37. As a 使用自动保存的设计师, I want 最终工作窗布局经Host保存并在重开时恢复, so that 我的窗口位置关系与Work Set内容分别保持。
38. As a 遇到保存失败或修订冲突的设计师, I want 保留输入并得到明确恢复反馈, so that 动画成功不会掩盖保存失败。
39. As a 使用工作窗的设计师, I want 取消、撤权或关窗后旧回调不能继续提交, so that 迟到结果不越过当前权限与生命周期。
40. As a 使用停靠工作窗的设计师, I want 既有模糊覆盖、按钮退出恢复与抓手行为保持, so that 新呈现机制不会破坏停靠流程。
41. As a 使用展开工作窗的设计师, I want 展开窗仍不能停靠且拖素材不触发拖窗, so that 不同手势维持清晰职责。
42. As a 需要减少动态效果的用户, I want 取消延后及尺寸/透明度过渡并直接到功能终态, so that 功能可达且没有动画等待区。
43. As a 使用不同系统外观的用户, I want 轮廓和选择背景随外观保持正确, so that 浅色、深色与适用辅助显示条件不重新产生异常。
44. As a 维护工作资料的设计师, I want 本轮修正不修改素材原件或工作集成员身份, so that 界面改进不损害资料安全。
45. As a 验收本轮修正的用户, I want 证据绑定实际新候选、真实key状态和完整外框画面, so that 通过结果对应实际体验。

## Implementation Decisions

- 维持既有原生呈现边界：AppKit负责整个悬浮Work Window，React保留主工作台和独立大预览。原生工作窗、交互控制器及原生适配/窗口控制模块承担必要修正；不另造测试专用产品入口。
- 唯一Local DAM Host保留Library、Work Set、成员、修订、文件交接与提交权威。Work Window Layout仍是设备呈现状态，独立于Work Set内容；Work Window Expansion Anchor关联紧凑与展开的空间参考，用户主动移动会移动该参考。
- 修复窗口系统外轮廓与玻璃圆角的不一致。使用公共API或受支持窗口配置/承载方式；实时诊断私有setter不能直接作为生产修复接口。不以关闭正常阴影、移除玻璃、绘制遮盖线或禁用聚焦来满足验收。
- 保持紧凑220×240pt、默认展开640×520pt，展开受当前屏幕可用尺寸约束；内容超出容量继续滚动，不引入素材数自适应大小。
- 锚点先计算中心展开目标：左右越界则使用对应紧凑边缘及垂直中心，否则固定中心；顶部/底部只做必要夹取。没有主动移动则精确恢复展开前紧凑frame；主动移动展开窗则按新位置保持相应空间关系收起，程序夹取不算主动移动。
- 展开窗框180ms、EaseInEaseOut，紧凑前景协调退出；顶部按钮延后150ms开始并淡入200ms，主体延后180ms开始并淡入300ms。主体包括图片、名称、色板和备注。收起窗框230ms、EaseInEaseOut，展开与紧凑前景在230ms内交叉淡化。
- 原版专属前景曲线没有恢复，前景沿用原生动画组默认，不称精确曲线已复刻。选择背景两方向均160ms、EaseInEaseOut，是DAM明确选择的参数，不称原版恢复值。
- 业务状态与视觉过渡分离：选择立即有效，仅背景透明度过渡；从当前视觉状态接续反选。整个呈现切换保持清晰图片/文字，不拉伸、动态模糊或清空输入和草稿。
- 可见内容即可操作；未显现及仅作为退出画面展示的控件不接误点。再次收起或拖窗立即中断并接管当前显示位置/透明度，旧延后任务、旧完成和旧回执不能覆盖新状态或复活旧选择。
- 减少动态效果时取消延后和尺寸/透明度过渡，直接到功能终态。保留既有停靠覆盖层独立生命周期、展开不可停靠、素材拖动与拖窗分离，以及输入法/颜色草稿/自动保存保护。
- 优先复用现有受限展示快照、原生意图、运动关联及Host布局提交接缝。没有作出必须新增schema或公共API的决定；必要内部调整可自主进行，但不得改变已发布兼容承诺、权限与数据保护语义。
- 保存的是有效终态与用户位置决定，不能让中间动画frame或迟到完成覆盖最终Work Window Layout。保持幂等、取消、撤权和真实进程退出语义。

## Testing Decisions

- 测试接缝沿用用户已确认的最高正式边界：正式B原生入口 → 唯一Host → 实际可见结果 → 保存重开 → 相关失败/取消保护。本次不新增产品测试入口或新的跨模块接缝，无需重新访谈相同边界。
- 好的测试断言用户可见行为及持久结果：位置、呈现、可操作性、目标选择、草稿保留、最后有效布局和原件保护；不复制几何/动画实现来证明自身，也不把私有setter对照当生产修复验收。
- 原生呈现/交互模块通过既有生产AppKit测试和正式窗口操作覆盖；窗口控制/适配/Host通过既有运动回执和真实临时库接缝覆盖保存、撤权、中断及旧回调保护。既有原生激活、生产AppKit输入与动画中断、Host运动完成屏障、布局恢复、编辑/颜色草稿和真实临时库故障测试是可复用先例。
- 正式入口为工作模式中打开或恢复Work Set并点击可发现的控件；工作树B启动命令为 npm run start:work-b。不得用直接IPC、Store注入或写库代替用户点击/键入。运行后只读布局核对可以补充持久证据，但必须与用户操作分列。
- 轮廓验收覆盖紧凑/展开、实际点击取得key、失焦、重新聚焦、拖动及呈现中断。原生isKeyWindow/key appearance状态与画面按时间配对，窗口捕获明确保留framing；辅助功能树的聚焦文字、过滤外框的单窗截图或孤立诊断窗不能替代正式结果。
- 位置验收覆盖屏幕中间、左右可用空间不足、顶部/底部最少夹取、无主动移动往返、主动移动展开窗后收起及保存重开。若设备覆盖不足，明确保留缺口，不声明多屏/Spaces已通过。
- 动效验收用连续帧绑定新候选，检查分段时序、窗框与前景清晰、收起交叉淡化、快速重复及拖窗接管；窗口180ms完成不能被记为主体淡入全部完成。采样不足保留流畅性未验状态，不以静态图或源码常量证明逐帧质量。
- 输入验收覆盖主体开始淡入时选择/点击/素材拖动、尚未显现控件误点拒绝、新输入取消旧计划、单选/多选/快速反选以及菜单和拖动范围立即反映选择。
- 保护验收覆盖有备注/组合输入/颜色草稿时切换和中断、自动保存失败、修订冲突、取消、关闭和Host撤权后的迟到完成；保留旧有效提交和原件。继续使用已指定公开素材及可恢复真实临时库，不访问未指定用户库。
- 回归覆盖紧凑停靠、弹出、覆盖模糊、按钮退出/恢复、抓手接管、展开不可停靠与素材拖动不触发拖窗。独立大预览和菜单交付的既有业务契约不得因呈现机制回归。
- 减少动态效果及适用系统外观检查功能终态、输入可达与正确轮廓；测试更改系统设置时恢复用户原状态。受影响检查从最小相关范围开始，必要构建和修改的测试必须执行；旧候选结果不迁移为新PASS。

## Out of Scope

- 素材数驱动的自适应展开大小；Dropover整应用逐像素复制；原版未知参数的虚构恢复。
- 主工作台、独立大预览重设计；新增菜单、Finder定位、云分享、摇晃或刘海入口。
- 整体原生进程合并、全应用资源预算、Windows对等实现或未取得设备覆盖的多屏/Spaces完成承诺。
- 重写Host、第二套业务数据库、权限扩大、读取其他用户库或修改素材原件。
- 使用私有运行时诊断接口作为产品方案；以禁用正常功能或移除系统材质掩盖问题。
- 本次规格发布不开始产品实施，不推送代码、发布应用或替换普通默认产品入口，不自动执行历史验收队列。
