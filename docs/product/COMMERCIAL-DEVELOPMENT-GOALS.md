# 商业级开发目标与验收

制定于 2026-09-07；2026-09-14按[产品基准](PRODUCT-FOUNDATION.md)及ADR 0483/0484
调整定位与优先级。本文定义目标，不代表
功能已交付，也不沿用旧阶段或 Issue 队列。当前工作记在 TASK.md，实际验证统一见[CURRENT-STATE](../handoff/CURRENT-STATE.md)。工程自主与真实验收遵循[开发指南](../../CONTRIBUTING.md)和[验收流程](../agents/ui-ux-acceptance.md)。

## 产品结果

让视觉创作者在本地可靠地收进素材、凭文字或视觉线索找回、检查来源与
质量，并放心复用。差异化是内置AI+理解、可解释检索与实用插件。内置能力覆盖
配色占比、标签建议、描述、提示词反推及适用OCR；标签/描述/OCR属于基础自动策略，反推默认手动，Embedding显式启用；结果可保存、找回和复用。
无模型时基础管理可用是韧性要求，不把AI降为可选产品附加项。
2026-09-14补充的工作模式是核心：可保存的多素材工作集、多悬浮窗口、图片/受支持
视频参考和安全跨应用交接。先用图片验证一个切片不等于视频目标已完成；具体媒体
支持范围依据解码/预览/交接证据确定。更复杂的剪辑、复合原稿与格式长尾按需求扩展。

商业级意味着用户能长期依赖数据、理解失败、完成任务并获得可维护的版本。
“苹果级”是体验质量参照：内容优先、反馈清楚、操作一致、键盘可达、视觉
克制和可恢复。它不代表 Apple 认证，也不要求为了外观重写技术栈。
保留 Electron/React 及 Windows/macOS 共用产品流程；平台差异进入 Adapter。

设计依据采用 Apple 的 [macOS 设计指南](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos)、
[反馈原则](https://developer.apple.com/design/human-interface-guidelines/feedback) 和
[可访问性指南](https://developer.apple.com/design/human-interface-guidelines/accessibility)。
以下性能数字和产品范围是本项目的初始目标，不是 Apple 的认证标准或现有实测值。
视觉实现继续遵循仓库 [DESIGN.md](../../DESIGN.md)，不另造重复设计系统。

| 动态参考可保留 | 已支持视频可关联多个选定参考帧、时间位置和来源网址；卸载录屏插件不删除媒体/记录 | 录屏插件与基本视频参考能力分开；静帧不冒充源码或完整视频理解 |

| 桌面操作完整 | 核心任务可用键盘完成，焦点可见且可恢复；按钮有可访问名称；错误有可行的恢复动作 | 逐个真实工作流验证，不按组件数量或截图漂亮程度验收 |
| 可安装与维护 | 明确支持平台/版本上的安装、冷启动、升级、诊断与数据保全通过；发行材料和支持说明可用 | 打包脚本不等于发行证据；签名、信任材料和实际平台验证单独跟踪 |

完整版本必须贯通收进、找回、检查、复用与恢复；任何孤立模块、测试或
局部 UI 改进都不得作为完整商业版的交付证明。

## 质量门槛

- 数据：原始字节保全、目标不覆盖、重复确认不重复入库、失锁拒写以及
  事务失败不产生虚假成功均为硬性条件；用生成夹具注入故障验证。
- 状态：首次加载、后台刷新、成功空结果、失败与重试各有清楚反馈；
  旧请求不得覆盖新请求，刷新失败不得伪装成清空成功。
- 交互：核心路径无需鼠标也能完成；打开/关闭检查器或弹层后焦点有明确
  去处。仅颜色不能承担状态意义；支持系统减少动态效果偏好。
- 性能初始目标：固定 16 GB 内存、SSD 参考设备及 10,000 条合成素材下，
  本地检索 p95 不超过 200 ms，普通控件反馈不超过 100 ms，冷启动到可操作
  首屏 p95 不超过 3 s。先记录基线和测试条件，再逐项达标，不通过调整统计
  口径掩盖回退。macOS 与 Windows 分开记录，不能互相代替。
- 可用性：测试任务包括首次入库、跨字段找回、检查/复用和误删恢复。
  邀请经同意的目标用户验证；目标为至少 4/5 人无需指导完成全部核心任务，
  每个失败点有记录和修复复测。此项尚无用户研究证据。
- 发布：没有未解决的数据损坏、权限越界、核心流程阻断问题；其余已知
  问题有可理解的影响说明。构建通过不能替代安装/升级与真实交互验证。

## 开发顺序与当前交付

在可靠素材管理上贯通内置分析与检索/复用，先明确核心UX任务和状态，再验证
小范围真实能力并细化UI；根据实用插件检验版本化契约。高阶工具、完整SDK生态、
新云端开发API/MCP及市场计费不成为当前前置。当前能力缺口和验证以
[实施状态](../agents/implementation-status.md)为入口，不从旧阶段恢复执行队列。

### 历史交付记录（2026-09-09）

以下保留当时的状态与验收范围；“下一批”“正在实施”等描述只指当时，

首项交付“可恢复的 Library 读取体验”已于 2026-09-09 完成源码集成与隔离验收：

- 显式区分加载、空库、筛选无匹配和读取失败，提供重试/清除筛选动作。

  Renderer 验证，不启动会读取真实数据的正式 Electron 入口。

## 开发与验收责任

主 Agent 负责规划、关键设计、实现、调试、自检、文档、审查和集成，
不依赖预设的辅助开发模型或跨应用委托流程。

1. 根据当前请求和证据明确完整用户结果、依赖、允许文件、接口与验收用例。
2. 在已授权范围内完成实现和必要测试，对可解决的失败持续修复。
3. 审查实际差异、直接调用方及验收遗漏，保留无关改动和原有暂存内容。
4. 记录实际执行命令与结果；局部完成不代表商业版本完成，未验证或受阻
   部分明确说明，不自动提交或延续旧任务。

既有代码、文档和验证成果保留。当前目标内必要内部接口/schema、依赖与构建调整自主完成，同步直接调用方和必要恢复验证。
指定真实资料/库/模型测试直接纳入实施；已发布兼容承诺、新隐私范围、不可逆原件影响、额外购买与对外发布保留必要权限判断。
具体流程以[CONTRIBUTING](../../CONTRIBUTING.md)为准；历史“正式接线前逐项批准”不再作为通用门槛。
