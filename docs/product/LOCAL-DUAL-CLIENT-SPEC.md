# DAM 正式本机双客户端规格

日期：2026-10-02。依据用户已确认的 Q1–Q9 双客户端方案。
这是已确认的实施与验收基准；架构获批不代表功能已交付。
当前接线、实测结果与未覆盖范围见[实施证据矩阵](LOCAL-DUAL-CLIENT-IMPLEMENTATION.md)。

## Problem Statement

DAM 当前正式界面通过 Electron 专用桥接访问本机业务，普通浏览器不能完成同样的
文件选择、素材库写入、账号与 AI 操作。Codex 内置浏览器因此无法直接走完整用户
路径；此前远程桌面试验不能稳定满足这一需求，MeshCentral 已被放弃并清理。

用户需要一个能日常使用的正式 Browser Asset Workspace，并让后续开发优先通过
Codex 内置浏览器操作、检查和复测。维护另一套简化页面、使用假保存或复制出第二个
后端，都无法证明桌面产品的正式行为，同时会导致界面、权限和数据状态分裂。

## Solution

Desktop Asset Workspace 与 Browser Asset Workspace 共用同一套正式产品界面和
同一个 Local DAM Host。用户可从桌面版或浏览器版入口启动；浏览器版不依赖先打开
桌面主窗口。本机程序负责文件、数据库、账号、后台任务、已有推理服务和原生窗口，
浏览器负责呈现并发起经过检查的业务操作。

两端使用相同的页面内文件选择器，覆盖本机盘符、目录浏览、路径输入、文件选择和
明确的新建目录动作。已保存修改在两端同步；并发编辑冲突保留草稿并提示复核。
Workspace Recovery Draft 定期暂存本机，刷新、断线或重启后可以提示恢复，和正式
保存分开。关闭界面只解绑客户端；明确“退出 DAM”才审查所有未保存内容并结束 Host。

范围是全部现有正式业务的双端等价，包括已有、符合准入条件的 AI 调用；当前禁用
或尚未交付的模型安装与推理能力不在本轮补齐。没有模型仍可使用基础产品。
浏览器业务验收与原生系统专项验收分别留证、分别给结论。

## User Stories

1. 作为 DAM 用户，我希望在本机浏览器里日常管理素材，以便使用正式产品完成完整工作流。
2. 作为桌面用户，我希望两端拥有相同的界面和操作流程，以便切换客户端时无需重新学习。
3. 作为 DAM 用户，我希望两端使用同一份素材库和后台状态，以便不产生两套数据或重复任务。
4. 作为浏览器用户，我希望通过“DAM 浏览器版”入口启动后台和界面，以便无需先打开桌面主窗口。
5. 作为桌面用户，我希望通过“DAM 桌面版”入口打开正式窗口，以便保留原生工作方式。
6. 作为双端用户，我希望再次启动入口能连接已有 Host，以便避免重复后端争用同一素材库。
7. 作为开发者，我希望测试配置与正式使用配置完全分离，以便验收不会读取或改动真实设置和素材。
8. 作为浏览器用户，我希望关闭标签只关闭当前界面，以便后台任务与账号流程按原有生命周期继续。
9. 作为桌面用户，我希望关闭窗口只关闭当前界面，以便另一端和后台继续工作。
10. 作为 DAM 用户，我希望通过明确的“退出 DAM”审查所有未保存内容并退出，以便安全结束整个程序。
11. 作为正在编辑的用户，我希望取消切库或退出后继续编辑，以便草稿、当前库和任务状态不被提前清除。
12. 作为浏览器用户，我希望后台未启动或不可连接时看到原因和普通启动方式，以便知道如何恢复，而不是得到虚假的成功提示。
13. 作为素材管理者，我希望在页面内逐层浏览本机盘符与文件夹，以便整个文件选择流程都能在浏览器完成。
14. 作为熟悉路径的用户，我希望输入目录路径并获得清楚的错误反馈，以便快速定位现有文件夹。
15. 作为素材管理者，我希望在选择器中明确创建新目录，以便准备新的素材库或已有功能需要的存储位置。
16. 作为素材管理者，我希望按业务支持范围选择一个或多个文件，以便收录素材时保持与桌面相同的规则。
17. 作为用户，我希望取消选择、超时或失效选择不会执行后续操作，以便避免误创建、误导入或使用旧授权。
18. 作为用户，我希望所选目录仍经过素材库、模型位置或 OCR 环境各自的检查，以便浏览目录不被误当作写入或执行权限。
19. 作为素材管理者，我希望创建、打开、关闭和重新打开素材库遵守同一安全协议，以便两端都只有经过检查的活动库能写入。
20. 作为旧库用户，我希望仅打开或查看素材库不会悄悄迁移它，以便保留原有兼容性与迁移选择。
21. 作为素材管理者，我希望两端收录默认复制素材并保留外部来源，以便不会静默移动、改写或删除原件。
22. 作为素材管理者，我希望已有删除、回收站、恢复与恢复检查流程在两端等价，以便浏览器不会绕过原有保护或另走旧删除通道。
23. 作为素材管理者，我希望在两端整理普通文件夹、已有 AI 文件夹、标签及其已有别名和层级，以便组织关系不会因客户端变化而分裂。
24. 作为设计师，我希望已有色板、配色与占比流程在浏览器可用，以便继续从素材提取和复用颜色。
25. 作为寻找素材的用户，我希望词法、结构化及现有获准的增强检索在两端表现一致，以便理解并核对检索命中。
26. 作为浏览素材的用户，我希望列表、专注视图、检查和比较使用同一正式展示，以便浏览器保持批准的视觉与交互。
27. 作为注释用户，我希望笔记、描述、提示词草稿及正式保存遵循原有语义，以便暂存不会冒充提交结果。
28. 作为 OCR 用户，我希望读取、运行、取消和人工修订使用同一权威服务，以便迟到推理不会覆盖已确认修订。
29. 作为下载用户，我希望已有独立下载的选择、披露、进度与取消规则在两端一致，以便浏览器不会增加静默下载或外部素材访问。
30. 作为浏览素材的用户，我希望获得经过授权的预览，以便无需把原件路径或整个硬盘暴露给网页。
31. 作为用户，我希望切库、关库后旧媒体地址和请求失效，以便旧页面不能继续读取先前素材库。
32. 作为工作窗口用户，我希望窗口只能访问当前工作集成员，以便窗口或普通浏览器身份不能冒领其它窗口权限。
33. 作为创作者，我希望在浏览器中编辑已有工作集、参考展示、笔记与颜色，以便浏览器能够完成现有工作模式业务。
34. 作为双端创作者，我希望工作集保存、删除和成员引用保持同一规则，以便移除成员或关闭窗口不会删除素材。
35. 作为创作者，我希望浏览器能够请求 Host 打开和控制真正的桌面工作窗口，以便保留原生置顶等已有能力，并分别核验实际效果。
36. 作为双端用户，我希望一端正式保存后另一端及时刷新，以便看到同一已提交状态。
37. 作为并发编辑者，我希望两端修改同一内容时发现冲突并保留各自草稿，以便不会静默覆盖另一端的编辑。
38. 作为并发编辑者，我希望冲突时能读取最新保存内容并明确复核，以便系统不会自动换基准再次覆盖。
39. 作为正在输入的用户，我希望迟到保存、事件和检查应答不会覆盖更新的输入，以便快速操作和慢网络不会破坏当前编辑。
40. 作为用户，我希望切库和退出审查另一端与工作窗口的未保存状态，以便不会只检查发起操作的页面。
41. 作为浏览器编辑者，我希望草稿定期暂存在本机并显示实际接收状态，以便区分已暂存、未送达与正式保存。
42. 作为浏览器编辑者，我希望刷新、重新进入或重启 Host 后提示恢复已收到的草稿，以便继续尚未正式保存的工作。
43. 作为用户，我希望恢复草稿前核对当前素材、来源和保存基线，以便旧草稿不会自动覆写新内容。
44. 作为用户，我希望选择恢复或放弃草稿，并在正式保存成功后清除对应恢复记录，以便恢复行为由我控制。
45. 作为双端用户，我希望草稿按工作区、编辑者和类型分开，以便描述、笔记、OCR 与工作集草稿不会相互覆盖。
46. 作为用户，我希望断网时尚未发出的输入明确标为未暂存，以便不误以为突然崩溃后一定可以恢复它。
47. 作为用户，我希望重连先读取权威快照再恢复正常操作，以便漏掉事件后仍能校准当前库和任务状态。
48. 作为用户，我希望 Host 重启后旧会话与旧操作凭据失效，以便恢复视图不复活旧写入权限。
49. 作为用户，我希望写入丢失响应时看到提交结果未知并能检查结果，以便系统不会盲目重发导致重复修改。
50. 作为用户，我希望通知失败不会把已经完成的保存改判失败，以便提交结果与界面刷新状态清楚分开。
51. 作为账号用户，我希望两端观察同一 Host 管理的登录与凭据状态，以便不会创建相互竞争的账号生命周期。
52. 作为账号用户，我希望离开页面只解绑观察，而明确取消、改变目标和退出按既有规则收敛，以便迟到回调不会错误提交。
53. 作为账号用户，我希望在厂商页面亲自输入真实认证信息，以便凭据和完整认证地址不会进入验收材料或普通客户端事件。
54. 作为 AI 用户，我希望已有获准的推理、OCR、标签与视觉流程由同一本机服务执行，以便结果提交与权限一致。
55. 作为 AI 用户，我希望按当前动作披露并授权外部调用，以便不会因为浏览器化而静默上传或切换外部 provider。
56. 作为没有模型的用户，我希望基础入库、检索、整理和检查仍可用，以便 AI 环境不阻塞素材工作。
57. 作为 AI 用户，我希望看到同一份能力目录、前置条件和不可用原因，以便不会把禁用模型功能误认为已经可以执行。
58. 作为用户，我希望现有文字复制功能在两端可用且失败有反馈，以便不会把权限拒绝误显示为复制成功。
59. 作为用户，我希望当前有正式调用方且准入允许的系统动作由 Host 检查并执行，以便浏览器可发起已有操作，而未接线或禁用动作明确不可用。
60. 作为工作模式用户，我希望原生窗口布局只来自真实窗口状态，以便网页面板坐标不被保存为系统几何。
61. 作为本机用户，我希望浏览器入口仅供这台电脑使用且无需另建登录账号或信任测试 CA，以便简洁启动并保持本机权限边界。
62. 作为本机用户，我希望其它网站、未知客户端和越权角色不能调用 DAM 业务，以便本地接口不会成为通用文件或进程控制服务。
63. 作为 Codex 验收执行者，我希望文件选择、写入、暂存和预览都强制限定合成 profile，以便即使输入真实路径也不会越界。
64. 作为开发者，我希望全部正式方法、事件和不可用能力都有双端验收条目，以便不会只交付一个可运行演示。
65. 作为 Codex 验收执行者，我希望从普通入口通过可见控件完成用户路径，以便证明实际交互而不是后台注入状态。
66. 作为验收负责人，我希望 Browser、Desktop/原生和后台测试分别留证并给结论，以便一端通过不会掩盖另一端失败或未覆盖。
67. 作为用户，我希望界面在相关尺寸、缩放、主题和长内容下可用，以便共享代码仍能保持实际视觉与操作质量。
68. 作为用户，我希望退出先冻结新操作、排空任务并释放素材库锁，以便程序不会半退出或遗留未知写入。
69. 作为连接库入口用户，我希望已有资格检查、索引和同步反馈在两端一致，以便不改变第三方原件所有权或误宣称真实连接库已验收。
70. 作为模型 Workspace 用户，我希望查看现有摘要、存储位置和诊断，以便了解实际状态，而不会把下载或页面展示误当作验证激活。
71. 作为设置用户，我希望两端读取和修改同一份获准配置并处理冲突，以便路径、AI 和诊断设置不随客户端分裂。
72. 作为验收负责人，我希望从界面核对构建与环境标识，以便记录对应实际被测产品，而不是引用旧版本或不明实例。
73. 作为单素材参考用户，我希望原生单素材卡片兼容入口及其已有动作仍可访问，以便双客户端和工作集接线不会移除现有工作方式。
74. 作为图片工具用户，我希望已有工具的效果审查和派生结果保存保持原有规则，以便预览不会冒充正式保存或覆盖原件。
75. 作为旧素材入口用户，我希望已有只读找回流程和准入反馈在两端一致，以便浏览器不会把旧数据访问扩大为迁移或写入权限。
76. 作为收录恢复用户，我希望从两端查看和处理已有恢复记录，以便失败收录重试或重新选择来源仍经过同一安全检查。

## Implementation Decisions

- **一个 Host、一套正式 UI。** 首轮由 Electron 承载 Local DAM Host，复用原生依赖、
  系统凭据保护与执行服务。桌面使用 IPC，浏览器使用仅回环的 HTTP 和事件通道。
  不启动两套领域服务，不让浏览器直接拥有 SQLite、文件写入或 GPU/进程执行权。
- **普通启动与 profile。** 桌面版与浏览器版入口启动或发现同一 profile 的 Host；
  浏览器入口启动本机程序后打开客户端。仅访问已退出 Host 的 HTTP 地址不能启动
  本地进程，界面应提供正确的启动说明。每 profile 单实例，启动失败不冒连其它 profile。
- **完全隔离开发状态。** 合成 profile 显式注入设置、应用存储、身份、凭据适配、
  素材根、缓存、日志及证据归属；普通 userData 路径不能单独作为隔离依据。
  开发文件访问与目录创建必须拒绝越界、链接逃逸和真实用户配置回退。
- **Host Command Facade。** 两种 transport 进入唯一命令编排、切库队列与退出准入。
  复用现有领域 Controller 和 LibraryQuiescence/ShutdownCoordinator，所有 Capture、
  Trash、Promotion 与写入继续使用检查后、持有独占租约的 Active Library connection。
- **Shared Client Interface。** 在正式 App 与 Store 初始化前安装适配器，UI 表达
  业务意图和订阅状态；不依赖散落的 Electron 全局对象或提前缓存错误 bridge。
  所有正式方法、事件、角色和不可用状态登记于同一能力目录，不开放任意 invoke。
- **客户端身份与角色。** Host 签发、校验并撤销客户端/session、角色和能力范围。
  桌面 Adapter 检查真实 sender/frame，HTTP Adapter 检查自身会话，不伪造 Electron
  event。主表面、受限 Asset Card 与 Work Window 各有授权范围；工作窗口保留成员校验。
  命令、选择、review/dispatch receipt 与草稿回执绑定真正 owner 和当前 Library 代际。
- **浏览器入口安全。** 只绑定本机回环地址，校验目标 Host、Origin、会话及跨站请求；
  不向局域网开放，不提供任意路径、SQL、脚本或进程接口。本机启动提供短期授权并
  建立会话，无需新增用户账号或自签名 CA；秘密不进入地址历史、日志、事件或报告。
- **File Selection Sessions。** 复用目的明确的选择 Adapter；两端使用同一页面内
  展示，Host 内部处理真实路径。选择会话有 owner、用途、范围、有效期和取消状态，
  返回不透明选择凭据；浏览器提交路径字符串不构成可信选择结果。选择后仍走现有
  素材库资格、存储位置、环境信任与操作确认；目录创建是单独的明确用户动作。
- **媒体与事件。** 两端共用媒体权限 resolver；读取前后检查当前库身份/代际，
  受限窗口另检查成员范围。HTTP 媒体端点不是通用文件服务器，避免向普通列表泄露
  原件路径。已提交变化经统一事件出口分发；漏达、重连与重启以权威快照校准。
- **在线冲突。** 复用 Notebook、OCR、WorkSet 内容已有版本/来源检查；Description
  编辑始终带保存基线。标签和设置不能被概括为已有全实体乐观锁，必须在共享 Host
  入口补足冲突检测。冲突保留用户草稿并让其复核，不自动换基准、合并或再次覆盖。
  原生窗口布局由原生 owner 写入，浏览器工作视图不冒充真实系统几何。
- **Workspace Recovery Draft。** 新增受控本机 profile 暂存与接收回执，区分可恢复
  工作区身份和临时连接身份。记录实体、类型、保存基线、来源身份与草稿序号；
  不同编辑者隔离。新连接重新授权后才能领取恢复记录，旧 grant 不可复用。
  恢复/放弃由用户决定；只有相应正式提交成功或明确放弃才清除该记录。
  不暂存凭据，不自动重放正式写入，不保证恢复 Host 尚未接收的最后输入。
- **公共兼容与 schema。** 新增 transport、选择、身份、事件和冲突语义是明确的
  公共兼容 Seam，同步直接调用方及验证。保留现有 IPC 名称、结果和保存/ownership
  语义；恢复草稿归应用本机状态，不因此悄悄升级素材库 schema、迁移旧库或放宽资格。
- **断线和未知提交。** 无幂等依据的写命令不自动重发；提交结果未知应检查权威结果。
  迟到回执只影响其对应版本，不覆盖后来输入；通知失败不撤销正式提交。
- **账号、AI 与原生 Adapter。** 保留现有 Main 账号生命周期、系统凭据存储、Pi/OCR
  执行边界和 AI 结果权威提交。Browser 复用工作集/参考展示，并可命令 Host 执行已有
  原生操作。模型、provider、下载和外发准入保持当前规则，不恢复禁用通道。
- **明确退出。** 关闭客户端不结束 Host。退出或切库汇集各客户端与工作窗口的草稿、
  暂存和未确定状态，取消后保留编辑；确认后冻结准入、排空并撤权。断开的客户端
  不被简单当作“无草稿”；暂存失败或状态未知必须披露。正常退出最终释放持有的库锁。
- **实施顺序。** 依次完成启动/profile、唯一命令面、浏览器 transport、共享 Client、
  媒体事件、选择器、草稿冲突和完整用户路径。切片降低风险，不缩减全量等价交付范围。

## Testing Decisions

主要验收边界沿用已确认的**统一客户端业务契约 → 正式 IPC/HTTP Adapter → 同一
Host Command Facade**。同一场景套件在两个正式入口执行，尽量用一个高层业务
边界验证外部结果；不为每个内部 helper 新造一套测试接口。

好测试断言用户可观察的状态、持久结果、权限拒绝、来源完整性和失败恢复，而非内部
调用次序、源码片段或 mock 被调用次数。正式数据链路使用受控 profile、真实临时
SQLite 与合成媒体；重开库/重启后读取核对保存。受影响的纯投影或平台 Adapter 可做
必要补充，但不能替代主业务套件。

现有先例包括 Active Library Host/IPC 与正式 Electron 合成端到端、Capture/Trash、
Library quiescence/shutdown、Workspace session 迟到事件、Notebook revision/冲突、
OCR 修订、WorkSet 保存及 Account lifecycle 测试。复用其资格检查、夹具和排空 seam；
SQLite 测试继续使用匹配 Electron ABI 的仓库启动器，不重编依赖来适配 shell Node。

另外必须覆盖：库切换与准备操作重叠、两个 transport 同时改变 authority、跨客户端

后台任务结果晚到，以及所有适用的失败、取消和重试分支。

**Computer Use：** 依项目 UI/UX 验收流程，以 Codex 内置浏览器为主要业务入口，由
用户指定的 GPT-6 Luna / high 子智能体执行，主 Agent 复核证据。从普通启动进入，
通过可见控件真实点击/键入，不以直接调用业务、改路由或注入 Store 跳过步骤。
正式保存须经后续界面重读核验；静态截图不独立证明持久化或动画行为。

本轮已有原生窗口、托盘、置顶、跨屏及准入允许的系统动作列入桌面专项；尚未交付
的跨应用文件交接在本轮不适用，不新增为必需验收。浏览器工具不能完成
路径时可按流程转桌面并记录原因，但 Browser 的失败/未覆盖仍保留，Desktop 通过
不抵消正式 Browser 等价要求。无所需工具或不能确认受控环境时记为
BLOCKED_UX_ACCEPTANCE。按实际端、平台和构建记录 PASS、FAIL、NOT_RUN 或阻塞；
必需路径尚有缺口时不宣布完整验收通过。

只记录合成测试表面与非敏感编号。真实素材、账号、权重、Runtime、安装、外部服务
和 provider 外发仍需对应授权。合成响应只能证明编排与传输，不能证明实际模型推理。
本规格编写只做文档与 tracker 验证，不新增产品运行证据。

## Out of Scope

- 当前禁用或未交付的模型安装、Runtime 管理及本地模型路径补齐；不因此承诺新模型可用。
- 新 provider、真实账号登录代办、模型/AI 依赖下载安装、真实库迁移、真实素材读取或外发。
- 自动改写或移动来源、放宽 Windows 备份/锁资格、绕过 Library ownership 与恢复检查。
- 局域网/远程访问、多用户服务、虚拟机、远程桌面或重新引入 MeshCentral。
- 已移除的网站采集、内置网页浏览、网站登录和外部网站搜索。
- 尚未交付的原生文件拖出、录屏、视频参考能力、插件市场或开发连接器扩建。
- 用浏览器面板替代真实 OS 窗口并宣称原生验收等价，或通过合成推理宣称实际模型已验收。
- 自动恢复正式写入、保证崩溃前所有输入零丢失、自动合并并发内容。
- 发布、分发、签名、用户安装或全产品未来规格的实现；现有打包配置可按双入口需要
  同步，但平台发布资格与真实安装证据仍需独立满足。
