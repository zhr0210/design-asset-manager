## Problem Statement

设计师在其他创作应用旁使用 DAM 工作集（Work Set）作为参考，需要一个小巧、清晰、易操作的 macOS 悬浮工作窗（Work Window）。现有 B 原生工作窗已提供紧凑、展开、停靠、素材拖放、色板和备注，但尚未落实已经批准的设计：紧凑窗仍为 290×310 pt，底板仍使用旧材质，顶部重复名称占据空间，关闭和菜单控件仍使用旧字符外观，停靠反馈还缺少真正的窗内模糊及按钮视觉退出。

菜单也存在范围不清的问题：展开态保留的选择会影响收起后的交付，用户在紧凑态看不到选择，却可能只交付工作集的一部分。现有原生目标过滤还会跳过不可用成员，掩盖引用故障并改变用户指定的交付范围。

工作集成员应保持可用。“离线/不可用”属于工作集引用故障（Work Set Reference Fault），需要修复或明确报告，不能设计成受支持的正常成员状态。

## Solution

用户从 B 的正式启动入口进入工作模式，打开或恢复一个工作集，即可使用 220×240 pt 的原生紧凑工作窗。整个紧凑及展开底板采用系统支持的 Liquid Glass，前景图片、文字及颜色保持清晰；顶部只保留常显的关闭和操作菜单，底部名称用于展开同一窗口。

窗口保留完整素材堆叠预览、同窗展开、背景拖窗、素材拖出及既定左右停靠行为。停靠时使用真正的窗内模糊和颜色覆盖，内容按钮退出并停止参与操作，停靠抓手接管恢复；恢复及新输入接管动画时，控件和用户内容正确回到可操作状态。

交付与 ZIP 菜单在紧凑态针对全部成员，在展开态针对所选成员，无选择时针对全部成员，并明确显示“全部 N 项”或“所选 N 项”。故障须明确反馈并保持原目标范围和用户内容，不能过滤故障成员后把不完整交付称为成功。

交付完成后，用户关闭并重新打开工作窗或整个 Host，能够找回工作集内容与正确布局；保存失败、修订冲突、取消及撤权继续保留既有保护。

## User Stories

1. 作为设计师，我希望从工作模式的可见工作集入口打开 B 原生工作窗，以便在创作应用旁查看参考。
2. 作为设计师，我希望重复打开同一个工作集时聚焦已有窗口，以便继续同一份工作内容。
3. 作为设计师，我希望恢复已保存的工作窗，以便继续上次的参考位置和展示状态。
4. 作为设计师，我希望紧凑窗默认只有 220×240 pt，以便减少桌面占用。
5. 作为设计师，我希望紧凑窗顶部只显示关闭与操作菜单，以便把空间留给素材。
6. 作为设计师，我希望工作集名称只在紧凑窗底部入口出现，以便清楚识别并展开工作集。
7. 作为设计师，我希望缩小窗口后仍保留可读字号与可点击区域，以便准确操作。
8. 作为设计师，我希望紧凑及展开底板使用 macOS 原生 Liquid Glass，以便与系统窗口视觉一致。
9. 作为设计师，我希望图片、文字与色块不被底板模糊，以便准确检查参考。
10. 作为设计师，我希望工作窗跟随系统明暗外观，以便在两种主题下都能读清内容。
11. 作为需要辅助显示设置的用户，我希望降低透明度时仍有清晰回退，以便正常阅读和操作。
12. 作为设计师，我希望横图和竖图在堆叠预览中等比完整显示，以便不遗漏内容。
13. 作为设计师，我希望在正常可见状态下始终找到关闭与菜单按钮，以便无需先悬停寻找入口。
14. 作为设计师，我希望拖动顶部空白和周边背景移动工作窗，以便调整参考位置。
15. 作为设计师，我希望拖动素材区域只启动素材拖出，以便避免意外移动窗口。
16. 作为设计师，我希望点击底部名称在同一窗口中展开网格，以便检查和选择更多参考。
17. 作为设计师，我希望展开态左上返回控件收起窗口，以便回到紧凑参考状态。
18. 作为设计师，我希望只有紧凑态能够左右停靠，以便展开检查时不被意外收走。
19. 作为设计师，我希望停靠保持窗口尺寸并在边缘留下恢复入口，以便随时找回参考。
20. 作为设计师，我希望停靠反馈使用窗内模糊并隐藏内容按钮，以便识别当前交互状态。
21. 作为设计师，我希望点击停靠抓手恢复屏内紧凑窗，以便立即继续使用参考。
22. 作为设计师，我希望拖动或点击能够中断正在进行的窗口动画，以便窗口及时响应新意图。
23. 作为需要减少动态效果的用户，我希望过渡遵循系统设置，以便降低运动干扰。
24. 作为设计师，我希望展开网格支持单选、Shift 逐项增减及保留多选的拖动，以便处理指定素材。
25. 作为设计师，我希望紧凑态交付始终针对整个工作集，以便不受看不到的历史选择影响。
26. 作为设计师，我希望展开态交付优先针对所选成员，无选择时针对全部，以便准确控制范围。
27. 作为设计师，我希望每个交付和 ZIP 入口明确显示范围及成员数量，以便操作前核对目标。
28. 作为设计师，我希望交付范围不因成员访问故障被悄悄缩小，以便得到可信的执行结果。
29. 作为设计师，我希望引用故障被明确报告，以便知道工作集需要修复，而不是接受一个正常离线状态。
30. 作为设计师，我希望故障后仍保留成员、备注和草稿，以便恢复工作内容。
31. 作为设计师，我希望原件、预览及处理后的副本保持各自身份，以便安全复用且不改变原件。
32. 作为设计师，我希望素材可从窗口各区域拖入，备注仍可接受普通文本，以便不将文件路径误写入备注。
33. 作为设计师，我希望通过 ⌘V 使用既有图片接入能力，以便快速加入参考。
34. 作为设计师，我希望从“添加”打开原生颜色浮层，以便选择不透明颜色并确认加入色板。
35. 作为设计师，我希望选色预览不保存，取消及重复颜色不会误提交，以便放心试色。
36. 作为设计师，我希望色板和工作备注保持在网格下方并自动保存，以便整理工作集辅助信息。
37. 作为设计师，我希望保存失败和修订冲突保留当前输入并明确反馈，以便恢复正确内容。
38. 作为设计师，我希望关闭并重开窗口或整个应用后找回成员、备注、颜色及布局，以便连续工作。
39. 作为设计师，我希望关闭窗口及移出成员不会删除工作集或素材原件，以便安全整理参考。
40. 作为设计师，我希望文本输入、输入法组合和未保存草稿在关闭及切库时得到保护，以便避免丢失编辑。
41. 作为设计师，我希望取消交付能够明确说明实际执行状态，以便区分已完成副本、等待退出和未确认结果。
42. 作为设计师，我希望通过空格继续使用既有独立大预览，并在文本编辑时正常输入空格，以便按当前工作场景操作。
43. 作为设计师，我希望素材拖出真正由接收应用取得副本后才被确认，以便知道文件复用是否完成。
44. 作为设计师，我希望工作窗在库关闭、切换或撤权后停止访问原库，以便保护资料库内容。

## Implementation Decisions

- 本轮范围为 B 悬浮工作窗已批准设计的原生组件应用，以及本次确认的菜单范围和引用故障语义；素材接入、色板、备注、选择、大预览及安全交付作为受影响回归路径保持。
- 沿用 AppKit 承担整个悬浮工作窗的紧凑态、展开态、菜单、输入及系统拖放；React 保留主工作台与独立大预览。遵循已接受的 ADR 0489 和 ADR 0493 的内容、窗口与 Host 分工。
- 主要修改原生工作窗呈现、原生交互控制、Host 工作窗适配、窗口布局归一化与菜单交付目标解析。复用现有工作集控制器、自动保存、文件交接和草稿恢复责任，不建设新的业务平台。
- 紧凑初始尺寸及从展开态收起的尺寸统一为 220×240 pt。原生最低尺寸校验、Host 几何归一化、恢复与停靠的直接消费者同步适配，避免重开或 Host 回写将窗口扩回 290×310。
- 旧 B 布局转为新紧凑尺寸时保留可恢复记录与合法位置；展开态布局、其他平台及普通窗口适配的既有语义保持。不得以全量覆盖设备布局或用户内容完成尺寸迁移。
- 紧凑态移除顶部重复工作集名称；顶部系统关闭与菜单常显，底部名称仍为展开入口。展开态左上控件为收起返回，紧凑态左上控件为关闭工作窗，两者语义不同。
- 按系统控件、图标、字体与交互状态呈现顶部操作。主要操作使用系统强调色，普通工具与素材选择遵循中性灰视觉规则；尺寸压缩不得压缩已批准字号和点击区域。
- 全底板在系统支持时使用原生 Liquid Glass；系统不支持或降低透明度时提供清晰可读的回退。前景内容保持清晰，避免重复底色、模糊、阴影或圆角叠加；回退不冒称已取得 Liquid Glass 资格。
- 原生背景玻璃与窗内停靠反馈是两个独立层次。停靠反馈使用真正的窗内模糊并叠加颜色，内容按钮视觉退出且不能继续接受操作；恢复时正确交还按钮和内容交互。
- 素材堆叠等比完整显示，不裁切或拉伸；顶部空白及周边背景拖窗，素材区域拖素材，底部名称点击展开，各区域手势互斥。
- 紧凑停靠保持宽高，约 84% 移至屏外、16% 留在边缘。既有进度与最后横向增量规则继续适用，展开态、素材拖出和程序移动不能触发停靠；目标侵入相邻屏幕时拒绝该侧停靠。
- 沿用已批准动画参数：停靠 EaseOut，最后拖动事件原始横向增量绝对值在 1 至小于 1.5 时为 0.6 秒、1.5 至小于 2 时为 0.45 秒、2 至小于 3 时为 0.35 秒、其他为 0.3 秒；点击弹出为 0.2 秒 EaseInEaseOut，并恢复至对应边缘内侧 12 pt。
- 覆盖层淡入淡出与移动完成分别交接；动画可由新输入中断并从实际显示位置接管，旧完成不能覆盖新操作。系统减少动态效果只改变过渡，不改变功能终态。
- 菜单对原件副本、预览副本、兼容 PNG、图像处理和 ZIP 使用统一目标范围：紧凑态全部，展开态有所选则所选、无选择则全部。选择可保留，但紧凑菜单不使用隐藏选择决定范围。
- 菜单数量是目标范围的成员数，显示“全部 N 项”或“所选 N 项”。操作面板与执行使用同一目标集合，不能显示全部却提交所选，也不能在执行时无提示扩大或缩小范围。
- 工作集成员应保持可用；不可用属于引用故障。不得通过过滤成员或伪造可用资格，把改变范围的不完整交付标为成功。故障保留引用、备注、草稿及已经产生的有效执行记录，并明确说明实际结果；既有部分完成/取消记录不得被抹掉。
- 正常交付前及读取时继续进行 Host 的库、会话、角色、成员、来源与文件校验。不能为满足“成员可用”而删除撤权检查、读取任意路径或形成新的权限入口。
- 既有支持格式、来源、数量及资源上限继续有效。不支持某种交付能力与预期成员访问故障分别报告，不以静默过滤代替明确结果；单次交付故障不冻结无关的窗口移动、备注编辑或其他合法能力。
- 工作集内容与设备工作窗布局分别持久化；原生仅拥有暂态呈现。Host 持有唯一资料库、修订、自动保存、文件交付与提交权威，只有原生运动实际终态确认后才保存相应布局。
- 继续使用现有受限原生桥、运动与手势关联、完成/取消/失败回执、自动保存和草稿恢复契约；本规格不引入新的公共 IPC、第二 Host、第二数据库或资料库 schema 升级。
- 关窗、退出、切库及取消继续处理输入法组合、未保存输入、实际文件来源和子进程退出；未知提交不盲目重发，未确认进程退出不释放占用或宣布完成。
- 本轮不决定原生进程合并及整应用性能预算。必要内部改动由实施者在以上用户结果和数据保护边界内自主完成。

## Testing Decisions

- 用户已确认主测试边界为“正式 B 原生入口 → 唯一 Host → 实际结果 → 保存重开”。通过已有工作模式、工作集入口和可见原生控件操作；不新增测试专用产品入口。既有 Host/工作窗端口及受限原生桥仅用于补充分支验证。
- 好的测试观察用户行为、执行目标、文件结果、持久化和保护语义，不断言私有控件树形状或复制实现算法。编译、受控 AppKit 事件、假 OS 端口和直接调用 Host 只能证明各自层级，不能代替正式用户路径。
- 测试对象包括原生工作窗和交互控制、Host 窗口布局/运动提交、菜单范围及安全交付、自动保存/草稿恢复。复用现有原生拖入、原生交互、颜色浮层、布局 v2、窗口运动 Host、自动保存与真实临时库测试先例。
- 现有工作集 Electron 端到端测试可作为业务路径先例，其入口及窗口类型与 B 原生窗分别核对；不得直接把 Electron 或浏览器测试结果转记为 B 原生验收。
- 在已指定的非隐私测试资料及隔离 profile/资料库范围内进行正式应用验证；故障、删除与迁移实验使用可恢复副本。不得全盘寻找测试素材，不读取凭据，不让本机敏感路径、素材或诊断秘密进入远端 Issue。
- 产品代码实施后，从最小受影响检查开始，运行修改过的测试及必要类型检查、原生编译和正式构建。此规格任务本身只验证文档、引用及发布内容，不启动产品构建或模型测试。
- 正式验收矩阵如下，内部故障注入与设备证据分开记录。

| 场景 | 用户可观察结果与验收要求 |
| --- | --- |
| 打开、重复打开、恢复 | 从工作模式打开工作集得到 B 原生窗；重复打开聚焦同一窗；恢复使用新紧凑尺寸及正确内容。 |
| 紧凑与展开 | 紧凑 220×240 pt，顶部无重复名称；关闭和菜单常显；底部名称展开同一窗，返回收起；点击区域与文字可用。 |
| 视觉与系统设置 | 在实际支持系统上观察紧凑及展开的全底板 Liquid Glass、清晰前景、系统按钮与主题；另验降低透明度及减少动态效果。旧系统回退仅在实际受测平台记资格。 |
| 完整预览与区域手势 | 横图、竖图完整等比显示；顶部/背景拖窗、素材拖出及名称点击分别有效，互不误触。 |
| 左右停靠与弹出 | 紧凑保持尺寸按既定比例停靠，覆盖层真实模糊、按钮退出、抓手接管；点击恢复至内侧 12 pt；展开态拒绝停靠。 |
| 动画接管 | 慢/快、反向及中断覆盖运动与覆盖层；新输入从实际显示位置接管，旧完成不回跳、不覆盖新保存。连续帧采样不足时保留流畅性未验。 |
| 菜单范围 | 同一多成员工作集先选 2 项再收起：紧凑显示并执行全部；展开显示并执行所选；取消选择后执行全部。逐项核对原件、预览、兼容 PNG、处理和 ZIP 的目标及实际结果。 |
| 引用故障 | 在可恢复副本中制造预期成员访问故障，观察明确失败/故障反馈、目标数量不被静默过滤、成员与用户输入不丢失；不得关闭校验或伪造成功。故障修复后能按原目标恢复执行。 |
| 保存与重开 | 修改备注、颜色及布局后关闭重开工作窗，再正常退出重开整个 Host；成员顺序、备注、颜色、布局及原件保护一致。 |
| 保存失败、冲突与撤权 | 真实临时库及现有 Host 端口覆盖写入失败、修订冲突、库关闭、迟到回执和新会话；旧完成不能提交到新权威，输入和最后有效内容保留。 |
| 素材与文本回归 | 逐区域拖入、保留多选拖出、单选/Shift、Delete 只移出引用、文本删除/空格、输入法组合及 ⌘V 正常；原件哈希保持，实际接收应用读回副本。 |
| 颜色与大预览回归 | 实际指针点击/连续拖动取色、只读 HEX、确认/取消/重复保护及色板保存成立；空格打开独立大预览，切图/关闭保留笔记草稿。受控事件不能替代物理输入结果。 |
| 交付取消及退出 | 取消及关窗期间核对已完成副本、未结束文件来源和实际进程退出；拖动结束或操作请求成功不冒称接收成功，不假释放资源。 |

- 每个结果绑定新的候选身份、原生资源身份、实际平台与所用资料范围。源码、依赖或资源改变后重验受影响证据；旧 PASS、旧截图及旧二进制不转记为本次完成。
- 本轮明确正式 macOS 原生路径的已测范围；真实多屏、Spaces、触控板、高帧率与其他设备缺口按实际工具和设备保留，不泛化为全设备完成，也不让用户承担代测。
