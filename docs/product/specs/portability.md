## 0379 · Pending Metadata Import Sessions Are Explicit, Portable And Source-Detached

决定来源：[0379-pending-metadata-import-sessions-are-explicit-portable-and-source-detached.md](../../adr/0379-pending-metadata-import-sessions-are-explicit-portable-and-source-detached.md)。这是按其命名能力/版本适用的来源契约，当前要求须结合本节适用范围与明确替代决定核对；本次迁移不新增交付资格。原文字句/数字/例外保留，以避免提炼丢失保证。

<a id="0379-p001"></a>

Metadata Portability Import Inspection remains temporary until the user commits items or explicitly chooses **Save Pending Metadata Import** when leaving with unresolved mappings/conflicts. Without that choice, closing, cancelling, quitting or restart clears the inspection projection, decrypted parser state, mapping draft and operation-owned temporary media; it creates no recent-file entry, remembered path or durable import session. The application may ask Save or Discard at an ordinary close boundary but never silently turns inspection into library content.

<a id="0379-p002"></a>

Saving creates one library-owned **Metadata Import Session** bound to the target Portable Library Lineage Identity and Local Library Instance Identity. It persists only normalized unresolved supported records and their required typed payloads, explicit asset/shared-object mapping and conflict choices, source export/package identity, complete selected source-file digest, schema/profile versions and enough state to rebuild a fresh ADR 0376/0380 plan. Already committed or excluded records, unrelated source-package entries, the complete source file/container, absolute/relative source paths, filename history, directory context, reusable bookmark/handle and age passphrase are not stored.

<a id="0379-p003"></a>

The save review reports unresolved record/payload classes, logical and physical library bytes, privacy-sensitive classes and the consequence that normalized content from an encrypted source becomes decrypted authoritative library state. A saved session moves with that library and is included in Full Library Backup under its normal encryption policy; it is not synchronized into another Registered Library or application-global history. No session is created when its required normalized records cannot be preserved losslessly under a supported versioned schema.

<a id="0379-p004"></a>

The selected `.dammeta`, JSON, CSV or age-wrapped source remains an untouched user-owned file. Saving never copies, moves, renames, deletes or keeps an open handle to it. If a later action requires data deliberately not retained in the session, including omitted package payloads or review media, the user must select a source again through a native picker; the complete digest and declared export/package identity must match before it can augment the existing session. A mismatch starts a separately inspected source rather than silently changing the saved task.

<a id="0379-p005"></a>

Portability Review Thumbnails and other inspection-only rendered media may enter a bounded device-local **Metadata Import Review Cache**. It contains no authoritative mapping/value state, is excluded from Full Library Backup and portability export, and may be cleared by cache policy or the user at any time. Losing it degrades only visual comparison; the saved normalized records, explicit choices and future import correctness remain intact, and unavailable thumbnails are never regenerated by reading offline originals without a new explicit operation.

<a id="0379-p006"></a>

A Metadata Import Session has no age-based automatic expiry because the user may need to add or reconnect originals before mapping. It remains visible in the owning library until completed or explicitly discarded. Completion or discard removes its unresolved normalized records, typed payloads, choices and review-cache associations from current library state while retaining only the bounded path-free Metadata Portability Import Result required by its ordinary result-retention policy; existing Full Library Backups remain immutable historical snapshots and no secure-erasure claim is made for filesystem/database history outside the current library transaction.

<a id="0379-p007"></a>

The current application has no Metadata Import Session, Save Pending Metadata Import review or Metadata Import Review Cache. This ADR records target architecture only and opens, decrypts, copies, remembers, backs up, discards or reselects no actual user package, and selects, imports, analyzes, stages, writes, rewrites, converts, moves, deletes or changes no runtime/user file, credential, sidecar, directory, database, cache, backup, metadata value, analysis result or source relationship and changes no public IPC, database schema or AI Worker API.

## 0381 · Portability Shared Objects Commit By Dependency And Undo By Exclusive Effect

决定来源：[0381-portability-shared-objects-commit-by-dependency-and-undo-by-exclusive-effect.md](../../adr/0381-portability-shared-objects-commit-by-dependency-and-undo-by-exclusive-effect.md)。这是按其命名能力/版本适用的来源契约，当前要求须结合本节适用范围与明确替代决定核对；本次迁移不新增交付资格。原文字句/数字/例外保留，以避免提炼丢失保证。

<a id="0381-p001"></a>

After ADR 0380 review, every reusable existing object or explicitly created user object becomes one **Portability Shared Object Commit Unit**. The unit revalidates the exact source identity, target choice, target type/lifecycle and relevant parent/name constraints immediately before one atomic transaction. Creating a new target object and its Portability Object Mapping succeeds together or rolls back together; mapping an existing object writes only the mapping/provenance and never edits that object's labels, names, hierarchy, relations or lifecycle.

<a id="0381-p002"></a>

Units execute in dependency-safe order without one unbounded global transaction. Required parent Collection Groups and endpoint Tag Concepts/collection objects settle before hierarchy or semantic-relation edges, and dependent asset relationships remain ineligible until every referenced target identity is committed. A failed/stale unit blocks only its dependent objects/relationships. The user may refresh or change its mapping, or explicitly exclude the object and dependent relationships so unrelated scalar metadata and resolved relationships may continue; failure never silently removes a selected relationship from an asset item.

<a id="0381-p003"></a>

Cancellation stops unstarted shared-object units. A started atomic unit finishes or rolls back before cancellation or ADR 0278 Library Switch reaches its checkpoint. Committed units remain truthful partial success and are not rolled back merely because a later unit or asset item fails. The result separates reused, newly created, mapped, relationship-committed, conflict/stale, failed, excluded and cancelled shared-object outcomes and identifies the dependent asset relationships still awaiting review.

<a id="0381-p004"></a>

A target-visible naming collision never proves identity or triggers automatic merge, suffixing, renaming or reparenting. When target rules disallow the reviewed name/scope, **Portability Shared Object Naming Conflict** offers Map To Existing Object, Create With User-Confirmed New Name, or Exclude Object And Dependent Relationships, consistent with ADR 0337. The application may suggest an available name but cannot select it automatically. Where the domain permits equal display labels for distinct semantics, separate identities remain separate and the review exposes type, source and hierarchy context rather than manufacturing a name difference.

<a id="0381-p005"></a>

Undo Metadata Portability Import first reverses eligible asset relationships/effects under ADR 0378, then evaluates shared-object effects in reverse dependency order. A mapping to a pre-existing object may be removed only when it was created by this import and no later saved session, import or committed relationship uses it; the target object itself is never changed or deleted. An import-created object and its mapping may be removed atomically only when every import-created dependent relation is gone, the object remains semantically unchanged, and it has no non-import membership, child/parent relation, alias/edit, other source mapping or other user/library use.

<a id="0381-p006"></a>

If the user edits or reuses an import-created object, or another operation adopts its mapping, undo preserves the object and mapping and reports an Import Undo Conflict rather than stripping shared organization from newer work. Safe cleanup of another independent created object may still succeed because shared-object undo is unit-scoped rather than all-or-nothing across the import. After the short undo window, object removal or mapping changes use their ordinary explicit tag/collection lifecycle and cannot masquerade as old import undo.

<a id="0381-p007"></a>

No shared-object unit creates or modifies an Original Asset, Design Asset, Source Tree/folder, System Collection, Built-In Tag catalog definition, Collection Board layout or AI result. The current application has no Portability Shared Object Commit Unit, dependency executor, Naming Conflict review or exclusive-effect undo. This ADR records target architecture only and reads or imports no actual package, maps or creates no runtime tag/collection, and selects, analyzes, stages, writes, rewrites, converts, moves, deletes or changes no runtime/user file, credential, sidecar, directory, database, cache, backup, metadata value, analysis result or source relationship and changes no public IPC, database schema or AI Worker API.
