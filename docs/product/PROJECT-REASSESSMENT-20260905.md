## 结论

定位成立：本地优先、AI 增强的视觉素材工作台，服务于“收进—理解—
找回—检查—复用”。当前最需要的是把这条用户路径做实。
现有工程积累包含有用的安全与持久化验证，但不足以把产品判为
“初步开发基本完成”。界面存在、测试通过和用户可以完成工作是三种证据。

最优先处理已接线行为中的错误成功，再交付一个小而完整的图片工作流。
建议首批验证对象为设计师、视觉策划师的图片参考库；剪辑师/编导的
视频、音频、时间码检索作为第二个实用闭环。此排序是基于当前图片能力
的工程建议，不是取消既定视觉创作者定位。

## 新的开发顺序：以用户可验收的结果推进

### 立即：消除错误成功，建立可信现状

本次直接开发：

- 缺少真实下载执行器时，新请求立即显示不可用，进度为零。
- 不分配虚构路径/大小、不写素材/假下载记录、不发入库动画。
- 新请求只留在当前会话，界面说明其不会在重启后保留。
- 历史下载只作未核验记录；不自动改写、恢复执行或据此宣称已入库。
- 源码保护规则禁止下载 Store 重新获得 addAsset 写入口。

这是风险修复，不是实际下载功能交付。已有模拟产生的历史素材是否
损坏尚未检查；需要单独的只读诊断与用户确认，不能批量删除“疑似假数据”。

### 接着：一个可重复的本地图片闭环

可验收故事：用户显式选择独立测试素材库 → 导入一组 JPEG/PNG/WebP →
立即看到可检索记录和预览 → 重启后仍能找回 → 查看原始内容 →
安全复制/导出到指定位置。缺少 AI 模型也能完成。

实现前先梳理现有正式数据库与已验证 Library 能力之间的最小接入方案。
复用已有 Copy/Preview/ownership/lock 逻辑；不要为复用而继续扩展全套
多库、联邦检索、迁移框架。旧数据只能通过保留原库的副本迁移验证。
若公共契约或真实数据操作需要批准，先交付可审查的差异和合成数据演示。

验收：确认前不写入；原始来源内容不变；失败不产生假素材；
重复点击不重复入库；重启能找回；断电/中断有明确结果；
删除/恢复保护用户状态；导出结果与被声明的原件或变体一致。
测试必须经过实际 UI → Preload → Main → 临时磁盘/数据库调用链。

### 然后：让 AI 带来可测量的找图收益

在同一闭环逐步接入 OCR、描述/建议标签、embedding 检索。
先提供一个经过验证的本地组合；保持能力 Adapter 可替换。
不足的机器能完成基础素材管理，分析可取消/重试且不覆盖用户编辑。

建立有标注的公开/自生成图片小评测集及中文任务：
“找那张带红色大字的活动海报”“找到相似构图”“查找图中的一句文字”。
先测词法基线，再测 AI 增益，记录 Recall@k、人工相关性、错误建议、
首条结果/整批时延、内存和失败恢复；没有改进就不增加模型。

模型选择顺序：用途与质量 → 许可与可再分发性 → 硬件/量化 →
下载体积/运行内存/延迟 → 格式/Runtime 兼容 → 可回滚升级。
具体模型名单须在接入时用最新官方资料和本机评测确定，本报告不把
某个模型品牌固化成架构。用户任意 URL/Hugging Face 输入仍需下载前
可解释的来源、许可、大小与格式验证；仓库代码不能随权重自动执行。

### 再做：小范围试用和性能、恢复、安装

建议从 3–5 位真实创作者的明确找图任务开始，先用获许可的测试素材。
测完成率、导入异常、找回所需时间、错误操作可恢复性和 AI 建议采纳率。
先完成一平台可重复安装/升级/卸载验证，再覆盖另一平台；跨平台声明
必须对应实测结果。可先给内部开发包，不能等同于已签名正式版。

建议性能预算是待测目标：10k 素材列表滚动可用、普通筛选/词法查询
P95 ≤ 300ms、图片批量导入期间界面可交互；具体机器和测试集一起记录。
100k 素材作为压力等级，不在未测情况下宣传。预算不达标时优先做
数据库分页/索引、缩略图调度和视口虚拟化，再做微优化。

商业交付还需安装签名、升级回滚、数据导出/恢复帮助、可脱敏诊断、
第三方许可清单和不依赖在线账号的素材可访问性。付费形式待验证，
无需为未确认的订阅方案先建账户和云平台。

### 后续独立闭环：视频与编导创作上下文

按试用证据选择关键帧、镜头级标签、时间码搜索、字幕定位、选片板和
带出处的剪辑交接。先做一个“搜到某段并跳到时间码”的实际故事。
自定义字段长尾、跨库联邦、插件市场、来源文件改写、复杂导出调度
和多模型自动路由暂缓实施；相关 ADR 保留，未被否定或删除。

## 架构与开发方式

保留 Electron Main 的可信写入、窄 Preload、React 工作区、
Python 推理 Worker。现阶段没有证据支持微服务化或重写技术栈。
按入库、检索、分析、复用的 Module 组织实现，以调用者的产品意图
构成小 Interface，把路径、SQL、模型执行细节留在内部 Adapter。

每次开发应同时说明：用户入口、完整调用链、存储后果、失败呈现、
重启后行为和证明命令。只新增该故事所需的状态/实现/测试。
独立验证可以帮助解决风险，但最终交付必须接入真实产品路径。

文档只保留一个当前任务账本及本报告中的新方向，不复制全部未来 ADR。
具体任务使用 Context Router 与近邻 README；不以 260k 上下文填满
作为全面理解的标准。不以代码行数下降作为优化验收，不批量删除未接线代码。
