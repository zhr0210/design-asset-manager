结论：**可以合成一个用户任务/进度入口；不能因“同一个模型”直接变成同一份语义结果。当前实现实际也不是同一个模型。**

- **画面描述**：`src/main/visual-ai/caption-recipe.ts:31` 调用生成式视觉 Provider 的 `/chat/completions`，输出严格 `{caption}`，最多 240 字符；作为描述证据提交，遵守人工内容优先与历史/current 边界。
- **以图检索**：`src/main/retrieval-workspace/retrieval-runtime.ts:155` 调用独立 SigLIP2 image encoder；当前空间为 CPU float32、768 维、L2/cosine，并绑定模型/制品/运行器/图像配方指纹。持久向量、索引、查询结果属于搜索系统。`asset-retrieval-store.ts:77` 保存独立空间、向量和生成时间。
- **共享模型≠共享输出**：caption 是可读文本，embedding 是用于距离比较的数值证据；文本描述不能直接替代图片向量。把图片描述再编码并检索，是另一条“由描述找图”的链，会损失未被描述的视觉信息，不能继续冒称原有以图相似能力。
- **共享一次物理执行需要额外能力**：只有未来模型/runtime 确实同时提供合格 caption 与兼容 image embedding，并有已验证的双输出协议，才可能一次读取/一次模型调用产出两种结果。当前源码没有这种协议；仅同一模型名称不足以证明可共享前向计算、向量空间或质量。

建议的合并边界：

1. **一个“理解素材”父任务，两个能力子结果**：可统一选择范围、准备材料、资源调度和进度展示；保留 caption 与 embedding 各自状态、版本、证据、重跑与过期判断。
2. **允许部分成功**：描述失败不废弃已生成的有效向量；向量失败不隐藏有效描述；只重跑缺失/失效能力。共享调用时用共享 execution ID 记实际用量，避免重复计费。
3. **不得捆绑查询授权**：外部查询图仅获一次会话文件 grant，当前契约禁止隐式入库、外发、持久化向量或触发其他分析。用户“以图查询”不能自动生成持久描述。库内已兼容向量可直接复用，也不应为了查询强制重做描述。
4. **分别保存权威**：可以返回一个组合 envelope，内部仍是 `captionEvidence` 与 `embeddingResult`；搜索命中列表是随库内容、硬条件、索引与查询变化的结果，不是素材分析的固定第三字段。
5. **模型变更分别失效**：caption 的编辑/配方变化与 embedding space 迁移不是一回事；不能通过一个 completed/ready 标志覆盖两种资格。

依据：`docs/subsystems/asset-discovery.md:9` 明确“不能因共享模型而合并结果权威”；`docs/subsystems/ai-system.md` 的请求/视觉章节要求能力独立证据和提交边界；ADR 0182/0183 约束临时查询、精确空间兼容和 canonical 向量持久性。两个 ADR 尾部“当前未实现”是旧源码背景，与本工作区已有检索实现冲突，应作为历史背景而非当前事实。
