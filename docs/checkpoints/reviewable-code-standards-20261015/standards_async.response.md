验证计划应以“取消请求、逻辑完成、物理退出”三个独立状态为核心，不能在 Promise reject、超时或停止 ACK 时直接释放驻留资源。

1. **确定修改边界**：沿 Worker 启动器、资源 Governor、任务生产者/消费者、关库/退出及 UI 状态调用链核对；冻结候选和预期行为，区分消费者准备保护与模型驻留许可。
2. **确定性竞态测试**：用屏障与可控延迟覆盖取消前/加载中/执行中/完成同时取消、超时边界两侧、延迟 ACK、阻塞退出、迟到结果、乱序 close、旧 launch 清理晚于新实例。断言 UNKNOWN 继续占用/隔离，只有对应实例真实 close 才释放；旧事件不得释放新实例。
3. **权限与数据保护**：换库、撤权、关库或退出后，旧任务即使迟到成功也不能提交；重跑失败保留旧结果。检查等待回调是否依赖当前锁/队列，防止持锁等待造成死锁。
4. **并行与收尾**：前后台并行任务共享预算，取消一个任务不影响其他任务；Host drain 等待已登记清理。测试结束前停止并等待自有进程、计时器、监听器与异步刷新，不能杀身份不明进程。
5. **测试有效性与执行范围**：新增保护测试先在可恢复候选上恢复旧错误，确认命名行为的断言失败，再恢复修复通过；编译错误、准备超时和 skip 不算反证。按实际改动选择 `test-python-worker-runtime`、`test-real-ai-runtime-process-runner`、`test-library-quiescence` 及实际消费者测试，运行修改的测试与 `typecheck`，必要时构建；不能仅跑修改目录。
6. **正式验收另列**：后续允许执行时，通过普通界面观察取消、等待、失败/恢复和占用实际释放；真实推理仅用已许可的现有模型，不下载权重。开发测试通过不能替代真实 UI/推理资格，外部请求取消也不能证明远端停止或零费用。
