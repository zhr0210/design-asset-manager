# 开发与贡献指南

本页是人和 AI 共用的工程入口，不是新的任务队列。产品语义见
[产品基准](docs/product/PRODUCT-FOUNDATION.md)，架构见 [ARCHITECTURE](ARCHITECTURE.md)，
自主权与隐私底线见 [AGENTS](AGENTS.md)。

## 1. 从一个用户结果开始

任务先写“普通用户从哪里进入、做什么、得到什么、怎样确认保存”，而不是只写类名和内部票号。
技术子任务可以拆分，但父级用户目标必须等实际路径成立才关闭。
当前负责人允许 AI 在该目标内自主调整代码、内部接口、必要 schema、依赖、构建和测试；
不逐文件申请。改变公开兼容承诺、不可恢复的数据行为或产品范围时，解释取舍，不静默改变要求。
外部贡献者向上游提交 PR 的治理，与项目所有者委托自己的编码 AI 是两种场景，不照搬他仓审批步骤。

## 2. 环境与源码

Windows/macOS 使用同一产品代码，原生依赖和资格分别验证。当前 Windows 产品以 Windows 正式 Host 验收，
浏览器负责主要共享 UI；WSL/虚拟机是可选工具，不因更改文档自动迁移开发环境。
Linux/Windows/macOS 的 node_modules、虚拟环境和 Runtime 产物不得混用；活动库只交给唯一 Host。

先看 `package.json`、锁文件和 `docs/REHOST.md`，核实 cwd、Node、Electron ABI、安装脚本与平台资源。
不把文档中的旧版本号当作当前安装事实，不为 shell Node ABI 不同而重编并破坏 Electron 使用的依赖。
在当前授权范围内自主准备必要依赖；真实验收只用现有模型，不下载、补齐或更新模型权重。查清来源、许可证、磁盘空间、安装副作用及资源成本。
工具未提供权限时报告实际限制，不能将 AGENTS 当作关闭沙箱或读取秘密的许可证。

| 工作 | 当前项目命令入口；执行前核对脚本仍存在 |
| --- | --- |
| 按锁恢复开发依赖 | `npm ci`；注意生命周期脚本和平台原生依赖 |
| 类型检查 | `npm run typecheck` |
| 生成正式构建 | `npm run build`；会更新构建身份，不能冒充只读 |
| 桌面 / 本机浏览器 | `npm run start:desktop` / `npm run start:browser` |
| 纯 TS/不依赖 Electron SQLite 的聚焦测试 | `node scripts/run-ts-test.mjs scripts/<实际测试>.test.ts` |
| SQLite/Electron ABI 测试 | `node scripts/run-electron-node-test.mjs scripts/<实际测试>.test.ts` |
| Python 隔离检查 | `npm run test-python-unittest`；缺依赖的跳过不算通过 |
| 代码导航与索引维护 | `npm run context:route -- --task "具体任务"`；相关变更后 `npm run context:check` |

表中尖括号是路径示意，必须替换为存在的测试，不能直接当命令执行。
普通 `dev` 和正式启动会接触实际配置；选择 profile 前核对设置、凭据、库和缓存是否真的归属于它。
仅传一个 `--user-data-dir` 不证明全部服务已经隔离。产品路径问题应修产品，不用测试替身掩盖。

## 3. 任务上下文、实现与审查

所有项目任务都按主题和影响范围核对已有决定；ADR的作用涵盖产品边界、设计、数据/隐私、架构、技术和协作取舍，不按任务类型设读取白名单。调研、规划、需求或设计讨论、文档和操作任务同样适用；这些只是例子，不是完整清单。

按当前问题选择首入口：功能/体验任务从[所属子系统](docs/subsystems/README.md)及相关行为规格进入，取舍比较可从[ADR主题](docs/adr/indexes/topics.md)进入，文档维护从本文§7进入。再按涉及的行为、数据、权限或兼容范围核对相关决定与必要的详细契约；[任务类型](docs/adr/indexes/tasks.md)只调阅读重点，不规定所有任务先读ADR。涉及代码/工程变更时按[开发规范](docs/code-standards.md)核对适用保证。已有ADR解释有意选择及其原因，不因“没有新架构决定”跳过相关取舍；也不以无关ADR数量证明理解。

读取围绕要回答的问题收口：先定位标题/关键词再读适用章节，区分源码事实、当前约定和修改提案。工具输出截断时核对关键段落是否实际可见，缺失则缩小范围补读，或明确缩小结论；不要把批量读取请求当作已读证据。context:route是筛选线索，预算延后或未命中不表示决定不适用；沿所属专题/原文引用补查，不递归通读所有链接或493篇记录。

若方案与有效决定冲突，显式指出对应条款、前提变化和取舍；核对用户最新明确要求与具体替代范围，不能静默推翻或将所有内部改动重新变成审批。规范和ADR不冻结内部类名/目录/接口；SDK/API值查安装类型与原始资料，不凭模型记忆猜。

先描述触发与前后结果，核对相邻入口、状态权威和下游假设；内部重构保持契约可说明依据，不机械写新文档。生成文件经生成器更新，不手改seal摘要。逻辑放在真正拥有它的模块，替换重复责任并同步调用者；不为规避旧实现并排造无消费者平台，也不把不同权限/生命周期混在一起。文件大小只是诊断线索，不是硬拆分指标。只对触及范围整理格式，不以全仓格式化或压成超长单行掩盖差异。

## 4. 选择与执行验证

从最小相关检查开始，按数据/跨层/平台/依赖风险扩大；修改的测试要执行，必要构建不跳过。确定性回归、实际数据库/SDK与正式用户验收各自存证。具体行为保证见开发规范，实际UI/模型/原生步骤见[真实验收](docs/agents/ui-ux-acceptance.md)。

复验记录普通入口、候选/客户端/OS、实际输入与服务范围、断言结果及未运行项。真实质量和“调用成功/JSON合法”分开，用量/费用/输出硬限未知就写未知。已有watch诊断可复用，不重复启动；真实功能不能靠测试替身、禁用逻辑或注入成功状态关闭。

## 5. 真实测试与持续许可

禁止Agent读取或导出Cookie、密码、访问/刷新令牌、私钥、浏览器历史、完整认证回调、凭据保险库；不读取完整秘密配置、进程环境或内存转储调试。正常应用可通过既有安全机制内部使用账号，Agent只看非敏感结果。工具/OS权限由实际环境提供，文档不能关闭它们。

用户已将必要的真实应用、真实资料库、实际模型/服务验证纳入工程任务。已明确目标/材料/服务/费用范围后，
可持续执行和复测，不再逐次提问“是否开启真实测试”。必要原生验证也属于对应交付，不将旧批次排除记录当永久禁令。

只在当前 TASK 中用非敏感别名记录所选资料、允许操作、服务和费用边界，并引用已有许可。
不重复建立庞大授权数据库，不记录令牌或私有认证网址。未知私人目录不因“可能有用”而打开。
Agent 在模型上下文中看到的截图、OCR或文件内容也属于披露；仅使用已确认可用于开发的材料。
正常应用内部使用账号，Agent不读保险库/浏览器登录数据库。首次登录和多因素认证由用户在正规界面完成。

迁移、删除、故障和崩溃实验先用真实内容的可恢复副本；普通目标库的非破坏性验收单列，
不把副本当原库，不把小样本当整库或所有格式。检验备份的实际读取和恢复动作，勿只写“已备份”。
新增购买、无预算计费或目的地/资料范围扩大时，只解决该具体边界；继续其他独立工作。

## 6. Git、候选与长任务

一个工作副本一个写入者；多个代理可读，需并行写时使用明确独立副本。不要在验收中不断替换同一候选。
WIP不等于脏数据。主Agent负责完整交付及前端信息架构、交互和视觉定稿。只记录和处理本任务可归属的差异，不覆盖别人的暂存/未跟踪内容，不全量reset/clean/stash/add或覆盖；本地检查点只含本任务差异。
已授权本地检查点可按实际任务路径建立；同文件混有他人修改时核对 patch/hunk，不能仅凭文件名全部纳入。
普通本地 commit 与远端 push、公开发布不同；后两项需要发布范围，不自动执行。

交接复用 `TASK.md` 和 `docs/handoff/CURRENT-STATE.md`：当前任务、已验证用户结果、候选身份、剩余问题、下一动作。
运行细节与原始证据放已有批次目录，只留一个链接；不要每个小步复制完整仓库或嵌套全部历史ZIP。
上下文切换保存短检查点和自有进程状态。旧 PID 要重新核验，不杀身份不明进程、不重启用户其他工作。
一次授权范围内连续推进；重复失败无新证据时先定位或换只读审查，不无限扩大架构。

## 7. 文档维护

AI开发直接按[AGENTS](AGENTS.md)的任务导航定位唯一正文；功能/机制从[子系统目录](docs/subsystems/README.md)进入，目标细节从[规格目录](docs/product/specs/README.md)进入。不增加独立文档总入口或要求先遍历目录。源码旁README只解释局部拥有者，跨层专题解释协作，互相引用而非复制全文。

README介绍产品；产品基准保存目标；ARCHITECTURE解释结构；CONTRIBUTING说明工程方式；AGENTS保存四类简短常驻约定与任务导航。
DESIGN独占视觉规范，CURRENT-STATE独占可用能力与运行身份，TASK保存当前任务；[任务主台账](docs/tasks/TASK-REGISTRY.md)独占跨系列状态与剩余条件。其他文档链接，不复制实时快照。
每次修改文档，写入前按以下职责选择目标，写入后检查差异是否混入其他职责；现存章节的位置不构成继续追加同类内容的依据。

| 内容职责 | 目标文档 |
| --- | --- |
| 当前有效的视觉语言、材质、排版、布局、组件样式及通用反馈/动效 | DESIGN.md |
| 功能状态、用户流程、手势作用范围、保存与取消等用户行为契约 | 对应模块规格（docs/product或docs/design）；不另建重复权威 |
| 技术机制、状态权威、桥接与持久化 | ARCHITECTURE、子系统专题及模块README；重大取舍进入ADR |
| 当前实施范围与下一动作 | TASK.md；跨系列状态归任务主台账 |
| 实际能力与运行身份 | CURRENT-STATE.md |
| 验收证据、版本结果及历史记录 | 对应验收报告或历史文档；当前入口保留追溯链接 |
| 领域概念与术语 | CONTEXT.md；不混入技术实现或任务记录 |

context:route提供有界的源码、契约和反馈导航，不执行文档文字或授权恢复旧队列。迁移先保存身份与逐条去向，保留有效要求、例外及来源；冻结证据不为目录整齐改写。目标与现状不符不能通过降低目标消除；只有循环链接而无正文不算覆盖。旧版本和原报告按[历史索引](docs/history/README.md)/[交接记录](docs/handoff/README.md)追溯。

文档审查同时核对内容归属、当前规则与历史的区分、来源及引用是否保全。格式校验只能补充结构检查，不能替代职责审查。
CONTEXT及ADR按语义问题查阅。新增ADR仅用于难以逆转的取舍，不为每个函数或补测增加一份。
功能移动/删除要迁移使用说明与消费者；历史证据不改写成新版本通过。
交付报告先说明“现在能做什么、怎么进入、实际测到哪里、还缺什么”，再列必要技术证据。

### AI材料的行为验收

供AI读取的约束含义、术语定义、ADR/规格适用范围、阅读/写回入口或索引召回发生变化时，每个有因果关系的修改批次结束后，由主Agent自动完成一次行为验收。同批修改合并，不每保存一句派代理。仅排版、标点、对齐或不影响可发现性的修链，执行适用结构检查即可；是否触发按实际含义/适用范围/检索影响判断，不按文件扩展名。验收对象是本批材料能否帮助实际任务，不以文档存在、篇幅、引用数量或Agent自评证明质量。

#### 三层达标标准

| 层次 | 本场景须证明 | 不达标表现 |
| --- | --- | --- |
| 找得到 | Agent在无阅读提示的自然任务下，自主到达支撑结论的权威章节；范围与任务相称，关键返回内容实际可见 | 索引绕行/误导导致漏掉必要正文；关键内容被截断却视为已读；无关全量加载影响任务 |
| 用得对 | 将适用规则转成具体判断或检查；分清现行约定、实现事实、未来目标与修改提案，正确处理前提/例外/替代 | 只列文件或复述原则；误用旧规则、删除例外、将目标说成已实现；把约定当不可改变的内部实现 |
| 推动任务 | 材料提供本任务应有的项目事实、边界和取舍背景，使Agent能识别关键差异、未决条件及可执行下一步 | 缺失或含糊的项目材料导致泛化建议、遗漏关键条件，或无依据地把候选方案当唯一答案 |

第三层只评项目材料应提供的帮助，不按文风、与主Agent意见一致或一次给出最终优秀方案评分。回复平庸不自动证明文档失败：主Agent须用实际轨迹、必要原文和错误/遗漏说明关联，再区分文档缺失/误导、任务歧义、工具问题与Agent自身判断不足。无法归因时记录待定位，不为迎合答案堆规则、指定技术或写入评分答案；文档问题也不能推给模型了事。

#### 执行与不达标处理

1. **先定独立判据。** 依据用户已确认要求、原有规范/源码，写出场景任务、应识别的关键事实/约束、不能接受的误判和三层预期。主Agent在派发前保存判据，与验证提示分开；不能从本次新措辞反推“正确答案”，也不能看到失败后放宽正确标准求通过。
2. **固定候选。** 为受影响文档与检索工具记录字节身份；验证期间不修改候选。可用隔离的非敏感仓库资料副本；记录其包含/排除范围，缺失资料只作具体覆盖限制，不假称完整环境。Agent指令性只读不冒称OS/沙箱强制隔离。
3. **简短任务盲探查。** 默认低思考强度、全新上下文，不继承编写会话或上一轮答案。派发只含简短自然任务、工作区和必要执行边界：不提示“依据项目文档/规范”“先查看索引/详细文档”“检查已有取舍”，不指定入口、文件、ADR编号、检索顺序/关键词、预期结论、评分答案，也不要求列读取文件/命令或报告检索过程。让子智能体从正常项目指令自行决定是否和怎样检索；主Agent在后台核对可观察工具轨迹，不能靠任务措辞诱发期望阅读。发出前审查提示，含这类引导则改短后再派；已泄题的运行不算无引导验收，保留记录并换新上下文。验证代理只读，主Agent唯一写入；不启动应用/模型/服务、联网或接触资料库/秘密，不递归委派。
4. **按三层检查可观察行为。** 选一至两个代表任务，并加适用的相邻/边界案例。逐场景记录判据、实际读取/返回章节、关键判断及影响，不能只写“质量不高”或“答对了”。不规定唯一检索顺序，不以读完所有链接或文件数量评分；涉及写入才核对归属。关键正文未读、只靠摘要/先验或截断后缺少必要条款，不能标为该范围通过；未读但不影响当前结论的详情只限制后续深入设计。自报“读过”不够，不索取隐藏思维链。
5. **定位原因、修改并复验。** 用轨迹与正文定位任务歧义、入口/召回不足、正文含糊/冲突/遗漏、工具截断/上下文过载或Agent误用。修真正拥有者：导航问题改索引，语义问题改正文，工具问题修工具/读取范围；不统一往AGENTS加约束。Agent判断不足先保留证据、换独立样本核对，不因一次普通方案就改项目要求。每次修正记录失败→原因→改动→候选身份，再用全新子智能体和等价短任务复验失败场景及受影响相邻场景；不添加阅读提示、正确路径或预期结论，不复用已知答案的上下文。
6. **判定与收尾。** 每个场景分别记录“通过 / 未通过 / 未验”及三层依据：所需正文与适用判断支持本次结论、没有影响结果的关键缺口才通过；已观察到关键误判/遗漏为未通过；工具、范围或材料不足以判断为未验。小范围局限可限定通过结论，不能把关键失败改名为局限。所有尝试及旧失败保留，不连续重跑后只挑一次成功、不取平均分冲抵关键失败；同候选结果反复不一致则保留未通过/未验并加强定位。影响大或严重保护增加相邻案例/更强复核。重复无新证据时停止盲目重跑，保存原因与下一验证动作；不无限堆规则或为了收尾降低判据。

有关键未通过/未验时，本批对应文档能力不能宣布验收完成；可交付已验证的具体范围，并明确剩余缺口，不冻结无关工作。主Agent自审不冒充独立验收。结果只证明本候选与实际场景，不保证所有未来模型/措辞，也不代替独立代码审查、产品真实验收或保护测试。

主Agent自行选场景、派发、审查、微调和复验，不逐文件要求用户确认。只有暴露未决定的产品/语义冲突才提出具体取舍。子智能体报告写入/只读建议由主Agent核对后写回；原始失败、场景/判据、候选、代理模型/思考设置、实际轨迹、理解与修复/复验留本任务检查点，相关事故/经验进入既有问题/LESSONS，产品术语和ADR不因这个工程流程另建。验证调用不得无限自我递归：验证代理不再派验证代理；同批协议/记录调整合并，由主Agent对最终候选收口。


## 8. 原有开发入口与局部规则

- `node scripts/handoff-preflight.mjs`是离线只读环境盘点，不代表产品可运行。
- `npm run prototype:work-mode`只打开合成交互原型；[原型交接](docs/design/CORE-EXPERIENCE-PROTOTYPE-20260914.md)。
- `npm run preview:library-canvas`启动正式应用与隔离生成测试库；[正式接线说明](docs/design/FORMAL-LIBRARY-CANVAS-20260914.md)。这些入口均不能代替普通真实profile验收。
- Router可用`npm --silent run context:route -- --task "任务描述" --json`；显式模块用`--module asset-lifecycle`。路由给候选路径/检查，不要求全读全跑；修改治理索引后运行`npm run context:check`和`npm run test-agent-context-router`。
- `.codeindex/tests-map.json`是验证配置集合，不是全部测试清单；新增未跟踪执行源码/命令须显式纳入候选闭包，不将tracked覆盖率当全候选覆盖率。
- 文档维护按需运行`scripts/check-agent-context.py`、`check-adr-router.py`、`check-forbidden-paths.py`、`check-docs-sync.py`，不为纯文档改动跑全产品测试。
- 领域、Issue及分流约定见[domain](docs/agents/domain.md)、[issue tracker](docs/agents/issue-tracker.md)、[triage](docs/agents/triage-labels.md)。
- 默认不读生成物、评测数据集或`src/main/extensions/photoshow/unpacked`第三方内容；相关任务才选范围。
- TASK只在获准实施后记录本请求；只读审查或先提建议时不更新。历史完整记录保持可查。
- HEAD、WIP、候选tree、实际build、平台Runtime与模型资格分别记录；历史generated身份不证明当前进程。

## 9. 本地开发反馈闭环

每次明确开发任务执行：用户结果/范围 → 模块与代码核对 → 相关问题/经验转成检查 → 实现与验证 → 写回问题与证据 → 提炼经验 → 目标完成停止。不创建定时巡检，不自动恢复整个历史队列。

### 读取与写回

`npm run context:route -- --task "具体任务" --json`仍返回模块、源码和验证候选，新增`feedback`：相关未解决问题、分组经验、下一检查及写回位置。`npm run context:check`同时检查记录格式与路由归属。路由读文档、不执行条目文字；记录不提供新的执行授权。预算计入输出元数据，超过条目数或字节预算时延后完整记录并提示回索引读取余项，不截断检查动作；必需上下文仍无法容纳时明确失败。

| 内容 | 权威入口 |
| --- | --- |
| 具体开发问题及当前处理状态 | [DEVELOPMENT-PROBLEMS](docs/agents/DEVELOPMENT-PROBLEMS.md)；链接原始报告 |
| 可复用检查与原因 | [LESSONS](LESSONS.md)，共通/界面/Host/跨端分组，数量足够时再拆详细文件 |
| 当前任务与跨系列责任 | TASK / TASK-REGISTRY，引用问题id，不抄问题全文 |
| 实际能力、候选与资格缺口 | CURRENT-STATE，引用验收报告 |
| 原失败、运行结果与复验 | 本任务检查点，绑定候选、客户端、环境与允许资料/服务范围 |
| 已改变的行为/机制/视觉 | 对应交互规格/模块README/架构/DESIGN，各自保持职责 |

### 问题与经验条目

条目使用`### DAM-PNNN — 标题`或`### DAM-LNNN — 标题`，设置稳定id锚点。紧接四行检索元数据：`- Routes: 现有路由id, 其他id`、`- Group: common/frontend/host/integration`、`- Status: 状态`、`- Check: 可执行的检查动作`。Check是检查要求，不是自动运行的命令。详细正文保存触发、复现、原因、责任/任务、版本、证据与复验；不记录秘密或私人素材。

问题状态为needs-reproduction/open/in-progress/blocked/resolved/not-planned。缺信息、旧报告或静态线索先待核实；认领关联当前获批任务，避免重复修。resolved须有适用复验与正确结果，blocked写明具体依赖。经验为active/superseded/archived；只读相关组，`Routes: *`只用于共通要求。已解决问题及旧经验保留证据，但不默认进入待处理集合。

一次事故一个主记录，可以关联多路由；三处渠道重复报告不算三次事故。经验写条件、动作、原因、事件和证据，依新证据更新，不堆现象。

### 三日期候选与提升

经验可增加下列元数据（旧四项字段继续有效）：

- `Events: [{"id":"稳定事故id","reviewed":"2026-10-15","evidence":"docs/checkpoints/本任务/README.md#具体证据"}]`，JSON数组；reviewed是Asia/Shanghai复盘日期，也接受带时区时间并换算。相同事件重复记录不增加日期；相同id的冲突证据/日期报错。日期必须真实，不补造三次历史。
- `Severity: ordinary`或`critical`。critical用于严重安全、数据损失或越权；须至少一个事件证据。
- `Promoted: docs/code-standards.md#具体规则`，已提升的唯一规范或保护测试引用。只写真实已落实的消费者，不能把标签当保护。
- `Deferral: 暂不提升的具体理由及重新检查条件`，仅指正式规则的提升评估，不延期当前严重风险的立即处置；适用于已达候选条件但需继续评估的经验，不清零事件或删除严重记录逃避提示。

至少三个不同复盘日期出现新的同类事故证据时列为规则候选；critical立即列候选。按根因/缺失保证归类，旧事故重读、重试和多渠道不产生新事件。任务路由在相关经验上返回`promotion`，包含状态、不同日期数、严重性及提升/暂缓引用；它是检查提示，不自动执行文字或授权新产品改动。

候选评估适用范围、反例、技术自主权、现有重复规则和检查消费者。通用保证进入开发规范，局部保证进入模块/保护测试，视觉/交互分别回所属规范。保留原经验事件及提升链接；改变产品取舍仍由用户决定。既有保护和当前事故处理不等第三次，也不按年龄自动归档。

### 验证和预览

真实AI验收允许真实Worker和适用外部推理，仅用现有模型、不下载权重。普通CI的隔离开关不代替真实推理结果。每次涉及UI/UX按DESIGN/交互规格检查受影响正式入口；后端改变可见反馈也适用。缺陷须复现、核对根因并验证修复，无法证明就保留未通过；详见[真实验收](docs/agents/ui-ux-acceptance.md)。

预览材料保存构建身份、步骤、前后截图及适用连续帧/录屏，与问题/报告链接；合成视觉、正式数据链路、Browser和原生结果分别标注。不把旧候选截图、页面可打开或绕过失败路径当通过。已有`start:desktop`/`start:browser`与验收流程承担预览入口；本地记录不自动托管、上传或发布。

项目继续用package.json统一检查与构建，复用现有跨平台CI和模块导航；不为文件名一致再造Makefile、贡献者黑名单或无消费者Docker发布。模块README说明职责、状态权威、执行链、契约、失败与验证，并链接关键源码；子系统可跨多个目录，依赖版本以锁文件为准。


## 10. 文档与候选检查入口

`python3 scripts/check-documentation.py`检查当前权威入口、链接/锚点、子系统/路由及词库唯一性；不扫描依赖/模型缓存或把历史媒体缺失当新证据。`python3 scripts/documentation-governance.test.py`验证链接、候选归属与条款保全检查行为。

`python3 scripts/check-docs-sync.py --paths-file <本任务JSON路径数组> --declarations <按子系统说明契约未变的JSON> --mode phase-summary`只评估明确候选。声明形如`{"asset-discovery":{"contracts":"unchanged","reason":"具体为何契约保持，以及核对了哪些消费者"}}`；有语义变化则更新拥有者正文。无范围时输出NOT ASSESSED，不以其他WIP让检查假绿；默认advisory不阻断，严格模式缺范围会失败。

`check-documentation.py --migration`只用于2026-10-15这次迁移的冻结来源/逐段身份审计，需要本地检查点before.zip，不是每次CI的历史对照仪式。普通CI执行当前结构/导航和治理行为测试，不依赖被忽略的本地ZIP；迁移源文本与去向另有可追溯记录。


## 11. ADR的分类与有界读取

`node scripts/adr-context.mjs route --kind design --topic work-mode --task "悬浮窗交互与数据权限" --json`只返回默认最多3条候选元数据，不读取ADR全文给模型；再由任务读取选中的原文和详细契约。`--limit`可在1–8内调整；延期数量和目录可见，不截断正文求预算。

`--list-types`和`--list-topics`列小型类型/主题目录；未列出的任务类型使用general路径，不当白名单。类型只调关注优先级，主题/影响范围决定相关性。无范围不回退全量Core；无命中提示补范围，不代表无适用决定。历史默认不选，追溯时显式`--include-history`；Proposed仍明确标注，未声明状态不冒称未批准。

分类元数据由.codeindex/adr-index.json维护，29个主题目录只列标题/性质/声明状态；新增或修改决定时同步元数据和对应目录，运行`node scripts/adr-context.mjs check --json`、`node --test scripts/adr-context.test.mjs`和现有ADR/文档检查。该工具不执行文档文字，也不自动改变任何决定/资格。
