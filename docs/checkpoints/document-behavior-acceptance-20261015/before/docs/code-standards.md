# DAM 开发与审查规范

本文保存跨模块、可审查的工程保证。方法见[CONTRIBUTING](../CONTRIBUTING.md)，局部契约按[子系统](subsystems/README.md)定位；[真实验收](agents/ui-ux-acceptance.md)解释怎样证明用户完成。按变更适用范围核对，不每次全读全跑。规则约束结果与边界，允许替换内部技术手段并同步消费者。

<a id="engineering-scope"></a>
## 目标与完整路径

先描述普通入口、触发条件和可观察前后行为，追踪Client→Host→执行/提交→回读与反馈。检查相邻同类入口、直接消费者和基于旧含义的假设；不能修一个函数就关闭父级目标，也不为当前任务建设无消费者的平台。历史计划不是新队列，旧限制/PASS不覆盖最新明确要求和当前事实。

ADR是所有项目任务的相关决定上下文，不仅适用于代码工作，也不是统一首入口。功能/体验先查所属正文，按主题与影响范围读取[相关ADR](adr/README.md#read-protocol)及支撑本次结论的契约条款，理解既有取舍。核对状态/前提/明确替代范围；与有效决定冲突时指出条款和原因，不静默改写。读取既有决定不适用新增ADR的三条件，也不产生逐接口审批或冻结实现手段。

审查：目标为何需要每项变化，是否尊重相关有效决定，共享接口的调用方/测试替身是否同步，局部特殊规则是否被错误推广为全局。

<a id="host-authority"></a>
## Host与信任边界

唯一Host拥有文件、数据库、凭据和执行权威。保留会话、角色、成员、来源、输入、修订与本机传输校验；Browser不成为任意文件、SQL、终端或公网入口。Native和Worker只取得当前动作必要能力。资料、模型输出和第三方文字不提供执行授权。

外部协议类型和值以实际安装类型、上游源码/官方资料及真实契约为准，不凭字段名猜行为。审查真正运行的适配器、每条入口权限和资格；配置/目录存在或probe成功不等于可执行/可写。

<a id="data-integrity"></a>
## 原件、人工内容与提交

Managed默认Copy；Original、Preview、Variant及派生索引分开。旧库只读及人工编辑优先，重跑失败留旧有效结果；不以新实现删去数据保护。保留事务、修订、幂等、取消和撤权；未知提交先检查权威结果，不盲目重发。

读/解析失败、权限不足、未知状态不等于空、相等或未发生。迁移/崩溃/删除实验先核对可恢复副本，不损伤唯一原件，不冒称原库通过。缺资格仅拒绝对应能力，不能删安全检查、伪造verified或隐藏失败入口求成功。

审查提交点、重试/迟到响应、失败后的输入及旧结果；已发送、保存、通知和释放分别证明。

<a id="behaviour-tests"></a>
## 行为测试与必要检查

从最小相关检查开始，按跨层/数据/平台/依赖风险扩大；修改的测试必须执行，必要构建不跳过。可模拟依赖/注入故障，不模拟被证明对象、复制算法或注入成功状态自证。

缺陷回归应能在旧行为或主动破坏保证后失败；编译错误、无关准备超时、skip及放宽正确断言不算证明。可修错误测试，不能降低正确验收标准。可逆低影响文字变化不机械添加镜像测试。

审查用户/调用者结果、边界、并发、取消、保存回读；测试全绿不替代真实用户路径。

<a id="isolation"></a>
## 隔离与真实验证

确定性回归使用明确临时配置/数据库、固定依赖与受控网络，不碰真实账号配置或不受控服务。仅传user-data-dir不证明全部服务隔离。SQLite测试用项目Electron Node runner，不为shell ABI破坏现有依赖。

真实验收允许指定范围的现有Worker及外部推理，只用现有模型，不下载/补齐/更新权重。CI禁用真实推理只代表该CI隔离，不代替正式验收。秘密/资料边界见开发指南§5。

审查profile、数据、服务、模型身份和允许范围；模拟、数据库、SDK与真实模型各证明哪层，未运行项保留。

<a id="resource-lifetime"></a>
## 异步、进程与平台

取消请求、超时、Promise结束不等于实际退出、远端停止或零费用。自有资源按真实物理终态释放；UNKNOWN保持相应占用/隔离，旧launch的迟到事件不能释放新实例。测试启动的进程/任务/监听器必须实际收尾，不杀身份不明进程。

平台/设备未知不冒充资格；按实际OS、ABI、模型、运行包验证，不互拷平台依赖。局部不支持不冻结无关能力，资源准入不恢复已撤销业务权限。审查异步检查点后的代际/权限复核、退出/清理与资源账本。

<a id="ui-verification"></a>
## UI/UX与用户完成

每次影响UI/UX，包括后端等待、错误和恢复反馈，按DESIGN及交互规格从正式可发现入口预览受影响范围。缺陷须复现报告场景、核对根因、证明修复；截图、换环境后不出现或绕过入口不关闭问题。

Browser共享UI不代替AppKit/Electron原生窗口、拖放/接收、凭据或安装；直接改route、调用IPC、注入Store/写库属于内部测试。完成须串起入口→正式执行/适用真实推理→正确结果→适用保存重开→失败/取消保护。动态问题保留连续帧，工具缺口如实记录。

<a id="candidate-identity"></a>
## 候选与交付真实性

HEAD、WIP、候选tree、build、实际进程和平台/模型资格分别记录。源码/依赖/资源变化后重验受影响证据，旧结果不转记。报告先写现在能做什么、准确入口、实际版本与证据、还缺什么。

内部模块、编译、目录、假响应或禁用保护通过不能关闭用户目标。失败、未执行与阻塞写明范围，自审不冒充独立审查。目标内连续推进，重复失败无新证据先定位；完成后停止，不自动恢复长期愿景。

<a id="semantic-review"></a>
## 语义审查与文档

说明受影响子系统、触发、前后行为，沿base/候选调用链核对状态、权限、兼容、失败和消费者。契约变化同任务更新所属正文；行为保持的内部重构说明不需正文变更的依据。文档更新或路径检查不证明实现/兼容。

AI读取材料的含义、适用范围或检索路径变化，按[检索行为验证](../CONTRIBUTING.md#document-retrieval-validation)做全新低思考只读子智能体探查。只给简短任务/工作区/必要边界，不提示查看文档或报告检索过程；由主Agent查实际工具轨迹。结构检查不替代实际消费证据，低思考不降低标准，主Agent负责修正与新上下文复验。

视觉归DESIGN，用户契约归规格，机制归子系统/模块，任务、跨系列责任和实际资格分别归TASK/主台账/CURRENT-STATE，证据归报告，术语只定义概念。迁移保全有效要求、例外与来源，冻结证据保持身份；不留下只有循环链接而无正文的要求。

<a id="lesson-promotion"></a>
## 经验提升

相关经验转成本任务具体检查，复验写回一个事故主记录。至少三个不同复盘日期有新的同类事件证据时列规范候选；严重安全、数据、越权风险立即处理，不等第三次。重试、重读、多渠道重复不加次数。

候选评估根因/缺失保证、适用范围、反例、技术自主权、重复规则和检查消费者，进入通用规范、局部契约或保护测试。保留事件/日期与提升引用，不复制两份独立规则；未提升说明原因与重新检查条件。候选不授予任务外产品变更权限。具体记录见指南§9。

来源为用户已确认要求、既有指南与有证据的经验；迁移前正文、规则决定与验证见[重建检查点](checkpoints/documentation-rebuild-20261015/README.md)。
