# 简短自然任务的无引导检索验收

用户明确要求：不要提示子智能体查看文档/索引/详细内容，让它自行走项目检索链；任务尽量短。本轮修改了CONTRIBUTING验收步骤3–5，并同步开发规范/工程专题：提示只含自然任务、工作区和必要执行边界，不给阅读/检索提示，也不要求列命令、文件或检索过程。主Agent从工具轨迹评估，答对但未检索必要正文不判索引通过。

## 实际派发任务

完整消息与设置见[dispatch.json](dispatch.json)，以下是全部任务正文：

1. 精简合并给AI用的项目约束和索引，给出实施计划。
2. 修正文档标点和Markdown表格对齐，给出处理计划。
3. 想让各悬浮窗进程自行保存工作集并处理文件交付，评估这个方案。

各消息除此仅有候选路径及“只读；仅在该工作区评估，不修改、不联网、不运行应用/模型/服务，不再委派”。没有提示依据文档、查看索引、已有取舍或报告读取步骤。三者均fork_turns=none、gpt-6.1-sol、low，设置由本轮子会话实际turn_context核对。宿主仍注入正常根AGENTS/环境；全新上下文不是去掉项目正常指令。

## 判据与结果

[criteria.json](criteria.json)在派发前基于用户要求和既有数据/Host决定独立保存，不放入候选或子任务提示。主Agent逐项查看实际调用、返回正文及最终回答，见[evaluation.json](evaluation.json)、probe-sessions.json及三个trace.json；只提取工具调用/输出/最终回答，不记录隐藏推理。

- 精简场景：5次只读调用，自行读AGENTS→任务/主题索引→维护正文及工程/来源材料；计划包含唯一正文、原要求/例外保全、检索验证及实际消费者核对。读到了新盲探查规范。较多治理背景阅读是观察到的成本，不宣称最少上下文最优。
- 排版场景：3次只读调用，自行找到维护协议，正确判断纯标点/表格对齐适用结构/差异检查，无需额外语义探查或全产品测试；未因为提示要求验证而作答。
- 窗口场景：4次只读调用，自行走任务/主题→工作窗/双端目录→ADR0489/0485/0491原文→相关子系统及针对性源码；区分呈现优化与Host拥有持久化/授权/交付的边界。没有被提示查既有决定。

三场景均PASS_SCOPED，判的是本候选的自主检索/理解，不等于产品实现或所有未来措辞/模型必然遵循。先前长提示结果不删除、不转记为此次无引导标准通过。
