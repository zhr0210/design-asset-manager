## 用户提出的问题

用户认为 Magpie 的 AGENTS 更像阅读指南：按正在处理的任务引导 Agent 去读相应文档，而把大量规范和上下文保存在其他文件。希望避免在 AGENTS 堆积上下文和约束，影响 Agent 的判断与工程发挥。

这是新的组织与自主性议题，不把此前闭环实施许可扩展为自动删除或弱化现有要求。

## 本轮核对

- 研究使用2026-10-14固定的 Magpie 快照，不代表最新远端文件。其前四节分别导向子系统说明、代码规范、贡献治理和经验。
- 同一份 Magpie AGENTS 后半仍内联了订阅移交插件的实际运行归属，说明它也会把容易修错执行路径的信息放进入口，不是绝对只准链接。
- DAM 当前 AGENTS 已有按任务导航，但还内联工程自主权、保护、执行与完成、文档归属的大段细节；部分内容在 CONTRIBUTING 和真实验收流程已有更完整说明。
- 文件行数或字符数不能单独判断上下文效果。应检查常驻内容是否必要、相关任务能否找到要求，以及规则是否在限定实现手段或重复描述已有目标。

## 已确认：组织与约束分别审视

**组织变化**：将详细方法和适用条件放回相应权威入口，AGENTS 保留任务触发、阅读导航、写回导航与少量通用约定。要求的语义不因迁移丢失。

**约束变化**：判断一项规则是否过时、重复、适用范围过宽、把历史事故推广成全局禁令，或无必要地锁定技术实现。需要时明确取消或改写其具体替代范围；不把这种决定隐藏在文档搬迁里。

用户已明确同时审视两者，分别记录决定，再安排内容归属。后续逐条记录：原要求及来源、当前目的、保留/改写/取消、适用范围、依据，随后确定目标文档、读取触发和检查消费者。移动文字不自动代表取消语义，保留语义也不要求每次启动全文加载。

## 已确认方向：重复经验进入正式规则候选

用户认为跨上下文工作容易重蹈覆辙，需要保留“三个不同复盘日期重复出现”的经验提升机制。按这一方向收敛如下语义：

- 每次发现立即处理当前问题并记录有证据的经验；第三次不是首次修复或首次记录的门槛。
- 同类问题在至少三个不同复盘日期有新的复发证据，进入正式工程规范候选。日期集合不要求连续，使用项目约定时区Asia/Shanghai。
- 一个未解决事故反复被阅读、同一失败反复重跑、三个渠道重复报告，不产生三次独立复发。复盘日期对应新的事件/变更证据，事件id与日期分别保存。
- “同类”按根因或缺失保证归类，不只按错误文字。类别拿不准时保留待核实，不用计数制造确定性。
- 达到门槛后应主动评估候选，而不是直接向AGENTS追加全局禁令。评估范围、正反例、技术自由度、重复规则与具体消费者；适合自动验证的落实到测试/工具，需解释的规则写入对应规范。
- 严重安全、数据损失或越权风险立即处理并补保护，不等待三次。既有明确保护也不重新等待累计。
- 同一保证有唯一规范归属。经验档案保留事件、日期和升级后的引用，避免复制两份长期独立维护的规则。

当前CONTRIBUTING第9节仍写“不强制按出现三天”，现有经验元数据也未实现上述候选提示；本节是新决定记录，待本轮访谈收敛后在明确范围内替换旧条款。不能声称候选识别工具已经生效。

这项机制沿用已确认的任务触发闭环：在相关任务的检查、修复和结束复盘中更新记录，不新增夜间定时巡检。没有新事件证据时不增加日期计数。

## 拟议职责方向

| 内容 | 倾向归属 |
| --- | --- |
| 当前任务读什么、结果写哪里、谁是权威 | AGENTS 精简入口 |
| 工程自主权、协作/WIP和变更审查的详细方法 | CONTRIBUTING 对应章节 |
| 真实资料/服务范围、正式入口、模型、UI检查与完成证据 | 真实验收流程；AGENTS说明触发时机 |

| 视觉与通用交互呈现 | DESIGN；任务涉及UI时读取 |
| 事故与可执行检查 | 本地问题和LESSONS；现有context路由按相关性消费 |
| 旧限制、阶段许可或被后续决定替代的要求 | 核对来源和替代范围后归档，不混作常驻当前规则 |

关键不是把约束从 AGENTS 挪到另一份每次必读的大文件。要明确什么时候读哪一段，并让启动、实施、验证、写回阶段实际消费它。

## 已确认：启动时保留四类简短约定

方案A：AGENTS以任务导航为主，仍保留少量开工前必须明确的共通约定，例如目标内工程自主权、用户资料/秘密保护、其他WIP保全，以及不能用未验证结果宣称完成；细节进入有触发条件的相应文件。

方案B：AGENTS只保留路由与文件权威，共通约定也完全链接到其他文件，必须确保相关动作前读取到位。

用户选择方案A：保留简短的工程自主权、资料与秘密保护、其他WIP保全、结果真实性要求，其余详细规则按任务导航读取。没有固定行数指标，以每项是否必须开工前知道和是否可稳定导航为准。
