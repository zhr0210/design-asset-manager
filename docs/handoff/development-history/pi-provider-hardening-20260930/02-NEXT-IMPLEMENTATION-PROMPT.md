保留现有WIP、index和无关文件；一个写者。先保存允许目标的前态摘要。当前实际源码优先于历史快照，测试及验收标准不能为变绿而降低。

## 顺序

1. 将SDK认证能力和DAM产品许可分开。修复F04：Anthropic订阅OAuth不作为正常可执行选项，UI/Main均限制，保留API入口和旧数据；其他Provider不得被错误连带禁用。Google在同等传输保护闭合前明确不可执行，而不是泛化为账户错误。
2. F01调用真实Google适配器建立离线红灯；实现或选定满足现有目的地/重定向/取消/原始字节限制的受支持传输。无法在本批准范围正确接通时交付清楚的安全不可用状态，不删除保护凑PASS。
3. F02验证当前OpenAI真实登录入口的options契约。在Main持有稳定非个人身份host ID；同时对照当前官方注册、账号身份、client复用和令牌验证要求。不能只加临时UUID。若需升级Pi或新增外部依赖，应先记录明确差异和新增授权，继续其他不依赖部分。
4. F03为text/secret/manual_code/select建立窄契约，保留有界选项id/label；Main校验本操作允许答案。真实Codex首个select经Worker/Main/React走通，再覆盖取消、过期、迟到答案和两种登录分支。
5. F05/F06核对真实OAuth适配器网络与副作用。登录不是模型策略写入许可；无明确授权时合成服务的policy POST为零。认证、刷新、目录和推理分别定义受控网络范围与预算，避免全局粗暴替换fetch。
6. 运行受影响真实临时Host与凭据/退出回归、类型检查、构建。改Worker须重新封印，旧摘要不能当新证据；不通过重新封印隐藏额外依赖或未知源码。
7. OBS01仅先做资源校验的冷/热与取消基准；未明确接受的缓存优化不绕过依赖完整性。性能问题不变成再造全局Runtime平台的理由。

## 必须验证

- 每个被产品宣称支持的Provider/认证/动作组合，至少一项执行实际固定SDK入口的隔离测试。Mock可以替代网络，不可以替掉正在验证的Provider前置条件。
- Google不再在未发送前发生意外自定义fetch错误；超大响应/重定向/取消保护同样有效；或明确被准入表禁用。
- OpenAI缺ID/错ID明确拒绝；稳定ID跨Worker保持；新账号未完成身份验证不替换旧账号。
- Codex选择项可见，答案只接受当前合法ID，非密码输入框代替所有prompt。
- 未获准模型策略写入为零；认证失败不擦除旧凭据；刷新/登出/迟到操作不跨账号。
- 相同失败不会增加隐式推理重试；取消不冒称远端费用停止；旧结果/手工编辑/幂等效果保留。
- 证据绑定最终源码和封印；缺真实账号继续NOT_RUN。禁止把未执行的命令或被工具阻止的调用记为PASS。
