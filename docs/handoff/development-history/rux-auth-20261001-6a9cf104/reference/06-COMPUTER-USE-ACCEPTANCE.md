# Computer Use 是交互验收的硬门槛

## 1. 证据类型不可互相替代

本次用户要求适用于**最终用户路径和交互验收**。单元、状态机、SDK、Host/SQLite、IPC安全测试继续用代码，它们承担不可见的数据与安全验证。禁止把“只用Computer Use”误解成删除这些后台测试，也禁止把这些测试的PASS当作CU的PASS。

统一记录：
- `CONTRACT_PASS`：纯逻辑、实际SDK或后台契约的限定通过。
- `INTEGRATION_PASS`：正式Main/Preload/Renderer与Host接线通过，可能存在代码准备或只读状态观测。
- `CU_PASS`：指定完整用户任务，仅由可见屏幕与原生鼠标/键盘完成。
- `REAL_AUTH_PASS`：指定真实账号连接验收，与CU和推理分别记录。
- `BLOCKED_TOOLING / NOT_RUN / FAIL / STALE`：不得转换为PASS。

没有屏幕观察及原生输入工具时，编码AI仍可做已授权的安全代码工作，但必须在交付写 `BLOCKED_UX_ACCEPTANCE`。不能因为“browser plugin不可用”改用evaluate后宣称人为验证完成。

## 2. CU执行通道

允许：实际屏幕截图/屏幕视觉定位、鼠标点击/拖动/滚动、键盘输入与快捷键、操作系统原生菜单和文件选择器、用户在系统浏览器中的厂商认证。辅助功能信息可以帮助识别当前屏幕上真实可见控件，但不得用隐藏DOM/测试ID/内部路由完成动作。

禁止作为CU动作：
`page.goto`进入内部路由、改location.hash、React navigate注入、executeJavaScript、page.evaluate、直接electronAPI/IPC、调用store.getState/setState、写localStorage伪造状态、直接SQL生成结果、通过DOM selector/locator自动跳到未见控件、force click、合成登录成功、屏幕无入口但用快捷内部脚本调用功能。

相同代码操作可存在于独立后台测试中，但必须单独runId/证据类型，不能把它们混在一次CU轨迹中。测试旧深链兼容也可用代码做路由契约，不计“新用户能找到入口”。

## 3. 夹具与普通启动

使用独立受控测试profile，预先建立生成图片目录；这是允许的环境准备。测试“创建/打开资料库”时必须通过界面与原生选择器完成，不能先调用Host.create再说创建流程通过。

某用例明确要求已有库时，可准备受控fixture，但记录生成方法、数据范围和起始状态。不能在执行轨迹中直接把应用切到待测页、预填已登录token或跳过错误。

从正常启动落点开始；不以加载 `#/ai-console` 的测试入口启动。记录实际app可执行/构建identity、profile类型、平台、分辨率、DPR、主题。开发热更新、测试构建、真实用户启动的副本分别标明。检查入口变更必须验证实际运行二进制/构建不是陈旧副本。

## 4. CU证据格式

每例记录caseId、buildId、前置条件、执行人/工具、开始截图、逐步动作、观察结果、结束截图、异常、敏感信息处理和结论。

动作条目至少：sequence、timestamp、screenBefore、目标控件可见文字/位置描述、input(type/click/key/scroll)、screenAfter、结果说明。只有“点击成功”日志没有屏幕前后不能证明目标可见且可操作。

后台证据可在动作完成后由独立只读检查验证持久结果，但不能反馈给CU操作者作为隐藏导航捷径。比如CU保存后检查SQLite字节，属于补充数据证明，不是CU动作。

账号敏感页面不得全屏无过滤录制。浏览器URL查询参数、密码、邮箱、验证码、回调code、token均需在采集时遮挡或暂停录制并注明敏感区段；不先保存带秘密原片再上传。敏感录制暂停期间不编造未观察动作，不要求用户把授权URL粘贴聊天。

## 5. 必测用户任务（具体案例以JSON为准）

### 导航与归属

U01 首次未开库，从普通首页发现并进入AI连接，不创建库。
U02 已开空库，进入AI和返回素材页，空库提示不遮挡全局入口。
U03 开库失败，界面展示恢复状态，账号设置仍可进入；不修改失败源文件。
U04 关闭资料库后，全局AI/设置/帮助依旧可见。
U05 1024宽度下顶部拖动区域/弹层不遮挡AI按钮。
U06 1440宽度及明暗主题路径一致。
U07 仅用Tab/Shift+Tab/Enter/Escape进入AI、退出浮层并恢复焦点。
U08 从素材检查器“配置模型”进入指定连接/任务页，再返回相同素材、筛选、文件夹、草稿和滚动位置。
U09 原生卡片“配置AI”返回主窗口统一入口，不跳旧编辑器。
U10 任务中心中下载与已有AI任务能找到正确控制，库内计划与执行状态分开。

### 连接与认证

U11 新建本机连接，不要求理解Pi/legacy，也不静默携带别的账号秘密。
U12 编辑旧连接后ID与已保存凭据关联保留；取消dirty编辑可返回原值。
U13 常用API连接的“安全保存”清空输入，不回显密钥；只读摘要不泄露。
U14 点击Continue with ChatGPT后流程起点清楚，看到等待浏览器与取消入口。
U15 在浏览器回调后，应用先显示验证/保存中；不能提前显示已连接。
U16 合法拒绝授权快速终止，有可理解提示，不等待五分钟才反应。
U17 用户取消，浏览器迟到返回不能替换旧账号或恢复操作。
U18 离开连接页再返回，合法登录仍由Main持有，用户能继续或取消；不是重新创建尝试。
U19 回调未到达，提示检查同机浏览器/重新授权，而不是让用户猜端口。
U20 token交换/签名验证/保险库失败各显示正确阶段，原账号保留；故障由独立合成后台设置，CU操作不造假。
U21 身份成功但无plan权限，明确区分，不自动图片调用。
U22 登录成功后重开页面、退出并重启受控app，账号状态和权限仍正确。
U23 目录可读但模型验证失败，分别显示；配置本身不触发图片推理。
U24 选择其他连接/删除连接/重新登录时，过时答案和旧事件不污染新状态。

### 核心素材与清理回归

U25 通过原生文件选择器导入生成图，原件不移动；从列表能检索与查看。
U26 人工标签、描述、OCR修订可保存，模型缺失不阻塞。
U27 文件夹与色板仍在文件夹视图，新增/返回路径清楚。
U28 工作集创建、打开原生窗口、关闭恢复；移除成员不删素材。
U29 回收站恢复，不能把“移除工作集成员”误当删原件。
U30 旧控制台已迁内容在新归属可达，旧默认页面不出现永久不可用安装/清显存按钮。
U31 帮助页能读取当前buildId与安全诊断，导出不含秘密或原件路径。
U32 所有新全局入口在返回导航后保持一致，无新增隐藏配置岛。

### 真实账号专题（需要用户辅助，单独权限）

A01 指定账号在DAM所在机器系统浏览器完成认证；观察真实回调、应用验证、持久状态。
A02 重启同一受控profile确认账号状态，不进行模型请求或读取素材库。
A03 用户撤销或登出后本地状态正确，不绕过授权用旧token继续。

真实账号未运行时，上述A例保持NOT_RUN。合成U14–U24通过不能使A01变为通过。

## 6. 可用性失败判定

以下任一项出现即失败：需要操作者知道内部路由；按钮只有代码能触发；入口只能在特定已有库出现而无说明；登录等待阶段没有反馈；失败文案无法给出安全下一步；账号显示成功但没有持久提交；同一设置在两个编辑器中冲突；返回配置丢失素材草稿；截图与实际执行构建不匹配。

不以“我知道怎么用代码进去”或“点击aria locator没有异常”为修复成功理由。

## 7. 合理的自动化与人类评审分工

编码Agent运行可重复契约测试；CU验收Agent只收到任务意图和公开UI规范，不预先给它内部route或testId完成任务。用户只介入真实账号密码/二次验证、重要产品取舍和删除清单批准。主审查者结合屏幕轨迹与后台数据证据签收。

如果工具缺失，输出准确阻塞清单、已经完成的代码与测试，不暂停无关安全工作，也不自行放宽门槛。下一会话从保存的检查点继续；不能重跑已发生的真实登录或付费请求来“恢复状态”。
