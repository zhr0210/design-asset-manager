## 正式调用与限定资格

Main在创建Host前建立同一个VisualAdmission，传入production dependencies；development使用当前固定bundle，packaged路径使用resources中的最小部署目录。Host的storage seam仅在Main内部组合，Renderer/Preload/public IPC无新增通用SQL、文件或process权限。六个现有意图为intent、batch、execution enable、decision upgrade、background analysis、background OCR。

- Windows x64；实际本地固定可写NTFS与held exclusive lease。初始完整source镜像 ≤1048576 bytes，现有DDL growth ≤4 MiB；mutable source native生命周期上界5 MiB，不扩大镜像资格。
- exact SQLite3.53.1/sourceId/native addon/bundle，来源MAIN win32 VFS句柄、保留no-reparse组件、单link/regular对象及hash/metadata/connection身份检查；完整旧版schema/identity/FK验证后才传helper，before-DDL重验。空间以真实volume测量，fault hook只能缩减额度。
- 原子Job启动在launcher首条CLR指令前；private commit限额128 MiB/process、256 MiB/job；RSS为观察高水位而不是硬RSS门。现有UNKNOWN或double hold/suspension仍拒绝，唯一controller hold只借用不可释放的资源能力。
- target/status由保留parent相对NtCreateFile/no-reparse/create-only创建，同句柄写/flush/readback，HELD贯穿实际事务结论。Runtime不编译/下载/安装，不依赖测试guardian或fixture。
- afterBackup后先查取消，再原生拒既有WAL/SHM并CREATE_NEW零字节journal，早于任何新SQLite read。事务内同值user_version强制打开实际journal，FILE_CONTROL取得win32句柄，身份重叠核对后才关guard并进DDL。只复制这一次journal对象的方法表观察原xClose，不改共享VFS、URI或连接。
- 未handoff取消仅清理身份、link1、size0、来源SHA未变的自有空reservation；先known close，再relative DELETE open重验并同句柄SetDisposition，不用DELETE_ON_CLOSE/path unlink。handoff后仅验证SQLite journal关闭与名字消失，不自动删后续名字。
- recordCommit在现有同步Main SQLite事务中写不可变协议marker；finish(committed)等target/Job、pending I/O和source handles的物理退出。COMMIT事实先于pragma恢复/ACK hooks；ACK丢失用原requestId当前scope核对，不重迁移。精确取消reason仅在known-close后恢复既有业务拒绝；无关错误仍失败，UNKNOWN保账/poison/quarantine，不重试旧numeric handle。

productionQualified=true仅指上述schema profile；formalAdapterWired=true。restoreAllowed=false、namespaceMetadataQualified=false，尚无永久不可变/物理断电/任意同用户恶意writer或loader隔离资格。缺bundle、漂移、ABI/native/source不符、超界或不支持平台仍明确拒绝；普通库操作不由这一局部资格统一冻结。macOS沿用既有Adapter，本轮未执行macOS验证。
