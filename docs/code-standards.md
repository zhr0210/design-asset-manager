# DAM 开发与审查规范

本文保存跨模块的工程保证，实施者和审查者都按受影响场景使用。每条给出适用范围、可执行检查和证据入口；入口中的测试是定位线索，不代表本次已经执行或通过。实际命令以[package.json](../package.json)为准，执行方法归[CONTRIBUTING](../CONTRIBUTING.md)，局部机制归[子系统/模块](subsystems/README.md)，用户完成归[真实验收](agents/ui-ux-acceptance.md)。

先沿用户结果确定适用条目，再检查源码、调用者和结果。既不只看改动行，也不每次全读全跑。规则约束结果和边界，允许替换内部实现；不增加逐文件审批、不自动启动历史队列或对外发布。审查意见应指向具体保证、触发场景、观察到的偏差与证据；只写“违反规范”不能替代问题说明。

### 扩大回归范围的触发条件

| 变更触发 | 需要补查的范围 | 验证要求 |
| --- | --- | --- |
| Shared Client、IPC、事件、schema、错误分类或权限谓词 | 全部受影响正式调用者、测试替身、相邻分支和注册保护；适用的双端及持久化兼容 | 核对完整数据形状、错误/取消/旧版本分支；运行相关契约/集成组，数据变化验证保存重开与迁移保护 |
| 共享组件、选择器/class、导航生命周期、CSS能力或布局断点 | 所有受影响页面/状态、适用主题/宽度/键盘/草稿；DESIGN与交互规格 | 跑受影响UI组并从正式入口预览；影响全局或无法可靠缩小范围时扩大至对应完整UI组，不仅本页。Browser不能替代原生专项 |
| Worker/任务/计时器、队列、超时或资源计算 | 所有受影响生产者/消费者、并行任务、迟到响应、取消/退出/恢复及阈值边界 | 用可控顺序/延迟及负载检查；执行生命周期/资源相关组，核对测试结束后无自有残留 |
| 依赖、锁文件、构建、原生桥接或打包资源 | 受影响平台的类型/构建/ABI、实际产物资源闭包与启动入口；适用安装/升级 | 源码构建与目标平台运行分列；交叉构建不证明安装可用，缺目标平台保留对应资格缺口 |

不是每次运行所有长期检查。选择较小范围需用调用/依赖证据说明为何足够；本轮无关产品检查不因文档改动被自动启动。
