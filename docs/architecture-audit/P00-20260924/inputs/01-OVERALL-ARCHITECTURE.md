## SYS-01｜总体架构决策

### 1.1 一句话定义

**模块化单体业务宿主 + 持久化分析任务 + DAM 设备资源协调器 + 隔离计算进程 + 可替换推理后端 + 可追溯结果及可重建检索。**

这里的“设备资源协调器”统一管理 DAM 发起的工作负载，并观察设备压力；它不是操作系统调度器，不能控制或保证任意其他应用的资源。

保留 Electron / TypeScript / React / SQLite 的整体形态，先复用已有 Library Host、Capture、OCR、工作集与权限验证。以接口接入不同 Runtime，不要求所有模型使用同一个引擎，也不要求一个业务模块对应一个进程。现有选型和正式调用关系见 [S00 §4–6]。

### 1.2 三个方案的取舍

| 方案 | 收益 | 风险/代价 | 决策 |
| --- | --- | --- | --- |
| 保留现有宿主，逐步模块化 | 继承库安全和已验证链路，可边整理边增加功能 | 需要兼容入口、来源映射和一段迁移期 | 主路径 |
| 独立本地 AI 守护进程 | 未来可多客户端共享 Runtime | 新增认证、安装、进程托管、库授权与升级组合 | 保留将来抽出的边界，不先部署 |
| 全面换桌面栈或微服务化 | 部分模块可能独立优化 | 不能自动解决任务、授权、质量，重建成本大 | 无源码/性能证据时不采用 |

### 1.3 不可破坏的不变量

I01 导入默认 Copy，不静默移动、覆盖、删除外部原件。  
I02 Original、Preview、Variant 分别拥有身份、所有权和来源。  
I03 Managed、Eagle Connected、Legacy Read-Only 三种库不混写。  
I04 用户描述、确认标签、OCR 修订和组织关系优先于 AI 重跑。  
I05 AI 标签可直接服务检索，但仍是带来源的建议；反推不是恢复原始提示词。  
I06 服务配置、API Key、可连通状态均不等于上传授权。  
I07 AI 失败或资源不足不阻塞基本入库、浏览、词法搜索和复用。  
I08 工作集是引用，关闭窗口或删除工作集不删除素材。  
I09 任务意图可持久化，库会话/执行授权不可作为永久权限保存。  
I10 模型完成输出不等于结果有效，结果有效不等于已经提交。  
I11 Runtime、权重、执行配置、能力就绪和质量验证是不同对象。  
I12 参考实现、历史 Accepted ADR 和构建成功不是正式交付证据。

I01–I08/I10–I12 延续并细化 [S00 §2.2、5.2、7.2、10]；I09 是断点恢复需求下的目标设计。[U01]

### 1.4 不先决定的事项

不预设最低硬件、资料库性能上限、默认模型大小、具体云厂商、内存预留默认百分比或最终向量数据库。均通过后面的配置契约、比较实验与用户取舍确定。架构包中的数值测试目标是建议验收参数，不是已达成性能。

## HOST-03｜进程、目录与生命周期

### 3.1 运行结构

```text
Renderer / 原生参考窗口
        │ 窄 Preload：校验后的数据契约
        ▼
Electron Main：可信控制面 / Composition Root
  ├─ Library Host：身份、lease、授权、schema、事务提交
  ├─ 领域应用服务：收录、组织、笔记、工作集、素材生命周期
  ├─ Analysis Orchestrator：能力计划、任务推进、结果验证
  ├─ Job Scheduler：队列、优先级、恢复、超时与重试
  ├─ Resource Governor：遥测、准入、预算、让出策略
  ├─ Runtime Supervisor：托管进程、模型驻留、健康检查
  ├─ Egress Gateway：目标验证、授权、限流、成本
  └─ Query/Projection Service：数据库读取、索引投影、分页
        │                     │                     │
        ▼                     ▼                     ▼
隔离图片/索引计算       托管模型/OCR进程       外部服务/已授权云端
   无库写权限              无库写权限           无库访问权限
        └───────── 结构化结果与统计 ───────────────┘
                              ▼
                    Host复核 → 事务 → Outbox
```

**模块不是进程**：最初可以在 Main 内实现轻量控制逻辑；图像解码、长时间计算和大索引工作才隔离。utilityProcess 可用于 Node 工作进程；Python/原生 Runtime 由适合的平台进程适配器启动。不能用 utilityProcess 文档推断它直接托管任意 Python，也不能把独立进程自动当成安全沙箱。[S19]

### 3.2 建议责任树

```text
src/main/
  composition/                  启动、装配、退出；不放推理策略
  library-lifecycle/            保留 Host、会话、权限与数据权威
  capture-intake/                保留 Candidate/Promotion 和 Copy
  managed-download/             保留下载传输与恢复 Journal
  image-tools/                  受控变换、另存副本
  organization/                 标签/文件夹/色板应用服务
  notebooks/                    图片笔记、草稿和并发修订
  work-mode/                    工作集、成员权限、原生窗布局
  assets/                       读取投影、生命周期门面；不另造写库连接
  ai/
    capabilities/               能力定义与结果契约
    planning/                   一键计划、子任务、合并/拆分
    recipes/                    输入策略、提示、结果/语言/质量规则
    profiles/                   不可变执行配置、兼容候选选择
    providers/                  请求/响应适配，不拥有业务保存
    evidence/                   验证、来源、当前有效结果选择
  jobs/
    journal/                    任务意图、尝试、检查点
    scheduler/                  优先级、重试、公平性、背压
    recovery/                   崩溃恢复、重新绑定与远端状态核对
  resources/
    telemetry/                  平台/Worker读数及数据可信度
    policy/                     用户预算、压力状态、迟滞
    admission/                  原子多资源许可
    feedback/                   峰值估计校准和决策解释
  runtimes/
    supervisor/                 托管生命周期、模型驻留、故障隔离
    adapters/                   各Runtime可控制能力
  model-library/                权重/可执行制品、验证与组合目录
  egress/                       授权、服务目标、密钥引用、成本
  artifacts/                    受控派生物、来源、缓存、GC
  search/                       查询服务、FTS/向量投影、混合排序
  design-assistance/            受控设计辅助工作流与提议
  observability/                trace、错误、健康状态、诊断导出
  integrations/                 Eagle/Legacy 等边界，不默认通用 SDK
  platform/                     OS、路径、文件身份、密钥、原生能力

src/shared/
  contracts/                    IPC/Worker/未来移动端序列化契约
  domain/                       不依赖Electron/数据库的领域类型和规则
  workflows/                    纯计划/投影；不作为持久业务权威

src/preload/                    主窗/工作窗/卡片各自窄方法
src/renderer/                   现有表面；Store仅保存展示/交互状态
ai-service/                     先保留，逐项映射旧代码与正式OCR
workers/                        新隔离计算仅在实际接线时创建
```

以上是目标逻辑布局，不要求立即改名或建立空目录。旧入口用兼容适配渐进转接，真实模块路径由 P00 审查决定。不得同时建立 `assets` 和 `library-lifecycle` 两个素材写入权威。

### 3.3 生命周期所有者

| 对象 | 唯一主要所有者 | 结束条件 |
| --- | --- | --- |
| 库连接/独占 lease | Library Host | drain 完成、已开始提交收敛后释放 |
| 作业意图 | 库内 Job Journal | 任务终态或经策略归档 |
| 作业执行尝试 | Analysis Orchestrator | 提交、取消、失败或失效 |
| 模型进程/驻留 | Runtime Supervisor | 验证已卸载或进程退出 |
| 预算账本 | Resource Governor | 对应消费确实消失后归还 |
| 网络调用 | Egress Gateway | 终态/超时；可能仍需核对远端状态 |
| 窗口授权 | Window/Library Scope | 关闭、成员变更、关库、会话撤销 |
| 索引投影 | Projection Service | 代际替换或库关闭 |

资料库持久任务与应用级资源管理分离：应用级模型下载可以独立于开库；针对已关闭库的分析不得偷偷继续。

## CONTRACT-04｜公共契约与依赖规则

### 4.1 十个必须区分的对象

| 对象 | 负责的问题 | 不负责 |
| --- | --- | --- |
| Capability | 用户需要什么结果 | 模型路径/进程管理 |
| AnalysisRecipe | 输入、提示、验证方法是什么 | 瞬时资源情况 |
| ExecutionProfile | 用哪组模型、Runtime与参数 | 库权限 |
| BackendDescriptor | 后端支持/控制/隐私能力 | 用户已经授权什么 |
| AnalysisJob | 对什么素材做什么、是否完成 | 活跃 GPU 状态 |
| ExecutionAttempt | 本次实际模型、配置、远端请求 | 永久覆盖用户数据 |
| ResourcePermit | 当前可占用哪些资源 | 素材读取与网络授权 |
| InputGrant | 可读哪些受控输入、有效多久 | 任意原件路径 |
| EgressGrant | 向何处发送哪些内容和预算 | 任意服务自动 fallback |
| AnalysisEvidence | 有效结果、来源、质量与输入 | 用户最终确认关系 |

### 4.2 契约形式

建议把跨语言/跨进程的数据契约作为单一来源，优先评估 JSON Schema 2020-12；TS 类型和 Python 校验从其生成或通过同一夹具校验，不各写一套逐渐漂移。[S24]

纯内部函数不必全部 JSON 化。内部 `AbortSignal`、数据库事务句柄、文件句柄不能序列化到 Renderer。IPC 接口使用明确方法，不暴露任意 channel、SQL、路径或 shell。

```typescript
// 目标契约示意；不是可直接替换现有代码的已验证实现。
type CapabilityId = 'tags' | 'caption' | 'ocr' | 'prompt-reverse' | 'embedding';
type BackendOwnership = 'dam-managed' | 'user-managed' | 'remote';

type Result<T> =
  | { ok: true; value: T; traceId: string }
  | { ok: false; error: {
      code: string;
      category: 'validation' | 'permission' | 'resource' | 'backend'
              | 'quality' | 'storage' | 'conflict' | 'cancelled';
      retry: 'never' | 'after-condition' | 'bounded';
      safeMessage: string;
    }; traceId: string };

interface AnalysisIntent {
  libraryId: string;
  assetIds: string[];
  capabilities: CapabilityId[];
  trigger: 'automatic' | 'manual' | 'backfill';
  reuse: 'reuse-valid' | 'force-new-run';
  clientRequestId: string; // 去重一次提交，不是永久禁止重跑
}

interface BackendDescriptor {
  id: string;
  ownership: BackendOwnership;
  executionLocation: 'verified-local' | 'remote' | 'unknown';
  capabilities: CapabilityId[];
  supportsCancellation: 'confirmed' | 'best-effort' | 'none';
  supportsResidencyControl: boolean;
  supportsUsageQuery: boolean;
  contractVersion: string;
}
```

共用 `Result` 只统一外层错误语义；OCR 空结果、检索无命中、资源等待不能全都变成异常。旧 `ok/value` 和 `success/error` 由兼容适配承接，不让一次修改扩散到全部调用方。[S00 §11 A11]

### 4.3 主要端口

| 端口 | 最小职责 | 约束 |
| --- | --- | --- |
| LibraryAccessPort | 当前库权限、资产快照、提交检查 | 不返回可转交外部Worker的DB连接 |
| AnalysisCommandPort | 提交/取消/重试/查询任务 | 宿主验证范围；Renderer不能指定任意模型文件 |
| InputMaterializerPort | 生成受控预览/裁剪/分块 | 像素、字节、时长和来源限制 |
| InferenceProviderPort | 探测、推理、取消、统计 | 返回不可信结果；不自行写库或换后端 |
| ResourceAdmissionPort | 原子申请/调整/结束许可 | 不因超时自动假设内存释放 |
| RuntimeControlPort | 托管启动/驻留/卸载/核验 | 外部服务权限单独表达 |
| EvidenceCommitPort | 验证后幂等提交和有效结果选择 | 重新检查会话、内容版本、执行epoch |
| SearchQueryPort | 分页、过滤、命中理由、索引状态 | 不要求Renderer持有全库 |
| ToolProposalPort | 搜索/证据/提议/确认应用 | 不允许Agent直接无限制写入 |

### 4.4 依赖方向

Domain/Contracts 不依赖 Electron、SQLite、HTTP、具体模型 SDK。能力与任务模块依赖端口；Adapter 实现端口；Composition Root 负责注入。资源模块不知道如何生成标签；Provider 不知道如何修改文件夹；Search 不成为素材原件权威。

测试和依赖规则要可执行，但不追求为每个函数建立抽象工厂。出现第二个真实实现、需要隔离副作用或明确跨权限边界时才引入接口。

## AI-05｜推理后端与前沿技术路线

### 5.1 后端组合

| 后端 | 目标角色 | 接入阶段 | 不作出的承诺 |
| --- | --- | --- | --- |
| llama.cpp + 已验证视觉模型 | 桌面基线，先保留原有真实基准 | 优先 | 旧 b11057 自动具备最新参数 |
| MLX-VLM | Apple Silicon 对照后端 | 独立验证后接入 | 任意模型都更快、更省内存 |
| ONNX Runtime / Windows ML | OCR、Embedding、分类/检测专用路径 | 独立验证 | 所有 Windows 都有可用 NPU，所有算子都加速 |
| Ollama / LM Studio / 兼容服务 | 用户管理的本地接入 | 复用Provider契约 | DAM可随意关闭服务；localhost保证不外发 |
| 云 API | 资源不足/用户选择时的授权路径 | 独立外发与预算 | 参数、结构化输出、取消在所有厂商上一致 |
| vLLM / SGLang | 未来自托管服务候选 | X04 | 必须安装到桌面或只支持服务器 |

机制参考：[S01–S03、S06–S08、S10–S11、S16–S17]。Windows ML 文档区分基础 CPU/DirectML 支持与需 Windows 11 24H2+ 的硬件优化 EP；不得合并成一个“全部支持/全部不支持”的结论。[S07]

### 5.2 普通模式和高级模式

普通模式使用版本化 `VerifiedPreset`：模型、配套投影、Runtime、OS/架构、能力、ExecutionProfile、测试证据和限制共同组成。不是仅显示某个模型名字。

高级模式允许外部服务、自定义模型/参数和显式实验开关；仍经过输入校验、权限、预算和能力验证。未知参数不能静默忽略后宣告生效。配置手册按后端版本记录支持、默认、范围、失败表现和恢复方法。

### 5.3 加速采用顺序

| 层次 | 机制 | DAM 放行方式 |
| --- | --- | --- |
| 减少无效工作 | 不默认反推、结果复用、独立重跑、能力化输入尺寸 | 确定业务语义，负向回归 |
| 执行复用 | 同模型短窗口批量、视觉特征/前缀缓存、避免频繁换模 | 键隔离、内存核算、命中正确性 |
| Runtime 优化 | 支持的高效注意力、量化、分块预填充、线程/批次调整 | 每个实际组合对照质量与体验 |
| 实验优化 | 推测解码、MTP、低位 KV/TurboQuant、特殊缓存 | 默认关闭；版本锁定，实验报告后选入配置 |

llama.cpp、MLX-VLM、vLLM 的机制并不自动等价；某种缓存压缩率也不等于整个应用峰值下降幅度。TurboQuant 的作者介绍与 vLLM 的特定实现研究可作为取舍参考，不继承任何通用“无损且更快”保证。[S01、S03、S16、S28–S29]

每次只改变一个主要因素；分别测冷加载、首结果、总耗时、峰值、后台交互退化、质量、取消与卸载。短标签和长反推分别评估。

## AI-06｜能力计划、分析配方与执行配置

### 6.1 用户动作转为能力计划

默认基础计划为 `tags + caption + ocr`；高级反推只由用户触发。单项与一键共用相同能力实现，不复制两套业务代码。[U01]

```text
Promotion成功/用户手动/历史回填
  → AnalysisPolicy 检查自动分析与范围
  → Planner 展开逻辑任务
  → 复用有效结果或创建新任务
  → 排队时持久记录 intent + recipe选择策略
  → 执行前选择具体profile并冻结attempt快照
  → 准入、输入、推理、验证、各能力独立提交
```

任务入队不触发隐式下载或云上传。缺模型时进入等待条件；新导入素材仍然可用。自动策略首次启用的授权/说明可以覆盖明确范围内的连续后台任务，不要求每张图片弹一次确认。

### 6.2 逻辑独立与物理合并

标签和描述可以共用一份输入、一个驻留模型，或在条件一致时合并请求。合并条件至少包含：库权限、素材版本、授权范围、模型/配方兼容、优先级/截止时间和恢复策略。初期不跨资料库合并请求。

若使用一次完整 JSON 返回两个能力，必须收到完整响应后分别校验字段。标签完整有效而描述语义不达标时，标签可以成功；**传输截断/JSON 残缺时不能捞出片段报成功**。真正独立的子请求可以在另一个子请求仍执行时提交。不承诺同一个未完成 JSON 中的标签能提前成为权威结果。[S00 §9.2]

合并后单项取消：标记对应逻辑任务取消，拒绝其提交；物理请求仍服务其他有效任务时不必全取消。所有订阅者都取消才请求停止底层执行。

### 6.3 Recipe 应记录什么

`recipeId/version/digest`、能力、输入预处理版本、裁剪/缩放、颜色处理、提示模板、输出 schema、语言规则、有效空值规则、质量检查、最大输入/输出预算、重试类别、结果投影版本。

提示变化必须生成新版本/哈希。旧 `visual-ai-v1` 不能追溯已发生的提示变化时，旧证据标为历史版本未知细节，不能伪造当时精确提示。[S00 §9.2]

### 6.4 ExecutionProfile 应记录什么

模型/权重 digest、视觉投影/分词器 digest、Runtime release/构建、Provider版本、硬件后端、量化、上下文/图像token/输出token上限、线程、并发、batch、KV策略、缓存开关、支持的取消粒度、资源估计、验证报告和使用限制。

任务指向“可用的均衡标签配置”可以是路由意图；每次 attempt 必须冻结实际解析出的具体 profile。云模型无法获取权重哈希时记录供应商模型标识、声明版本、响应版本字段和“不可完全复现”限制，不编造 digest。

### 6.5 输入策略

标签/描述常用整体受控预览；OCR 视需要使用高清派生或分块；反推按用户意图使用整体或区域；配色记录实际采样范围。所有策略都必须限制压缩字节、解码像素、帧数及临时占用，先取得资源许可再做大解码。

避免因整体模板强制 OCR 使用过小预览。OCR 分块需保存原图尺寸、方向修正、裁剪原点、缩放和坐标映射。不能直接把某模型坐标误当原图坐标。

## JOB-07｜持久任务、幂等与恢复

### 7.1 数据粒度

`AnalysisBatch` 是用户一次选择或后台范围的聚合；`AnalysisJob` 是素材×能力的逻辑工作；`ExecutionAttempt` 是一次实际后端尝试；`PhysicalInvocation` 可服务多个兼容 Job。四者分开，避免重试一个描述时把整个批次重新分析。

```text
queued → waiting_condition → ready → running → validating → committing → succeeded
  │            │                  ├→ retry_wait → ready
  │            │                  ├→ failed_final
  ├→ cancelled └→ paused          └→ cancelled / superseded
```

`waiting_condition` 携带资源不足、缺模型、缺授权、预算不足等原因；闭库后记录的持久意图不能拥有 `ready` 的执行权限。进程内 `committing` 是短暂状态，其恢复根据数据库提交事实判断。

### 7.2 去重、重跑与执行epoch

- `clientRequestId` 去重同一次提交；手动强制重跑必须产生新的 run generation。
- 自动任务的逻辑复用键包含库、素材内容版本、能力、配方和执行选择策略版本；按 `reuse-valid` 避免重复。
- 结果缓存键额外包含实际模型/profile和输入 digest，不能因为任务意图相同就复用不同模型结果。
- 任务领取使用持久 claim epoch；同一 Job 的新 attempt 使旧 worker 的 epoch 失效。实际提交还核对 Library generation 和 asset content revision。
- 执行允许至少一次尝试，效果通过唯一约束和条件事务保持幂等；不对任意云 API 承诺全局 exactly-once。

### 7.3 原子提交与 Outbox

在同一个库数据库事务内：插入有效 Evidence、按版本/优先规则更新当前结果、更新 Job 成功状态、写入待投影事件。失败即整体回滚。Worker 不参与数据库写入。

索引构建和 Renderer 通知在提交后执行；Outbox 可重复消费，消费者按事件 ID/资产修订幂等处理。通知失败不把成功提交标为推理失败。

包含大文件的结果先在授权 staging 写入并校验，发布稳定文件后进行元数据事务，失败文件成为可识别孤儿而不是半个正式素材；通过既有 Capture/Promotion Journal 协调，不能宣称文件系统与 SQLite 有一个天然跨系统事务。[S00 §8.1]

### 7.4 关库和崩溃恢复

关库顺序：停止新领取 → 撤销输入/外发和待确认权限 → 标记中断意图 → 取消或收敛已运行任务 → drain 已开始的提交 → 关闭索引读句柄/窗口权限 → 释放数据库与 lease。[S00 §8.3]

重新开库：取得新 lease/generation → 扫描未终结任务 → 核对内容和策略 → 核对模型/配置/外发/预算 → 按有效恢复政策询问一次或自动续跑。默认建议 `ask-on-reopen`；用户明确启用 `auto-when-open` 后可以后台续跑。关闭库期间不持续分析。

只恢复素材×能力进度，不默认恢复某个 token/KV。若后端以后提供 checkpoint，作为可选能力并检查模型、输入与格式版本，失败则回退到新 attempt。

### 7.5 远端不确定状态

网络断开或超时后，远端可能仍在运行。记录 provider request ID、发送前成本预留、可查询状态和幂等能力。支持查询时先查询；不能查询且可能重复计费时进入 `remote_outcome_unknown`，按用户已设置的重试策略处理，不无限重试。

取消表示 DAM 不再接受该任务结果，不保证云厂商已经停止执行或计费；迟到响应也必须通过 generation/epoch 校验。

### 7.6 批量、背压与公平性

历史回填分页生成任务，保存高水位或明确素材范围，不把百万任务和图片全部装入内存。发现新素材与扫描旧库使用不同游标；游标推进与任务入队形成一致记录。

优先级建议：用户交互相关 > 手动单项/高级请求 > 新素材基础分析 > 历史回填/维护。使用 aging 和按能力的公平轮转避免 OCR 长期饥饿；模型局部性只在短窗口内优化，不得压过长时间等待的高优任务。资源不可用时即使优先级最高也不能突破安全预算。

失败消息以批次/原因聚合；成功的标签立即参与 AI 分类/检索，其他任务继续，失败后保留旧有效证据。

## RES-08｜智能资源协调器 Resource Governor

### 8.1 职责及非职责

统一协调 DAM 发起的视觉模型、OCR、Embedding、缩略图、图片变换、索引构建、下载解码与模型安装工作。不同领域保留自身 Journal/恢复语义，共享的是资源准入契约，而不是把全部任务改写成一个万能 AI 队列。

目标是保护交互与其他应用可用性，按用户预算在闲时增加吞吐、忙时退让。它不能为其他应用锁定物理资源，不能从 CPU/GPU 利用率直接推断响应体验，也不应让另一个 LLM 实时决定底层安全准入。

Windows DXGI 提供的是 OS 预算及调用进程的使用信息，不等于全机空闲显存；Apple Silicon 的统一内存不应被 RAM 和 VRAM 两份账重复计算；MLX 内存限制是指导值。[S04–S05、S09]

### 8.2 配置模型

```text
ResourcePolicy
  mode: quiet | balanced | throughput | custom
  reserveForOtherApps:
    systemMemoryRatio
    dedicatedGpuRatioByDevice
  maxDamMemoryBytes? / maxDamGpuBytesByDevice?
  maxCpuThreads / maxConcurrentHeavyJobs
  allowBatteryExecution / pauseOnThermalPressure
  manualPause / idleAcceleration
  modelSelection: automatic | pinned-profile
  modelSwitchCooldown / telemetryFreshnessLimit
  recoveryPolicy: ask-on-reopen | auto-when-open
```

比例只表达 DAM 的预算目标。0% 预留也不得消除系统安全余量；100% 预留意味着不启动额外高负载工作，不能要求应用基础界面占用为零。用户把预算调低到当前占用以下时，先停止准入并逐步卸载，不假装内存立即下降。

“算力百分比”采用可控代理：线程数、并发、批次、任务间隔、进程优先级和暂停边界。对不支持硬限制的 GPU，不显示为可严格执行的固定百分比。

### 8.3 物理资源池与遥测

| 池/信号 | 建议结构 | 不可混淆 |
| --- | --- | --- |
| 系统物理内存 | 总量、可用估计、压力、swap趋势 | 不用 free 字节单独决定一切 |
| 统一内存 | poolId、共享属性、推荐工作集及实际占用 | 不叠加同一物理页面的CPU/GPU读数 |
| 独显显存 | adapterId、专用总量、可用估计、各进程预算 | 宿主预算不代替 Worker 预算 |
| 进程内存 | processIdentity、private/working-set/allocator/cached等口径 | 不能无说明相加RSS和共享映射 |
| CPU | 负载、线程许可、事件循环/交互延迟 | 不等于温度或全部应用体验 |
| 电源/温度/空闲 | 数据来源、supported、timestamp、quality | unknown 不得当作低压力或false |
| 磁盘/网络 | 可用空间、写入速率、并发、暂存预算 | 不只控制模型，不管输入/索引IO |

每条读数记录 `sampledAt、source、scope、unit、confidence、supported、error`。遥测超时、采集失败、GPU重置、睡眠唤醒均触发重采样和更保守的准入。Electron powerMonitor 仅提供部分跨平台信号，按实际版本确认。[S20]

初期默认只收集聚合压力和 DAM 自身进程信息，不采集其他应用窗口标题、文件内容、截图或用户输入。“没有鼠标键盘动作”与“设备没有计算任务”是两个条件。

### 8.4 估算完整峰值

预计占用至少包括模型权重、视觉投影、KV、激活/预填充峰值、解码/裁剪缓冲、IPC复制、Runtime allocator缓存、并发上下文、模型切换临时双驻留和安全余量。

模型文件字节不能直接当驻留内存。多张图片的 batch 也不能只按文本 token 估计。估计键至少包含硬件、Runtime、模型/profile、能力、输入尺寸桶、batch、上下文和缓存方式；实测分布反馈至估算器。没有样本的组合用保守估计和小任务校准，不在真实大库中以 OOM 试探上限。

### 8.5 原子准入和账本

采用一个 DAM 级协调器，按物理池核算并一次性取得所需资源。对资源池 p，可采用以下**概念公式**：

```text
可新增预算(p) = max(0, min(
  用户DAM上限(p) - DAM已承诺占用包络(p),
  最新系统可用估计(p) - 尚未物化的预留(p) - 安全余量(p),
  该执行进程可用的OS预算余量(p)  // 仅适用于该进程且读数可靠时
))
```

预算与观测是两条检查路径：已经物化到实际占用的 reservation 不能在同一个空闲估计里再扣一次。台账要区分 reserved-not-allocated、allocated、releasing、released；预测与实测不一致时取更保守结果并校准。统一内存按物理池去重，而不是盲加各组件RSS。

一次申请涉及 RAM+VRAM+CPU+临时磁盘时必须全有或全无。不得持有一半 GPU 许可无限等待 CPU，也不得先在不同模块分别“看空闲”再各自启动。先处理大缓存回收，再重新测量、准入；不把未来可能释放的空间当成当前可用。

### 8.6 两种许可与失联处理

| 许可 | 开始 | 结束 |
| --- | --- | --- |
| ModelResidencyPermit | 模型加载前预留，包括加载峰值 | 确认卸载或进程终止并完成核对后 |
| TaskComputePermit | 一次预处理/执行开始前 | 计算与临时缓冲结束；未结束的驻留另算 |

许可字段建议有 ID、coordinator epoch、owner process identity、model instance/attempt、资源池及额度、heartbeat、状态、撤销原因。许可过期意味着“失联待核对”，不是“资源已经释放”。

进程失联时禁止扩大使用；先停止新准入、查询进程身份和现有占用，再按所有权决定停止 DAM 托管进程。PID可能重用，需结合启动时间/进程句柄/实例token。主进程重启后先重建实际驻留观察，再开放队列，不信任旧账本显示的零占用。

### 8.7 闲忙闭环

```text
观测 → 确定压力状态 → 调整新任务准入/并发 → 执行一个最小工作单元
   ↑                                              ↓
   └──── 峰值/耗时/交互影响/卸载核验 ←─────────────┘
```

| 状态 | 进入条件（具体阈值待校准） | 行为 |
| --- | --- | --- |
| paused | 用户暂停/库不可执行 | 不领取；保留任务 |
| constrained | 压力高、遥测失真、预算下调 | 停新任务，降线程/并发，回收闲置模型 |
| interactive | 用户活跃或前台请求 | 优先交互，后台小单元运行 |
| balanced | 稳定有余量 | 有界并发、有限驻留 |
| idle-boost | 用户允许、设备稳定低压、接电等条件满足 | 缓慢增加batch/并发，不越用户预算 |
| emergency | 严重压力/后端失控 | 请求取消、卸载/停止受管进程；保留可恢复意图 |

采用快速降速、缓慢恢复、进入/退出不同阈值、最短保持时间和冷却期，避免数值抖动导致模型频繁切换。状态转换用假时钟和可重放遥测测试，不能只靠真实机器手动观察。

### 8.8 模型自动/手动选择

选择顺序：能力兼容 → 最低质量 → 用户本地/云端授权 → 平台就绪 → 资源可容纳 → 延迟/成本/切换代价。资源充裕不是必须上大模型的理由。

自动切换在素材/能力 attempt 边界进行。先卸载旧模型再加载新模型是低资源默认策略；同时驻留需独立预算允许。手动 pinned profile 不可绕过预算；不足则等待或说明可选路径。对高级反推，低质量小模型不应无提示冒充等价结果。

普通模式只在已验证候选集合内切换。高级自由组合在完成能力验证前标为实验/未验证，不自动加入后台池。任何上云切换都先过 EgressGrant，不以“提高体验”为由静默外发。

### 8.9 抢占与防反复取消

后端支持协作式取消时请求停止；不支持时，在最小任务完成后停止新工作，或终止归 DAM 所有的运行实例。不得挂起持有GPU资源的进程并把预算计为释放。

记录已等待时间、已执行时间和中断次数；频繁被取消的任务进入更小输入/不同允许配置/仅闲时队列或等待用户处理，防止无限“启动—取消—重试”。压力恢复后不恢复已撤销权限。

## AI-09｜Runtime、模型驻留与能力就绪

### 9.1 所有权模型

| 类型 | DAM 可以做 | DAM 不应做 |
| --- | --- | --- |
| dam-managed | 按已授权安装/启停/加载/卸载、核对退出 | 运行未审核脚本、开放无认证公网 |
| user-managed | 能力探测、请求、限流、支持范围内取消 | 未授权关闭整台服务或卸载其他应用的模型 |
| remote | 授权请求、成本控制、查询状态 | 控制对方GPU或保证即时停费 |

Provider 管“请求”，Runtime Adapter 管“生命周期”，Model Library 管“制品”。这三者可以共享少量描述数据，但不能合并成一个包含所有平台逻辑的巨大 AIService。

### 9.2 状态模型

```text
artifact_missing → downloading → verified → installed
                                    ↓
                              runtime_compatible
                                    ↓
                           starting → loaded → probed
                                               ↓
                       capability_ready / incompatible / unhealthy
```

连接成功、模型列表成功、权重下载成功、进程存活与能力可用都分开。Smoke test 使用内置非敏感夹具，分别检查图像输入、契约、语言、空结果和取消；成功只能证明该测试范围，不是完整质量认证。[S00 §3、9]

### 9.3 Runtime Supervisor

负责受控可执行文件/参数白名单、进程身份、健康探测、启动超时、stderr限额、崩溃退避、终止与卸载验证。托管本地服务优先 loopback、随机会话凭据、明确端口所有权；不能仅看到端口已开就认为是自己启动的服务。

模型驻留缓存采用引用数/活跃任务数 + TTL + 压力驱逐。TTL是空闲回收规则，不是用户授权有效期。参考 LM Studio、Ollama、Immich 的机制，具体预算与权限由 DAM 决定。[S10–S11、S13]

关库时取消该库任务并清理含素材的视觉/KV缓存；纯模型权重是否保留由应用资源策略决定。敏感缓存清理无法可靠证明时，停止专用托管进程；外部用户服务无法保证清除时应明示限制，不能把“本地”写成无残留保证。

## SEC-10｜权限、网络外发与云端控制

### 10.1 三重许可

`LibraryScope` 决定可读取/提交哪个库与素材；`ResourcePermit` 决定是否可消耗本机资源；`EgressGrant` 决定是否可向指定服务发送指定内容。三者不能互相替代。

InputGrant 短时有效，绑定库 identity/generation、素材内容revision、实际派生物、用途和字节/像素范围。优先向 Worker 传受控材料；不把整个库根或任意原件路径交给模型进程。确需文件路径时只给私有 staging 中的单个输入，仍有撤销与清理流程。

### 10.2 EgressGrant 结构

```text
grantId、libraryId、asset/selection scope、allowedCapabilities
providerId、endpointOrigin、endpointConfigRevision、model/profile范围
inputClass: preview | region | full-resolution-derived | original
允许发送的 metadata 字段
validFrom/validUntil、revocationVersion
maxRequests、成本额度/币种、是否允许自动后台/重试
```

保存配置只保存密钥引用和连接资料，不创建grant。服务地址、供应商、模型路由、输入类别或授权范围发生变化应重新判断授权。允许一次基础分析不等于永久允许整库云反推；反复读列表不需要确认。

### 10.3 本地服务可能代理云端

把 endpoint 的网络位置与实际计算位置分开：localhost 可能转发远程请求。只有受管已验证本地配置才能标记 verified-local；高级外部服务若无法证明最终位置，标为 unknown，要求用户了解其外发可能性。Ollama 文档本身同时包含本地与云功能说明，不能仅凭服务名称作隐私保证。[S11]

### 10.4 请求安全

远程使用 TLS；loopback HTTP 仅在明确本地边界下允许。URL、DNS解析、重定向、代理、超时和最大响应体由 Egress Gateway 管理。用户明确配置的本地端点与素材直链下载采用不同白名单策略，不能把 SSRF 防护一律关掉以兼容本地服务。

禁止模型或素材中的文本自行提供网络目标；不把服务密钥转发给重定向后的未知地址。需要重定向时逐跳重新验证授权，不继承原站点凭据。校验压缩/解码体积，避免恶意响应耗尽内存。

密钥存 OS 凭据存储或经过评审的宿主安全存储；Renderer、日志、任务快照、普通导出中只出现 key reference。安装包和诊断包不得包含开发者密钥。

### 10.5 云端预算与错误

请求前预留估计费用/请求额度；请求后按实际 usage 结算；结果未知保留未结算状态。供应商没有可靠价格或usage时显示估计/未知并限制请求数，不伪造精确成本。批量与并发不能绕过总额度，重试也计入额度。

429/暂时网络故障采用有上限退避并尊重有效限流信息；401/403 不无限重试；结构错误/图像不支持属于兼容或质量问题。provider 熔断隔离，不因一个云端故障停止本地素材管理。

### 10.6 Agent 与模型结果都是不可信输入

素材内的文字、OCR、描述、文件名和网页来源字段只能当数据，不当可执行指令。所有工具调用经过宿主参数校验、权限与业务前置条件；写入先生成提议，用户确认后执行。MCP 或提示模板不能替代该边界。[S18、S26]

## EVIDENCE-11｜结果、质量和用户覆盖层

### 11.1 证据结构

```text
Evidence
  evidenceId、libraryId、assetId、assetContentRevision
  capability、inputArtifactDigest、inputTransformVersion
  recipeId/version/digest、profileSnapshot、backendDeclaredVersion
  jobId、attemptId、claimEpoch、requestGeneration、createdAt
  value（按能力类型）
  quality: structure/language/semantic/status/reasons
  attribution: measurement | observation | inference | creative
  provenanceLinks、supersedesEvidenceId?
```

原始响应默认不长期保存；诊断确需留存时需明确本地保留策略、脱敏和期限。证据中保存满足追溯所需的版本与结果，不等于将敏感输入写入应用级日志。

### 11.2 质量分层

| 层 | 例子 | 处理 |
| --- | --- | --- |
| 传输完整 | 是否正常结束/被截断/返回过大 | 不完整不成功 |
| 结构正确 | schema、字段类型、数量范围 | 不合法拒绝，有限同策略重试 |
| 语言/格式 | 中文标签、反推语言、重复标签 | 单独质量状态；不只靠提示要求 |
| 能力语义 | OCR空结果有效、描述无输入不可能推断 | 规则+夹具+人工质量基准 |
| 任务适用性 | 反推可用于创作、检索可用 | 记录验证范围，不伪称绝对事实 |

模型自报 confidence 仅作原始信号，未校准前不作为自动删除、事实确认或强制模型切换的唯一依据。可以将低质量结果保留为非当前证据，或拒绝进入常用投影；具体规则在能力配方中版本化。

### 11.3 当前结果和用户状态

AI Evidence 采用追加记录；`CurrentEvidencePointer` 由策略选择。`UserOverlay` 单独保存手动描述、确认标签、拒绝建议、OCR修订和用户选择当前结果的意图。

“当前”不按最后完成时间盲选：检查素材版本、request generation、任务未取消、profile质量规则和用户手动选择。晚到的旧attempt不得覆盖新分析；后端切到更小模型不能自动覆盖被用户固定的优质证据。

成功标签可立即进入 AI 文件夹和检索，但与 ConfirmedTag 分表/分关系。用户拒绝的建议按规范化身份/来源范围保留，避免下一次同模型重跑立即无解释地重复出现。模型重跑不清空用户确认标签。

### 11.4 OCR 特殊结构

OCR 保留区域文字、原始模型得分、坐标体系、reading order、输入变换和人工修订。旧修订绑定旧证据/区域身份；新模型重分块后不能按数组下标硬套。可以提供修订迁移候选，但需可靠定位或人工确认。空白素材成功识别为无文字是 `succeeded-empty` 语义，不是模型失败。[S00 §9.1]

### 11.5 旧数据兼容

v2视觉记录可投影为历史标签/描述/反推证据，保留原始来源和不确定字段；v8 OCR 与修订保持独立。只有旧数据确有的版本才写入，不补造 digest、耗时或质量评分。新读模型可同时读取旧/新结果，切换写入口时保持单一权威，不双写两套互不一致的当前状态。

## DATA-12｜数据所有权、事务与演进

### 12.1 存储分区

| 数据 | 所在位置/权威 | 不得混入 |
| --- | --- | --- |
| 素材身份、原件、组织、工作集、证据、库内Job | Managed Library / Host | 全局App DB的素材表 |
| Eagle原件 | Eagle | Managed复制/移动逻辑 |
| Eagle索引、同步意图 | 独立连接库索引/Journal | 受管库写入授权 |
| Legacy历史库 | 用户选定只读文件 | schema初始化/自动迁移 |
| 设备资源设置、Runtime安装、健康统计 | App状态 | 隐式复制的OCR/素材正文 |
| 模型权重/可执行依赖 | Model Workspace | 素材Original |
| FTS/向量索引 | 库级可重建投影 | 唯一不可恢复业务事实 |
| 密钥 | OS/宿主安全存储 | 普通任务JSON/日志 |

延续 [S00 §7]；App 级全局列表不得在关库后持有可写库连接。手机端未来采用自身本地缓存和同步协议，不直接读取桌面绝对路径。

### 12.2 概念数据集合（不是立即创建全部表）

`analysis_batches / analysis_jobs / execution_attempts / analysis_evidence / current_evidence / user_overlays / projection_outbox / projection_checkpoints / artifacts / artifact_lineage / embedding_spaces / index_generations / egress_grants / usage_ledger`。

已有领域表不重复再造。Job和Evidence与素材引用、幂等键、状态/创建时间索引要依据真实查询设计。App侧只保存设备预算、Runtime/模型安装状态和不含素材内容的估算统计；活跃许可内存账本可带恢复日志，但日志不证明资源已经释放。

### 12.3 集中迁移入口

保留 v1–v8 的历史含义与现有触发语义，先建立 `inspect → plan → review/authorize → migrate → verify` 的统一入口/注册表，再逐步收敛分散模块。不能让首次普通读取顺便升级任意旧库。[S00 §7.3]

迁移记录包括源/目标schema、能力清单、最低读取/写入版本、迁移ID/digest、备份位置和验证结果。更高版本的库被旧功能打开时不得降级；若无法证明只读兼容，清晰拒绝而不是尝试写入。

新库初始化可以按当前设计建立；已有库的升级需要可审阅计划。具体新版本号必须由源码核对后分配，不在本架构包预先占用“v9”。

### 12.4 备份与回退

迁移前使用一致性数据库备份方法，另行记录原件/派生物清单及文件状态；SQLite Backup API 不是整个资料库的全量文件备份。[S22]

区分三种回退：代码入口回退、索引代际回退、数据备份恢复。已升级库不能简单降schema或用旧二进制硬写；存在新数据时恢复旧备份会丢弃之后修改，必须明确影响并经授权。不要在运行中复制一个 `.sqlite` 文件就当成完整WAL数据库快照。[S23]

### 12.5 崩溃一致性和垃圾回收

采用先写staging、校验、发布和事务关联的有日志流程。元数据事务与外部文件操作不声称全局原子。启动恢复时检查 Journal 和孤儿文件；只有确定没有正式引用、没有活跃任务/下载/窗口/缓存持有时才回收。

安全问题优先拒绝写入，但应允许在可验证的只读范围内找回数据。真实损坏/断电恢复需要独立实验，现状稿历史合成测试不能替代。[S00 §10.3]

## DATA-13｜派生物、缓存、来源与去重

### 13.1 派生物服务

`ArtifactService` 统一描述必要预览、可选高清预览、缩略图、OCR分块、用户裁剪副本、未来视频帧和分析输入，不混淆其所有权。记录 parent asset/artifact、内容digest、变换版本、尺寸、色彩/方向、坐标映射、用途、引用计数/持有者及清理类别。

关键区分：图片工具另存的新素材有自己的 Asset 身份；临时OCR分块不是新素材；必要预览不能被普通缓存GC误删；生成副本不能无条件复制来源素材的AI证据。[S00 §2.2、3]

### 13.2 缓存分层

| 层 | 复用键至少包含 | 生命周期 |
| --- | --- | --- |
| 解码/缩略图 | 库范围、内容digest、变换/尺寸/色彩版本 | 磁盘/内存LRU，必要预览有保护 |
| AI结果 | 内容、输入变换、能力、配方、模型/profile | 有效证据复用，不是任意旧文本 |
| 视觉特征 | 内容、encoder/projector、输入版本、Runtime/cache格式 | 预算化，关库清理敏感内容 |
| 前缀/KV | 以上相关字段+实际提示token前缀及模板/缓存格式 | 精确前缀与状态兼容，跨库默认不共享 |
| Embedding | 输入digest、embeddingSpaceId | 与索引代际绑定 |
| 查询结果 | 库、查询规范化、权限/范围、投影revision | 短期缓存，更新事件失效 |

MLX-VLM 的视觉特征复用是机制参考，不代表其默认缓存键已经满足 DAM 权限要求。[S03]

共享计算只能在输入内容、版本与授权都吻合时发生。缓存命中不能绕过新会话检查。记录命中率也应关注净内存与磁盘成本，不无限缓存以追求命中率。

### 13.3 删除、撤销与GC

素材进入回收站后，查询默认过滤并阻止新的自动分析；已经开始的任务按素材生命周期规则取消/失效。物理清理需单独计划，检查原件、派生物、窗口引用、索引和恢复记录。关闭库先撤销访问，再清理敏感缓存；不因缓存尚有文件就允许旧URL继续读取。

### 13.4 重复与相似候选

精确字节哈希可识别同内容候选，但不能把文件名相同当重复。感知哈希/向量用于近似候选，结果可用于人工比较，不自动删除或合并身份。两个重复素材的来源、笔记、确认标签、组织关系可能不同，需要明确合并计划和恢复点。

## SEARCH-14｜查询、全文、向量与命中解释

### 14.1 先收回查询权威

Host/Query Service 执行过滤、分页、排序和聚合；Renderer维护当前页、选择与显示投影，不加载全库来完成每次搜索。先保留现有语义等价的名称、文件名、标签别名、描述、OCR和反推词法命中。[S00 §8.2]

使用稳定排序键与游标；游标绑定查询、范围及必要的投影/权限版本。数据变化时定义刷新语义，不持有长时间读事务来模拟不必要的永久快照。索引后台更新期间可以返回 `indexing / partial / stale` 状态，而不是假称全量结果。

### 14.2 词法检索

FTS5 是候选基线，保留结构化过滤与精确标签关系，不把所有查询拼成字符串 SQL。中文/多语言分词、别名、短词、符号、文件名、OCR混合文本、匹配片段偏移需要自己的测试集。选择unicode、trigram或自定义分词时比较实际召回/索引体积/维护代价，不默认声称中文已解决。[S21]

有界、短事务更新主库FTS；更重的向量/外部投影由隔离执行或独立可重建存储承接。Library Host仍控制写入准入，避免任意Worker打开权威数据库。

### 14.3 EmbeddingSpace 与 IndexGeneration

```text
EmbeddingSpace
  模型/权重版本 + 图文encoder配对 + tokenizer
  维度 + normalize + distance + pooling
  图像/文本预处理 + 量化/输出语义版本

IndexGeneration
  库 + EmbeddingSpace + 索引实现/格式版本
  coverageCursor + processed/eligible计数 + 状态
```

相同维度不代表相同空间。切换模型建立新空间/代际，在旧空间仍可服务时增量回填新索引；切换前验证覆盖率、抽样召回和失败率。新空间未完成时如提供部分检索需明确覆盖范围，不混算不同空间的相似度。[S15]

图像和文本向量需确认为同一对齐空间。内容变更、素材删除和用户修订触发正确的投影失效。向量存储丢失时可从权威数据与可重算任务恢复，但重算可能有时间/费用，不承诺免费即时完成。

### 14.4 向量实现选择

先建立一个能跑真实小样本的精确近邻基线，作为正确性对照；大库近似索引在 SQLite嵌入式扩展、本地索引文件或隔离搜索进程之间通过基准选型。评价过滤、中文图文质量、删除/更新、内存、native ABI、许可、备份和代际切换，不能仅看向量数量宣称胜出。

没有真实第二实现前，不创建庞大的通用向量数据库平台；用 `VectorIndexPort` 隔离最小必要操作即可。此文不锁定具体向量数据库包版本。

### 14.5 混合检索与解释

```text
QuerySpec
  → 结构化过滤/权限与生命周期筛选
  → 词法候选 + 向量候选
  → 去重与可解释融合（先用版本化排序策略）
  → 可选、有预算的重排序
  → SearchHit + EvidenceRefs + IndexStatus
```

不要直接相加不同量纲的BM25/余弦分数。可先用排名融合或经测试的归一化策略；版本化、可回退。对用户明确的硬约束（如文件类型/尺寸/标签范围）不允许生成模型为了“更像”而忽略。

命中解释优先由实际检索证据构造：用户标签命中、OCR某区域、描述词法匹配、视觉相似候选。语言模型润色解释时必须引用Evidence，不能为向量相似编造不存在的物体或文字。

### 14.6 搜索与资源竞争

交互查询的轻量词法结果先返回；需要模型的query embedding优先于历史回填，但仍遵守资源许可。Embedding模型可采用已验证的小常驻配置，或在资源不足时返回词法结果并说明语义暂不可用，不令普通搜索完全等待大模型加载。

## ORG-15｜组织、笔记、工作集与多窗口

目标是整理代码责任，不重做已批准的交互。保留普通文件夹、AI动态分类、色板、笔记、工作集和原生参考窗口已有生命周期。[S00 §3、7、8]

| 模块 | 目标边界 | 关键保护 |
| --- | --- | --- |
| 标签目录 | 身份、别名、层级、合并计划 | 改名不改变ID；防环；AI候选不等于确认关系 |
| 文件夹/色板 | 持久组织关系与引用 | 不复制或移动原件 |
| AI动态分类 | 基于当前有效标签的查询投影 | 成功新标签及时反映，撤回/失效同步更新 |
| Notebook | 内容修订、草稿、保存、冲突 | 不把内存草稿当崩溃恢复；需要时独立持久草稿 |
| WorkSet | 内容与成员引用、备注 | 删除引用不删除素材 |

现有工作窗数量/成员数量是现状约束，不能在重构中偷偷解除或当作最终理论上限。[S00 §8.3]

## MEDIA-16｜收录、下载、图片处理与素材删除

### 16.1 保留现有业务链路

收录继续走 Candidate → staging → 校验 → 必要预览 → Promotion → Asset。下载完成只代表字节到达，入库成功才代表素材可用。已有 Capture恢复不能靠重新下载并生成新身份掩盖部分提交。[S00 §8.1]

下载网络并发、解码、hash、缩略图与图像变换逐步接入ResourceAdmissionPort，但不把下载Journal变成AnalysisJob。域恢复状态归原模块，资源许可只是执行条件。

### 16.2 自动分析触发

Promotion事务产出 `AssetPromoted` Outbox；自动分析策略消费事件、去重创建基础任务。补偿扫描寻找“符合策略但缺任务”的素材。禁止在Promotion事务内同步等模型回复，避免模型故障阻塞导入。

用户导入时关闭自动分析，则不补发未授权的后台任务；以后启用历史回填由独立范围计划处理。模型安装成功只解除等待条件，不自动扩大分析范围。

### 16.3 格式与安全

维持已验证格式和大小边界，扩展支持先做解码/安全/预览/资源测试。识别解压炸弹、异常维度、恶意元数据、符号链接和来源变动。Copy默认不删除来源；图片工具默认生成新素材，不覆盖原件，不套用旧AI结果。

### 16.4 删除/恢复

回收站是独立领域操作，仍禁止恢复旧 `assets:delete` 作为通用删除口。删除使相关分析任务失效、索引过滤和窗口引用状态更新；恢复后是否复用证据检查内容/版本。物理清理通过审阅计划、文件所有权证明和恢复策略执行，不自动删除Eagle原件或只读旧库。[S00 §3、2.2]

## DESIGN-17｜受控 AI 辅助设计

### 17.1 第一条完整工作流

```text
设计Brief
 → 结构化约束（用途/风格/颜色/尺寸/媒介/必需与偏好）
 → 查询计划（不直接SQL）
 → 搜索候选与真实Evidence
 → 对照/分组/说明差异
 → WorkSetProposal
 → 用户确认
 → 由WorkSet应用服务写入
```

产物不是“一段看起来合理的AI总结”，而是带素材ID、证据引用、约束满足情况和缺口说明的提议。没有相关素材时承认缺口，不编造素材或直接网络补图。

### 17.2 建议功能

**需求检索**：把自然语言Brief转为QuerySpec，保留可审计原始约束与规范化版本。  
**风格比较**：比较候选颜色、构图、文字区域和语义；测量与推断分开。  
**参考工作集提议**：给出少量不同思路的参考组合，注明选择依据；确认后保存。  
**复用说明/提示词**：基于已选素材生成创作提示，标明为推演，不当作原始提示词。  
**差距提示**：指出工作集缺少哪些用户明确要素；不自动产生新素材或购买资产。

### 17.3 工具与权限

最小工具：`searchAssets、getAssetEvidence、getAuthorizedPreview、proposeWorkSet、applyConfirmedProposal`。最后一个方法验证用户确认receipt、计划digest和库revision，不能只接受模型传入的 `confirmed: true`。

多步状态可参考 LangGraph 的checkpointer思路，但优先用现有任务、应用服务和轻量状态机实现。未来确需复杂分支再接入编排框架，业务授权与事务仍由DAM掌握。[S25]

设最大步骤、总token、云成本、总时间和可访问素材数量。工具失败不能无限重试；任何写操作都保留可检查的提议及变更范围。素材/OCR中的“忽略此前指令”不产生执行权限。

## OBS-18｜错误、追踪、健康与诊断

### 18.1 一条分析Trace

```text
request / batch / job / attempt
  ├─ plan / choose-profile
  ├─ wait-resource / prepare-input
  ├─ model-load / infer / validate
  ├─ commit / project / notify
  └─ cancel / unload / reconcile
```

借鉴 OpenTelemetry Trace/Span 语义即可，不要求用户部署遥测服务器。默认本地、脱敏、限额；网络导出另行授权。[S30]

### 18.2 需要回答的问题

为何等待、为何换模型、为何没有上云、哪个阶段耗时最多、资源峰值来自哪里、结果为何拒绝、哪份证据当前有效、恢复后为什么不重跑已完成部分。

记录 `decisionCode、supportingSignals、policyVersion、estimated/observedUsage、actualProfile、evidenceLevel`，不要记录其他应用窗口标题、API Key或整张图片base64。用户导出诊断包前列明范围，提供本地脱敏报告。

### 18.3 状态与通知

任务等待、资源受限、provider健康、模型安装和分析质量分别表达。失败分类至少包括配置、授权、资源、模型兼容、传输、格式、语义、存储、冲突、取消和远端结果未知。通知按批次/错误原因聚合，成功即用不等待全批次。

### 18.4 保留策略

按库和App设日志/临时文件/缓存上限，使用轮换与低优先级GC，清理不可阻塞交互。用户内容不用于默认远程产品遥测；质量评估集来自明确授权样本，不隐式上传私人素材。

## PLATFORM-19｜平台与模型供应链治理

### 19.1 安装与就绪流水线

```text
版本化目录/手动选择
 → 来源与许可信息披露
 → 下载许可/空间预检
 → 断点下载与完整性校验
 → 安全解包/安装（禁止目录穿越与越界链接）
 → Runtime与权重配套验证
 → 启动Smoke test
 → 能力/质量/资源范围登记
 → 可用Preset
```

可信来源、文件hash、配套制品与可执行依赖分开管理；存在hash不自动证明发布者可信。普通模式仅运行已审查的安装路径，不自动执行模型仓库remote code。高级模式的风险授权不能扩大资料库读写范围。

### 19.2 平台矩阵

| 平台类别 | 需单独验证 |
| --- | --- |
| Apple Silicon macOS | Metal/MLX、统一内存、冷热加载、温度、电池与签名依赖 |
| Intel macOS（是否支持待决） | CPU/可用后端、最低体验和OS范围；不默认MLX |
| Windows x64 独显 | GPU/驱动/Runtime组合、显存遥测、进程终止与路径 |
| Windows x64 集显/CPU | 共享内存池、CPU保底、后台并发与响应 |
| Windows ARM64（是否支持待决） | 原生依赖和EP，不从x64结果推断 |
| 手机端未来 | 云推理授权、离线上传、系统后台限制、同步冲突 |

跨平台契约不保证所有平台都提供相同硬件指标。不可用能力以 unsupported/unknown 表示；核心素材管理仍可运行。

### 19.3 工程依赖

先审查锁文件和现有Electron/Node/native ABI，不从 `package.json` 范围推断安装精确版本。升级Electron、安全边界、打包和原生模块要独立变更与验证；不要为临时测试重编better-sqlite3破坏原Electron环境。[S00 §4、10；S18]

未来开源准备包含第三方依赖及模型许可清单、SBOM候选、密钥扫描、可复现测试夹具、平台构建说明、安全报告渠道。不在本轮替用户选择项目许可证，不把“开源”当允许再分发任意模型权重。

## EXT-20｜未来扩展边界：完整设计，延后依赖

### 20.1 手机端与云推理

手机以收集、浏览、轻量组织和云分析为主，不复制桌面Runtime。共享领域语义/JSON契约，而不是共享Electron IPC和本地路径。

```text
Mobile CaptureIntent/本地离线队列
 → 用户选择的同步/上传边界
 → 云端素材接收或临时推理材料
 → 云AnalysisJob/Evidence契约
 → 同步确认/结果合并
```

可研究桌面配对转交、自托管资料服务或托管同步；目前未选定形态。上传素材保存与发给模型是两个授权目的。临时推理输入有保留期限和删除策略；不能承诺云端无残留而没有服务能力支撑。

### 20.2 多端同步设计

需要稳定对象ID、设备ID、每对象修订、变更日志、冲突策略、删除tombstone、内容hash、上传检查点和幂等服务接口。区分“本地操作已保存”“服务器已接收”“其他设备已同步”。不能用客户端时间戳简单覆盖所有编辑。

同步原件、派生物、用户编辑、AI证据和模型配置分别定规则；API密钥和设备窗口布局默认不跨端同步。Embedding索引通常可重建，不必整份同步。不能直接同步活动SQLite/WAL文件作为多端数据库方案。[S23]

### 20.3 MCP/专业工具连接器

先暴露只读搜索、证据和提议；写入复用既有审阅/确认机制。记录tool schema版本、权限、审计和调用预算。协议规范可参考MCP，但其存在不证明插件已经安全或已实现。[S26]

Eagle保留自身专用配对与原件权威；Legacy仍只读。未来Figma/Adobe等连接器需要真实API、授权与许可调研，当前只保留领域端口，不虚构已经可调用的外部接口。

### 20.4 视频/音频/录屏/抠图/图层

为未来定义MediaDescriptor、时间范围、帧/区域输入与来源关系。视频任务可以按片段/帧恢复，帧证据必须含时间戳和原素材版本；音频OCR不是同一能力。录屏需要OS权限与显式状态；抠图/图层作为可撤销派生物，不覆盖原件。

这些能力需要格式、编解码、资源、安装与安全专项验证。禁止仅因为图像工作集已存在就宣称视频工作流完成。[S00 §3、11]

### 20.5 自托管云与高级推理

vLLM/SGLang可在独立服务阶段比较；桌面仍调用稳定推理端口。新增认证、多租户隔离、限流、输入存储TTL、队列、计费、资源隔离和运行观察后才能公开部署。Immich远程ML的分离思路值得参考，但其内部服务安全假设不能搬到公网。[S14、S16–S17]

推测解码、KV压缩、共享缓存的收益用对应服务负载验证，不将后端实验配置升级成用户业务必需参数。[S28–S29]

## DEV-21｜适合 AI 编码工具的仓库治理

### 21.1 四层文档

产品不变量（稳定） → 架构决策/契约（版本化） → 当前实现/调用链（随源码更新） → 历史证据（不可改写成当前通过）。文档包不是第二份永远独立的源码真相；接入仓库后通过模块清单与阶段报告链接真实代码。[S00 §11.1]

### 21.2 每个模块的最小交接

职责、公共入口、数据所有者、允许依赖、禁止能力、current/legacy/tracer/prototype状态、典型调用链、聚焦测试、最近有效证据、已知缺口。模块README只负责局部导航，不复制所有全局规则。

### 21.3 每次 AI 实施的固定循环

读真实工作区与当前状态 → 核对阶段依赖 → 写修改范围/风险 → 小步修改 → 运行对应层级测试 → 自查diff/负向边界 → 更新报告和上下文 → 停在本阶段，不擅自连续实施全部计划。

增量任务、跨会话进度记录和端到端验证的工作方式参考Anthropic工程报告；本方案额外要求工作区保护、范围授权和不可伪造证据。[S27]

### 21.4 必须防止的 AI 编码问题

不覆盖用户未提交变更；不执行 `git reset --hard/clean -fd` 作为恢复手段；不按文件大小机械拆分；不删除测试换取通过；不把真实模型失败改成mock后称真实通过；不让新代码绕过Host/权限；不在多个Agent中同时编辑同一契约和migration。

并行适用于可隔离的调研、测试夹具、独立Adapter；共享契约先定稿，独立worktree中合并，先核对工作区快照是否包含所有未提交内容。主责任Agent整合证据，用户审核风险与行为变化。

| T23 | 大库与后台体验：冷/热、混合工作负载 | 指定硬件L5/L6 |
| T24 | 未验证平台/模型不冒充可用 | CI/能力矩阵与报告审核 |

### 22.3 资源与体验指标

记录交互/查询P50/P95/P99、Main event-loop delay、冷启动/模型加载/首结果/总耗时、峰值及稳态RAM/VRAM、swap增长、OOM、后台吞吐、取消响应、卸载时延、模型切换次数、资源估计误差和索引覆盖率。

比较“无后台任务”的同机基线与“有后台分析”，不是只看tokens/s。建议先以1k/10k/100k合成元数据和逐级真实素材样本建立测量阶梯；这不是100k性能承诺，也不是用合成数据代替真实解码和模型负载。

可在ADR中设定例如交互P95退化比例、压力变化到停止新准入的时间、队列最大内存等目标；本包不捏造已达到的数字。各硬件档先实测基线，再由用户批准阈值。确定性安全断言（如未授权外发、用户字段覆盖、重复成功效果）期望为零例外。

### 22.4 能力质量指标

标签精确性/重复/语言及可检索性；描述无依据断言率；OCR字符错误/区域定位及修订保留；反推的可复用性与禁止“原始提示词”误导；检索Recall@K/相关性及证据解释准确性。样本选择记录来源与授权；开发集/验收集分开，不能反复针对同一套样例调提示后称泛化。

### 22.5 报告格式

代码revision+工作区digest、OS/硬件、Runtime/模型/profile/recipe、输入范围/hash、命令/退出码/日志、假时钟/种子、成功失败数、未覆盖项、相对基线、证据等级和结论适用范围。真实环境缺失时标 BLOCKED/NOT_RUN，不写 PASS。

## MIG-23｜增量迁移、不做清单和接手方式

### 23.1 迁移顺序

**先核实 → 固定边界 → 抽出契约/配方/证据 → 建立任务和资源许可 → 完成单个标签闭环 → 扩展基础/高级能力 → 接入自适应资源和云端 → 查询与设计辅助 → 多后端与全系统核验。**

每阶段保留调用方、明确唯一写入权威和回退点。不要先创建全部目录，再让后续AI猜每个空模块如何拼起来。详细 P00–P27 与 X01–X04 任务卡见实施手册。

### 23.2 保留/替换/删除策略

| 现有区域 | 迁移策略 |
| --- | --- |
| Library Host / Capture / 三库边界 | 保留权威；只按已测责任提取内部模块 |
| visual-ai / ocr 正式入口 | 保留兼容，逐步转接新planner/provider/evidence/jobs |
| 旧ai-service/core资源与模型代码 | 先查可达性、测试与有价值策略，再抽取/隔离 |
| 旧全局DB/受限IPC | 不恢复其权限；有明确替代后逐项清理 |
| Renderer内存搜索 | 以同语义QueryPort转接，比较结果和增量更新 |
| 大Store/AIConsole | 按状态所有权/调用链拆，不重画界面 |
| 测试与历史文档 | 标明证据等级/时点；证明重复/无效才合并删除 |

切换策略可使用有版本的特性开关；同一业务操作只允许一个权威写路径。影子模式仅用于无副作用比较，不默认双倍真实推理、双计费或双写。

### 23.3 本轮不做

不全面重写技术栈；不把每个模块拆成微服务；不默认安装所有推理框架；不开发通用节点编辑器；不训练自有基础大模型；不承诺任意GPU严格算力百分比；不实现通用插件市场或手机同步全栈作为桌面重构前置；不重新启用退休网页功能；不默认跑真实库/收费云/下载大型模型；不重做UI/UX。

未来功能在框架中有责任和数据边界，不等于现在创建其所有空接口/数据库表。只在实际能力需要时实现，减少未使用抽象。

### 23.4 开始执行前要取得的材料

完整工作区快照（含未跟踪文件的受控副本/清单）和真实锁文件；AGENTS/CONTEXT/TASK及代码导航；正式入口与历史基线报告；可用于隔离测试的临时库与非敏感夹具。缺私有文件就明确列缺口，不能把交接稿的链接当成已读内容。

### 23.5 成功判断

新增一个模型后端时主要增加Adapter/版本化Profile/验证记录；新增一个分析能力时主要增加Capability/Recipe/Validator而不是修改全部业务；后台任务能在不越权、不重复覆盖数据的条件下暂停和恢复；搜索和设计辅助建立在可追溯证据上；另一个AI接手时能从状态、ADR和测试找到事实。

**最终目标不是一个更大的AIService，而是一套可以持续更换模型、仍保持数据和体验稳定的素材分析执行系统。**
