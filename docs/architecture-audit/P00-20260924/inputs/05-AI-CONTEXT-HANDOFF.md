## 二、用户已经明确的需求，不必重复询问

桌面macOS/Windows，未来iOS/Android主要收集管理并用云推理。电脑后台分析应尽量不给其他应用添负担，用户可设内存/显存预留目标、选择本地/云端和自动/手动模型大小。闲时加快、忙时减速。

默认后台基础分析为标签、描述、专用OCR；保留一键和单项触发/重跑。高级提示词反推仅用户主动启动，支持批量。标签成功立即可用，其他能力失败独立提醒。任务进度持久保存，合法重开后确认或按用户预设恢复未完成部分。

## 三、目标架构和不能破坏的边界

模块化单体Host + 持久任务 + DAM资源协调器 + 隔离计算进程 + 可替换Provider/Runtime + 独立证据/用户覆盖层 + 可重建混合检索。

Copy不是Move；Original/Preview/Variant不混所有权；Managed/Eagle/Legacy不混写；用户描述、确认标签、OCR修订优先；工作集是引用。AI建议可检索但不是确认事实；反推不是原始提示词恢复。AI不可用不阻塞基础管理。内置网页浏览/登录采集等已退休，不自动恢复。[S00 §2]

Worker不直接写库，Host在有效lease/generation下提交。任务持久化只保存意图，不延续旧会话权限。关库撤权，重开重新检查。服务配置/密钥/连通不等于素材外发授权，localhost也不保证最终本地计算。[S11]

资源预留是DAM软预算而非OS全局硬保证。统一内存去重核算；多资源原子准入；模型驻留许可与计算许可分开。任务结束、许可过期或服务失联不等于物理内存已释放。自适应先用规则与迟滞，不用大模型实时决定调度。

能力独立不要求每项重复推理；完整响应通过对应验证后可各自提交，截断JSON不能捞字段报成功。Job/Attempt/PhysicalInvocation分开；结果、成功状态、Outbox一致提交；新旧写入口切换只有一个权威。
