# U01｜用户需求记录

记录日期：2026-09-24。来源：本次对话中用户对八项问题的回答及本轮文档请求。下列为保留含义的整理，不是新增需求。

1. 优化整体代码框架，尤其 AI 推理；需要前沿开源推理与优秀应用调研，研究效率、流程和代码结构。
2. 当前不制定交付版本；优先细化软件框架和 AI 辅助设计能力，暂不做 UI/UX 设计。
3. 桌面面向 macOS、Windows；未来 iOS、Android 以收集管理为主，AI 使用云端。希望低配置电脑后台分析时仍能使用其他应用；用户可设内存/显存预留比例、选择云端 API，并自动或手动选择不同大小模型。
4. 一键综合分析与标签、描述、OCR、提示词反推独立执行同时保留。标签、描述、OCR 默认后台基础分析；反推为用户主动触发的高级能力，支持批量。已成功的标签立即可用；失败提醒。
5. 普通模式提供少量经过验证的模型与 Runtime 组合；高级模式自由配置，并有使用手册。
6. 基础能力后台智能调度批量运行；反推由用户选择。任务中断要持久保存已完成进度，重新开库后确认或依据有效后台策略继续未完成部分。
7. 当前主要自己使用，未来开源给其他用户。
8. AI 编码工具主要执行、用户审核；架构整理期间可能增加功能。特别需要闲时加快、忙时放缓的内存/显存/算力资源调度模块。
9. 用户认可上一轮提出的功能与架构方向，并要求一份尽可能完整的整体框架，以及分步 AI 编程提示词。
10. 必须标注参考资料，使长上下文或切换其他 AI 后可追溯。

## 需要保持为“待决”的细节

最低支持硬件/系统版本、资料库规模上限、性能数字、默认预留比例、恢复策略默认值、云端供应商/计费上限、最终向量索引实现、具体模型/Runtime 版本、未来同步产品形态尚未由用户确定。架构文档可以提出候选或测试参数，不能把它们写成已承诺事实。

## 解释约定

- “预留百分比”在目标设计中解释为 DAM 的使用预算和让出策略，不是操作系统为其他任意程序作出的硬性资源保证。
- “标签成功立即使用”不等于自动转为用户确认标签。
- “断点恢复”默认指素材×能力任务进度，不保证恢复到生成中的某个 token。
- “认可方案”不等于已经允许访问真实资料库、下载模型、发生云端付费请求或运行外部安装脚本。
