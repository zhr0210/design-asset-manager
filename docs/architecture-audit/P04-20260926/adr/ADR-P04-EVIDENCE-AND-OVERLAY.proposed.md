# ADR提案：按能力保存证据，以请求代次和用户覆盖选择当前结果

状态：**Proposed**；日期2026-09-26；仓库ADR编号待评审分配。关联DAM-A003、DAM-A012、R09/R14、T02/T04/T05/T06。不得因本文件存在标Accepted。

问题：综合视觉结果用完成时间竞争current，没有单能力新旧次序；重跑保留用户状态依赖各处规则。OCR独立存储已有重要保护，但未保存独立修订基准。历史数据缺少精确配方与请求次序。

决定提案：由小接口的Host证据模块隐藏校验、追加、每能力代次/claim、当前指针、用户覆盖和历史兼容；保留原人工/确认关系；OCR空结果有效。只有完整物理响应可以进入单能力验证，逻辑成功独立提交。使用独立只读legacy引用而非复制/编造历史Evidence。

候选比较：

- 继续综合表+按时间取最新：改动最少，但无法表达独立失败和晚到保护。
- 为四能力复制控制器/写表/人工规则：局部直观，但权限、重试、修订规则易漂移，故不采用。
- 本提案：共享Host提交与纯选择规则，各能力有值validator；增加代次/兼容复杂度，但能统一保护用户状态和解释来源。

取舍：新增schema与兼容调用方适配必须一起评审；无法支持新能力状态的旧bundle契约不伪造完整结果。P04持久门控只防旧提交，P05才承担队列恢复；保留旧有效结果优于从旧在途响应回收结果。

待审：标签来源族与规范化版本、caption解除覆盖后的保留文字语义、新能力质量门槛、schema编号/DDL、旧API新投影契约、P05单一claim所有者。当前不批准实际数据库演进或默认后台分析。

验证/回退：见VALIDATION-PLAN与COMPATIBILITY-MIGRATION；任何降级都必须保留新增证据与人工状态。无运行证据前不认定新接口可用。
