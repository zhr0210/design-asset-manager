# 文档消费的子智能体验证草案

2026-10-15，Asia/Shanghai。用户建议每次写入供AI读取的约束、术语、索引等材料后，使用低思考强度子智能体实际检验检索链路，主Agent依据结果微调，减少用户逐项发现导航问题的负担。用户已回复“采纳”，语义批次自动验证、纯排版结构检查的范围已确认；生效方法归[CONTRIBUTING](../../../CONTRIBUTING.md#document-retrieval-validation)，本页保留讨论来源，不维护平行规则。

## 已核对现状

当前结构检查验证路径/锚点、分类覆盖和迁移保全；adr-context行为测试验证元数据筛选、预算与状态。它们没有证明一个全新上下文的Agent拿到普通任务后，会主动选择正确入口、阅读相关原文并理解适用边界。本轮自审及工具测试不能冒称已有这种独立行为验证。

## 建议的验证方式

1. 主Agent在修改前明确本次材料要影响的可观察行为，并依据用户已确认要求/源码或原规范写验收判据。判据不从本轮新措辞反推，避免自证。候选固定到明确文档字节，验证期间不并发修改。
2. 每个有语义变化的文档批次结束后启动全新上下文、低思考强度的只读子智能体。只给普通用户任务、工作区与只读边界，不透露期望文件、ADR编号、正确路径、作者解释或评分答案。它从项目正常AGENTS/任务导航开始，自主检索。
3. 用一至两个代表任务检查：是否从正确入口选择主题/任务类别，找到适用正文而非止于摘要，能区别有效/Proposed/历史与实际资格，能概述相关保证、冲突或下一动作，知道结果写到哪里，未全量加载无关语料。加一个相邻或边界案例检查规则是否过度扩大。任务数量按本次影响范围，不固定全仓题库每次全跑。
4. 保存可观测工具调用/读取路径和相关章节、用过的路由参数/输出、最终理解及其证据。只审查可观察检索与行为，不要求隐藏思维链；子智能体自报“读过”不够，路径是否出现于工具轨迹与结论是否由原文支持需主Agent核对。
5. 失败先区分任务歧义、入口不显眼、关键词/索引召回不足、内容冲突、误解及上下文过载。主Agent修复材料/导航，不把正确路径偷偷加入验证提示。复验用新子智能体及等价新措辞，避免旧代理记住答案。重复失败仍无根因时保留未通过并定位，不无限重复生成规则。
6. 主Agent是唯一写入者，验证代理只读指定候选；不动产品/资料库/秘密，不自动启动应用/模型/外部服务。若环境无法只读强制隔离，则记录实际工具边界，指令性只读不能冒称沙箱强制。日常验证不派任务让它真正执行有副作用的行为，可让其提出可核对下一动作。

## 已采纳的触发与成本范围

推荐对约束含义、术语定义、ADR/规格适用范围、阅读/写回入口和索引召回变化自动触发；同一有因果关系的小批修改合并一次，不每保存一句话派代理。纯排版/修链仍执行相应结构检查，只有影响可发现性时才需行为探查。改变范围较大、严重保护或低思考代理结果不稳定时增加相邻案例或较强复核，不因低思考配置降低验收标准。

正常情况下主Agent自行选择场景、派发、查看轨迹、修改和复验；不再让用户逐文件/逐检查确认。只有暴露尚未决定的产品/语义冲突才提出具体取舍。通过说明只覆盖本候选和实际探查场景，不保证未来所有模型/措辞都遵循，也不把它等同独立代码审查或真实产品验收。

实施归属建议：AGENTS写文档行加一句触发导航，详细方法放CONTRIBUTING文档维护；检查点保存场景、独立判据、候选身份、代理设置、实际轨迹/结论及修复复验。失败复发进入既有本地问题/LESSONS，不为此另建平行产品术语/ADR/平台。


## 后续验收规范：不引导查阅

用户要求派发仅给简短自然任务、工作区和必要执行边界，不提醒依据文档/规范、查看索引/详细内容或检查已有取舍，也不要求报告文件/命令/检索过程。主Agent从实际工具轨迹判断自主链路。之前长提示只属旧范围记录，不当无引导通过；本次用短提示新上下文复验，生效方法已收紧CONTRIBUTING第7节。
