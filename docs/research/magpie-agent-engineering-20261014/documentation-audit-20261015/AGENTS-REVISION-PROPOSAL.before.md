## 三日期机制的执行草案

每条经验保存同类事件的证据链接、事件id与复盘日期，按Shanghai日期去重。一次事故的重试或多来源重复报告不增加复发次数；旧事故后来再读也不算新复发。

至少三个不同日期出现新的同类复发证据时，路由/检查器把它标为规则候选；严重安全/数据/越权风险立即标候选并处理。候选仍然是建议，不赋予任务外执行权限。

普通工程规则由AI在当前获批任务内评估范围、重复规则、反例与技术自由度，选择合适规范或保护测试落实并写明消费者；独立开发规范的新增建议及归属见上节。涉及产品目标、设计取舍、兼容承诺或资料/费用/权限边界变化时，保留相应用户决定。

提升后保留原经验的事故和日期，链接唯一正式规则/检查，不复制两份独立维护。若候选尚不适合提升，记录具体原因与以后重新检查的条件，不能只把计数清零。既有保护不会因缺少三日期历史而失效。

当前工具仅解析路由、分组、状态、Check，尚不识别这些候选数据。后续实现需有去重、日期、严重等级、已提升引用、路由提示与预算回归，不能先在文档里宣称自动识别已成立。
