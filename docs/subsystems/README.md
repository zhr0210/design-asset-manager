# 软件子系统

按运行中的状态/权限拥有者组织五个一级系统；一个系统可跨Main、Client、Renderer、原生helper与Worker，内部模块不再平铺成一级系统。按当前问题进入正文的阶段/场景索引，再查必要源码和相关决定；不要求读完五份说明。文档合并不改变进程、API、数据权威或产品资格。

| 子系统 | 负责什么 | 先看哪些场景 |
| --- | --- | --- |
| [GUI与窗口系统](gui-shell.md) | 页面、外壳、设置/详情/预览、输入与状态投影、参考窗口呈现 | 启动/Client安装、导航/草稿、连接反馈、工作台内容、原生窗口；不拥有业务数据库 |
| [应用Host与系统集成](local-host.md) | 单一可信进程、命名通信/角色、应用配置/会话/退出、平台系统能力与文件交接 | 双端生命周期、配置/路径迁移、媒体helper、拖出/ZIP/接收；不代替Library内容或AI资格 |
| [资料库与素材管理](library-lifecycle.md) | 库身份/lease/事务、存储角色、Copy入库、文件夹/标签/笔记/工作集数据及恢复 | 开库/维护、原件/派生、人工优先、内容修订、媒体身份和旧库只读 |
| [AI能力与执行](ai-system.md) | 连接/账户、模型制品、能力请求/后台任务、推理/资源、验证与提交协调 | 按连接→模型→请求→OCR/视觉能力→执行/释放定位；各阶段仍有独立状态 |
| [搜索与检索](asset-discovery.md) | 词法/颜色/语义/图像检索，索引、快照/分页、模型空间与命中解释 | 查询/索引与向量生成分开，AI提供执行能力，Host保留权限与结果提交 |

设置页面归GUI，配置保存/路径操作归Host，库维护归Library；工作窗呈现归GUI，成员/修订归Library，实际文件交接归Host。跨系统动作在起点说明完整链，再链接真正拥有者，不复制一份独立状态机。DESIGN只管设计规范，交互只管可观察行为；[INTERACTIONS](../design/INTERACTIONS.md#按场景定位)及[真实验收](../agents/ui-ux-acceptance.md)分别导航预期和证据方法。

## 维护与审查

正文以职责/状态权威、完整执行链、失败/取消/兼容、平台、源码和验证说明机制；复杂主题用章节索引，不用文件数量代表模块数量。局部接口与算法继续归源码旁README，现行行为归产品/交互规格，视觉归DESIGN，实际资格归CURRENT-STATE，证据归任务报告。

变化时说明触发及前后行为，对照base/候选追踪消费者、权限/数据、副作用及适用决定，更新唯一拥有者或说明契约未变依据。保全有效要求/例外/来源；旧专题只兼容导航，不重建第二套正文。源码存在不证明功能完成，历史PASS不转记。人读与机器文档目录/路由一起维护，方法及三层行为验收见[CONTRIBUTING](../../CONTRIBUTING.md#document-retrieval-validation)。
