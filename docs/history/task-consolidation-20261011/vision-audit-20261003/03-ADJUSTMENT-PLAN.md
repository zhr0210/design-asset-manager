# 03｜优化调整与有界执行计划

状态：**PROPOSED**。本次没有实施。本文件是当前路线调整，不是再建一个与DP/RUX平行的永久规划体系。

## 1. 战略顺序：保留双客户端，恢复AI产品纵切

```text

   ↓
WC01 当前Windows收敛（本包唯一可直接批准的实施批次）
  文件归属/基线 → F01错误隔离 → 平台分发与身份对账
  → 当前文档/失败队列 → 相关验证/增量交接
   ↓
原DP02与DP03的Windows前置：codec资格 + schema备份/升级资格
   ├─ 指定真实本地/已允许API小样本（另授权）
   └─ 独立caption与基础能力组合（合成开发可先行）
   ↓
原DP04：资源Governor v1
   ↓
原DP05：验证组合 + 后台标签/描述/OCR + 模型选择
   ↓
原DP06–08：大库/全文、向量混合检索、设计工作集助手
   ↓
原DP09–10：平台发行、移动收集/同步
```

已确认的双客户端23票/76故事仍保留责任，但每批必须区分完成子集与总承诺。不为修一个已明确的Windows AI问题额外要求全部76故事、所有Provider、所有Runtime或完整插件平台先完成。

## 2. 当前暂停扩展的事项

在WC01与Windows正式前置闭合前，不新增Provider品牌、通用Agent平台、远程/LAN服务、多用户账号系统、插件市场、又一套任务调度器或第三套客户端。不继续以无正式调用方的旧Runtime缓存/状态模块提取作为主进度。不对所有旧目录做批量格式化、改名或删除。

这些是推荐优先级，不是撤销用户已批准功能。确有紧急安全修复或当前正式依赖时，最小处理并登记，不扩成全局重构。

## 3. WC01实施契约

**目标：**接手AI能清楚知道正在改哪一个候选；Windows不支持某一视觉能力时不拖死无关能力；当前状态、命令、来源和失败记录一致。

**不是目标：**本批直接完成Windows所有AI、真实账号登录、安装模型、真实用户库迁移、完整Governor或全部双客户端CU。

**工作区：**指定Windows仓库。开始前重读当前HEAD、TASK及直接文件；本报告的hash只作前态参考。发现更新先重算差异，不恢复本报告时的旧文件。

**允许的实现责任（仍需用户批准）：**现有准入器的内部错误分类/边界；最小平台准备与构建身份工具；已有current文档、源码清单与测试命令闭包；对应合成测试。若需改公共语义或数据协议，先列出具体差异并按同批批准范围复核，不能从“优化”推导任意schema变更。

**默认禁止：**真实素材/凭据读取；外部网络和下载；运行真实模型；用户库写入；Git reset/clean/stash/add .；提交/推送/发布；整体删除`.scratch`或AIModels；修改历史日志为PASS。

## 4. WC01六张实施任务卡

### W01｜固定候选与WIP归属，不清空工作区

**输入：**当前Git状态、HEAD、工作目录、`.scratch/local-dual-client`终态摘要、当前`package.json`与相关源码。

**动作：**
1. 记录HEAD、原始index/staged摘要、已跟踪修改、未跟踪记录；NUL porcelain不得trim前导空格。
2. 将当前改动至少分成“已提交双客户端”“Windows Pi准备/平台seal”“Host schema维护提取”“保留旧Runtime evidence提取”“文档/生成build ID”。记录每组的原授权与相互依赖。
3. 对本批计划修改的文件保存before及摘要。选择性候选缺少被import的未跟踪文件时，先报`CANDIDATE_INCOMPLETE`，不要临时从宿主目录偷偷补文件。
4. 形成一次性干净候选目录方案：来自准确tree + 明确批准的patch + 可证明的既有依赖/资源准备。不能把用户整个工作目录连同AIModels/真实配置复制进去。
5. 对原生依赖沿用已匹配Electron ABI的测试启动器，禁止为shell Node重编整个项目。

**门：**源、依赖、Runtime和证据身份明确；本批回退只反向处理自身仍匹配的差异；不要求先提交用户全部WIP。

**交付：**一份`CANDIDATE-MANIFEST`与文件组清单，引用原运行记录；不要再复制数份同内容状态表。

### W02｜修复F01：能力不可用不全局熔断

**先复现：**用本包`tools/replay-admission-probe.cjs`或等价原生产函数测试保留Windows红灯；加入正式Controller到共享准入的最小集成断言。

**设计必须区分：**
- `capability-unavailable`：未支持平台/codec/version，无真实资源危险；只影响该能力/执行配置。
- `attempt-failed`：该次可确定结束的调用失败，许可按实际释放归还。
- `resource-unsafe`：真实峰值超限、占用未知或根资源池不可信，按受影响池保守暂停。
- `authority-revoked`：库/客户端/操作权限失效；不能靠恢复资源许可复活写权限。

优先使用现有错误码和局部类型，不为了分类建立全能错误平台。检查可支持性应尽量早于素材材料准备；但UI预检查不是Main权威。

**实现：**保留视觉codec资格拒绝；将仅平台未支持与实际估算危险分开。释放所有本次材料/计时器，保留任何未确认退出的占用。`resume()`只能恢复适用状态，不能清空真实危险记录。OCR的自身Runtime/信任/权限资格继续独立检查。

**必须通过：**
1. Windows不支持视觉输入 → 返回明确不可用 → 资源全部归零。
2. 相同账本后续OCR/生成探测的“资源申请”在预算满足时可被受理；不等于OCR/模型已可运行。
3. 真正估算超限仍阻止受影响操作；UNKNOWN在真实release前不归还；多个UNKNOWN互不代清。
4. 排队取消、库切换、关闭、重复dispose、过期receipt不泄漏、不负数、不复活旧任务。
5. macOS原有合格路径不被修改为免校验；无Mac实际工具时保留NOT_RUN，并运行可用的跨平台契约。

**不做：**删除`darwin/arm64`检查直接放行Windows；把未知遥测当0；在UI伪造已就绪；再次构造两个独立资源账本。

### W03｜把平台分发、构建与测试候选绑定起来

**动作：**
1. 对照HEAD的Mac release和WIP的Win release，检查准备脚本、锁、Node路径、worker源、policy/认证协议、许可证、额外文件和Main seal的闭包。
2. 固定source inputs和platform artifacts的角色。目标构建只能读取对应目标的合法manifest；不能用测试注入`releaseSha256`覆盖来通过正式验证。
3. 基于现有脚本输出离线的准备计划；既有已批准Windows依赖可核验使用，无需重复下载。需要下载时明确目标/版本/大小/来源，未获权限则该子步骤等待，不静默联网。
4. `.gitattributes`仅对确有字节契约的文本加明确LF规则；Windows CRLF问题与可执行权限分别处理。不得一次`renormalize`全部历史WIP或压缩包。
5. 构建身份写入候选的生成区/实际输出后重新冻结。区分source tree、build、Runtime release、依赖和测试输入；当前开发generated.ts旧值不当作运行中About事实。
6. 在独立候选用默认生产资源入口进行离线verify和合成单次协议测试；缺少分发物不能用覆盖fixture宣布候选可用。

**门：**候选在声明的Windows目标上可按记录重建；tamper/wrong platform/missing runtime/extra package/symlink仍拒绝；不依赖未声明宿主文件。完整安装/签名不在本批，NOT_RUN保持。

### W04｜统一current入口与约束解释

**具体修正：**
- README顶层改为当前本地双客户端入口、准确平台状态、单一current链接。
- CURRENT-STATE只保留本次候选/当前WIP差异、已验证范围、下一步、阻塞、历史索引。
- RELEASE-ACCEPTANCE保留交付门；把“仍是Legacy / 下一步#12”等过期事实移到带日期的历史区。
- REHOST标明原full-project快照与当前本机Windows提交的关系；不暗示未推送提交已在远端，不替用户push。
- AI Gateway说明通过共享Client/Host进入；Pi与OCR执行责任准确；旧`.ai-run`入口作为历史，不冒充Windows当前。
- CONTEXT保持词汇与不变量索引；长历史详情另存并保留链接。第一次只处理当前任务涉及章节，不做全库搬家。
- AGENTS采纳04提案的补充范围，不整份覆盖，不丢原件/权限/CU/真实账号边界。

**门：**新AI只读README→current→对应模块，就能知道当前候选、真实可用性与未运行项；没有两个文件互相声明相反current。

### W05｜把失败变成可执行队列

**动作：**将已声明失败映射到当前候选和影响，不重复运行全历史。
- 平台资格阻断：保留明确expected unavailable，但不能将它当成功功能。
- Pi默认资源失败：由W03默认入口证明；fixture通过单列。
- 测试runner错误：恢复正确runner并保留原失败；不提高时限蒙混。
- 当前命令引用未跟踪文件：处理候选闭包，不删除治理检查。
- visual golden：先核对同一构建/字体/数据/尺寸/DPR；真实差异按批准设计处理，不能直接改阈值或baseline。
- 历史源码正则断言：证明原约束被行为/注册/权限测试替代后才修断言，不以代码重命名作为理由直接删保护。

每行必须有`case/file、source/build、actual result、root-cause class、user effect、owner、next command、gate impact`。未知填UNKNOWN，不写“已知所以可忽略”。

**门：**context检查和本批相关测试在最终候选成立；未关闭项说明阻塞哪个具体交付门，不通过重新定义范围隐去76故事。

### W06｜验证、独立复核与停止

1. 最后一次代码变化后，重跑受影响准入/取消/回收、类型、context、候选资源检查；保留sourceDigest。
2. 用当前正式客户端从可见入口确认AI配置可发现、Windows不支持项原因清楚、一次视觉失败不让无关状态永久挂起。没有工具则CU为BLOCKED，不用改route/IPC代替。
3. 只读reviewer核对生产是否有测试放行入口、是否放宽真实资格、是否误删WIP/数据、证据是否绑定最终候选。
4. 输出一个增量包或可直接Remote定位的run目录：before/after、patch、source+artifact manifest、原始测试日志、失败清单、review、最终STOP。
5. 更新固定current投影。保留历史FINAL，不把旧snapshot重新写成当前。`nextBatchAuthorized=false`，不自动进入真实账号或Windows生产资格任务。

## 5. WC01之外：Windows真实AI前置的细化范围

这部分用于下一次规划，不包含在默认WC01授权中。

### 5.1 受控图片预处理的Windows资格

复用现有Worker和预算接口，增加真实平台Adapter/资格数据，而不是在业务函数到处判断OS。限定Win x64、已锁定Sharp/libvips/Node/Electron组合和输入范围；合成PNG/JPEG、透明/方向/极大尺寸/错误文件、取消/子进程close、峰值超限、强制退出、资源返还逐项验证。依赖版本变化撤销资格，Mac原组合保留。

测的是预处理峰值与行为，不是模型峰值；合成可用不能推导所有格式/低配电脑已验。平台未支持给明确修复路径，不让用户看到“连接成功所以可以分析”的假状态。

### 5.2 现有schema升级的Windows备份资格

优先限定已有本地NTFS目录和现有库布局。核对独占锁、SQLite/native匹配、journal模式、一致性备份、校验、空间预留、重命名/flush/句柄语义和失败恢复。使用真实临时库，不用SQLite替身证明落盘原子性；测试v1/现有相关版本到所需版本、DDL/commit/ack切点、关闭竞争、重开与旧读者拒写。

不自动升级用户库；不将为Windows新增支持改写为放宽所有网络盘/同步盘/外置文件系统资格。未知盘保持不支持。统一维护模块可以复用，但生产必须使用自己的合格backup port，不能沿用测试hook充资格。

### 5.3 最小真实模型/账号验收

优先一个已安装本地兼容服务和一个当前允许的API/ChatGPT连接，而不是全品牌测试。用户明确指定账号/服务、生成素材、实际外发目的地、调用数、时间与费用上限；仅登录不自动授予推理。

从普通UI完成选择→审阅→执行→保存→重开→检索，检查成功回执复用不重复调用、失败保留旧内容、取消不晚写。Keychain/safeStorage采用单独合成秘密与系统实际保护测试；密码/token只由用户在厂商页面或本机安全入口处理，不进入报告。

没有真实账号授权时，可以交付代码/合成证据，但根因与真实可用性仍NOT_RUN。不得重新永久禁用登录后宣称用户故障解决，也不得绕开身份验证来得到“登录成功”。

## 6. 原AI主线的恢复标准

### DP03：独立描述先行

新增caption自己的配方、结果和请求代次/用户覆盖关系，不再依赖综合四字段请求。标签成功可用、caption失败不回滚、OCR无字是有效结果、高级反推仍手动。必要schema方案按当时真实版本评审，禁止预设v14或重写全部证据。跨客户端只消费同一Host结果，不复制任务。

### DP04：Governor v1只整合现有账本

统一系统RAM、各独显VRAM、统一内存池；驻留与任务峰值分开。用户百分比转换为DAM预算目标，未知遥测保持未知。忙时快速退让、恢复迟滞、模型切换冷却；给后台明确可行配额，不只用封顶aging声称无饥饿。用户外部服务不受DAM进程终止权。该能力不得用停留在旧禁用Runtime分支的实现冒称交付。

### DP05：真正后台三能力

每项能力只有实际配置/设备资格满足才启用；不能直接把production qualification从null改verified。恢复按素材×能力，保留unknown核对，不自动重推可能计费的远端请求。手动模型固定不绕预算，资源不足不偷偷上云。先完成一个真实组合的批次，再扩大组合目录。

### DP06–10：不再因平台扩建无限顺延

Host受控分页/中文全文与后台计数可先做独立切片；之后向量空间代际、可解释混合检索、设计提议工作集。移动端仍为后续产品，loopback server不直接升级公网同步服务。原生窗口和macOS/Windows双平台检查贯穿，不等签名发行阶段才第一次考虑。

## 7. 连续执行与授权边界

同一批准批次内，一个切片适用门通过后自动继续，不逐票询问“继续”。缺少工具/平台/外部授权只暂停依赖部分。最多三次有证据的同问题修复；连续两次同错无新增证据，转更小复现/独立审查，不降低门槛。

阶段检查点记录修改、证据、未完成测试、实际进程事实与下一动作。上下文不足时保存磁盘检查点；跨会话自动恢复需要真实运行器，本计划不声称已部署。只有用户批准范围完成、真实阻塞、预算耗尽或用户暂停时停止；始终准确保留PARTIAL。
