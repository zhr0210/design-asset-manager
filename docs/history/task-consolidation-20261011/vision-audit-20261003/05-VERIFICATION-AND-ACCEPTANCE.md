# 05｜验证标准、失败分类与交付门

## 1. 不再使用单一“全部通过”

| 验证层 | 证明什么 | 不证明什么 |
|---|---|---|
| 源码/包存在性 | 所需路径已提供 | 内容正确、Runtime可执行、模型可用 |
| 类型/静态检查 | 当前输入能被工具接受、归属/依赖符合规则 | 用户任务、资料库恢复、平台可用 |
| 生产函数隔离检查 | 真实算法/状态机在明确输入下的行为 | 完整Host/原生系统/真实模型 |
| 临时真实Host/SQLite/HTTP | 真实事务、协议、权限、幂等、资源释放 | 用户可发现入口或真实厂商服务 |
| Browser CU | 指定构建/客户端的普通可见用户路径 | 原生置顶/跨屏/桌面拖拽/签名安装 |
| 原生CU | 指定平台的真实系统效果 | 其他平台或Browser流程 |
| 指定真实AI验收 | 特定模型/配置/平台/账号的实际结果链 | 全Provider、所有模型、全部质量与最低配 |

最终报告按这些列分别填写。一个脚本里若部分步骤用IPC/Store建立业务状态，整条不能称纯CU；后台诊断可另做，但不得代办用户原本必须经过的步骤。

## 2. WC01最低验证集合

### A. 来源与候选

当前HEAD/WIP/候选tree分开；index/staged before/after；依赖锁；平台release与Main固定摘要；默认路径而非fixture override；必要脚本都随候选存在。line-ending、target、missingfiles、unexpectedfiles、symlinks必须保留测试。

### B. F01错误隔离矩阵

| 输入/事件 | 期望 |
|---|---|
| 不支持平台的视觉prepare | 明确不可用、无Worker调用、无遗留材料 |
| 不支持之后的OCR资源申请 | 预算满足则可以申请；OCR自己的Runtime/数据权限另验 |
| 不支持之后的Pi生成探测资源申请 | 同上；不借此自动调用Provider |
| 实际codec峰值超限 | 受影响池保持保守限制，不盲resume |
| 已发请求但进程退出未知 | 占用直到对应release；一个release不替另一个清账 |
| 排队取消/过期/重复dispose | 无重复归还、负数、丢失活动任务 |
| 关库/换库/撤权后迟到响应 | 无晚写；资源恢复不恢复旧业务权限 |
| 其他能力正在执行 | 局部失败不删除另一任务/模型驻留占用 |

### C. 当前脚本与历史记录的关系

可复用的起点：`visual-admission.integration.test.ts`、`ocr-controller-lifecycle.test.ts`、`library-quiescence.test.ts`、`pi-runtime-verification.test.ts`、`local-dam-command-replay.test.ts`、`local-dam-browser-unknown-commit.test.ts`。实施时先确认真实文件、runner和依赖；不要把这份列表当自动运行整个仓库的指令。

SQLite测试用仓库Electron Node runner；无SQLite的纯脚本使用适合其API版本的Node runner。遇到MockTimers等运行器错误，保留原结果，限定重跑；不得为了运行shell Node测试重编用户的Electron原生依赖。

## 3. Windows生产前置的验收要求

**图片预处理：**真实平台进程、固定codec版本、尺寸/字节/透明/方向/损坏输入、冷/热运行、取消/close、峰值/预算；不运行真实大模型也可以验证这一层。

**schema：**新建本地临时库、已有相关版本、独占锁、备份有效性、完整性、空间不足、句柄持有、flush/重命名、DDL失败、commit成功ack丢失、恢复/重开、旧读者拒写。合成DBAdapter不能替代此门。

**Pi：**正式target准备输出、完整清单、真实固定Node/SDK、默认Host加载、自有HTTP响应、单次调用/截断重试总预算、取消/UNKNOWN、无环境凭据混入。平台覆盖夹具是补充，不替代默认分发。

**真实服务：**用户指定账号/本地服务、生成输入和有限预算；从UI执行并重开读取，保留原件摘要。目录成功≠图像理解，JSON成功≠质量合格，HTTP取消≠远端停止计算或计费。

## 4. 双客户端优先用户路径

当前不重做所有76故事，但以下受影响路径必须与候选绑定；其余仍在原规格中登记未完成。

1. **普通启动到AI配置。**Desktop与Browser各从批准入口进入；未开库/已开库/关库/恢复错误时均能找到“AI与模型”；旧URL只作兼容测试，不代替正常入口。
2. **Copy→检索→详情→保存→重开。**合成素材，正式Host，选择器不越界；人工描述/标签不被AI覆盖。
3. **两客户端冲突。**A保存、B保留脏输入；显示差异，明确采用新基准后再保存；迟到旧响应不覆盖。
4. **网络断流与未知提交。**断连禁写、输入保留、重新校准不自动写、权威重读确认；底层重发最多一个业务效果。
5. **切库/退出。**有草稿时审阅，取消精确恢复；确认退出收敛全部参与者；关闭一个surface不谎称Host退出。
6. **Windows不支持某AI前置。**显示准确原因和下一步；局部不支持后仍能操作无关配置/资源，不变成全局僵死。
7. **原生工作集。**置顶、隐藏/恢复、跨屏、关闭/内容保存需真实桌面工具；Browser发出请求成功不算系统效果PASS。

现有DESIGN中的1024/1440及后续小窗口要求，以最新批准规格为准。对640等辅助尺寸报告实际viewport/DPR；缩放命令未生效不能写已验收。Goldens先同构建/字体/数据/尺寸，失败保持失败；更改设计基准需明确批准。

## 5. 失败分类

| 类别 | 处理 |
|---|---|
| 当前正式行为错误 | 最小红灯→修复→相关绿灯；阻塞所影响用户路径 |
| 生产平台不支持 | 明确产品状态；补资格前不得开启；不能计成可用性通过 |
| 分发/ABI/缺依赖 | 核对target和runner；经批准准备，不使用环境偶然依赖 |
| 测试代码/runner错误 | 原失败保留；证明测试修订未减弱语义，重跑正确入口 |
| 旧实现细节断言 | 用行为/注册/安全测试对等替代；不能单为PASS删除 |
| 视觉真差异 | 对照批准设计修复；未经批准不更新baseline或阈值 |
| 源码/证据身份不匹配 | 相关旧证据STALE，不借另一工作区的绿灯 |
| 无工具/外部权限 | 对应门BLOCKED/NOT_RUN，独立工作继续 |

“旧失败”不是根因；“有22个FAIL”也不直接意味着22个生产缺陷。每行要有当前source和影响范围。

## 6. 持续执行的退出条件

本批适用代码、来源、资源/取消和文档门通过，并有诚实的CU/真实平台状态。所有属于本批的P0/P1必须关闭，或者明确形成受限交付且不能对外宣称该功能可用。

脚本退出0但没有执行目标用例不算PASS；父包装脚本返回0也不能掩盖子命令exit3。本次审阅就保留了context检查的独立exit3。

不把工具调用次数、历史PASS之和、截图数或几千行清理数作为业务完成指标。独立reviewer若不可用，写SELF_REVIEW而非伪造第二执行者。完成后STOP，新批次需要新范围。
