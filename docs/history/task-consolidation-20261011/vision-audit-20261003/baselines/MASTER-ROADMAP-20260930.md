# 02｜从当前代码到完整产品的开发总路线

2026-09-30｜目标设计，不是已实现事实｜版本2.0。

本路线继承原目标架构，不重开P00–P27已产出的全部规格。用DP编号管理从当前现场基线开始的交付批次，旧P编号仅用于来源追踪。授权按批次推进，不把十阶段一次交给AI无限执行。

## 1. 不变目标

DAM是本地优先的素材管理与创作参考工作台。保留macOS/Windows，未来移动端侧重收集管理、云端推理。入库不等待AI；默认基础分析为标签/描述/OCR；高级反推由用户主动选择，可批量。每个能力成功即用，失败不清空旧有效结果、不覆盖人工内容。配置服务、登录、处理位置声明、能力证明与本次外发授权分别管理。

用户能选择本地或已批准云端、普通验证组合或高级配置。资源目标是尽力遵守DAM预算并响应系统压力，不承诺把物理RAM/VRAM硬隔离给其他应用。大小模型切换发生在可验证边界，不能以资源不足为由偷偷上云。

素材Original/Preview/Variant、Managed/Eagle/Legacy、用户编辑/AI证据、工作集引用/素材生命周期继续分离。暂不重做UI/UX；只为新能力补必要配置、状态和错误展示，沿用DESIGN与共享组件。[H02/S00]

## 2. 目标结构与最小依赖

```text
素材收录/用户请求
  → 能力计划 tags / caption / OCR / advanced reverse
  → 库内持久任务意图与尝试
  → 当前Host会话、内容版本、执行许可、外发许可
  → 模型/Runtime执行配置选择
  → 设备资源许可 + 模型驻留许可 + 单次计算许可
  → 受控输入
      ├─ Pi Gateway / API / 已运行外部本地服务
      └─ DAM托管本地Runtime / 专用OCR
  → 能力结果验证
  → Host事务：证据、当前结果、幂等回执、Outbox
  → 分页读取、词法/向量投影、工作集和设计辅助
```

Pi是调用/认证适配层，不负责替代Host、资源Governor、业务重试或所有任务持久化。SDK类型不扩散到数据库与Renderer。当前单能力控制器先通过窄适配参与计划，不先重写成全能队列。[W01/S04]

横切能力：凭据与连接身份、来源谱系、可解释诊断、权限/撤销、schema升级、分层测试、跨AI锚点。开发AI的检查点不进入用户资料库；应用任务恢复与编码会话恢复不是同一机制。

## 3. 阶段图

```text
DP01 当前基线/旧OCR候选/锚点/真实验收入口
 ├─ DP02 指定本地/API真实验收（需明确外部权限）
 └─ DP03 独立描述与基础分析组合
       └─ DP04 资源Governor v1和运行成本
              └─ DP05 已验证配置的三能力后台执行
                   └─ DP06 Host大库查询/全文与分页
                        └─ DP07 Embedding/混合检索与来源
                             └─ DP08 设计辅助与工作集工具
                                  └─ DP09 发行与开源门槛
                                       └─ DP10 手机端与同步

DP02未获真实账号授权，不阻塞DP03/DP04的源码与合成验证；
DP05生产启用必须有相应能力/设备的真实资格，DP02单次成功不等于后台资格。
EXT01 OpenAI订阅、EXT02 Google原生是独立支线，不让它们阻塞主素材闭环。
Windows检查、安全回归、诊断与文档随阶段推进，不等到DP09才第一次考虑。
```

阶段顺序是当前推荐；DP06可以在接口稳定后提前做只读调查或独立查询切片，但不能与其他写者无协调修改同一Host文件。

## 4. 主线阶段

### DP01｜当前基线收敛与可复用验收入口——下一批详细计划

交付：在真实仓库按当前代码移植旧OCR Runtime观察撤权补丁；完成Mac相应测试；建立版本化锚点；增加只在明确授权后调用的已开放服务验收入口。详细范围见[03](03-DP01-IMPLEMENTATION-PLAN.md)。

不做：再次重构Pi、打开被禁Provider、真实账号/模型、schema变更、依赖升级、缓存重构、自动提交。目标不是新一轮架构文档，而是消除已知遗留并让下一批有精确起点。

退出：当前缺陷测试/原后台OCR受影响回归通过；新锚点区分完成范围与生产资格；验收入口默认零网络、零凭据读取，合成环境走真实Controller/Host；生成最终增量与状态。

### DP02｜已开放本地/API路径的真实验收

先选一个**已经允许的本地兼容服务**和一个**已经允许的API连接**，不一次验证所有品牌。用户指定服务、模型、凭据建立方式、生成输入、调用/费用上限；默认不扫描已有设置或账号。不获批准则只完成计划与合成脚手架，保持WAITING_AUTHORIZATION，不伪造PASS。

沿正式Gateway和Controller到临时Host，检查能力小图、综合分析、独立标签、单次高级反推、可取消/迟到拒写、重开读取及成功回执复用。按真实Provider收集请求数量、首响应/总耗时、输入输出token、可得费用估计及不确定性。目录请求计入网络预算，网络超时不触发盲目重发。

同时提供独立Keychain资格切片：只用临时隔离profile和专门生成的合成秘密，真实safeStorage读写/重启/不可用拒绝；必须另批OS保护动作，不读取真实密钥。Windows凭据与安装验证单列。

退出：报告精确列出“哪个连接/模型/版本/平台/动作通过”；不扩展为整个Provider所有模型通过。不把请求协议正确或双色图通过认定为设计稿质量合格。

### DP03｜独立描述与真正可组合的基础分析

已有tags和OCR不重做。新增独立caption能力、配方版本、输入身份、结果证据及当前有效投影；保留用户手工描述覆盖层。先完成手动单项与小批，再让“一键基础分析”展开三个独立逻辑任务，高级反推不默认启动。

首先审查真实v13 schema与当前综合证据；确需新增持久字段才写本票DDL和升级/兼容/备份决策，不预设下一版一定v14。模型/Provider选择留在ExecutionProfile，配方与质量规则留在能力内。综合旧证据可投影但必须保留来源，不能冒充新的独立分析。

第一版允许分别执行，保持共享预处理与模型驻留的扩展点；物理请求合并要有完整响应与逐能力校验后再引入。不从截断JSON抽出标签冒充成功，不因caption失败回滚已经完成的OCR。

验收：tags成功/描述失败/OCR有效空三种状态可同时存在；单项重跑不改变其他成功结果和人工编辑；旧综合和新单项共享正确请求代次/当前结果规则；断点恢复不重做已成功能力；新分析不自动调用反推。

### DP04｜资源Governor v1与运行成本治理

最小对象：平台遥测样本（值/采样时间/可信度）、用户策略、资源池、原子准入、模型驻留许可、任务计算许可、释放凭据、决策原因。先复用VisualAdmission/OCR/Pi监管，逐步转接，不能同时存在两个都认为自己独占同一设备的账本。

资源池分开系统RAM、各独显VRAM、统一内存。统一内存不能再把CPU/GPU占用简单相加。用户百分比转换为DAM使用目标和安全余量；未知GPU读数不能当0使用量。除内存外记录线程/并发、忙闲、电源/热状态与实测峰值。不能用“没有键鼠输入”单独认定空闲。

规则优先：压力升高快速降速，稳定后缓慢恢复；任务间切换，设冷却期；已运行不可抢占任务按最小安全边界停止。取消Promise不是资源释放，UNKNOWN继续占账；非本应用启动的服务不能擅自终止。手动请求优先但在可行预算内为后台设置有限轮转/配额，不能只靠有上限的aging声称无饥饿。

本阶段量化Pi每动作全量校验成本；先验证可共享的同一次校验和不可变版本边界，再决定是否缓存。缓存失效、替换、额外包遮蔽、symlink、改版本、取消必须有反例；缓存不是默认必做项，收益或可信边界不足就继续全量校验并标明成本。

退出：合成压力轨迹下并发准入不超账、UNKNOWN不早放、Windows未知遥测安全降级、忙闲状态稳定；真实目标机上浏览/搜索交互有基线与后台对照。性能目标在测试前冻结；尚无最低配置实机时不承诺最低配体验。

### DP05｜验证过的模型组合、后台三能力与模型切换

普通模式采用少量Model/Runtime/量化/预处理/配方/设备组合，安装就绪、能力证明、资源资格分别记录。高级模式自由配置，但未验证组合要明确标记，不能把“能返回模型列表”当可自动调度。

为每个能力注册执行适配器，由一份计划读取既有意图。后台资格包含实际模型/Runtime峰值、输入上限、同批资源、电源策略、会话许可和版本有效性。仅当相应真实资格获准并通过，才替代当前production qualification=null；合成测试不能直接写verified=true进入用户路径。

自动或手动大小模型选择先按能力质量/许可筛选，再按资源和延迟择优；正在生成中不任意替模型。使用实际配置生成新attempt与证据。云端后备必须已有适用外发/成本授权，不能静默转发。长输出的高级反推与短标签不同策略，不强行共享相同输出预算。

持久恢复以素材×能力为单位。旧会话sent/unknown仅凭“重启过了”不能重领；补人可理解的核对/放弃/重新请求路径，并明确旧证据与外部执行不确定性。确认重试不等于确认旧进程已经物理退出；释放设备预算还需要独立证据。

退出：默认新入库计划能渐进产出三能力结果；成功即时可读、失败聚合提醒、暂停/恢复/重开有证据；交互不因后台批次被阻塞。只对验收组合启用，不追求一次覆盖所有Runtime。

### DP06｜Host查询、中文全文、大库与后台更新一致性

将主列表和检索逐步由Renderer全量投影改为Host受控分页。索引是可重建投影，SQLite权威数据不变。中文分词、别名、OCR和用户描述优先级单独验证，不假定默认英文tokenizer足够。

同时处理B01计数每5秒全量聚合的OBS。先对1千/1万/10万**合成元数据**测查询形态和耗时，再选择提交事件驱动计数缓存或增量投影；这不证明10万真实缩略图加载性能。记录写放大、构建耗时、内存与重启重建。

分页版本区分结果集合/排序变化与行内容刷新；不能每写一条AI结果就强制用户从第一页开始。权限撤销、回收站和内容删除及时生效，快照不能延长旧读取权限。

退出：大量后台结果写入时仍可连续翻页和搜索；缓存失效/重建不丢权威结果；查询有可解释命中。API批次计数与全库计数分别限界。

### DP07｜Embedding、混合检索、来源谱系与重复候选

向量空间身份至少绑定模型/版本/维度/归一化/预处理；维度相同不代表空间兼容。更换Embedding建立新索引代际，允许旧代只读过渡或重建，不悄悄混用。

合并词法、用户标签、OCR、描述、图像/文本向量及颜色/尺寸条件，排序融合通过标注样例验收。命中解释引用实际证据，普通搜索不必每次启动生成模型。

建立Original→Preview/裁剪→分析输入→证据→索引的谱系与缓存键；绑定内容、模型/投影、预处理与库权限。精确哈希与感知相似分开，重复候选不自动删除素材。派生失效可重建，来源不丢失。

退出：模型切换/旧向量/回收站/撤权/裁剪坐标均正确；质量测试用固定查询集，不只计算索引能不能返回一个结果。

### DP08｜面向设计工作的受控AI助手

先做“需求描述→解析条件→本地检索→证据说明→工作集提议→用户确认保存”。明确风格、构图、颜色等可观察事实与创作推测，反推不宣称找回原始prompt。

只提供searchAssets/getAssetEvidence/proposeWorkSet等窄工具；不开放任意SQL、任意路径、删除原件或任意shell。OCR/素材文字是不可信数据，不得作为执行系统指令。建议与真正写入分开，工具写入幂等；撤销工作集修改不删除素材。

复用已有Work Set、原生窗口和用户笔记，避免新增一套重复素材实体。公开工具协议/MCP属于后续边界，不为它建设全能插件市场。

退出：助手可以完成可复现的设计参考任务并解释证据；含恶意素材文本的测试不能突破权限；失败不留下半提交工作集。

### DP09｜平台、开源与发行准备

平台工作持续推进，本阶段汇总真实Windows/macOS、CPU架构、独立Node分发、原生依赖、OS凭据、沙箱和安装签名的证据。不能由macOS目录副本启动成功推定Windows安装包可用。

开源前逐项检查许可证、模型许可/制品来源、供应链、默认数据外发、日志脱敏、依赖重建、干净环境构建、回退与用户手册。危险示例/测试放行不能进入生产可配置表面。无真实账号时API功能可标未配置，但不能伪称跨服务验收完成。

用户数据迁移另有样本与备份计划，真实库操作单独批准。发布、推送、签名账号及商用服务注册不是持续编程默认权限。

退出：平台矩阵、安装/卸载、升级/失败回退、模型组合手册和已知限制完整，公开标签与实际可用能力一致。

### DP10｜手机收集管理、云推理与多端同步

共享素材身份、能力结果语义和同步契约，不共享Electron IPC、桌面绝对路径或SQLite连接。移动端先做收集、组织、浏览与云推理授权；不强行移植桌面本地模型运行时。

同步与推理上传分开授权；离线收集队列、重传幂等、内容哈希、修订冲突、删除标记、设备撤权及带宽/费用单列。不要用同步整个活动SQLite文件代替多端冲突协议。

退出：桌面/移动离线编辑与重新连接可复现；失效设备不能继续读/写；云端不代持用户未授权数据。视频/音频/录屏/抠图/专业工具按真实用途增量接入，不成为手机第一步的全部前置。

## 5. Provider独立支线

### EXT01｜合规的OpenAI订阅接入

可以与DP03等只读规格并行，但生产启用有独立门槛。先依据W02/W03复核当前开源/本地分发场景适用性；付费或远程托管场景不能直接继承相同路径。

最小技术范围：稳定host ID、实际应用名、首次注册与返回账号client复用、PKCE/state/nonce、固定回调、签名/issuer/audience/expiry/nonce/subject校验、权限scope、受控JWKS/令牌网络、账号选择、刷新串行与旋转、取消/重放/崩溃补偿。ID token有效不等于有推理权限。现有Pi适配不满足时采用经过批准的窄认证桥或固定依赖升级，不手写密码学，不复用旧Codex内部路径冒充新认证。

先真实SDK/适配器+假网络，再另批生成输入/指定账号/额度的真实验收。通过前保持产品限制；旧凭据不自动迁移、删除或外发。

### EXT02｜Google受控原生传输

在“继续禁用”“经批准升级到支持保护的SDK”“专用窄传输”之间基于固定源码作决策；保持目的地、重定向、原始字节、取消、重试及终态保护。不简单删除approvedFetch，也不靠生产全局fetch猴子补丁掩盖差异。实际协议合成测试通过后再做单独真实服务资格。

Claude订阅和Copilot不作为默认解锁任务。任何厂商规则变化重新查一手资料，不能由模型名单或旧登录成功推定允许。[W04]

## 6. 各阶段都必须有的开发产物

每批只有一份简明实施说明、一份明确文件范围、一套任务/验收表和一个当前状态入口；复杂schema/身份契约才补独立设计决策。每个子任务交付真实代码/测试或明确的阻塞事实，不以更多文档替代目标。

最终交付应含精确before/after、当前源码清单与显式算法、实际命令/退出码/日志摘要、失败保留、独立复核边界、NOT_RUN、当前进程事实、STOP与下一批待授权。每完成一片更新检查点，不每片打包全仓库。

当前阶段和历史P任务映射见[06](06-SOURCES-AND-TRACEABILITY.md)；完整机器依赖见[PLAN-STATE](PLAN-STATE.json)。
